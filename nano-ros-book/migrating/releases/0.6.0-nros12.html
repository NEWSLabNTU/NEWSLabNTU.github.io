nano-ros Book

0.6.0-nros12

Reference · Level 2: Building real applications

A project generated with 0.6.0-nros11 builds as it is: codegen is unchanged, so nothing needs to be generated again.

Edits you may need to make

  • A system contract written with the old spellings is refused. Each error names the new spelling. Run play_launch migrate <contract> --write to rewrite a contract in one step. The renames are:

    • functions: is now capabilities:.
    • A hazard’s enters: is now leaves:.
    • A manifest-level paths: is now event_chains:.
    • min_rate_hz, max_rate_hz and rate_hz are now min_rate, max_rate and rate, written with a unit (100Hz).
    • A contract’s supervision: moves to the target’s platform file.
    • policy: is now the checker’s --deny <rule>.
    • integrity_levels: is now use: of a profile.
    • max_transport on an endpoint or a service is now a link.
    • observes: written as a string is now { input }.
    • early.drop is now early.decrease.

    The system model is now schema 6, and contracts.scope_paths is now contracts.event_chains. Older models still load.

  • A contract’s QoS values and launch arguments are checked. reliability, durability, history and liveliness must name a ROS 2 value. A typo such as transient-local is refused, and the error names the key, the value and the values allowed. system_default and best_available are accepted. A contract whose arguments fail is now an error[manifest-args]; before, the contract was dropped without a word. Arguments fail on a required argument not passed, a value outside its choices:, or a QoS $(var …) outside the allowed set. Fix the value the error names.

  • A parameter the store has no room for stops the boot. Before, the node ran on its compiled default and the launch or YAML value was lost without a word. Now:

    • In C++, declare_parameter<T>(name, default) latches NROS_CPP_RET_FULL on the node, and the entry halts boot.
    • In C, rclc_add_parameter and rclc_parameter_declare_* return RCLC_RET_FULL for a full store, where they used to return RCL_RET_ERROR. Code that compares against RCL_RET_ERROR needs the new value.
    • Every language logs a line naming the node, the parameter, the store’s size and the knob that sets it.

    To make room, set max_parameters under [knobs.params] in system.toml, or set NROS_MAX_PARAMETERS or CONFIG_NROS_MAX_PARAMETERS. If you leave it unset, the size is derived when every node in the image declares its parameters under params: in its contract.

  • list_parameters filters by prefix and depth as rclcpp does.

    • A prefix matches itself, or itself followed by .: robot no longer selects robotics.
    • depth counts the separators after the prefix: with prefix robot, depth 1 no longer returns robot.arm, and depth 2 does.
    • With no prefix, depth N returns names with fewer than N separators.
    • Depth 0 still returns every name below the prefix.

  • In C++, a parameter whose launch or YAML value has another type than its declaration stops the boot. Before, declare_parameter<T>(name, default) returned the code default without a word, so the node ran on a value its launch file did not state. The usual case is an integer written for a double: kp: 1 for a parameter declared double. The boot log names the node, the parameter, the value and the fix, for example parameter "kp" is declared double but the launch value is the integer 1; write 1.0 in the YAML. Before you upgrade, check your launch and YAML files for integers written where the code declares a double. Upstream rclcpp throws on the same mismatch.

  • A C or C++ component package whose project() name differs from its package.xml <name> is refused at configure. The message names both values and both files. Rename one so they match, as ament expects.

  • A Rust image on a board builds optimized by default. Before, it built cargo’s dev profile when the image stated no profile. It now builds release with fat LTO, as C and C++ images already did: the mps2-an385 FreeRTOS talker drops from 914,880 bytes of flash to about 500,000. A host image still builds dev. For a debug build on a board, run nros build <image> --profile=dev, or set profile = "dev" on the image.

  • A C or C++ FreeRTOS image on zenoh gets a 512 KiB default heap, derived the way a Rust image’s is, instead of the old 3 MiB fallback. That is about 2.5 MiB less RAM per image. The C talker template peaks at about 90 KB. A larger image prints its own peak on its nros: heap peak boot line; one that needs more sets NROS_FREERTOS_HEAP_KB, as before.

  • Logging to /rosout takes no extra code. In an image built with the rosout capability, the executor creates one /rosout publisher per node and sends each log record from that node’s publisher, as rcl does. Rust nros::rosout::pump and C++ rclcpp::rosout::Publisher are deprecated: both still work, but they add a second publisher, so delete them. C’s rclc_rosout_publisher_init and rclc_rosout_pump stay, for a node made with rclc_node_init_default.

New commands and options

  • nros build --cmake-args=<args> passes arguments to every CMake configure of the build: a CMake image’s, a west image’s and a CMake package’s. The = is required. One value can hold several arguments, split with plain shell quoting (--cmake-args="-DA=1 -DB='x y'"), and the flag repeats. --cmake-args=@<file> reads one argument per line, with # comments. Allowed: -D, -U, -W*, --log-level, --log-context and --debug-find. A name nros build sets itself, and -DCONFIG_* (which goes in the image’s conf), are refused, and the error says where the setting goes. colcon’s spelling, --cmake-args -DA=1, is refused with your arguments shown rewritten.
  • [image.<id>.build] cmake_args = [...] in system.toml states an image’s own CMake arguments, checked the same way. They follow [image_defaults.build] cmake_args, and --cmake-args= comes after both.
  • [image_defaults.build] cmake_args also reaches the metadata probe, which runs once for the whole workspace before any image builds. Put a path the probe needs there, such as -DEigen3_DIR=... for a library of your own: --cmake-args= and an image’s own cmake_args do not reach it. A change to the list probes again.
  • nros build --cargo-args=<args> passes arguments to every cargo command of a cargo image, split, repeated and read from @<file> like --cmake-args=. Allowed: --features, --no-default-features, --all-features, -v, -q, --timings, --locked, --offline and --frozen. In a workspace, name a feature with its package (--features=<pkg>/<feat>). A feature the build chooses itself (the RMW, the platform, a board or capability feature) is refused: choose those in system.toml.
  • nros build --profile=<name> builds with that profile instead of the image’s profile, for one build. It takes the same values as [image.<id>] profile: a cargo profile or a CMake build type. A single-package cargo project now honours profile too; before, it was dropped without a word.
  • An application trace marker: rclc_trace_marker(id, arg) in C, rclcpp::trace_marker in C++ and nros::trace_marker::emit_app_marker in Rust send an event through the installed callback trace sink, on the same clock as the executor’s callback events. Ids 1 to 15 are yours; 0 and the executor’s ids are refused with an error. On Zephyr the default sink writes the CTF stream; on FreeRTOS, POSIX, NuttX and ThreadX the event goes to a sink the application installs.

New boards

  • s32z270-rtu0-zephyr, a Zephyr board for the NXP S32Z270 RTU0 Cortex-R52. It builds and links; no emulator models it. A board’s west_board may now carry a board revision (board@rev/soc/variant), so no -DBOARD_REVISION is needed.
  • s32z270-freertos-rtd, the S32Z270 RTU on NXP’s FreeRTOS port, built from a provisioned NXP kernel (NXP_FREERTOS_S32ZE_DIR) and RTD (S32_RTD_PATH). Name the board instead of setting FREERTOS_DIR and FREERTOS_PORT. The network glue is not part of it yet.

Other new features

  • RCLCPP_<LEVEL>_THROTTLE(logger, clock, ms, ...) compiles and throttles, measuring its window on the clock you pass, as rclcpp does. That clock can be *get_clock(), a steady clock, a system clock, or a ROS time clock driven by /clock. The first record at a call site is logged, then at most one per ms. RCLCPP_<LEVEL>_ONCE, _SKIPFIRST and _SKIPFIRST_THROTTLE are new at every level. All of them work on freestanding targets and take no lock. The C throttle gains rclc_log_throttle_admit_at, which takes the clock reading from the caller.
  • A C or C++ image carries only the parts of the API it calls. Before, every image kept the whole C and C++ API: a talker that only publishes still carried the action server and client. The mps2-an385 FreeRTOS C talker drops from 631,440 to about 424,000 bytes of flash.
  • An image of C and Rust components, with no C++ source, configures on the CMake road and on Zephyr. Before, nros build and nros configure --census stopped with “node pkg ... exec ... is lang rust (a rust component), not c”.

Fixes

  • A list parameter from a launch <param from> file, or written as value="[1, 2]", reaches the node as an array of doubles, integers, bools or strings, instead of one comma-joined string. A list that mixes types is refused at boot with a log line, as ROS refuses it. [] seeds nothing, so the declared default stands.
  • ros2 param list and ros2 param dump see every parameter of a node. Before, list_parameters stopped at 64 names without saying so, and get_parameters refused a request for more than 64.
  • The C and C++ metadata probe holds 1,024 parameters, so a component that declares more than the 32-slot default (an Autoware controller declares about 150) is probed instead of running on compiled defaults.
  • A board package inside your workspace (src/<board>/nros-board.toml) is found by the west configure that nros build starts, so a Zephyr image on that board builds without NROS_EXTRA_BOARD_PATH.
  • A build directory follows the nros that builds it. Before, a directory first configured by another nros kept running that binary and failed with “in-tree nros CLI is STALE”. A bare cmake re-configure still uses the cached tool, but now stops at once, naming the tool and both versions, when that tool’s codegen version is one the tree does not accept.
  • A Zephyr C++ image built with newlib on a 64-bit Arm board, such as fvp-aemv8r-smp, can call fabsl and copysignl, so code that reaches Eigen’s long-double abs builds without a -Dfabsl define of its own.
  • A new C project from nros new for the nucleo-f767zi Zephyr board builds again: its main stack is now 118,424 bytes.
  • A failed C or C++ metadata probe is reported as a failure, naming the node, the first error line and the log. Before, the image was built on default sizes without a word. NROS_PROBE_FAILURE=warn (the default for an interactive build) finishes with a warning line, and NROS_PROBE_FAILURE=refuse makes nros sync and nros configure fail. Set refuse in CI.
  • A failed probe now reports its cause: the linker’s first undefined reference line instead of ld returned 1 exit status, and a CMake error’s message instead of its header alone.
  • A component that declares no publisher, subscription, timer, service, action or parameter is refused by the metadata probe with a sentence naming it, instead of a bare “exit 254”.
  • A Zephyr configure with no seed from nros configure finishes in two passes, as its message says. Before, it failed twice first.
  • A FreeRTOS, NuttX or ThreadX C or C++ image writes compile_commands.json when its stack floor is checked, so the stack walk is tighter: the new FreeRTOS C talker walks 130,424 bytes instead of 147,060. A project that sets CMAKE_EXPORT_COMPILE_COMMANDS keeps its choice.
  • A Rust Zephyr image uses much less main-thread stack for a graph query (listing names and types: about 20 KB to 3.5 KB) and for a parameter declaration (about 25 KB to 8 KB). A graph query also no longer stops at 64 names, and returns names in sorted order, as the ROS 2 RMWs do.
  • A Rust package in a workspace with no bringup builds after an nros build --dry-run plan of it. Before, the build failed with “cannot update the lock file … because –frozen was passed”.
  • The API docs and C headers of the RMW layer, the zenoh RMW, nros-board-common and nros-orchestration-ir state facts in plain words instead of citing internal design numbers.
