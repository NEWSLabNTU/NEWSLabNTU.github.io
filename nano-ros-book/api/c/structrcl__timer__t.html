Detailed Description

Timer structure.

Already an arena handle before phase-487: rclc_executor_add_timer creates the timer inside the executor arena and records (handle_id, _executor) here, and every live accessor forwards there. The period, callback, context and clock are the REGISTRATION INPUTS: rclc's rclc_timer_init_default(timer, support, period, callback) takes them at init, before any executor exists, and a removed timer can be added again, so they stay. phase-487 W3 removed the one field that was a copy, last_call_time_ns: written by init and reset, read by nothing, and stale for any timer the executor ran (issue 1049).

◆ clock

const struct rcl_clock_t* rcl_timer_t::clock

The clock this timer is scheduled against, or NULL for the WALL timer rclc_timer_init_with_context creates (phase-430 W1).

rcl's rcl_timer_init takes a rcl_clock_t * here and rcl's timer keeps it; ours does the same, in the same position, so a reader of one recognises the other. The clock must outlive the timer — the executor reads its type at rclc_executor_add_timer time, not at init.
