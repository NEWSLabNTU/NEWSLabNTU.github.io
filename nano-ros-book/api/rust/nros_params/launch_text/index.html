Module launch_text 

Source
Expand description

The ONE reading of a launch parameter’s baked text.

An embedded image has no launch runtime to hand --params-file to, so the build bakes every launch parameter as TEXT and the image types it when it seeds the store. That text is written by nros_orchestration_ir::launch_param_text and read here; the two are one convention and are tested as a round trip.

The reading follows what ROS gives the same value:

  • a scalar is true / false (any of the three cases rcl accepts), then an i64, then an f64, then a string – the order rcl’s YAML reading gives an unquoted scalar;
  • a whole text in single quotes is a STRING, with '' read as '. The writer quotes a string that would otherwise read as something else;
  • a YAML flow sequence [a, b, c] is an ARRAY. The first element decides the element type and every other element must have it, which is rcl’s rule (parse.c: “Sequence should be of same type”): [1, 2.5] is refused, not widened. A quoted element is a string.

The list used to be baked as a,b,c and read as one string, so a [40.0, 50.0, 60.0] from a config/*.param.yaml reached the node as the string "40.0,50.0,60.0" – and a one-element list as a scalar.

No allocation: the element type is decided in one pass over the text and the value is filled in place in a second, so no temporary array exists.
