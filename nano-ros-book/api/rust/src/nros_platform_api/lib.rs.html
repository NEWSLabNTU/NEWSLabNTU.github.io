1//! Platform capability sub-traits for nros.
2//!
3//! This crate exists to break the dependency cycle between
4//! `nros-platform` (which depends on every platform crate via its
5//! feature-gated `ConcretePlatform` resolver) and the platform crates
6//! themselves (which need to implement these traits on their ZSTs).
7//! It contains only trait definitions — no implementations, no
8//! dependencies — so platform crates can take a build-time dep on it
9//! without creating a cycle back through `nros-platform`.
10//!
11//! `nros-platform` re-exports everything from this crate, so downstream
12//! code that writes `use nros_platform::PlatformClock;` continues to
13//! work unchanged.
14//!
15//! Each trait covers an independent system capability. Platform
16//! implementations pick which traits to implement based on what the
17//! hardware/RTOS provides. RMW shim crates declare trait bounds for
18//! the capabilities they need.
19
20#![no_std]
21//!
22//! # Naming convention
23//!
24//! Method names drop redundant prefixes when the trait name already
25//! supplies the namespace — e.g., `PlatformTcp::open` rather than
26//! `PlatformTcp::tcp_open`. Dispatch is always through a qualified
27//! path (`<ConcretePlatform as PlatformTcp>::open(...)`), so
28//! trait-to-trait collisions (PlatformTcp::open vs PlatformUdp::open)
29//! are disambiguated at the call site without needing a prefix on the
30//! trait method itself.
31//!
32//! Three categories still keep sub-namespace prefixes internally:
33//!
34//! * `PlatformThreading` — `mutex_*`, `condvar_*`, `task_*` because the
35//!   trait bundles three independent primitive families and unprefixed
36//!   `init` / `drop` would be ambiguous *within* the trait itself.
37//! * `PlatformUdpMulticast` — `mcast_*` because these methods have
38//!   different signatures from `PlatformUdp`'s same-name methods; keeping
39//!   the prefix makes call sites that use both traits self-documenting.
40//! * The `close` method appears on both `PlatformTcp` and
41//!   `PlatformSocketHelpers` — the first is TCP teardown, the second is
42//!   zenoh-pico's generic "shutdown + close" helper. Both live unprefixed
43//!   in their respective traits; call sites disambiguate via the
44//!   qualified path.
45//!
46//! # Status (Phase 84.F4)
47//!
48//! The platform ZSTs (`PosixPlatform`, `ZephyrPlatform`, etc.) do **not**
49//! currently implement these traits — every platform exposes its methods
50//! as *inherent* `impl Platform { fn foo() {} }` blocks, and shim crates
51//! dispatch by name match. 84.F4 migrates each platform to `impl
52//! PlatformX for Platform { fn foo() {} }` one trait at a time, with the
53//! shims switching to `<P as PlatformX>::foo()`. Until that work is
54//! complete the traits here are a target specification.
55

83/// Monotonic clock.
84///
85/// The most critical platform primitive. Must be backed by a hardware timer
86/// or OS tick — never by a software counter that only advances when polled.
87pub trait PlatformClock {
88    /// Monotonic nanoseconds since a platform-defined epoch. Never
89    /// decreases. See `<nros/platform.h>` for the full contract
90    /// (RFC-0073).
91    fn clock_ns() -> u64;
92
93    /// Granularity of [`Self::clock_ns`] in nanoseconds: the smallest
94    /// non-zero difference two successive reads can report. Non-zero,
95    /// and constant after platform init.
96    fn clock_resolution_ns() -> u64;
97}

132/// The image's one ending — phase-366 / RFC-0077.
133///
134/// Mirrors `nros_platform_panic` in `<nros/platform.h>`. Rust's
135/// `#[panic_handler]`, a C precondition failure and a C++ terminate all arrive
136/// here, so an image has one fatal path instead of one per language.
137///
138/// The ABI could express ALLOCATION but not fatality, so each language invented
139/// its own ending and four libraries each hardcoded a different one. This is the
140/// missing half.
141pub trait PlatformPanic {
142    /// Terminate the image. Never returns.
143    ///
144    /// `msg` is a DIAGNOSTIC, not a C string: `len` bytes, no NUL required,
145    /// possibly empty, and not necessarily UTF-8 — a port forwarding to a text
146    /// sink should treat it as bytes.
147    ///
148    /// Implementors must tolerate being called from ANY context: interrupt,
149    /// scheduler locked, or before the kernel starts. That rules out anything
150    /// needing a scheduler, which is why this is not "log at Fatal, then halt".
151    ///
152    /// Implementors SHOULD emit `msg` where a human can read it first. A silent
153    /// halt is the one behaviour no RTOS in this tree chose for itself.
154    fn panic(msg: *const u8, len: usize) -> !;
155}

176// ============================================================================
177// Cooperative yield
178// ============================================================================
179
180/// Scheduler yield primitive.
181///
182/// Used inside `socket_wait_event` and similar "let another task make
183/// progress" points where the caller isn't actually waiting for I/O
184/// readability — the background read task already owns that — it just
185/// needs to relinquish the CPU so the real waiter can run.
186///
187/// Prior to Phase 77.22 each backend hand-rolled its own 1-ms busy
188/// sleep (`libc::usleep(1000)`, `vTaskDelay(1)`, `tx_thread_sleep(1)`,
189/// `k_usleep(1000)`, `select(.., 1 ms)`) — all with slightly different
190/// units and no common home.
191///
192/// **ISR-safety**: on the hosted-RTOS backends (FreeRTOS / NuttX /
193/// Zephyr / ThreadX) the underlying primitives panic or error when
194/// invoked from an ISR. Don't call `yield_now()` from an interrupt
195/// handler.
196///
197/// **Bare-metal has no real yield**: there's nothing to yield *to*.
198/// The default bare-metal impl is `core::hint::spin_loop()` (a pure
199/// CPU hint: emits `YIELD` / `PAUSE` / `WFE` depending on the arch,
200/// safe everywhere). Board crates that have armed an IRQ source may
201/// opt in to deep idle (`wfi`) via a separate `BoardIdle` hook — not
202/// part of this trait because calling `wfi` without an IRQ source
203/// deadlocks.
204pub trait PlatformYield {
205    /// Relinquish the CPU long enough for another task / thread to run.
206    ///
207    /// Non-blocking in the sleep sense — returns as soon as the
208    /// scheduler has had an opportunity to pick a different runnable.
209    fn yield_now();
210}

216/// Errors returned by [`PlatformScheduler`] entry points.
217#[derive(Debug, Clone, Copy, PartialEq, Eq)]
218pub enum SchedError {
219    /// The active platform doesn't expose this control surface
220    /// (e.g. bare-metal with no scheduler, or an RTOS without an
221    /// affinity API).
222    Unsupported,
223    /// The requested policy is valid for this platform but the
224    /// numeric arguments fall outside the platform's accepted range.
225    OutOfRange,
226    /// A platform-specific syscall / kernel call failed; check
227    /// `errno` (POSIX) or the RTOS error code for details.
228    KernelError,
229}
230
231/// Per-thread OS scheduling policy.
232///
233/// `Fifo` / `RoundRobin` / `Deadline` / `Sporadic` map to platform-
234/// native scheduling classes when available. `Platform(...)` is the
235/// escape hatch for RTOS-specific knobs (e.g. ThreadX preempt-
236/// threshold) that don't map cleanly into the portable variants.
237///
238/// User-facing API (`Executor::open_threaded`) takes the abstract
239/// [`Priority`-like](crate) values and `PlatformScheduler` translates
240/// them into platform-native numerics — direction-flipped priority
241/// (Zephyr / ThreadX low-numeric = high-priority vs POSIX / FreeRTOS
242/// high-numeric = high-priority) handled internally. Phase 110.D.
243#[derive(Debug, Clone, Copy, PartialEq, Eq)]
244pub enum SchedPolicy {
245    /// POSIX `SCHED_FIFO`. `os_pri` is the platform-native numeric
246    /// priority; out-of-range values surface `SchedError::OutOfRange`.
247    Fifo { os_pri: u8 },
248    /// POSIX `SCHED_RR` with `quantum_ms` time slice.
249    RoundRobin { os_pri: u8, quantum_ms: u32 },
250    /// Linux `SCHED_DEADLINE` (sched_setattr). All values nanoseconds.
251    Deadline {
252        runtime_ns: u64,
253        period_ns: u64,
254        deadline_ns: u64,
255    },
256    /// NuttX `SCHED_SPORADIC` server. Phase 110.E.
257    Sporadic {
258        budget_us: u32,
259        period_us: u32,
260        hi_pri: u8,
261        lo_pri: u8,
262    },
263}

275// Phase 110.E.b — `PlatformTimer` (ISR-driven periodic refill)
276// ============================================================================
277
278/// Errors returned by [`PlatformTimer`] entry points.
279#[derive(Debug, Clone, Copy, PartialEq, Eq)]
280pub enum TimerError {
281    /// The active platform doesn't expose a periodic-timer surface
282    /// (e.g. bare-metal without a board-side `SysTickHook`).
283    Unsupported,
284    /// `period_us` is below the platform's minimum timer resolution
285    /// or above its maximum representable interval.
286    OutOfRange,
287    /// A platform-specific syscall / kernel call failed; check
288    /// `errno` (POSIX) or the RTOS error code for details.
289    KernelError,
290}

292/// Periodic timer for ISR-driven sporadic-server budget refill
293/// (Phase 110.E.b). The trait factors out the per-platform timer
294/// surface so the executor (`nros-node`) can register an atomic
295/// refill callback without becoming generic over the platform —
296/// see `docs/design/0017-platform-timer.md`.
297///
298/// Default `create_periodic` returns [`TimerError::Unsupported`] so
299/// platforms without a timer surface inherit safe behavior; `destroy`
300/// is a no-op default for the same reason.
301pub trait PlatformTimer {
302    /// Opaque per-platform handle (FreeRTOS `TimerHandle_t`,
303    /// Zephyr `*mut k_timer`, ThreadX `*mut TX_TIMER`, POSIX
304    /// `timer_t`). Must be `Send + Sync + 'static` so the executor
305    /// can stash it across thread boundaries.
306    type TimerHandle: Send + Sync + 'static;
307
308    /// Register a periodic timer that fires `callback(user_data)`
309    /// every `period_us` microseconds. Returns the platform-native
310    /// handle for later destruction.
311    ///
312    /// # Safety
313    ///
314    /// `user_data` must outlive the returned handle. The callback is
315    /// invoked from a platform-defined timer context (direct ISR on
316    /// Zephyr / bare-metal, deferred via `xTimerPendFunctionCall` on
317    /// FreeRTOS, signal handler on POSIX) — bodies should be
318    /// short and use atomic ops only.
319    fn create_periodic(
320        _period_us: u32,
321        _callback: extern "C" fn(*mut c_void),
322        _user_data: *mut c_void,
323    ) -> Result<Self::TimerHandle, TimerError> {
324        Err(TimerError::Unsupported)
325    }
326
327    /// Cancel + free the timer. Idempotent on already-destroyed
328    /// handles. Must drain in-flight callback invocations before
329    /// returning so the user_data pointer is no longer accessed.
330    fn destroy(_handle: Self::TimerHandle) {}
331
332    /// Phase 110.E.b follow-up — register a one-shot timer that
333    /// fires `callback(user_data)` exactly once after `timeout_us`
334    /// microseconds. Used by per-callback runtime measurement: arm
335    /// just before dispatch with `timeout_us = budget_us`; on
336    /// callback completion call `cancel`. If the timer fires first
337    /// the callback overran its budget.
338    ///
339    /// Default returns `Unsupported` so platforms without a oneshot
340    /// surface inherit safe behavior.
341    fn create_oneshot(
342        _timeout_us: u32,
343        _callback: extern "C" fn(*mut c_void),
344        _user_data: *mut c_void,
345    ) -> Result<Self::TimerHandle, TimerError> {
346        Err(TimerError::Unsupported)
347    }
348
349    /// Phase 110.E.b follow-up — cancel a previously-armed oneshot
350    /// timer. Returns `true` when the cancellation prevented the
351    /// callback from firing, `false` when the callback already
352    /// fired (or the timer was already cancelled). Default is a
353    /// no-op returning `false`.
354    fn cancel(_handle: &mut Self::TimerHandle) -> bool {
355        false
356    }
357}

359pub trait PlatformScheduler {
360    /// Apply the requested policy to the calling thread.
361    ///
362    /// Default returns [`SchedError::Unsupported`] so single-core bare-
363    /// metal targets and RTOS impls without per-thread scheduling
364    /// pickup the no-op behavior automatically. Platforms with a
365    /// real scheduler override this.
366    fn set_current_thread_policy(_p: SchedPolicy) -> Result<(), SchedError> {
367        Err(SchedError::Unsupported)
368    }
369
370    /// Cooperative yield. Same semantics as
371    /// [`PlatformYield::yield_now`]; mirrored here so consumers don't
372    /// need to import both traits when only the scheduler control
373    /// surface is in scope. Default is a `core::hint::spin_loop()`.
374    fn yield_now() {
375        core::hint::spin_loop();
376    }
377
378    /// Pin the calling thread to the CPUs whose bit is set in
379    /// `cpu_mask`. Default returns [`SchedError::Unsupported`] —
380    /// platforms with affinity APIs override.
381    fn set_affinity(_cpu_mask: u32) -> Result<(), SchedError> {
382        Err(SchedError::Unsupported)
383    }
384}

408/// Wall-clock / system time.
409///
410/// Used for logging timestamps and `z_time_now_as_str()`.
411/// On bare-metal without an RTC, return 0.
412///
413/// ONE method for one fact, matching `nros_platform_time_now_ns` in the C ABI
414/// (issue 0532 item 5). It replaced `time_now_ms` + `time_since_epoch_secs` +
415/// `time_since_epoch_nanos`.
416///
417/// The old doc justified the split by zenoh-pico's FFI shape: "zpico-platform-
418/// shim forwards each of these directly to a `_z_time_*` symbol, so collapsing
419/// them into a Rust struct would require the shim to decompose the struct on
420/// every call." That argument was against a STRUCT, and it still holds — but a
421/// single `u64` is not a struct. The shim now takes one value and derives the
422/// pair with a divide and a remainder, which is both cheaper than two FFI calls
423/// and, unlike them, cannot tear across a second boundary.
424pub trait PlatformTime {
425    /// Wall-clock nanoseconds since the Unix epoch, or 0 if this platform has
426    /// no real-time clock.
427    fn time_now_ns() -> u64;
428}

430// ============================================================================
431// Threading (multi-threaded platforms only)
432// ============================================================================
433//
434// Handle types are opaque `*mut c_void` to match the shape zenoh-pico
435// passes across the FFI boundary. The original draft had typed wrappers
436// (`TaskHandle`, `MutexHandle`, ...) but every shipped platform used
437// `*mut c_void` internally and the shim never materialised the typed
438// forms — keeping them in the trait would have required a pointless
439// cast at every impl site. (F4.1 / F4.5 decision, 2026-04-24.)
440//
441// Mutex / condvar / task method names keep their sub-namespace prefix
442// (`mutex_*`, `condvar_*`, `task_*`) because the trait bundles three
443// independent primitive families and unprefixed `init` / `drop` would
444// be ambiguous *within* the trait itself.
445
446/// Threading primitives: tasks, mutexes, and condition variables.
447///
448/// # Threading
449///
450/// Mutex / condvar operations must be safe under concurrent callers.
451/// **Recursive mutex (`mutex_rec_*`) must support same-thread
452/// re-entrancy** — zenoh-pico relies on this; a non-recursive mutex
453/// backing `mutex_rec_*` deadlocks under load.
454///
455/// # ISR-safety
456///
457/// **None of these methods are ISR-safe** on hosted RTOSes
458/// (FreeRTOS / NuttX / Zephyr / ThreadX) — the underlying primitives
459/// panic or error when invoked from an ISR. Only `core::hint::spin_loop()`
460/// in [`PlatformYield::yield_now`] is.
461///
462/// For single-threaded platforms (bare-metal), all operations should
463/// be no-ops returning `0`, except [`task_init`](Self::task_init)
464/// which should return `-1`.
465pub trait PlatformThreading {
466    // -- Tasks --
467
468    /// Spawn a new task. `task` is opaque caller-provided storage;
469    /// `attr` carries scheduling hints (priority, stack size) or
470    /// `null` for defaults; `entry` is the task entry point; `arg`
471    /// is forwarded to `entry`. Returns `0` on success, non-zero
472    /// on failure.
473    fn task_init(
474        task: *mut c_void,
475        attr: *mut c_void,
476        entry: Option<unsafe extern "C" fn(*mut c_void) -> *mut c_void>,
477        arg: *mut c_void,
478    ) -> i8;
479
480    /// Block until `task` exits. Cleans up the task storage on
481    /// success.
482    fn task_join(task: *mut c_void) -> i8;
483    /// Mark `task` as detached — its storage is reclaimed on exit
484    /// without a join.
485    fn task_detach(task: *mut c_void) -> i8;
486    /// Request `task` to terminate at the next cancellation point.
487    /// Cooperative.
488    fn task_cancel(task: *mut c_void) -> i8;
489    /// Terminate the calling task immediately. Does not return.
490    fn task_exit();
491    /// Free the task storage allocated by `task_init`.
492    fn task_free(task: *mut *mut c_void);
493
494    // -- Mutex --
495
496    /// Initialise a non-recursive mutex in caller-provided storage.
497    fn mutex_init(m: *mut c_void) -> i8;
498    /// Tear down a non-recursive mutex.
499    fn mutex_drop(m: *mut c_void) -> i8;
500    /// Lock; block if held.
501    fn mutex_lock(m: *mut c_void) -> i8;
502    /// Try to lock; non-zero return immediately if held.
503    fn mutex_try_lock(m: *mut c_void) -> i8;
504    /// Unlock; only the owning thread may call this.
505    fn mutex_unlock(m: *mut c_void) -> i8;
506
507    // -- Recursive mutex --
508
509    /// Initialise a *recursive* mutex (same-thread re-entrancy
510    /// permitted). Required by zenoh-pico.
511    fn mutex_rec_init(m: *mut c_void) -> i8;
512    /// Tear down a recursive mutex.
513    fn mutex_rec_drop(m: *mut c_void) -> i8;
514    /// Lock; re-entry from the owning thread must succeed.
515    fn mutex_rec_lock(m: *mut c_void) -> i8;
516    /// Try to lock; same re-entry semantics as `mutex_rec_lock`.
517    fn mutex_rec_try_lock(m: *mut c_void) -> i8;
518    /// Unlock; releases when the lock count returns to zero.
519    fn mutex_rec_unlock(m: *mut c_void) -> i8;
520
521    // -- Condition variables --
522
523    /// Initialise a condition variable in caller-provided storage.
524    fn condvar_init(cv: *mut c_void) -> i8;
525    /// Tear down a condition variable.
526    fn condvar_drop(cv: *mut c_void) -> i8;
527    /// Wake one waiter on the condition variable.
528    fn condvar_signal(cv: *mut c_void) -> i8;
529    /// Wake all waiters on the condition variable.
530    fn condvar_signal_all(cv: *mut c_void) -> i8;
531    /// Phase 124.B.7.a — ISR-safe variant of [`Self::condvar_signal`].
532    /// Callable from interrupt / signal-handler context. Backends
533    /// implement via async-signal-safe primitives (POSIX:
534    /// `eventfd` write forwarded by a worker thread; RTOS:
535    /// `xSemaphoreGiveFromISR`, `tx_event_flags_set` from ISR,
536    /// `k_sem_give` from ISR). Returns non-zero when the backend
537    /// has no ISR-safe path — caller can fall back to
538    /// `condvar_signal` (with the obvious latency cost).
539    ///
540    /// Default body: forward to `condvar_signal`. POSIX and other
541    /// backends override to use their async-signal-safe primitive.
542    fn condvar_signal_from_isr(cv: *mut c_void) -> i8 {
543        Self::condvar_signal(cv)
544    }
545    /// Atomically release `m` and block on `cv`. The mutex is
546    /// re-acquired before this function returns.
547    fn condvar_wait(cv: *mut c_void, m: *mut c_void) -> i8;
548
549    /// Wait with absolute monotonic deadline (milliseconds since
550    /// the [`PlatformClock::clock_ns`] epoch). Returns non-zero on
551    /// timeout.
552    fn condvar_wait_until(cv: *mut c_void, m: *mut c_void, abstime: u64) -> i8;
553
554    // -- Wake primitive (Phase 130) --
555    //
556    // Binary-semaphore-shaped primitive for the executor's wake_flag
557    // / spin_once cv-wait pair. Default bodies return "unsupported"
558    // (`-1`, size 0) so existing single-thread bare-metal platforms
559    // don't need to override; platforms that want event-driven wake
560    // (POSIX, Zephyr, FreeRTOS, NuttX, ThreadX) override with their
561    // native binary semaphore.
562
563    /// Initialise a binary-semaphore-shaped wake primitive in
564    /// caller-provided storage. See `<nros/platform.h>` for the
565    /// per-platform backing primitive (POSIX `sem_t`, Zephyr
566    /// `k_sem`, FreeRTOS `xSemaphoreBinary`, …). Default returns
567    /// `-1` (unsupported).
568    fn wake_init(_w: *mut c_void) -> i8 {
569        -1
570    }
571    /// Tear down a wake primitive. Default returns `-1`
572    /// (unsupported).
573    fn wake_drop(_w: *mut c_void) -> i8 {
574        -1
575    }
576    /// Block until signaled or `timeout_ms` elapses. Returns `0` on
577    /// signal, `1` on timeout, `-1` on error. Default returns `-1`
578    /// (unsupported).
579    fn wake_wait_ms(_w: *mut c_void, _timeout_ms: u32) -> i8 {
580        -1
581    }
582    /// Wake one waiter. Idempotent — a signal pending when another
583    /// arrives is coalesced (the primitive stays at value 1).
584    /// Default returns `-1` (unsupported).

827///
828/// Matches the post-Phase-129 platform-ABI pattern: the portable

850    /// `nros_log::Severity::as_u8()`.
851    fn write(severity: u8, name: &[u8], message: &[u8]);
852
853    /// Best-effort drain of any internal buffer. Default = no-op.
854    fn flush() {}
855}

905// ============================================================================
906// Inter-VM / mailbox transport (NVIDIA IVC and similar)
907// ============================================================================
908
909/// Inter-processor mailbox transport, modelled after NVIDIA Tegra IVC.
910///
911/// IVC (Inter-VM Communication on Tegra; in practice CCPLEX↔SPE on AGX
912/// Orin) is a header-prefixed lock-free SPSC ring in shared DRAM, paired
913/// with a hardware doorbell for wake. One channel is one peer — there
914/// is no discovery, naming, QoS, or fanout — which is why it's a *link*
915/// transport (peer to TCP/UDP/Serial/RawEth inside zenoh-pico) rather
916/// than a new RMW backend.
917///
918/// Channel handles are opaque `*mut c_void` to match the shape zenoh-pico
919/// passes across its FFI boundary. The driver crate (`nvidia-ivc`)
920/// translates between this opaque handle and either NVIDIA's FSP
921/// `tegra_ivc_*` API (`fsp` feature) or a Unix-socket pair
922/// (`unix-mock` feature, host dev + CI).
923///
924/// **Zero-copy contract** (Phase 11.3.A). NVIDIA's FSP IVC API is
925/// fundamentally a "borrow ring slot, fill, commit / release"
926/// pattern. Both backends mirror that here so consumers don't branch
927/// on backend:
928///
929/// - [`Self::rx_get`] returns a pointer into the channel's RX slot
930///   (and writes the frame length to `*len_out`); [`Self::rx_release`]
931///   advances the producer-visible cursor. Returns null +
932///   `*len_out = 0` if the ring is empty.
933/// - [`Self::tx_get`] returns a writable pointer to the next free TX
934///   slot (and writes the slot capacity to `*cap_out`);
935///   [`Self::tx_commit`] makes the slot visible to the peer (and
936///   rings the per-frame doorbell on FSP — see `notify` for batching).
937///   [`Self::tx_abandon`] frees the slot without sending. Returns
938///   null + `*cap_out = 0` if the ring is full.
939///
940/// Single outstanding RX slot and single outstanding TX slot per
941/// channel — borrow, finish, repeat. Multi-frame batching is the
942/// caller's job (loop `tx_get` / fill / `tx_commit`, then one
943/// `notify`).
944///
945/// `frame_size` is the fixed per-channel frame size negotiated at
946/// carveout setup (typical NVIDIA IVC: 64 bytes per frame, 16 frames
947/// per channel). The link layer uses it to pick its reassembly buffer.
948pub trait PlatformIvc {
949    /// Resolve a channel ID into an opaque handle. Returns null on
950    /// failure. The numeric ID matches the NVIDIA channel index
951    /// (`channel 2 = aon_echo`).
952    fn channel_get(id: u32) -> *mut c_void;
953
954    /// Fixed frame size negotiated for this channel, in bytes.
955    fn frame_size(ch: *mut c_void) -> u32;
956
957    /// Borrow the next-available RX frame. Writes the frame length to
958    /// `*len_out` and returns a pointer into the ring. Returns null +
959    /// `*len_out = 0` if no frame is available.
960    fn rx_get(ch: *mut c_void, len_out: *mut usize) -> *const u8;
961
962    /// Release the most recently `rx_get`'d frame back to the
963    /// producer. Pair 1:1 with `rx_get` calls that returned non-null.
964    fn rx_release(ch: *mut c_void);
965
966    /// Borrow the next free TX slot. Writes the slot capacity to
967    /// `*cap_out` and returns a writable pointer. Returns null +
968    /// `*cap_out = 0` if the ring is full.
969    fn tx_get(ch: *mut c_void, cap_out: *mut usize) -> *mut u8;
970
971    /// Commit `len` bytes from the most recently `tx_get`'d slot.
972    /// Slot is then visible to the peer; per-frame doorbell may also
973    /// fire on FSP. Pair 1:1 with `tx_get` calls that returned
974    /// non-null.
975    fn tx_commit(ch: *mut c_void, len: usize);
976
977    /// Abandon the most recently `tx_get`'d slot without sending.
978    /// Pair 1:1 with `tx_get` calls that returned non-null.
979    fn tx_abandon(ch: *mut c_void);
980
981    /// Ring the doorbell. On FSP this is redundant (commit/release
982    /// already invoke `ch->notify_remote`); on unix-mock it's a no-op
983    /// (SOCK_DGRAM wakes the peer naturally). Provided for symmetry
984    /// so callers can batch-commit then notify once.
985    fn notify(ch: *mut c_void);
986}

988// ============================================================================
989// Serial (UART / PTY)
990// ============================================================================
991
992/// Serial (byte-stream) transport.
993///
994/// Used by XRCE-DDS's HDLC-framed serial transport and (once the
995/// bare-metal migration lands) by zenoh-pico's serial link layer.
996///
997/// # Handle model
998///
999/// `open()` returns a platform-defined [`Handle`](PlatformSerial::Handle)
1000/// — an FD on POSIX, a port-table index on bare-metal, whatever the
1001/// impl wants. Every other method takes the handle back. This lets a
1002/// single platform impl service multiple concurrent devices (e.g.,
1003/// `zpico-serial`'s two-port table) without the trait constraining
1004/// the impl to a single active device.
1005///
1006/// Single-device platforms return the same handle forever and ignore
1007/// it internally; `INVALID` gives a well-defined "no live handle"
1008/// sentinel for shims that stash the current handle in a `static`.
1009///
1010/// # Path conventions
1011///
1012/// `path` in `open()` is platform-specific: a null-terminated UTF-8
1013/// device path on POSIX (e.g., `/dev/ttyUSB0` or a PTY), or a
1014/// board-defined port identifier on bare-metal (typically parsed by
1015/// the platform's internal handler). Callers pass the locator string
1016/// from their config unchanged; interpretation is the platform's job.
1017///
1018/// # I/O conventions
1019///
1020/// Read / write return `usize::MAX` on hard error. Read with
1021/// `timeout_ms == 0` should block for a platform-chosen default;
1022/// positive values are the poll/select deadline in milliseconds.
1023/// Returning `0` from `read()` indicates "no data within timeout" and
1024/// is **not** an error — both XRCE and zenoh-pico tolerate
1025/// timeout-zero reads.
1026pub trait PlatformSerial {
1027    /// Platform-specific handle type. POSIX returns the FD (`i32`);
1028    /// bare-metal returns a port-table index (`u8`). Must be `Copy`
1029    /// so shims can stash it in a `static`.
1030    type Handle: Copy;
1031
1032    /// Sentinel handle meaning "not a live device". Shims initialise
1033    /// their cached handle to this and compare against it to detect
1034    /// "transport not yet opened" states.
1035    const INVALID: Self::Handle;
1036
1037    /// Returns `true` if `h` is a live handle (not [`INVALID`](Self::INVALID)
1038    /// and points at a device that was opened and not yet closed).
1039    fn is_valid(h: Self::Handle) -> bool;
1040
1041    /// Open the serial device identified by `path`. Returns a live
1042    /// handle on success, [`INVALID`](Self::INVALID) on failure.
1043    fn open(path: *const u8) -> Self::Handle;
1044
1045    /// Close the given handle. No-op if already closed or invalid.
1046    fn close(h: Self::Handle);
1047
1048    /// Configure baud rate (in bits per second). Returns 0 on success,
1049    /// -1 on error. Called after `open()`; implementations may choose
1050    /// to apply the baud rate during `open()` instead and make this a
1051    /// no-op.
1052    fn configure(h: Self::Handle, baudrate: u32) -> i8;
1053
1054    /// Read up to `len` bytes into `buf`. Returns the number of bytes
1055    /// read, `0` on timeout, or `usize::MAX` on hard error.
1056    fn read(h: Self::Handle, buf: *mut u8, len: usize, timeout_ms: u32) -> usize;
1057
1058    /// Write `len` bytes from `buf`. Returns bytes written, or
1059    /// `usize::MAX` on error.
1060    fn write(h: Self::Handle, buf: *const u8, len: usize) -> usize;
1061}
