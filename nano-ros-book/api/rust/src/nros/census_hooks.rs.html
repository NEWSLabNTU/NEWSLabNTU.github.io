1//! The census hooks — the executor-side entities the recording RMW backend
2//! cannot see, for EVERY language's node API (issue 1419, issue 1556 item 1,
3//! RFC-0100 Amendment 1).
4//!
5//! Publishers, subscriptions, services and clients reach the RMW session, so
6//! `nros-rmw-metadata` records them with no help from here. **Timers and guard
7//! conditions never touch the RMW** — they register directly on the executor —
8//! so a backend cannot observe them at all, and they are precisely the entities
9//! a SystemModel also cannot see (issue 0257). And the RMW's `create_publisher`
10//! carries no node — by that layer the owning node is resolved away — so a
11//! backend alone yields a census whose entities belong to no node.
12//!
13//! Four hooks close that: [`on_node_create`] opens a node and makes it current
14//! (`configure()` / `register()` declares one node's entities at a time, so a
15//! cursor is exact, not a guess); [`on_timer_create`] and
16//! [`on_guard_condition_create`] record a callback slot the backend never sees;
17//! [`on_param_declare`] records a parameter as the code declared it.
18//!
19//! # Why the hooks live HERE
20//!
21//! They were born in `nros-cpp` (phase-308, phase-463 W1), which made the
22//! census a C++-only instrument: a Rust node's `create_node` / timers /
23//! parameters never crossed them, and a C node that opens its own node through
24//! `nros-c` reached the recording backend with no node attribution and its
25//! timers not at all. `nros` is the crate every language's node API sits on —
26//! `nros-c` and `nros-cpp` both depend on it, and a Rust node's `register()`
27//! runs through its `node_runtime` — so ONE hook layer here serves all three.
28//! A copy per API crate would be the second spelling this repository keeps
29//! paying for.
30//!
31//! # Cost
32//!
33//! The CALLS are unconditional, in every shipping path; the BODIES exist only
34//! under `metadata-mode`, a host-only feature no RTOS board can reach
35//! (`check-rtos-feature-set-excludes-analysis`). Without it every hook is an
36//! empty `#[inline]` function and compiles to nothing.
37//!
38//! # Layer rule (phase-308)
39//!
40//! These are ADAPTERS. No JSON, no schema struct, no slot arithmetic — those
41//! live once in [`crate::node_metadata`] and `crate::metadata_mode` (plain
42//! text, not a link: that module exists only under `metadata-mode`).
43//! `check-census-hooks-complete` holds both the rule and every entry point's
44//! call.

46/// Issue 1419 -- the census executor's sizing, independent of the contract it
47/// checks. ONE spelling for every hosted census funnel (`nros-cpp`'s and
48/// `nros-board-linux`'s).
49///
50/// A native image's callback table, node table and arena are DERIVED from the
51/// contract (`nros ws entity-inventory`, phase-412), with no headroom on
52/// purpose, and the census producer is that same image. So a contract one
53/// entity short sized its own census run one slot short: setup stopped at
54/// `ExecutorFull` before the recorder saw the entity that did not fit. A census
55/// opens its executor at the executor's own ceilings instead: 64 callback slots
56/// (the `u64` ready-set bitmask), 64 nodes, and 16 MiB of `MaybeUninit` arena
57/// (address space, not resident memory). Census-only: the backing is leaked
58/// from the heap of a host process that writes one file and exits, and none of
59/// it exists on the RTOS road, where `metadata-mode` is not compiled.
60#[cfg(all(feature = "metadata-mode", feature = "rmw-cffi"))]
61pub const CENSUS_SIZING: nros_node::ExecutorSizing = {
62    let d = nros_node::ExecutorSizing::DEFAULT;
63    nros_node::ExecutorSizing {
64        cbs: 64,
65        sc: d.sc,
66        nodes: if d.nodes > 64 { d.nodes } else { 64 },
67        arena: if d.arena > (16 << 20) {
68            d.arena
69        } else {
70            16 << 20
71        },
72    }
73};

75/// A node was created — make it current so subsequent entities attribute to
76/// it.
77///
78/// Re-opening a node of the same name makes it current again rather than
79/// failing: a tiered Rust entry runs a component's `register()` once per tier
80/// executor, and each tier's run creates the same node (issue 1419).
81/// phase-463 W5 I4 -- `true` iff the hook bodies exist (`metadata-mode`).
82///
83/// An empty `#[inline]` body costs nothing, but its ARGUMENTS still do: a
84/// namespace read back from the executor, a `from_utf8` over the node name.
85/// LLVM keeps those, because it cannot prove a lookup or a validation loop is
86/// free of effects -- measured: 48 bytes of `nros_node_init_ex` in every
87/// NuttX C image with the hook "off". A call site whose arguments do work
88/// computes them under `if ACTIVE`, a constant, so the whole block folds away
89/// and the call is still there for `check-census-hooks-complete` to see.
90pub const ACTIVE: bool = cfg!(feature = "metadata-mode");

92#[inline]
93pub fn on_node_create(_name: &str, _namespace: &str, _domain_id: u32) {
94    #[cfg(feature = "metadata-mode")]
95    {
96        // A refused begin means the recorder is full; every entity after it
97        // would be silently dropped, so say so rather than produce a census
98        // that under-counts.
99        if !crate::metadata_mode::begin_node(_name, _namespace, _domain_id) {
100            panic!(
101                "nros metadata mode: recorder rejected node `{_name}` — raise the \
102                 MetadataRecorder capacity"
103            );
104        }
105    }
106}

108/// A timer was registered on the executor.
109///
110/// Timers carry no name at the C and C++ ABIs (they are bound by function
111/// identity — `bind_timer<T, &T::method>`), so the recorded id is synthetic.
112/// That is fine: the count is what the executor sizing reads.
113///
114/// `kind` names the entry point (wall / clock / oneshot / in-group) so the
115/// census can tell a repeating timer from a one-shot delay; the period is
116/// recorded as the code passed it.
117#[inline]
118pub fn on_timer_create(_kind: crate::node_metadata::TimerKind, _period_ms: u64) {
119    #[cfg(feature = "metadata-mode")]
120    {
121        record(
122            crate::node_metadata::EntityKind::Timer,
123            _kind,
124            "timer",
125            Some(_period_ms),
126        );
127    }
128}

130/// A guard condition was registered on the executor. One callback slot, same
131/// as a timer.
132///
133/// Recorded as `TimerKind::GuardCondition`: still a `timers[]` row (one slot
134/// each, which is what the sizing consumers count) but with
135/// `kind: "guard_condition"`, so the census does not read a guard as a timer of
136/// period 0.
137#[inline]
138pub fn on_guard_condition_create() {
139    #[cfg(feature = "metadata-mode")]
140    {
141        record(
142            crate::node_metadata::EntityKind::Timer,
143            crate::node_metadata::TimerKind::GuardCondition,
144            "guard",
145            None,
146        );
147    }
148}

150/// A node declared a parameter, with the type and default the code passed.
151///
152/// Called BEFORE the store answers: an adopted launch seed is still a
153/// declaration the code makes, and a full store is a boot failure the census
154/// should still describe. Attributed to the current node through the cursor,
155/// like every other entity.
156#[inline]
157pub fn on_param_declare(_name: &str, _value: &crate::ParameterValue) {
158    #[cfg(feature = "metadata-mode")]
159    {
160        ensure_scope();
161        if !crate::metadata_mode::record_parameter(_name, _value) {
162            panic!(
163                "nros metadata mode: recorder rejected parameter `{_name}` -- a census \
164                 built from this sidecar would say the node declares fewer than it does"
165            );
166        }
167    }
168}

170/// The node an executor-side entity is attributed to when the code created it
171/// before ANY node — legal in C (`nros_timer_init` takes only a support
172/// context, and `nros-c`'s own `timer_clock_source.c` run test does exactly
173/// that). Recording it under a named scope keeps the slot in the count and
174/// makes the census say plainly that no node owns it; failing would turn a
175/// legal program into a panic in every native image that links the recorder.
176#[cfg(feature = "metadata-mode")]
177pub const EXECUTOR_SCOPE: &str = "__executor__";
178
179#[cfg(feature = "metadata-mode")]
180fn ensure_scope() {
181    if !crate::metadata_mode::has_current_node() {
182        on_node_create(EXECUTOR_SCOPE, "/", 0);
183    }
184}

186#[cfg(feature = "metadata-mode")]
187fn record(
188    kind: crate::node_metadata::EntityKind,
189    timer_kind: crate::node_metadata::TimerKind,
190    prefix: &str,
191    period_ms: Option<u64>,
192) {
193    use core::sync::atomic::{AtomicUsize, Ordering};
194    static SEQ: AtomicUsize = AtomicUsize::new(0);
195    ensure_scope();
196    let n = SEQ.fetch_add(1, Ordering::Relaxed);
197    let id = alloc::format!("{prefix}{n}");
198    let rec = crate::metadata_mode::EntityRecord {
199        callback_id: Some(&id),
200        period_ms,
201        timer_kind,
202        ..crate::metadata_mode::EntityRecord::new(kind, &id, "")
203    };
204    if !crate::metadata_mode::record(rec) {
205        panic!(
206            "nros metadata mode: recorder rejected `{id}` — an executor sized from \
207             this census would be too small"
208        );
209    }
210}
