1//! Phase 212.L.5 — top-level init API; phase-427 W9 — on every target.
2//!
3//! [`Context`] is WHERE this image is connected — locator, domain, RMW,
4//! session mode, and the source those came from (RFC-0089 "Context and
5//! `init`, settled"). One per process or image; a resolved value, not an
6//! entity on the graph. A `Node` is a named participant with its own
7//! entities, and one image holds several of those on one `Context`
8//! (RFC-0047).
9//!
10//! ## Where the values come from
11//!
12//! * **Hosted** (feature `env`): the process environment (`ROS_DOMAIN_ID`,
13//!   `NROS_LOCATOR`, `NROS_SESSION_MODE`, `NROS_RMW` / `RMW_IMPLEMENTATION`)
14//!   through the one hosted resolver, `crate::env::try_resolve_hosted`. A
15//!   launcher projects per-node values into that environment before exec.
16//! * **Freestanding** (no `env`): there is no process and no environment; the
17//!   same values are BAKED at compile time — `option_env!("NROS_LOCATOR")` and
18//!   `option_env!("NROS_DOMAIN_ID")`, exported into this crate's build by
19//!   `nros_zephyr_build::bake_nros_config()` from Kconfig (`build.rs`), or
20//!   present in the process environment of the build for the other RTOS lanes
21//!   (the board crates read the same two names the same way). The semantics
22//!   survive with the source moved from run time to build time: "the
23//!   environment this image was built for or launched in".
24//!
25//! The `env` feature gates ONLY the process-environment reader and the
26//! argv/launch entry points; `Context`, [`ContextSource`], [`InitError`],
27//! [`InitOptions`] and [`Context::config`] compile on every target. The floor
28//! for `Context` itself is `alloc`: `locator` and `rmw` are owned `String`s
29//! so the value outlives whatever transient produced it (an env cache, a
30//! parsed launch file, a harness-supplied override).
31//!
32//! ## The rclrs family
33//!
34//! [`Context::default_from_env`], [`Context::from_env`] and (hosted only)
35//! [`Context::new`] are the `rclrs::Context` constructors under the same
36//! names; [`InitOptions`] is rclrs's, with the one option it has. [`init()`] is
37//! the C++-symmetric anchor (`rclcpp::init`) and equals `default_from_env()`.
38//!
39//! Three patterns are supported (per the Phase 212.L canonical pkg shape):
40//!
41//! 1. **Node pkg** — register via the [`nros::node!`](crate::node!)
42//!    macro (Phase 172 W.3); the generated runtime owns the spin loop and
43//!    builds its `Context` through [`Context::default_from_env`].
44//! 2. **Application pkg + launch-aware** — call [`init_with_launch_auto`] (or
45//!    [`init_with_launch`] for an explicit path). The returned [`Context`]
46//!    carries launch-resolved fields (domain id, locator, RMW choice). User
47//!    code drives its own spin via `Executor::open` +
48//!    `Executor::spin`.
49//! 3. **Application pkg + custom spin** — call [`init()`] /
50//!    [`Context::default_from_env`] (or [`init_with_args`] / [`Context::new`]
51//!    for argv-style entry). Launch file is ignored; env vars +
52//!    `ExecutorConfig::from_env()` semantics still apply.
53//!
54//! To actually open a session, call [`Context::create_executor`] (`alloc`) or
55//! [`Context::create_executor_in`] (caller-supplied backing, nothing leaked),
56//! then name each node with `Executor::create_node`. The older spelling —
57//! materialise an [`crate::ExecutorConfig`] via [`Context::config`] and pass it
58//! to `Executor::open` — still works and is what a single-node entry wants;
59//! phase-427 W10 added the pair because it cannot express the second node.
60//!
61//! ## Launch overlay (current limitation)
62//!
63//! `init_with_launch_auto` / `init_with_launch` currently consume the
64//! launch-resolved knobs the parent `nros launch` process exports via env
65//! vars (`ROS_DOMAIN_ID`, `NROS_LOCATOR`, `NROS_SESSION_MODE`,
66//! `RMW_IMPLEMENTATION`, plus the placeholder `NROS_RUNTIME_OVERLAY` for
67//! the future structured overlay path). The launch XML is NOT parsed
68//! in-process; the runtime trusts the launcher to project the relevant
69//! params / remaps / env into the child environment. A follow-up wave wires
70//! the structured overlay (Option A — `nros launch --emit-runtime-overlay`
71//! → JSON sidecar consumed here). See Phase 212.L.5 notes.

99/// Errors returned by the init API.
100#[derive(Debug, Clone, PartialEq, Eq)]
101pub enum InitError {
102    /// `init_with_launch(path)` was passed a path that does not exist or
103    /// could not be read.
104    LaunchFileNotFound,
105    /// The launch file existed but could not be parsed.
106    ///
107    /// Phase 212.L.5 ships a stub — actual XML parsing arrives with the
108    /// runtime-overlay wave. Until then this variant is unused.
109    LaunchParseFailed,
110    /// A launch-derived env var (`ROS_DOMAIN_ID`, etc.) failed to parse —
111    /// or, freestanding, the baked `NROS_DOMAIN_ID` is not a decimal integer.
112    EnvParseFailed,
113    /// A domain id — from the environment, the bake, or an
114    /// [`InitOptions::with_domain_id`] override — exceeds
115    /// [`crate::DOMAIN_ID_MAX`]. Rejected here rather than
116    /// handed to a backend that can only fail later (the #206 rule).
117    DomainIdOutOfRange,
118    /// phase-427 W10 — [`Context::create_executor`] /
119    /// [`Context::create_executor_in`] resolved the identity and the RMW
120    /// session open then failed.
121    ///
122    /// The backend's own [`NodeError`] is CARRIED, not flattened into a flag:
123    /// `Transport(InvalidConfig)` (no backend registered, or more than one and
124    /// no selector) and `Transport(ConnectionFailed)` (the router is not there)
125    /// are different problems with different fixes, and issue 0465 is what
126    /// collapsing them cost the last time.
127    ExecutorOpenFailed(NodeError),
128    /// phase-427 W10 — [`Context::create_executor_in`] was handed a backing
129    /// smaller than the executor's tables need.
130    ///
131    /// Refused rather than accepted: `Executor::open_in` is `unsafe` precisely
132    /// because a short backing is undefined behaviour, so the safe wrapper
133    /// checks the length and names both numbers. `needed` is
134    /// `ExecutorSizing::DEFAULT.u64_len()` for this build — it moves with
135    /// `NROS_EXECUTOR_MAX_CBS` / `_MAX_SC` / `_ARENA_SIZE` / `_MAX_NODES`, so a
136    /// caller sizing a `static` from a literal will hear about it here rather
137    /// than corrupting memory later.
138    BackingTooSmall {
139        /// `u64` words the executor's tables need.
140        needed: usize,
141        /// `u64` words the caller supplied.
142        given: usize,
143    },
144}
145
146impl core::fmt::Display for InitError {
147    fn fmt(&self, f: &mut core::fmt::Formatter<'_>) -> core::fmt::Result {
148        match self {
149            InitError::LaunchFileNotFound => f.write_str("launch file not found"),
150            InitError::LaunchParseFailed => f.write_str("launch file parse failed"),
151            InitError::EnvParseFailed => f.write_str("env var parse failed"),
152            InitError::DomainIdOutOfRange => f.write_str("domain id out of range"),
153            InitError::ExecutorOpenFailed(e) => {
154                write!(f, "RMW session open failed: {e:?}")
155            }
156            InitError::BackingTooSmall { needed, given } => write!(
157                f,
158                "executor backing too small: {given} u64 words supplied, {needed} needed"
159            ),
160        }
161    }
162}

169/// Phase 212.L.5 — resolved init context.
170///
171/// Returned by every `init*` entry point and every `Context::*` constructor.
172/// Carries the fields the user needs to construct an [`ExecutorConfig`] and
173/// open a session.
174///
175/// Fields are owned (`String`) so the `Context` can outlive transient parents
176/// (env caches, parsed launch files, a harness-supplied locator). That is why
177/// the type's feature floor is `alloc`.
178#[cfg(feature = "alloc")]
179#[derive(Debug, Clone)]
180pub struct Context {
181    /// ROS 2 domain ID (`ROS_DOMAIN_ID`, default 0; baked `NROS_DOMAIN_ID`
182    /// freestanding).
183    pub domain_id: u32,
184    /// Middleware locator (`NROS_LOCATOR` / legacy `ZENOH_LOCATOR`; baked
185    /// `NROS_LOCATOR` freestanding). Empty means ABSENT: `nros` is
186    /// RMW-agnostic, so the linked backend substitutes its own default
187    /// (issue 0330).
188    pub locator: alloc::string::String,
189    /// Session mode (`NROS_SESSION_MODE` / legacy `ZENOH_MODE`, default `Client`).
190    pub mode: SessionMode,
191    /// RMW implementation hint (`RMW_IMPLEMENTATION` /  `NROS_RMW`).
192    ///
193    /// Empty when neither var is set, and always empty freestanding (an image
194    /// links exactly one backend). The runtime uses this to pick a primary
195    /// backend when multiple are linked; see `crate::internals::open_session`.
196    pub rmw: alloc::string::String,
197    /// Source of this context — useful for diagnostics + tests.
198    pub source: ContextSource,
199}

201/// Where the [`Context`] came from. Diagnostics only.
202#[derive(Debug, Clone, Copy, PartialEq, Eq)]
203pub enum ContextSource {
204    /// Built from env vars by [`init()`] / [`init_with_args`] /
205    /// [`Context::new`], or by [`Context::default_from_env`] /
206    /// [`Context::from_env`] on a hosted build.
207    Env,
208    /// Built from a launch file (path supplied to [`init_with_launch`]) or
209    /// auto-discovered via [`init_with_launch_auto`]. The launch XML itself
210    /// is NOT yet parsed (see module docs); the launcher's projected env
211    /// is the source of truth for now.
212    Launch,
213    /// phase-427 W9 — built from the constants baked into this crate at
214    /// compile time (`NROS_LOCATOR`, `NROS_DOMAIN_ID`) by [`Context::baked`],
215    /// which is what [`Context::default_from_env`] / [`Context::from_env`]
216    /// resolve to on a freestanding build. The entry macros
217    /// (`nros::main!`'s Zephyr arm, `nros::zephyr_component_main!`) produce
218    /// this one.
219    Baked,
220}

222/// phase-427 W9 — `rclrs::InitOptions`, with the one option it has.
223///
224/// Consumed by [`Context::from_env`] and [`Context::new`]; `None` for the
225/// domain keeps whatever the environment (hosted) or the bake (freestanding)
226/// resolved.
227#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
228pub struct InitOptions {
229    domain_id: Option<u32>,
230}
231
232impl InitOptions {
233    /// Default options: nothing overridden.
234    pub const fn new() -> Self {
235        Self { domain_id: None }
236    }
237
238    /// Override the domain id (`Some`) or keep the resolved one (`None`).
239    ///
240    /// `usize` because that is rclrs's signature. A value above `u32::MAX`
241    /// cannot be a domain id at all; it saturates here and the constructor
242    /// that consumes the options then rejects it as
243    /// [`InitError::DomainIdOutOfRange`], which is the loud place — a builder
244    /// method has no `Result` to carry the refusal in.
245    pub const fn with_domain_id(mut self, domain_id: Option<usize>) -> Self {
246        self.domain_id = match domain_id {
247            Some(d) if d > u32::MAX as usize => Some(u32::MAX),
248            Some(d) => Some(d as u32),
249            None => None,
250        };
251        self
252    }
253
254    /// The in-place twin of [`with_domain_id`](Self::with_domain_id) — rclrs
255    /// has both, and a ported `opts.set_domain_id(Some(7))` compiles as
256    /// written. Same saturation.
257    pub fn set_domain_id(&mut self, domain_id: Option<usize>) {
258        *self = self.with_domain_id(domain_id);
259    }
260
261    /// The domain override, if any.
262    pub const fn domain_id(&self) -> Option<u32> {
263        self.domain_id
264    }
265}
266
267#[cfg(feature = "alloc")]
268/// The range check every constructor applies to a domain id, whatever its
269/// source (env, bake, override): the same bound `try_resolve_hosted` enforces
270/// ("INCLUDING a baked one"), so a freestanding image cannot boot on a domain
271/// a hosted process would have refused.
272fn check_domain_id(domain_id: u32) -> Result<u32, InitError> {
273    if domain_id > DOMAIN_ID_MAX {
274        Err(InitError::DomainIdOutOfRange)
275    } else {
276        Ok(domain_id)
277    }
278}

280#[cfg(feature = "alloc")]
281impl Context {
282    /// Materialise an [`ExecutorConfig`] for a node with the given name.
283    ///
284    /// The returned config borrows from `self`, so callers usually do:
285    ///
286    /// ```ignore
287    /// let ctx = nros::Context::default_from_env()?;
288    /// let cfg = ctx.config("talker");
289    /// let mut executor = nros::Executor::open(&cfg)?;
290    /// ```
291    ///
292    /// phase-427 W10 — this is the shape where the executor IS the node it was
293    /// configured with, and it stays: an entry that opens exactly one node
294    /// wants exactly this. What it cannot express is the second node, which is
295    /// why `Context::create_executor()` + `Executor::create_node(name)` now sit
296    /// beside it — the session takes no name, and each node takes its own.
297    // phase-427 W10 — the one legitimate remaining use of the deprecated
298    // builder spelling: this method IS the executor-is-the-node shape, so it
299    // asks for it deliberately rather than by not having heard.
300    #[allow(deprecated)]
301    pub fn config<'a>(&'a self, node_name: &'a str) -> ExecutorConfig<'a> {
302        ExecutorConfig::new(self.locator.as_str())
303            .node_name(node_name)
304            .domain_id(self.domain_id)
305            .mode(self.mode)
306    }

308    /// `rclrs::Context::default_from_env()` — the environment, default
309    /// options.
310    ///
311    /// Hosted (feature `env`) this reads the process environment and is
312    /// exactly [`init()`]; freestanding it is [`Context::baked`], the build
313    /// environment this image was compiled for. RFC-0089 "Context and `init`,
314    /// settled": the semantics survive with the source moved from run time to
315    /// build time, which is the bounded half of this adoption.
316    pub fn default_from_env() -> Result<Context, InitError> {
317        #[cfg(feature = "env")]
318        {
319            init()
320        }
321        #[cfg(not(feature = "env"))]
322        {
323            Self::baked()
324        }
325    }
326
327    /// `rclrs::Context::from_env(options)` — [`default_from_env`](Self::default_from_env)
328    /// with the [`InitOptions`] applied on top: a
329    /// `Some` domain replaces the resolved one, `None` keeps it.
330    pub fn from_env(options: InitOptions) -> Result<Context, InitError> {
331        let mut ctx = Self::default_from_env()?;
332        if let Some(domain_id) = options.domain_id {
333            ctx.domain_id = check_domain_id(domain_id)?;
334        }
335        Ok(ctx)
336    }

338    /// `rclrs::Context::new(args, options)` — the argv constructor. HOSTED
339    /// ONLY: a freestanding image has no argv, so the name is absent there and
340    /// the compiler says so.
341    ///
342    /// **What it does with the arguments:** the same as [`init_with_args`] —
343    /// it does NOT parse them, and it does not silently ignore them either. A
344    /// vector carrying `--ros-args` is REFUSED LOUDLY at the call (logged
345    /// through `nros_log`, then a panic naming the flag —
346    /// [`REFUSE_INIT_ARGS`]); any other vector passes through to
347    /// [`Context::from_env`] untouched, because nothing was dropped. Parsing
348    /// `--ros-args` is remap resolution (RFC-0020 class 4) and belongs beside
349    /// `nros::resolve_name`, not in a constructor. RFC-0089: only the VALUE
350    /// carries the defect, so the call is the earliest point it is knowable.
351    ///
352    /// `S: AsRef<str>` is a superset of rclrs's `Item = String`, so
353    /// `Context::new(std::env::args(), InitOptions::new())` compiles as
354    /// written.
355    #[cfg(feature = "env")]
356    pub fn new<I, S>(args: I, options: InitOptions) -> Result<Context, InitError>
357    where
358        I: IntoIterator<Item = S>,
359        S: AsRef<str>,
360    {
361        refuse_ros_args(args);
362        Self::from_env(options)
363    }

365    /// phase-427 W9 — the freestanding constructor: the constants baked into
366    /// this crate at compile time.
367    ///
368    /// * `NROS_LOCATOR` — the middleware locator. Unset or empty ⇒ empty ⇒
369    ///   the linked backend's own default (issue 0330; for zenoh-pico that is
370    ///   multicast scouting, which native_sim NSOS cannot satisfy — hence the
371    ///   bake).
372    /// * `NROS_DOMAIN_ID` — the domain. Unset ⇒ 0; non-numeric ⇒
373    ///   [`InitError::EnvParseFailed`]; above `DOMAIN_ID_MAX` ⇒
374    ///   [`InitError::DomainIdOutOfRange`].
375    ///
376    /// Both names reach this crate's build the same way they reach the board
377    /// crates: on Zephyr, `build.rs` re-exports `CONFIG_NROS_ZENOH_LOCATOR` /
378    /// `CONFIG_NROS_DOMAIN_ID` from `$DOTCONFIG` (`nros_zephyr_build::
379    /// bake_nros_config`, the issue-0460 channel); on the other RTOS lanes the
380    /// fixture build exports them into the process environment. This is the
381    /// ONE `option_env!` site for the pair — the entry macros used to carry
382    /// their own copies (and `nros::main!`'s Zephyr arm had lost the domain
383    /// half, issue 0161's class), which is what "one source of the baked
384    /// shape" replaces.
385    ///
386    /// Mode is `Client` and `rmw` is empty: an image links exactly one
387    /// backend and nothing bakes a session mode today.
388    ///
389    /// Hosted builds have this too — it answers "what was baked", which a
390    /// hosted process rarely wants; [`Context::default_from_env`] is the
391    /// constructor that picks the right source for the build.
392    pub fn baked() -> Result<Context, InitError> {
393        Self::from_baked(option_env!("NROS_LOCATOR"), option_env!("NROS_DOMAIN_ID"))
394    }

396    /// The parse behind [`Context::baked`], with the two constants injected
397    /// so a unit test can exercise every arm without a build environment.
398    /// Public because the macros in `nros-macros` expand in another crate;
399    /// not API.
400    #[doc(hidden)]
401    pub fn from_baked(
402        baked_locator: Option<&str>,
403        baked_domain_id: Option<&str>,
404    ) -> Result<Context, InitError> {
405        let domain_id = match baked_domain_id {
406            Some(d) => check_domain_id(d.trim().parse().map_err(|_| InitError::EnvParseFailed)?)?,
407            None => 0,
408        };
409        Ok(Context {
410            domain_id,
411            locator: alloc::string::String::from(baked_locator.unwrap_or("")),
412            mode: SessionMode::Client,
413            rmw: alloc::string::String::new(),
414            source: ContextSource::Baked,
415        })
416    }

418    /// Replace the locator with one handed in at run time, when there is one.
419    ///
420    /// #166 / phase-286 W1 — native_sim test parallelism: the harness launches
421    /// an image with `-testargs --nros-locator=<loc>` and a per-test router on
422    /// that ephemeral port, and `nros_runtime_locator_override()`
423    /// (`nros-platform-zephyr`, argv-backed) hands it back here. `None` or an
424    /// empty string keeps the baked value, so on real hardware — where the hook
425    /// returns NULL — the bake stands. The entry macros call this after
426    /// [`Context::default_from_env`]; a hand-written entry may too.
427    pub fn with_locator_override(mut self, locator: Option<&str>) -> Self {
428        if let Some(loc) = locator {
429            if !loc.is_empty() {
430                self.locator = alloc::string::String::from(loc);
431            }
432        }
433        self
434    }

454/// phase-427 W10 — `rclrs::Context::create_executor`, and the ours-only
455/// no-leak twin beside it.
456///
457/// Both are gated on `rmw-cffi`, because an executor without the vtable
458/// runtime has no session to open; `create_executor` is additionally gated on
459/// `alloc`, because it is the one that leaks a default-sized backing.
460#[cfg(all(feature = "alloc", feature = "rmw-cffi"))]
461impl Context {
462    /// `rclrs::Context::create_executor()` — open the session this context
463    /// resolved and hand back the [`Executor`] that owns it.
464    ///
465    /// This is the entry a ported rclrs `main` lands on: upstream writes
466    /// `context.create_basic_executor()` (or `create_executor(runtime)`) and
467    /// gets an `Executor` back; ours returns a `Result`, so the port is a `?`.
468    /// The runtime argument has no counterpart here and is not accepted — one
469    /// executor per RTOS task is the model (RFC-0002), and there is no runtime
470    /// to choose between.
471    ///
472    /// The node name is NOT taken here. Name nodes with
473    /// [`Executor::create_node`], which is where several named nodes on one
474    /// session already live (RFC-0047).
475    ///
476    /// # Available on `alloc` only
477    ///
478    /// It leaks an executor-lifetime backing at
479    /// [`ExecutorSizing::DEFAULT`] — the reason it is `Executor<'static>` and
480    /// the reason it needs an allocator. A target without one calls
481    /// [`create_executor_in`](Self::create_executor_in) with its own
482    /// `static`, which is the same open with the storage supplied rather than
483    /// leaked. (Today [`Context`] itself has an `alloc` floor — its `locator`
484    /// and `rmw` are owned `String`s — so the pair moves together; if that
485    /// floor ever drops, this is the half that stays behind.)
486    ///
487    /// ```ignore
488    /// let context = nros::Context::default_from_env()?;
489    /// let mut executor = context.create_executor()?;
490    /// let mut node = executor.create_node("talker")?;
491    /// ```
492    pub fn create_executor(&self) -> Result<Executor<'static>, InitError> {
493        Executor::open(&self.session_config()).map_err(InitError::ExecutorOpenFailed)
494    }
495
496    /// OURS — [`create_executor`](Self::create_executor) with the storage
497    /// supplied by the caller instead of leaked.
498    ///
499    /// The freestanding form. An RTOS or bare-metal entry owns a
500    /// `static mut [MaybeUninit<u64>; N]` (or the array the `nros::main!`
501    /// macro sizes for it) and hands it in; nothing is allocated, and the
502    /// returned executor borrows the backing for `'b` rather than living
503    /// forever. rclrs has no counterpart — it allocates.
504    ///
505    /// `backing` must hold at least `ExecutorSizing::DEFAULT.u64_len()` words.
506    /// A shorter slice is [`InitError::BackingTooSmall`] naming both numbers,
507    /// never undefined behaviour: this is the safe wrapper around the `unsafe`
508    /// `Executor::open_in`, and the length check is what makes it safe. Size
509    /// the array with `ExecutorSizing::DEFAULT.u64_len()` rather than a
510    /// literal, since the default moves with `NROS_EXECUTOR_MAX_CBS` and its
511    /// siblings.
512    ///
513    /// ```ignore
514    /// static mut BACKING: [MaybeUninit<u64>; N] = [MaybeUninit::uninit(); N];
515    /// let context = nros::Context::default_from_env()?;
516    /// // SAFETY: single-threaded entry, taken once.
517    /// let mut executor = context.create_executor_in(unsafe { &mut *&raw mut BACKING })?;
518    /// let mut node = executor.create_node("talker")?;
519    /// ```
520    pub fn create_executor_in<'b>(
521        &self,
522        backing: &'b mut [MaybeUninit<u64>],
523    ) -> Result<Executor<'b>, InitError> {
524        let sizing = ExecutorSizing::DEFAULT;
525        let needed = sizing.u64_len();
526        let given = backing.len();
527        if given < needed {
528            return Err(InitError::BackingTooSmall { needed, given });
529        }
530        // SAFETY: `backing` is at least `sizing.u64_len()` words (checked
531        // directly above), is `u64`-aligned by its element type, is uniquely
532        // borrowed for `'b`, and the returned `Executor<'b>` is the only thing
533        // that can reach it for that lifetime.
534        unsafe { Executor::open_in(&self.session_config(), backing, sizing) }
535            .map_err(InitError::ExecutorOpenFailed)
536    }
537}

539#[cfg(feature = "env")]
540fn read_env_context(source: ContextSource) -> Result<Context, InitError> {
541    // issue 0687 — through the ONE resolver, not a third parse of the same four
542    // variables. This function had its own copy, and the copies had drifted:
543    // it did not warn on the legacy `$ZENOH_LOCATOR`/`$ZENOH_MODE` spellings
544    // the other reader deprecates, and it range-checked nothing, so
545    // `ROS_DOMAIN_ID=300` reached a backend that could only fail later.
546    //
547    // Issue 0330 — no backend default for the locator: `nros` is RMW-agnostic,
548    // so unset env leaves it EMPTY (= absent) and the linked backend
549    // substitutes its own (zenoh: `nros_rmw_zenoh::DEFAULT_LOCATOR`; xrce: its
550    // agent default; cyclonedds ignores the locator entirely). That is what
551    // `resolve_hosted` does with an empty `BootConfig` too.
552    let resolved =
553        crate::env::try_resolve_hosted(nros_node::BootConfig::default()).map_err(|e| match e {
554            nros_node::BootConfigError::DomainIdRange => InitError::DomainIdOutOfRange,
555            nros_node::BootConfigError::DomainIdParse => InitError::EnvParseFailed,
556        })?;
557    let locator = alloc::string::String::from(resolved.locator);
558    let domain_id = resolved.domain_id;
559    let mode = resolved.mode;
560    // issue 0687 — the `$NROS_RMW` half comes from the shared selector; the
561    // `RMW_IMPLEMENTATION` fallback stays HERE and only here. `Context.rmw` is
562    // a ROS-vocabulary HINT (`rmw_cyclonedds_cpp`), not the cffi registry
563    // selector (`cyclonedds`) — folding the two together would hand a ROS name
564    // to `resolve_backend`, which answers `Unknown` and fails the open.
565    let rmw = crate::rmw_selector()
566        .map(|s| alloc::string::String::from(s.as_str()))
567        .or_else(|| std::env::var("RMW_IMPLEMENTATION").ok())
568        .unwrap_or_default();
569    Ok(Context {
570        domain_id,
571        locator,
572        mode,
573        rmw,
574        source,
575    })
576}

593/// The refusal [`init_with_args`] and [`Context::new`] emit when handed
594/// `--ros-args`. The same text `NROS_RCLCPP_REFUSE_INIT_ARGV` carries for the
595/// C++ twin (`packages/api/nros-cpp/include/nros/log.hpp`), with the Rust
596/// spellings.
597#[cfg(feature = "env")]
598pub const REFUSE_INIT_ARGS: &str = "nros::init_with_args / nros::Context::new was given --ros-args, which nano-ros cannot \
599honour (RFC-0089, phase-417 W3.b). Proceeding would DISCARD it, so `-r chatter:=/other` would \
600silently become a wrong-topic bug at runtime -- the 'compiles and differs' the rule \
601forbids. Nothing in this process parses --ros-args yet, and honouring them is remap \
602resolution -- RFC-0020 violation class 4 -- so the parser belongs beside nros::resolve_name, \
603not in this wrapper. Today remaps and parameter overrides come from the LAUNCHER, which \
604projects them into the environment before exec. Call nros::init() / \
605nros::Context::default_from_env(), or nros::init_with_launch_auto() for the launch-aware \
606entry point.";
607
608/// The refusal's predicate, separately checkable (RFC-0089 §"where the
609/// refusal fires": an abort inlined into `init` can only be observed by a
610/// process that then dies, which is the shape of a check nothing runs).
611///
612/// Exact match only. `--ros-args-extra` is not the flag, and a prefix match
613/// would refuse an argument nano-ros never drops — the mutation the C++
614/// predicate's `static_assert`s pin, pinned here by a unit test.
615#[cfg(feature = "env")]
616pub fn args_have_ros_args<I, S>(args: I) -> bool
617where
618    I: IntoIterator<Item = S>,
619    S: AsRef<str>,
620{
621    args.into_iter().any(|a| a.as_ref() == "--ros-args")
622}
623
624/// The one refusal site, shared by [`init_with_args`] and [`Context::new`]:
625/// logged through `nros_log` (never `std::println!`, issue 0589), then a
626/// panic naming the flag — the same shape `rclcpp::init(argc, argv)` has in
627/// `nros.hpp`.
628#[cfg(feature = "env")]
629fn refuse_ros_args<I, S>(args: I)
630where
631    I: IntoIterator<Item = S>,
632    S: AsRef<str>,
633{
634    if args_have_ros_args(args) {
635        nros_log::log_error!(nros_log::get_logger("nros"), "{}", REFUSE_INIT_ARGS);
636        panic!("{}", REFUSE_INIT_ARGS);
637    }
638}

640/// Pattern 3 — like [`init()`] but accepts a `[--arg=value, ...]`-style argv
641/// iterator. The free-function twin of [`Context::new`] with default options.
642///
643/// **What it does with the arguments:** it does NOT parse them, and it does
644/// not silently ignore them either. The structured argv parse (`--ros-args -p
645/// foo:=42`, remaps) is remap resolution, which belongs beside
646/// `nros::resolve_name` and lands with the runtime-overlay wave. Until it
647/// does, an argument vector that carries `--ros-args` is REFUSED LOUDLY at the
648/// call: the refusal is logged through `nros_log` (never `std::println!`,
649/// issue 0589) and the process panics naming the flag — the same shape
650/// `rclcpp::init(argc, argv)` has in `nros.hpp`. A vector with no ROS
651/// arguments is unaffected, because nothing was dropped.
652///
653/// RFC-0089: only the VALUE carries the defect, so the call is the earliest
654/// point it is knowable; silence there is the "compiles and differs" the
655/// compile-or-conform rule forbids.
656#[cfg(feature = "env")]
657pub fn init_with_args<I, S>(args: I) -> Result<Context, InitError>
658where
659    I: IntoIterator<Item = S>,
660    S: AsRef<str>,
661{
662    refuse_ros_args(args);
663    init()
664}
