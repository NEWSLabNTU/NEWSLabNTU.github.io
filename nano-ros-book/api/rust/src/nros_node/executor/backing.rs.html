1//! phase-392 W6 — the executor's storage as a NAMED STATIC (RFC-0002 § 4.4b).
2//!
3//! # What this fixes, and what it does not
4//!
5//! Phase 392 prices an image's static RAM by reading its symbol table
6//! (`just mem-report`). Every later wave of that campaign is defined as a saving
7//! against those numbers, so a consumer the symbol table cannot see is a
8//! consumer the campaign cannot price — and the executor's storage was exactly
9//! that on every Rust image.
10//!
11//! **Not because the arena is inline.** It stopped being an inline
12//! `[MaybeUninit<u8>; ARENA_SIZE]` field in phase-271 (issue 0110), and
13//! [`Executor`](super::spin::Executor) has held `arena: &'s mut
14//! [MaybeUninit<u8>]` — a slice carved out of caller-supplied backing — ever
15//! since. Four documents, a build-script comment and a runtime advisory string
16//! went on asserting the inline shape for five phases; phase-403 caught the
17//! claim and phase-392 W6 corrected the sites.
18//!
19//! **Where that backing lives is the caller's choice**, and before this module
20//! the tree answered it three different ways:
21//!
22//! * **C** — all 34 in-tree `nros_executor_t` objects are file-scope `static`,
23//!   so the backing is carved from `_opaque` in `.bss`. Visible.
24//! * **C++** — `nros::Node::GlobalStorageHolder<0>::storage`, a template static
25//!   member, so also `.bss`. Visible.
26//! * **Rust** — every board entry (`linux`, `zephyr`, `freertos`, `nuttx`,
27//!   `threadx`, `esp32-qemu`, `mps2-an385`) reaches an `alloc` convenience
28//!   constructor, which leaked a `Box`. **Invisible**: a heap allocation has no
29//!   symbol. Measured on the native zenoh talker before this module: the largest
30//!   `nros_node` RAM symbol in the whole image was **1 byte**.
31//!
32//! This module closes the Rust arm — one change, every Rust board.
33//!
34//! # It is a MOVE, not a saving, and the second half is the caller's
35//!
36//! The same bytes are reserved either way; what changes is *which budget pays*.
37//! A leaked `Box` is drawn from the image's allocator arena. On a hosted target
38//! that arena is the OS heap and has no fixed reservation, so the static costs
39//! nothing that was not already spent. **On an RTOS it is itself a fixed
40//! static** — `CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE` on Zephyr,
41//! `configTOTAL_HEAP_SIZE` on FreeRTOS — already sized to hold this backing, so
42//! turning the reservation on there without lowering that knob reserves the same
43//! bytes twice.
44//!
45//! That pairing is per-image and only the image's author can measure it, so the
46//! opt-out is a knob rather than a guess: `NROS_EXECUTOR_BACKING_U64S=0` emits
47//! no static at all and restores the leak. A non-zero value overrides the
48//! reservation's SIZE, which is also how a fat entry — one declaring
49//! `max_callbacks` above `NROS_EXECUTOR_MAX_CBS` — keeps a static instead of
50//! falling back to the heap.
51//!
52//! **The Zephyr `CONFIG_` spelling is NOT wired yet.** `nros-node`'s build
53//! script resolves this through the same env → `$DOTCONFIG` reader every other
54//! executor knob uses, so `CONFIG_NROS_EXECUTOR_BACKING_U64S` would be honoured
55//! the moment `zephyr/Kconfig` declares it — but it does not, and a symbol no
56//! Kconfig declares never reaches the dotconfig. Declaring it belongs with the
57//! measurement that makes it necessary (issue 1145), not ahead of it: the
58//! natural `int … default 0` would mean "no static" on every Zephyr image the
59//! day it landed, which is the opposite of the default this chose. Until then
60//! the env knob is the whole interface.
61//!
62//! # Why there is no `// nros-pool:` annotation
63//!
64//! `scripts/gen-pool-inventory.py` evaluates a pool as a PRODUCT of knobs at
65//! their literal defaults. This one is a SUM — the executor's carved tables plus
66//! the arena, laid out with alignment padding between them — and its largest
67//! term, `ARENA_SIZE`, is itself derived
68//! (`env_usize("NROS_EXECUTOR_ARENA_SIZE", derived_arena)` in
69//! `nros-node/build.rs`), so the inventory would record it as a computed default
70//! even if the sum were expressible. A formula that is right for one build and
71//! wrong for the rest is the drift class this tree gates against, so this
72//! follows the two documented deliberate non-annotations
73//! (`nros_rmw_zenoh::shim::publisher`, `nros_rmw_cffi`): **the size is known to
74//! the compiler, so read it from the compiler's output.** `mem-report` prices
75//! the symbol from the ELF, exactly, with no formula to drift.
76//!
77//! # Placement
78//!
79//! `NROS_EXECUTOR_BACKING_SECTION` (build-time env, read by `nros-node`'s build
80//! script) puts the static in a named section, for the amendment-A case where a
81//! part has tightly-coupled memory the linker script can target — issue 0880
82//! does the same for `nros_thread_stacks` with `DTCM`. Two constraints, both
83//! load-bearing: **the section must be `NOLOAD`**, because this static is
84//! uninitialised and a loadable section would add its whole size to the image's
85//! flash footprint; and it must be reachable by every bus master that touches
86//! the executor's buffers, which on Cortex-M7 the TCMs typically are not.
87

95/// The reservation's size when nothing overrides it: one default-sized
96/// executor's worth.
97///
98/// One executor, not a multiple, because an entry opens ONE: the tiered boot
99/// paths open a second per tier, and those correctly fall through to the heap
100/// (see [`take`]).
101///
102/// Named by the GENERATED file when nothing overrides the size, so it is unused
103/// under `NROS_EXECUTOR_BACKING_U64S=0` (no static) and under an explicit
104/// override (a literal). Kept rather than `cfg`'d: it is what the override is
105/// judged against, and a constant that disappears with its consumer cannot be
106/// compared to anything.
107#[allow(dead_code)]
108pub(crate) const EXECUTOR_BACKING_DEFAULT_U64S: usize = ExecutorSizing::DEFAULT.u64_len();
109
110// `EXECUTOR_BACKING`, its size const, and the optional
111// `#[unsafe(link_section = …)]` on it are emitted by `build.rs`: `link_section`
112// takes a string LITERAL and the section name is a build-time input, and the
113// size may be overridden or the whole item suppressed. The file is EMPTY when
114// `NROS_EXECUTOR_BACKING_U64S=0`, which is why the include is unconditional
115// while everything that reads it is `cfg`-gated.
116include!(concat!(env!("OUT_DIR"), "/nros_executor_backing.rs"));

118/// The reservation must cover the sizing every `alloc` convenience constructor
119/// passes, or it is dead weight every image carries and no executor ever uses.
120///
121/// A `const` assertion rather than a test, deliberately: the only way to make it
122/// false is to set `NROS_EXECUTOR_BACKING_U64S` too low, and the person doing
123/// that wants to hear about it from the build they just ran, not from a test
124/// suite they may not run at all. `0` is the documented opt-out and is not
125/// reached here — it emits no static, so this whole arm is `cfg`'d away.
126#[cfg(nros_executor_backing_static)]
127const _: () = assert!(
128    EXECUTOR_BACKING_U64S >= EXECUTOR_BACKING_DEFAULT_U64S,
129    "NROS_EXECUTOR_BACKING_U64S is below the default executor sizing, so the \
130     reservation can never be taken and is pure dead weight; use 0 to decline \
131     the static entirely"
132);
133
134/// Has [`EXECUTOR_BACKING`] been handed out?
135///
136/// A latch, not a free list: the backing is handed out as `&'static mut` and
137/// never returned, exactly like the `Box::leak` it replaces. An executor that
138/// drops does not give it back — reclaiming it would need the executor's own
139/// tables to be provably dead first, which `Drop` cannot show for a slice it has
140/// already lent to `Dispatcher`.
141#[cfg(nros_executor_backing_static)]
142static TAKEN: AtomicBool = AtomicBool::new(false);
143
144/// Hand out [`EXECUTOR_BACKING`], once, if it can hold `words`.
145///
146/// `None` means "use the heap", and every path to it is legitimate rather than
147/// degraded — it is the caller's behaviour from before this module existed:
148///
149/// * the reservation is switched off (`NROS_EXECUTOR_BACKING_U64S=0`);
150/// * another executor already took it (a tiered boot opens one per tier);
151/// * this executor is sized past the reservation (a fat entry).
152///
153/// The `swap` is what makes the returned `&'static mut` sound: exactly one
154/// caller observes `false`, so exactly one reference to the static ever exists.
155#[cfg(nros_executor_backing_static)]
156pub(crate) fn take(words: usize) -> Option<&'static mut [MaybeUninit<u64>]> {
157    if words > EXECUTOR_BACKING_U64S {
158        return None;
159    }
160    if TAKEN.swap(true, Ordering::AcqRel) {
161        return None;
162    }
163    // SAFETY: the swap above succeeds exactly once for the life of the process,
164    // so this is the only reference ever created to `EXECUTOR_BACKING`, and it
165    // is `'static` because the static is. `words <= EXECUTOR_BACKING_U64S` was
166    // checked, so the slice is in bounds.
167    // The raw ref is bound first rather than dereferenced in place: `&mut
168    // *(&raw mut X)` reads as `deref_addrof` to clippy, and the obvious
169    // rewrite it suggests (`&mut X`) is the `static_mut_refs` hazard this
170    // spelling exists to avoid.
171    let ptr = &raw mut EXECUTOR_BACKING;
172    let all: &'static mut [MaybeUninit<u64>; EXECUTOR_BACKING_U64S] = unsafe { &mut *ptr };
173    Some(&mut all[..words])
174}

176/// The reservation is switched off, so there is nothing to hand out.
177///
178/// A stub rather than a `cfg` at the call site: `default_backing` reads the same
179/// either way, which is the paired-stub idiom `trace_register` uses one file
180/// over, and it keeps the `#[cfg]` in exactly one place.
181#[cfg(not(nros_executor_backing_static))]
182pub(crate) fn take(_words: usize) -> Option<&'static mut [MaybeUninit<u64>]> {
183    None
184}

186/// Has the static been claimed? Tests only.
187#[cfg(all(test, nros_executor_backing_static))]
188pub(crate) fn is_taken() -> bool {
189    TAKEN.load(Ordering::Acquire)
190}
191
192#[cfg(test)]
193mod tests {
194    use super::*;
195
196    /// The POSITIVE CONTROL, and the reason it and the two `None` cases share
197    /// one test: `TAKEN` is process-scoped by design, so a second test would
198    /// observe an already-consumed latch and assert nothing — the vacuous shape
199    /// `check-no-vacuous-tests` exists to catch.
200    ///
201    /// A test that only ever saw `take` return `None` would pass against a `take`
202    /// that can never succeed, which is exactly the bug that would make this
203    /// whole module inert while reading as if it worked.
204    #[cfg(nros_executor_backing_static)]
205    #[test]
206    fn the_static_is_handed_out_once_and_only_once() {
207        // Too large for the reservation: refused BEFORE the latch is touched, so
208        // this case cannot consume the one handout.
209        assert!(
210            take(EXECUTOR_BACKING_U64S + 1).is_none(),
211            "a request past the reservation must fall back to the heap"
212        );
213        assert!(
214            !is_taken(),
215            "an over-large request must not claim the latch"
216        );
217
218        let first = take(EXECUTOR_BACKING_U64S).expect("the first taker gets the static");
219        assert_eq!(
220            first.len(),
221            EXECUTOR_BACKING_U64S,
222            "the handout is the requested length, not the whole reservation"
223        );
224        assert!(is_taken());
225
226        assert!(
227            take(1).is_none(),
228            "a second taker must fall back to the heap — two `&'static mut` to \
229             one static is UB, which is the whole reason for the latch"
230        );
231    }
232
233    /// With the reservation off there is no static, so `take` is inert and no
234    /// image carries the bytes.
235    #[cfg(not(nros_executor_backing_static))]
236    #[test]
237    fn the_opt_out_removes_the_reservation_entirely() {
238        assert!(
239            take(1).is_none(),
240            "NROS_EXECUTOR_BACKING_U64S=0 must hand out nothing"
241        );
242    }
243}
