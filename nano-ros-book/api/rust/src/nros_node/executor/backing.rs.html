1//! phase-392 W6 — the executor's storage as a NAMED STATIC (RFC-0002 § 4.4b).
2//!
3//! # What this fixes, and what it does not
4//!
5//! Phase 392 prices an image's static RAM by reading its symbol table
6//! (`just mem-report`). Every later wave of that campaign is defined as a saving
7//! against those numbers, so a consumer the symbol table cannot see is a
8//! consumer the campaign cannot price — and the executor's storage was exactly
9//! that on every Rust image.
10//!
11//! **Not because the arena is inline.** It stopped being an inline
12//! `[MaybeUninit<u8>; ARENA_SIZE]` field in phase-271 (issue 0110), and
13//! [`Executor`](super::spin::Executor) has held `arena: &'s mut
14//! [MaybeUninit<u8>]` — a slice carved out of caller-supplied backing — ever
15//! since. Four documents, a build-script comment and a runtime advisory string
16//! went on asserting the inline shape for five phases; phase-403 caught the
17//! claim and phase-392 W6 corrected the sites.
18//!
19//! **Where that backing lives is the caller's choice**, and before this module
20//! the tree answered it three different ways:
21//!
22//! * **C** — all 34 in-tree `nros_executor_t` objects are file-scope `static`,
23//!   so the backing is carved from `_opaque` in `.bss`. Visible.
24//! * **C++** — `nros::Node::GlobalStorageHolder<0>::storage`, a template static
25//!   member, so also `.bss`. Visible.
26//! * **Rust** — every board entry (`linux`, `zephyr`, `freertos`, `nuttx`,
27//!   `threadx`, `esp32-qemu`, `mps2-an385`) reaches an `alloc` convenience
28//!   constructor, which leaked a `Box`. **Invisible**: a heap allocation has no
29//!   symbol. Measured on the native zenoh talker before this module: the largest
30//!   `nros_node` RAM symbol in the whole image was **1 byte**.
31//!
32//! This module closes the Rust arm — one change, every Rust board.
33//!
34//! # It is a MOVE, not a saving, and the second half is the caller's
35//!
36//! The same bytes are reserved either way; what changes is *which budget pays*.
37//! A leaked `Box` is drawn from the image's allocator arena. On a hosted target
38//! that arena is the OS heap and has no fixed reservation, so the static costs
39//! nothing that was not already spent. **On an RTOS it is itself a fixed
40//! static** — `CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE` on Zephyr,
41//! `configTOTAL_HEAP_SIZE` on FreeRTOS — already sized to hold this backing, so
42//! turning the reservation on there without lowering that knob reserves the same
43//! bytes twice.
44//!
45//! That pairing is per-image and only the image's author can measure it, so the
46//! opt-out is a knob rather than a guess: `NROS_EXECUTOR_BACKING_U64S=0` emits
47//! no static at all and restores the leak. A non-zero value overrides the
48//! reservation's SIZE, which is also how a fat entry — one declaring
49//! `max_callbacks` above `NROS_EXECUTOR_MAX_CBS` — keeps a static instead of
50//! falling back to the heap.
51//!
52//! **The Zephyr `CONFIG_` spelling IS wired** (issue 1171; this paragraph said
53//! the opposite until then). `zephyr/Kconfig` declares
54//! `NROS_EXECUTOR_BACKING_U64S` with the tree's `-1` DERIVE sentinel as its
55//! default, and `nros-node`'s build script reaches it through the same env →
56//! `$DOTCONFIG` reader every other executor knob uses (issue 0460). `-1` does
57//! not parse as a `usize`, which is exactly how every other `-1 = derive` knob
58//! in this tree falls through to its crate default, so the shipped default is
59//! still the derived size and no Zephyr image moved the day it landed — a
60//! plain `default 0` would have meant "no static" on all of them, which is the
61//! opposite of the default this chose.
62//!
63//! # Why an image would STATE the size rather than derive it
64//!
65//! Because the derivation cannot be paired with anything. Issue 1145 lowered
66//! one leaf's `CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE` by a size copied out of
67//! `nm` output, and that subtrahend is a function of the executor knobs: move
68//! `MAX_CBS`, the arena or the rx buffer and it is silently stale in whichever
69//! direction, with nothing to say so (issue 1171). It was also wrong on the
70//! second board the same conf builds for — the derived size is **87,256 B on
71//! `mps2_an385` and 88,328 B on `native_sim/native/64`**, because the carved
72//! tables hold pointers, so one number cannot pair both.
73//!
74//! Stating it inverts the dependency: the reservation is `8 * words` bytes on
75//! every target, the arena's lowering is arithmetic a gate can check
76//! (`check-executor-backing-arena-pairing`), and a stated size BELOW what the
77//! executor needs is the `const` assertion below — a compile error naming this
78//! knob, which is the direction that would otherwise re-create the double
79//! reservation in silence.
80//!
81//! **Zephyr no longer pairs it** (issue 1611). Issue 1324 moved every Zephyr
82//! Rust allocation onto the nros heap, so picolibc's arena holds no Rust bytes
83//! and the six example confs that lowered it now state neither number. The
84//! pairing above survives on ThreadX's rung.
85//!
86//! # Why there is no `// nros-pool:` annotation
87//!
88//! `scripts/gen-pool-inventory.py` evaluates a pool as a PRODUCT of knobs at
89//! their literal defaults. This one is a SUM — the executor's carved tables plus
90//! the arena, laid out with alignment padding between them — and its largest
91//! term, `ARENA_SIZE`, is itself derived
92//! (`env_usize("NROS_EXECUTOR_ARENA_SIZE", derived_arena)` in
93//! `nros-node/build.rs`), so the inventory would record it as a computed default
94//! even if the sum were expressible. A formula that is right for one build and
95//! wrong for the rest is the drift class this tree gates against, so this
96//! follows the two documented deliberate non-annotations
97//! (`nros_rmw_zenoh::shim::publisher`, `nros_rmw_cffi`): **the size is known to
98//! the compiler, so read it from the compiler's output.** `mem-report` prices
99//! the symbol from the ELF, exactly, with no formula to drift.
100//!
101//! # Placement
102//!
103//! `NROS_EXECUTOR_BACKING_SECTION` (build-time env, read by `nros-node`'s build
104//! script) puts the static in a named section, for the amendment-A case where a
105//! part has tightly-coupled memory the linker script can target — issue 0880
106//! does the same for `nros_thread_stacks` with `DTCM`. Two constraints, both
107//! load-bearing: **the section must be `NOLOAD`**, because this static is
108//! uninitialised and a loadable section would add its whole size to the image's
109//! flash footprint; and it must be reachable by every bus master that touches
110//! the executor's buffers, which on Cortex-M7 the TCMs typically are not.

119/// The reservation's size when nothing overrides it: one default-sized
120/// executor's worth.
121///
122/// One executor, not a multiple, because an entry opens ONE through this road:
123/// a tiered boot's SPAWNED tiers take their slots from the entry's own
124/// [`TierExecutorBacking`] instead (issue 1571), each slot this many words.
125///
126/// Named by the GENERATED file when nothing overrides the size, so it is unused
127/// under `NROS_EXECUTOR_BACKING_U64S=0` (no static) and under an explicit
128/// override (a literal). Kept rather than `cfg`'d: it is what the override is
129/// judged against, and a constant that disappears with its consumer cannot be
130/// compared to anything.
131#[allow(dead_code)]
132pub const EXECUTOR_BACKING_DEFAULT_U64S: usize = ExecutorSizing::DEFAULT.u64_len();
133
134// `EXECUTOR_BACKING`, its size const, and the optional
135// `#[unsafe(link_section = …)]` on it are emitted by `build.rs`: `link_section`
136// takes a string LITERAL and the section name is a build-time input, and the
137// size may be overridden or the whole item suppressed. The file is EMPTY when
138// `NROS_EXECUTOR_BACKING_U64S=0`, which is why the include is unconditional
139// while everything that reads it is `cfg`-gated.
140include!(concat!(env!("OUT_DIR"), "/nros_executor_backing.rs"));

142/// The reservation must cover the sizing every `alloc` convenience constructor
143/// passes, or it is dead weight every image carries and no executor ever uses.
144///
145/// A `const` assertion rather than a test, deliberately: the only way to make it
146/// false is to set `NROS_EXECUTOR_BACKING_U64S` too low, and the person doing
147/// that wants to hear about it from the build they just ran, not from a test
148/// suite they may not run at all. `0` is the documented opt-out and is not
149/// reached here — it emits no static, so this whole arm is `cfg`'d away.
150///
151/// **It also goes false the OTHER way, and a const assertion alone cannot see
152/// that** (issue 1284): a conf that STATES the knob stays put while the executor
153/// grows under it. That fails only in the image's own build, which no
154/// merge-gating lane runs, so twelve Zephyr leaves drifted twice in a week. `just
155/// check node-std-tests` now runs this assertion per stated claim at each
156/// claimed board's pointer width, and `tests/executor_backing_claims.rs` checks
157/// the host-width claims against [`EXECUTOR_BACKING_DEFAULT_U64S`] by number;
158/// `check-executor-backing-arena-pairing --claims` says which confs claim what.
159#[cfg(nros_executor_backing_static)]
160const _: () = assert!(
161    EXECUTOR_BACKING_U64S >= EXECUTOR_BACKING_DEFAULT_U64S,
162    "NROS_EXECUTOR_BACKING_U64S is below the default executor sizing, so the \
163     reservation can never be taken and is pure dead weight; use 0 to decline \
164     the static entirely"
165);

167/// Has [`EXECUTOR_BACKING`] been handed out?
168///
169/// A latch, not a free list: the backing is handed out as `&'static mut` and
170/// never returned, exactly like the `Box::leak` it replaces. An executor that
171/// drops does not give it back — reclaiming it would need the executor's own
172/// tables to be provably dead first, which `Drop` cannot show for a slice it has
173/// already lent to `Dispatcher`.
174#[cfg(nros_executor_backing_static)]
175static TAKEN: AtomicBool = AtomicBool::new(false);
176
177/// Hand out [`EXECUTOR_BACKING`], once, if it can hold `words`.
178///
179/// `None` means "use the heap", and every path to it is legitimate rather than
180/// degraded — it is the caller's behaviour from before this module existed:
181///
182/// * the reservation is switched off (`NROS_EXECUTOR_BACKING_U64S=0`);
183/// * another executor already took it (a second `Executor::open` in one
184///   process — a tiered boot's spawned tiers no longer come here, they take
185///   the entry's [`TierExecutorBacking`], issue 1571);
186/// * this executor is sized past the reservation (a fat entry).
187///
188/// The `swap` is what makes the returned `&'static mut` sound: exactly one
189/// caller observes `false`, so exactly one reference to the static ever exists.
190#[cfg(nros_executor_backing_static)]
191pub(crate) fn take(words: usize) -> Option<&'static mut [MaybeUninit<u64>]> {
192    if words > EXECUTOR_BACKING_U64S {
193        return None;
194    }
195    if TAKEN.swap(true, Ordering::AcqRel) {
196        return None;
197    }
198    // SAFETY: the swap above succeeds exactly once for the life of the process,
199    // so this is the only reference ever created to `EXECUTOR_BACKING`, and it
200    // is `'static` because the static is. `words <= EXECUTOR_BACKING_U64S` was
201    // checked, so the slice is in bounds.
202    // The raw ref is bound first rather than dereferenced in place: `&mut
203    // *(&raw mut X)` reads as `deref_addrof` to clippy, and the obvious
204    // rewrite it suggests (`&mut X`) is the `static_mut_refs` hazard this
205    // spelling exists to avoid.
206    let ptr = &raw mut EXECUTOR_BACKING;
207    let all: &'static mut [MaybeUninit<u64>; EXECUTOR_BACKING_U64S] = unsafe { &mut *ptr };
208    Some(&mut all[..words])
209}

211/// The reservation is switched off, so there is nothing to hand out.
212///
213/// A stub rather than a `cfg` at the call site: `default_backing` reads the same
214/// either way, which is the paired-stub idiom `trace_register` uses one file
215/// over, and it keeps the `#[cfg]` in exactly one place.
216#[cfg(not(nros_executor_backing_static))]
217pub(crate) fn take(_words: usize) -> Option<&'static mut [MaybeUninit<u64>]> {
218    None
219}

227// ============================================================================
228// issue 1571 — the SPAWNED tiers' executor backing, as the entry's own static
229// ============================================================================
230//
231// A tiered boot opens one executor per tier. The boot tier takes
232// `EXECUTOR_BACKING` through `Executor::open` like any single-executor entry;
233// every OTHER tier used to reach `default_backing` too, find the latch already
234// taken, and `Box::leak` a default-sized block — correctly sized, but invisible
235// to `mem-report` and drawn from the allocator arena, where issue 1568 had just
236// moved every C and C++ RTOS executor (tier and single) OUT of it.
237//
238// The fix is the C/C++ METHOD, not a second one: the tier count is known when
239// the entry is generated, so the entry (`nros::main!`) emits ONE named static of
240// `N - 1` slots — the C pack's `__nros_tier_executor_storage` — and the board's
241// `run_tiers` hands each spawned tier its slot. The slot is typed, so its size is
242// the executor's exact need by construction: the tier opens with
243// `ExecutorSizing::DEFAULT` (see `Executor::open_with_session_slot`) and the slot
244// is `ExecutorSizing::DEFAULT.u64_len()` words — the same const the boot
245// reservation above is judged against, so there is ONE spelling of "a default
246// executor's worth" for both.
247//
248// It is a MOVE, exactly like the boot reservation: on an RTOS the same bytes
249// leave the allocator arena (`CONFIG_COMMON_LIBC_MALLOC_ARENA_SIZE`,
250// `configTOTAL_HEAP_SIZE`, the NuttX kernel heap, the ThreadX byte pool) and
251// become linker-visible `.bss`.
252
253/// issue 1571 — one spawned tier executor's backing: exactly the words an
254/// executor opened with [`ExecutorSizing::DEFAULT`] carves.
255pub type TierExecutorBackingSlot = [MaybeUninit<u64>; EXECUTOR_BACKING_DEFAULT_U64S];
256
257/// issue 1571 — the spawned tiers' executor backing, `N` slots in ONE named
258/// static that the ENTRY owns.
259///
260/// `nros::main!` emits one per tiered entry, with `N` = the tier count minus the
261/// boot tier (which takes the `EXECUTOR_BACKING` road), and passes
262/// [`take`](Self::take) to the board's `run_tiers`. The board then refuses a
263/// short block with [`check_tier_executor_backing`] — the Rust twin of the C
264/// library's `nros_cpp_executor_storage_check`.
265///
266/// Placement is the caller's (RFC-0002 § 4.4b): the static lives in the entry's
267/// `.bss`, so `mem-report` prices it by name.
268pub struct TierExecutorBacking<const N: usize> {
269    /// The same once-only latch as the boot reservation's, per static: the
270    /// slots go out as `&'static mut`, so exactly one caller may observe them.
271    taken: portable_atomic::AtomicBool,
272    slots: core::cell::UnsafeCell<[TierExecutorBackingSlot; N]>,
273}
274
275// SAFETY: the slots are only reachable through `take`, whose latch hands them
276// out at most once, so no two threads can ever hold a reference to them.
277unsafe impl<const N: usize> Sync for TierExecutorBacking<N> {}
278
279impl<const N: usize> TierExecutorBacking<N> {
280    /// An untouched reservation. `const` so it can initialise a `static`, and
281    /// uninitialised (plus a `false` latch), so the static is all-zero `.bss`
282    /// and costs no flash.
283    ///
284    /// `large_stack_arrays` is allowed because this is only ever evaluated in
285    /// CONST context (a `static` initialiser): the array is built by the
286    /// compiler into `.bss`, never on a stack.
287    #[allow(clippy::new_without_default, clippy::large_stack_arrays)]
288    pub const fn new() -> Self {
289        Self {
290            taken: portable_atomic::AtomicBool::new(false),
291            slots: core::cell::UnsafeCell::new(
292                [[MaybeUninit::uninit(); EXECUTOR_BACKING_DEFAULT_U64S]; N],
293            ),
294        }
295    }
296
297    /// Hand out every slot, once. A second call returns an EMPTY slice, which
298    /// the board's [`check_tier_executor_backing`] then refuses by name rather
299    /// than aliasing a slot another executor is using.
300    ///
301    /// `mut_from_ref` is the point, not an accident: `&'static self` is how a
302    /// `static` is reached, and the latch is what makes the one `&mut` sound —
303    /// the same shape as the boot reservation's `take`.
304    #[allow(clippy::mut_from_ref)]
305    pub fn take(&'static self) -> &'static mut [TierExecutorBackingSlot] {
306        if self.taken.swap(true, portable_atomic::Ordering::AcqRel) {
307            return &mut [];
308        }
309        // SAFETY: the swap above succeeds exactly once per static, so this is
310        // the only reference ever created to `slots`; `'static` because `self`
311        // is.
312        unsafe { &mut *self.slots.get() }
313    }
314}

316/// issue 1571 — the tier backing a board was handed does not cover the tiers it
317/// must spawn. Carries both counts so the refusal names them.
318#[derive(Debug, Clone, Copy, PartialEq, Eq)]
319pub struct TierBackingShort {
320    /// Tiers the board spawns (every tier but the boot one).
321    pub spawned: usize,
322    /// Slots it was handed.
323    pub slots: usize,
324}
325
326impl core::fmt::Display for TierBackingShort {
327    fn fmt(&self, f: &mut core::fmt::Formatter<'_>) -> core::fmt::Result {
328        write!(
329            f,
330            "tier executor backing holds {} slot(s) but {} spawned tier(s) need one each \
331             — the entry's `TierExecutorBacking` was sized for a different tier table, \
332             or taken twice (issue 1571)",
333            self.slots, self.spawned
334        )
335    }
336}

338/// issue 1571 — the ONE refusal every board's `run_tiers` makes before it opens
339/// anything: `n_tiers` tiers run, one on the boot executor, so `n_tiers - 1`
340/// must each find a slot. Checked up front rather than at each spawn, so a
341/// short block never leaves a half-spawned tier chain.
342pub fn check_tier_executor_backing(
343    n_tiers: usize,
344    backing: &[TierExecutorBackingSlot],
345) -> Result<(), TierBackingShort> {
346    let spawned = n_tiers.saturating_sub(1);
347    if backing.len() < spawned {
348        return Err(TierBackingShort {
349            spawned,
350            slots: backing.len(),
351        });
352    }
353    Ok(())
354}

357// issue 1598 — each spawned tier's TASK memory (stack + control block), the
358// same "entry declares, board uses" method one step further: the executor
359// backing above is in `.bss`, and so now is the task that runs it.

362/// issue 1598 — the control-block region every [`TierTaskMemory`] carries,
363/// in 8-byte words. An UPPER BOUND over the kernels that take it (a FreeRTOS
364/// `StaticTask_t` on Cortex-M is about a hundred bytes); the port REFUSES a
365/// region smaller than its own control block at spawn, by name, so a kernel
366/// whose block outgrows this fails loudly rather than overrunning the stack
367/// that follows. Rust cannot name a C type's size at macro time, which is why
368/// this one number is a bound and the stack beside it is exact.
369pub const TIER_TASK_TCB_U64S: usize = 64;
370
371/// issue 1598 — one spawned tier's task memory as a board receives it: raw,
372/// `Copy`, no lifetime. The ENTRY owns the bytes ([`TierTaskMemory`]); the
373/// handout is once-only ([`TierTaskMemorySet::take`]), which is what makes the
374/// raw pointers exclusive.
375#[derive(Clone, Copy, Debug)]
376pub struct TierTaskMemoryRaw {
377    /// The stack: `stack_bytes` bytes, 64-byte aligned.
378    pub stack: *mut u8,
379    /// The stack's size in bytes — the tier's declared `stack_bytes` (or the
380    /// family default), rounded up to whole words.
381    pub stack_bytes: usize,
382    /// The control-block region: `tcb_bytes` bytes, 64-byte aligned.
383    pub tcb: *mut u8,
384    /// [`TIER_TASK_TCB_U64S`] words.
385    pub tcb_bytes: usize,
386}
387
388impl TierTaskMemoryRaw {
389    /// "This tier has no task memory from the entry": the port keeps its own
390    /// default (Zephyr's pool slot for a tier that declared no `stack_bytes`).
391    pub const NONE: Self = Self {
392        stack: core::ptr::null_mut(),
393        stack_bytes: 0,
394        tcb: core::ptr::null_mut(),
395        tcb_bytes: 0,
396    };
397}

399// SAFETY: the pointers name `'static` storage handed out once (see the set's
400// latch), so moving the row to the task that uses it is the whole point.
401unsafe impl Send for TierTaskMemoryRaw {}
402unsafe impl Sync for TierTaskMemoryRaw {}

404/// issue 1598 — one spawned tier's stack and control block, as ONE named static
405/// the entry owns. `STACK_U64S` is the tier's stack in 8-byte words;
406/// `TCB_U64S` the control-block region, [`TIER_TASK_TCB_U64S`] by default and
407/// `0` for a kernel whose control block the port keeps itself (Zephyr's
408/// `struct k_thread`, issue 1232 — a Rust entry cannot size it).
409///
410/// The control block comes first and the struct is 64-byte aligned, so the
411/// stack starts on a boundary every in-tree kernel accepts for a thread stack
412/// (the TCB region is a whole number of 64-byte lines).
413#[repr(C, align(64))]
414pub struct TierTaskMemory<const STACK_U64S: usize, const TCB_U64S: usize = TIER_TASK_TCB_U64S> {
415    tcb: core::cell::UnsafeCell<[MaybeUninit<u64>; TCB_U64S]>,
416    stack: core::cell::UnsafeCell<[MaybeUninit<u64>; STACK_U64S]>,
417}
418
419// SAFETY: the bytes are reached only through `raw`, collected into a
420// `TierTaskMemorySet` whose latch hands them out at most once.
421unsafe impl<const STACK_U64S: usize, const TCB_U64S: usize> Sync
422    for TierTaskMemory<STACK_U64S, TCB_U64S>
423{
424}
425
426impl<const STACK_U64S: usize, const TCB_U64S: usize> TierTaskMemory<STACK_U64S, TCB_U64S> {
427    /// An untouched reservation, `const` so it initialises a `static`
428    /// (all-zero `.bss`, no flash).
429    #[allow(clippy::new_without_default, clippy::large_stack_arrays)]
430    pub const fn new() -> Self {
431        Self {
432            tcb: core::cell::UnsafeCell::new([MaybeUninit::uninit(); TCB_U64S]),
433            stack: core::cell::UnsafeCell::new([MaybeUninit::uninit(); STACK_U64S]),
434        }
435    }
436
437    /// The raw row for this static — `const`, so the entry builds its
438    /// [`TierTaskMemorySet`] in a `static` initialiser.
439    pub const fn raw(&'static self) -> TierTaskMemoryRaw {
440        TierTaskMemoryRaw {
441            stack: self.stack.get() as *mut u8,
442            stack_bytes: STACK_U64S * core::mem::size_of::<u64>(),
443            tcb: self.tcb.get() as *mut u8,
444            tcb_bytes: TCB_U64S * core::mem::size_of::<u64>(),
445        }
446    }
447}

449/// issue 1598 — the spawned tiers' task memory, `N` rows in spawn (chain)
450/// order, behind a once-only latch.
451pub struct TierTaskMemorySet<const N: usize> {
452    taken: portable_atomic::AtomicBool,
453    rows: [TierTaskMemoryRaw; N],
454}
455
456impl<const N: usize> TierTaskMemorySet<N> {
457    /// `const`, for a `static` initialiser over the per-tier statics.
458    pub const fn new(rows: [TierTaskMemoryRaw; N]) -> Self {
459        Self {
460            taken: portable_atomic::AtomicBool::new(false),
461            rows,
462        }
463    }
464
465    /// Hand out every row, once. A second call returns an EMPTY slice, which a
466    /// board refuses by count rather than giving two tasks one stack.
467    pub fn take(&'static self) -> &'static [TierTaskMemoryRaw] {
468        if self.taken.swap(true, portable_atomic::Ordering::AcqRel) {
469            return &[];
470        }
471        &self.rows
472    }
473}

490    /// `spin.rs`'s `default_backing` — reached by every `Executor::open` under
491    /// the `alloc` feature — claims it. Any of this binary's other 365 tests
492    /// that opens an executor therefore consumes the one handout first, and
493    /// this test's own positive control (`take` returning `Some`) becomes
494    /// impossible. Measured: passes alone, fails in the full lane at the
495    /// `!is_taken()` assertion below.
496    ///
497    /// `just check node-std-tests` runs it in its own cargo invocation, which
498    /// is a second process. Same shape and same answer as `boot_report::tests`
499    /// one recipe over, and for the same underlying reason.
500    #[cfg(nros_executor_backing_static)]
501    #[test]
502    #[ignore = "needs a virgin process: TAKEN is a process-global latch that \
503                Executor::open consumes — run via `just check node-std-tests`"]
504    fn the_static_is_handed_out_once_and_only_once() {
505        // Too large for the reservation: refused BEFORE the latch is touched, so
506        // this case cannot consume the one handout.
507        assert!(
508            take(EXECUTOR_BACKING_U64S + 1).is_none(),
509            "a request past the reservation must fall back to the heap"
510        );
511        assert!(
512            !is_taken(),
513            "an over-large request must not claim the latch"
514        );
515
516        let first = take(EXECUTOR_BACKING_U64S).expect("the first taker gets the static");
517        assert_eq!(
518            first.len(),
519            EXECUTOR_BACKING_U64S,
520            "the handout is the requested length, not the whole reservation"
521        );
522        assert!(is_taken());
523
524        assert!(
525            take(1).is_none(),
526            "a second taker must fall back to the heap — two `&'static mut` to \
527             one static is UB, which is the whole reason for the latch"
528        );
529    }

561    /// issue 1598 — a tier's task memory is exactly the declared stack plus the
562    /// stated control-block bound, aligned for a thread stack, and handed out
563    /// ONCE: a second take is empty, never a second task on the same stack.
564    #[test]
565    fn tier_task_memory_is_the_declared_size_and_handed_out_once() {
566        static A: TierTaskMemory<128> = TierTaskMemory::new();
567        static B: TierTaskMemory<32> = TierTaskMemory::new();
568        static SET: TierTaskMemorySet<2> = TierTaskMemorySet::new([A.raw(), B.raw()]);
569        let rows = SET.take();
570        assert_eq!(rows.len(), 2);
571        assert_eq!(rows[0].stack_bytes, 128 * 8);
572        assert_eq!(rows[1].stack_bytes, 32 * 8);
573        assert_eq!(rows[0].tcb_bytes, TIER_TASK_TCB_U64S * 8);
574        assert_eq!(rows[0].stack as usize % 64, 0, "stack is 64-byte aligned");
575        assert_ne!(rows[0].stack, rows[1].stack);
576        assert_eq!(
577            core::mem::size_of::<TierTaskMemory<128>>(),
578            (TIER_TASK_TCB_U64S + 128) * 8,
579            "nothing but the TCB bound and the stack"
580        );
581        assert!(
582            SET.take().is_empty(),
583            "a second take must not alias the rows"
584        );
585    }
