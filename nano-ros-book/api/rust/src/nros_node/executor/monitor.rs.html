1//! RFC-0052 / phase-296 W3b.4/.5 — on-target contract monitors.
2//!
3//! The baked shape mirrors Phase 211.H's `qos_overrides`: codegen emits a
4//! `&'static [MonitorSpec]` table (plus one `static PubMonitorCell` per
5//! contracted publisher) from the SystemModel's contract layer; the entry
6//! installs it on the executor before entity creation. An uncontracted
7//! image bakes an empty table — every path below dead-code-eliminates.
8//!
9//! Publish counting is an atomic bump on the publisher handle (no clock,
10//! no lock on the hot path); the rate check runs on spin ticks over a
11//! ~[`RATE_CHECK_INTERVAL_US`] window and pushes violations into a small
12//! ring the entry glue drains into the `nros-diagnostics` reporter.
13//!
14//! W3b.5 adds three more rules on the same drain:
15//! - `max-age-runtime` — subscriber take-age (`epoch_now - header.stamp`
16//!   peeked from the raw CDR buffer at `RosMessage::STAMP_OFFSET`,
17//!   recorded into a [`SubMonitorCell`] on the take path).
18//! - `max-latency-runtime` — node-path (take → publish) latency: the
19//!   dispatch elapsed time is attributed to every monitored publisher
20//!   whose counter advanced during that dispatch (an upper bound on
21//!   take → publish, measured on the executor's monotonic clock). The span
22//!   is callback entry to exit, for every dispatch kind: a timer callback
23//!   is timed whether it fires in the drains or in the trigger-miss sweep
24//!   (phase-474 I6), and a service call it makes is inside the span. The
25//!   timer's release jitter (a late start) is not part of it; that is
26//!   `release-jitter-runtime`.
27//! - `deadline-miss-runtime` — a dispatched callback ran past its bound
28//!   SchedContext's `deadline_us`; what ELSE happens is the tier's
29//!   [`DeadlineAction`](super::sched_context::DeadlineAction).
30//!
31//! phase10-B3 adds the route rule beside it:
32//! - `route-latency-runtime` -- a node path whose trigger is an INPUT is
33//!   budgeted from the TAKE of that input to its output, and on a node that
34//!   reads its input on a timer tick that span includes the wait for the next
35//!   tick. `max-latency-runtime` times one dispatch and cannot see the wait,
36//!   so a route made of a long tick wait and a slow dispatch could exceed its
37//!   budget while every callback passed. The executor stamps the dispatch that
38//!   takes the trigger input (the earliest take not yet answered) and, at the
39//!   end of a dispatch that published one of the path's outputs, judges
40//!   take-to-dispatch-end against the path's `max_latency_ms`
41//!   (`route_take`, `route_judge`). Record only: the rule has no action.
42//!
43//! phase-462 W2 adds one more on the same drain, and it is the other half of
44//! what the contract's `on_violation` lowers to:
45//! - `silence-runtime` -- a contracted subscription that took NOTHING for a
46//!   whole `max_age_ms` window (`check_silence`). A violation is either "the
47//!   callback ran too long", which is the deadline action, or "the input
48//!   stopped coming", which is this; the four rules above can only see the
49//!   first kind.

57/// One contracted publisher's counters. Baked as a `static` by codegen
58/// (or declared by the fixture); the publisher handle bumps `count` on
59/// every publish, the executor reads deltas on spin ticks.
60#[derive(Debug, Default)]
61pub struct PubMonitorCell {
62    pub count: AtomicU32,
63    /// W3b.5 — max observed take→publish latency (µs) in the current
64    /// check window. Written by the dispatch loop (fetch_max), drained
65    /// (swap 0) by the latency check.
66    pub max_latency_us: AtomicU32,
67    /// Age of the stamp this publisher last put ON THE WIRE, in
68    /// microseconds: `epoch_now - outgoing header.stamp`.
69    ///
70    /// Distinct from `max_latency_us`, which times this node's own
71    /// take→publish work. This says how old the DATA is that the node just
72    /// published, which is the quantity a chain is made of.
73    ///
74    /// It exists to answer a question `max-age-runtime` cannot. That rule
75    /// measures `epoch_now - stamp` on the TAKE path, so if every node in a
76    /// chain propagates the original stamp -- the usual ROS convention, each
77    /// node copying its input's stamp to its output -- the age at the final
78    /// consumer already IS the end-to-end latency. If any node re-stamps
79    /// with `now`, the clock silently resets and the same number becomes
80    /// single-hop age instead. Same units, same magnitude, no warning.
81    ///
82    /// A publish age near zero on a node that consumes input is the
83    /// signature of re-stamping. Recording it here is what lets a chain's
84    /// provenance be checked at all, rather than assumed.
85    ///
86    /// `0` = never observed, matching the other cells: the type has no
87    /// `STAMP_OFFSET`, or no epoch source is installed.
88    pub last_publish_stamp_age_us: AtomicU32,
89    /// phase10-B3 -- the route rule's state for this output
90    /// ([`MonitorSpec::route_trigger`]): the trigger subscription's executor
91    /// slot + 1 in the low 16 bits (0 = no subscription bound, set when the
92    /// subscription registers), [`ROUTE_VIOLATED`] and [`ROUTE_PENDING`] above.
93    pub route: AtomicU32,
94    /// phase10-B3 -- when the earliest take not yet answered by a publish of
95    /// this output happened, executor clock in microseconds (wrapping). Valid
96    /// while [`ROUTE_PENDING`] is set in `route`.
97    pub route_take_us: AtomicU32,
98}
99
100/// phase10-B3 -- `PubMonitorCell::route`: a take of the trigger input is
101/// waiting for this output.
102pub const ROUTE_PENDING: u32 = 1 << 31;
103/// phase10-B3 -- `PubMonitorCell::route`: the last judged route was over its
104/// budget (report once until one is within it, as the latency rule does).
105pub const ROUTE_VIOLATED: u32 = 1 << 30;
106/// phase10-B3 -- `PubMonitorCell::route`: the bound slot + 1.
107pub const ROUTE_SLOT_MASK: u32 = 0xffff;
108
109impl PubMonitorCell {
110    pub const fn new() -> Self {
111        Self {
112            count: AtomicU32::new(0),
113            max_latency_us: AtomicU32::new(0),
114            last_publish_stamp_age_us: AtomicU32::new(0),
115            route: AtomicU32::new(0),
116            route_take_us: AtomicU32::new(0),
117        }
118    }
119}

121/// One contracted subscriber's take-age accumulator (W3b.5). The take
122/// path records `epoch_now - header.stamp` per message (fetch_max); the
123/// age check drains it (swap 0) per window.
124#[derive(Debug, Default)]
125pub struct SubMonitorCell {
126    /// Max observed take-age (ms) in the current check window.
127    pub max_age_ms: AtomicU32,
128    /// phase-462 W2 -- observations recorded since the last check, drained
129    /// (swap 0) by `check_age`. The age itself cannot answer "did anything
130    /// arrive": a window with no take and a window whose only take was
131    /// perfectly fresh both leave `max_age_ms` at 0.
132    pub takes: AtomicU32,
133    /// phase-462 W5b -- the executor slot + 1 whose readiness is this
134    /// endpoint's arrival evidence, set when the contract's `deadline` is
135    /// judged here rather than by the backend ([`admit_contract_deadline`]).
136    /// 0 = not armed: the backend judges the deadline, or none is declared.
137    pub deadline_slot: AtomicU32,
138    /// phase-462 W5b -- spins on which the armed slot had data, drained by
139    /// `check_age`. Counted for ANY message type, stamped or not, because a
140    /// deadline is a promise about arrival and says nothing about stamps.
141    pub arrivals: AtomicU32,
142}

144impl SubMonitorCell {
145    pub const fn new() -> Self {
146        Self {
147            max_age_ms: AtomicU32::new(0),
148            takes: AtomicU32::new(0),
149            deadline_slot: AtomicU32::new(0),
150            arrivals: AtomicU32::new(0),
151        }
152    }
153
154    /// Take-path hook: record one message's age. `stamp_us` is the
155    /// peeked `header.stamp` as µs since the UNIX epoch, `epoch_now_us`
156    /// the receive-side wall clock. A stamp from the future clamps to 0.
157    ///
158    /// phase-462 W2 -- also the silence rule's only evidence that this
159    /// endpoint is being fed. It counts what the AGE rule can see, which is
160    /// stamped takes on a type that carries a stamp: a contracted endpoint
161    /// whose messages carry no readable stamp records nothing here and is
162    /// reported silent. That is the intended verdict rather than a gap --
163    /// its `max_age_ms` cannot be judged either, and an unjudgeable promise
164    /// reported as met is the silent class this phase exists to remove.
165    pub fn observe(&self, stamp_us: u64, epoch_now_us: u64) {
166        let age_ms = (epoch_now_us.saturating_sub(stamp_us) / 1_000).min(u32::MAX as u64) as u32;
167        self.max_age_ms.fetch_max(age_ms, Ordering::Relaxed);
168        self.takes.fetch_add(1, Ordering::Relaxed);
169    }
170}

172/// Peek `Time { i32 sec; u32 nanosec }` little-endian at `offset` in a
173/// raw CDR receive buffer (encapsulation header included) and return µs
174/// since the UNIX epoch. `None` when the buffer is too short or the
175/// stamp is pre-epoch/zero (unstamped messages never fire age monitors).
176/// Record the age of the stamp a publisher just put on the wire.
177///
178/// Called from the publish path with the encoded CDR still in hand, using the
179/// same `STAMP_OFFSET` peek the take path uses. A no-op when the type carries
180/// no stamp, when no epoch source is installed, or when the publisher is
181/// uncontracted -- the same three ways `observe_age` folds away.
182///
183/// Stores rather than accumulates: this is "how old was the last thing
184/// published", a state, not a window maximum. A chain check wants the current
185/// value, and a max would be pinned forever by one stale message at startup.
186#[inline]
187pub fn observe_publish_stamp(cell: &PubMonitorCell, raw: &[u8], offset: usize, now_us: u64) {
188    if let Some(stamp_us) = peek_stamp_us(raw, offset) {
189        let age = now_us.saturating_sub(stamp_us).min(u32::MAX as u64) as u32;
190        cell.last_publish_stamp_age_us.store(age, Ordering::Relaxed);
191    }
192}
193
194pub fn peek_stamp_us(raw: &[u8], offset: usize) -> Option<u64> {
195    let sec_b = raw.get(offset..offset + 4)?;
196    let nsec_b = raw.get(offset + 4..offset + 8)?;
197    let sec = i32::from_le_bytes([sec_b[0], sec_b[1], sec_b[2], sec_b[3]]);
198    let nsec = u32::from_le_bytes([nsec_b[0], nsec_b[1], nsec_b[2], nsec_b[3]]);
199    if sec <= 0 {
200        return None;
201    }
202    Some(sec as u64 * 1_000_000 + nsec as u64 / 1_000)
203}

309/// phase-462 W5b -- what a subscription's creation does about its contract
310/// `deadline`, decided from the backend's OWN answer
311/// (`Session::supported_qos_policies`) at the moment it is created.
312///
313/// The served set is a run-time fact -- a C backend answers through the
314/// vtable (issue 1329) -- so it is asked here rather than restated in a build
315/// table that could disagree with it. Three outcomes:
316///
317/// * the backend honours `DEADLINE` and the profile carries the deadline: the
318///   backend judges it, nothing is armed;
319/// * the backend does not honour `DEADLINE`: a profile deadline EQUAL to the
320///   contract's is stripped (it came from the contract, and refusing it at
321///   create would turn a judgeable promise into a boot failure), and the row
322///   is armed so the silence rule judges it;
323/// * the profile never carried the deadline (a registration path that does
324///   not fold the launch overrides): the backend cannot judge what it was
325///   never told, so the row is armed too.
326///
327/// A profile deadline that DIFFERS from the contract's is the caller's own
328/// request and is left alone, so a backend that cannot serve it still refuses
329/// it by name. Returns the profile to create with and the row to arm.
330pub fn admit_contract_deadline(
331    mut qos: nros_rmw::QoSProfile,
332    served: nros_rmw::QoSPolicyMask,
333    ages: &'static [AgeMonitorSpec],
334    topic: &str,
335) -> (nros_rmw::QoSProfile, Option<&'static AgeMonitorSpec>) {
336    let Some(spec) = ages.iter().find(|a| a.topic == topic && a.deadline_ms > 0) else {
337        return (qos, None);
338    };
339    let serves = served.0 & nros_rmw::QoSPolicyMask::DEADLINE.0 != 0;
340    if serves && qos.deadline_ms != 0 {
341        return (qos, None);
342    }
343    if !serves && qos.deadline_ms == spec.deadline_ms {
344        qos.deadline_ms = 0;
345    }
346    (qos, Some(spec))
347}

349/// phase-462 W5b -- a released subscription's slot stops being any row's
350/// arrival evidence; its slot may be claimed by an unrelated entry next.
351pub(crate) fn deadline_unbind(ages: &[AgeMonitorSpec], slot: usize) {
352    for spec in ages {
353        let _ = spec.cell.deadline_slot.compare_exchange(
354            slot as u32 + 1,
355            0,
356            Ordering::Relaxed,
357            Ordering::Relaxed,
358        );
359    }
360}

362/// phase-462 W5b -- credit one arrival to every armed row whose slot is in
363/// `ready` (the executor's readiness bits for this spin).
364///
365/// Readiness, not dispatch, is the evidence, because it is the one point every
366/// entry passes on the spin thread: an os-priority entry is dispatched on a
367/// worker thread that holds no executor state, and a cooperative one only when
368/// its trigger passes.
369pub(crate) fn credit_arrivals(ages: &[AgeMonitorSpec], ready: u64) {
370    for spec in ages {
371        let slot = spec.cell.deadline_slot.load(Ordering::Relaxed);
372        if slot != 0 && slot <= 64 && ready & (1u64 << (slot - 1)) != 0 {
373            spec.cell.arrivals.fetch_add(1, Ordering::Relaxed);
374        }
375    }
376}

378/// phase-436 E4 — how often the stack-headroom rule may query the port, in µs.
379///
380/// On a painted Zephyr stack the query walks every UNUSED byte from the stack
381/// base (`z_stack_space_get`), so querying on every spin put that scan inside
382/// the control loop. The high-water mark only grows, so a throttled check sees
383/// the same low mark and only sees it later. Since E5 the query is also capped
384/// at the declared minimum (`stack_unused_bytes_upto`), so it reads at most
385/// that many bytes.
386pub(crate) const STACK_HEADROOM_CHECK_INTERVAL_US: u64 = 1_000_000;
387
388/// The same limit for a build with no clock: once per this many spins.
389pub(crate) const STACK_HEADROOM_CHECK_SPIN_STRIDE: u32 = 1_000;
390
391/// Whether the stack-headroom query is due.
392///
393/// `last_check_us` is `None` until the first check, which is immediate, so a
394/// bound set at boot is checked on the first spin. After that a clocked build
395/// waits one full interval and a clockless build one full stride of spins.
396pub(crate) fn stack_headroom_check_due(
397    now_us: Option<u64>,
398    last_check_us: Option<u64>,
399    spins_since_check: u32,
400) -> bool {
401    match (last_check_us, now_us) {
402        (None, _) => true,
403        (Some(last), Some(now)) => now.saturating_sub(last) >= STACK_HEADROOM_CHECK_INTERVAL_US,
404        (Some(_), None) => spins_since_check >= STACK_HEADROOM_CHECK_SPIN_STRIDE,
405    }
406}

481/// [`check_table_capacity`] against explicit capacities, so the refusal is
482/// testable at any knob value without rebuilding the crate.
483pub fn check_capacity_against(
484    n_rows: usize,
485    n_ages: usize,
486    max_rows: usize,
487    max_ages: usize,
488) -> Result<(), MonitorTableFull> {
489    if n_rows > max_rows {
490        return Err(MonitorTableFull {
491            knob: "NROS_EXECUTOR_MAX_MONITORS",
492            rows: n_rows,
493            capacity: max_rows,
494        });
495    }
496    if n_ages > max_ages {
497        return Err(MonitorTableFull {

578/// 32-bit FNV-1a of an endpoint ref -- the identity a trace marker and the SWD
579/// record carry for `Violation::fqn` (a string neither can hold).
580///
581/// FNV-1a because a decoder can recompute it in one line from the model's
582/// endpoint list (`scripts/read-violation-record.py` does), with no table
583/// baked into the image.
584pub const fn fqn_hash(fqn: &str) -> u32 {
585    let b = fqn.as_bytes();
586    let mut h: u32 = 0x811c_9dc5;
587    let mut i = 0;
588    while i < b.len() {
589        h ^= b[i] as u32;
590        h = h.wrapping_mul(0x0100_0193);
591        i += 1;
592    }
593    h
594}

675/// phase-474 I1 -- the image-wide violation record a debugger reads by NAME,
676/// for a board whose console reaches nobody.
677///
678/// The executor's ring is carved out of executor storage (no symbol, and a
679/// drain empties it), so on the Autoware Safety Island it could only be found
680/// by scanning RAM for rule-id string pointers, and it held the FIRST eight
681/// verdicts since boot. This record is the black box beside it: a `#[repr(C)]`
682/// static, every word a `u32`, never drained, keeping the LATEST
683/// [`MAX_VIOLATIONS`] stored violations of every executor in the image, with
684/// the running total.
685///
686/// Layout (version [`RECORD_VERSION`], little-endian `u32` words):
687///
688/// | word | field | meaning |
689/// | --- | --- | --- |
690/// | 0 | `magic` | [`RECORD_MAGIC`] (`"NRVR"`) |
691/// | 1 | `version` | [`RECORD_VERSION`] |
692/// | 2 | `capacity` | slots (`NROS_EXECUTOR_MAX_VIOLATIONS`) |
693/// | 3 | `slot_words` | [`RECORD_SLOT_WORDS`] |
694/// | 4 | `total` | violations stored since boot (the last `seq`) |
695/// | 5 | `head` | slot the NEXT violation takes (`total % capacity`) |
696/// | 6 | `dropped` | entries overwritten (`total - capacity`, saturating) |
697/// | 7 | `suppressed_before_arm` | verdicts before the monitors armed, all executors (phase-474 I2) |
698/// | 8 | `armed` | executors whose monitors armed (counted as each arms; at its first spin by default) (phase-474 I2) |
699/// | 9 | `reserved` | 0 |
700/// | 10.. | `slots` | `capacity` x [`ViolationSlot`] |
701///
702/// The newest entry is in slot `(head + capacity - 1) % capacity`; reading
703/// `capacity` slots backwards from there gives newest to oldest, and a slot
704/// whose `seq` is 0 was never written.
705///
706/// Present only when the image asked for the boot report
707/// (`NROS_BOOT_REPORT=1`, Zephyr `CONFIG_NROS_BOOT_REPORT=y`) -- the same
708/// opt-in as the SWD boot record it sits beside, so an image that does not
709/// opt in is unchanged. Read it with `scripts/read-violation-record.py`.
710#[repr(C)]
711#[derive(Debug)]
712pub struct ViolationRecord<const N: usize> {
713    pub magic: AtomicU32,
714    pub version: AtomicU32,
715    pub capacity: AtomicU32,
716    pub slot_words: AtomicU32,
717    pub total: AtomicU32,
718    pub head: AtomicU32,
719    pub dropped: AtomicU32,
720    pub suppressed_before_arm: AtomicU32,
721    pub armed: AtomicU32,
722    pub reserved: AtomicU32,
723    pub slots: [ViolationSlot; N],
724}
725
726impl<const N: usize> ViolationRecord<N> {
727    /// A valid, empty record: the header is written at compile time, so a
728    /// record with `total == 0` reads as "no violation since boot" rather than
729    /// as uninitialised RAM.
730    pub const fn new() -> Self {
731        Self {
732            magic: AtomicU32::new(RECORD_MAGIC),
733            version: AtomicU32::new(RECORD_VERSION),
734            capacity: AtomicU32::new(N as u32),
735            slot_words: AtomicU32::new(RECORD_SLOT_WORDS),
736            total: AtomicU32::new(0),
737            head: AtomicU32::new(0),
738            dropped: AtomicU32::new(0),
739            suppressed_before_arm: AtomicU32::new(0),
740            armed: AtomicU32::new(0),
741            reserved: AtomicU32::new(0),
742            slots: [const { ViolationSlot::new() }; N],
743        }
744    }
745
746    /// Store one violation, overwriting the oldest when full. Returns its
747    /// 1-based sequence number.
748    ///
749    /// Lock-free and callable from any executor thread: the slot is claimed by
750    /// a `fetch_add` on `total`, so two executors never write one slot unless
751    /// `N` more violations land during one write.
752    pub fn store(&self, v: &Violation) -> u32 {
753        let seq = self.total.fetch_add(1, Ordering::AcqRel).wrapping_add(1);
754        if N == 0 {
755            return seq;
756        }
757        let slot = &self.slots[(seq as usize - 1) % N];
758        slot.seq.store(0, Ordering::Release);
759        slot.rule.store(rule_code(v.rule), Ordering::Relaxed);
760        slot.fqn_hash.store(fqn_hash(v.fqn), Ordering::Relaxed);
761        slot.measured.store(v.measured, Ordering::Relaxed);
762        slot.declared.store(v.declared, Ordering::Relaxed);
763        slot.fqn_addr
764            .store(v.fqn.as_ptr() as usize as u32, Ordering::Relaxed);
765        slot.fqn_len.store(v.fqn.len() as u32, Ordering::Relaxed);
766        slot.seq.store(seq, Ordering::Release);
767        self.head.store(seq % N as u32, Ordering::Relaxed);
768        self.dropped
769            .store(seq.saturating_sub(N as u32), Ordering::Relaxed);
770        seq
771    }
772
773    /// The stored entries, newest first, as `(seq, rule code, fqn hash,
774    /// measured, declared)`. For tests and on-target self-checks; a debugger
775    /// reads the words directly.
776    pub fn newest_first(&self, mut f: impl FnMut(u32, u32, u32, u32, u32)) {
777        let total = self.total.load(Ordering::Acquire);
778        let n = (total as usize).min(N);
779        for k in 0..n {
780            let seq = total - k as u32;
781            let slot = &self.slots[(seq as usize - 1) % N];
782            if slot.seq.load(Ordering::Acquire) != seq {
783                continue; // overwritten or mid-write
784            }
785            f(
786                seq,
787                slot.rule.load(Ordering::Relaxed),
788                slot.fqn_hash.load(Ordering::Relaxed),
789                slot.measured.load(Ordering::Relaxed),
790                slot.declared.load(Ordering::Relaxed),
791            );
792        }
793    }
794}

796impl<const N: usize> Default for ViolationRecord<N> {
797    fn default() -> Self {
798        Self::new()
799    }
800}

1039impl<'s> ViolationChannel<'s> {
1040    pub(crate) fn new(ring: super::storage::CarvedVec<'s, Violation>) -> Self {
1041        Self {
1042            report: true,
1043            drain_report: crate::config::VIOLATION_DRAIN_REPORT,
1044            sink: None,
1045            reports: ReportQueue::default(),
1046            ring,
1047            counts: ViolationCounts {
1048                total: 0,
1049                dropped: 0,
1050                armed: MonitorArming::DEFAULT.armed_at_first_spin(),
1051                suppressed_before_arm: 0,
1052                arm_on_call: MonitorArming::DEFAULT.on_call,
1053                arm_grace_ms: MonitorArming::DEFAULT.grace_ms,
1054                spun: false,
1055                first_spin_ms: 0,
1056                arm_requests_seen: arm_requests(),
1057            },
1058        }
1059    }
1060
1061    /// Issue 1635 / phase-474 I1 -- THE one place a detected violation goes:
1062    /// the log floor (issue 0514) unless the drain hook reports instead, the
1063    /// image's sink's queue when one is installed (sent later, phase-474 I7),
1064    /// the trace marker when callback
1065    /// tracing is compiled in, the SWD record when the image keeps one, and
1066    /// the ring [`drain_violations`] reads.
1067    ///
1068    /// [`drain_violations`]: super::Executor::drain_violations
1069    pub(crate) fn record(&mut self, v: Violation) {
1070        if !self.counts.armed {
1071            // phase-474 I2 -- start-up: counted, never stored.
1072            self.counts.suppressed_before_arm = self.counts.suppressed_before_arm.saturating_add(1);
1073            #[cfg(nros_boot_report)]
1074            NROS_VIOLATION_RECORD
1075                .suppressed_before_arm
1076                .fetch_add(1, Ordering::Relaxed);
1077            return;
1078        }
1079        if self.report && !self.drain_report {
1080            log_violation(&v);
1081        }
1082        if self.sink.is_some() {
1083            // phase-474 I7 -- queued, not sent: the report leaves at the end of
1084            // a spin with slack (`Executor::flush_violation_reports`), so it
1085            // never costs the dispatch being judged.
1086            if self.reports.pending.is_full() {
1087                self.reports.pending.remove(0);
1088                self.reports.overflowed = self.reports.overflowed.saturating_add(1);
1089            }
1090            let _ = self.reports.pending.push(v.clone());
1091        }
1092        // `total` is this executor's sequence number for the verdict: the log
1093        // line and the trace marker carry it, so the two name one verdict by
1094        // one number. The SWD record numbers across every executor in the
1095        // image; on a single-executor image the two coincide.
1096        self.counts.total = self.counts.total.wrapping_add(1);
1097        #[cfg(nros_boot_report)]
1098        NROS_VIOLATION_RECORD.store(&v);
1099        #[cfg(feature = "trace-callbacks")]
1100        super::callback_trace::violation(self.counts.total, &v);
1101        if self.ring.capacity() == 0 {
1102            self.counts.dropped = self.counts.dropped.saturating_add(1);
1103            return;
1104        }
1105        if self.ring.len() == self.ring.capacity() {
1106            self.ring.pop_front();
1107            self.counts.dropped = self.counts.dropped.saturating_add(1);
1108        }
1109        // Cannot fail: a slot was just made if the ring was full.
1110        let _ = self.ring.push(v);
1111    }
1112
1113    /// Hand every entry still in the ring to `f`, oldest first, with its
1114    /// sequence number, and empty the ring.
1115    pub(crate) fn drain(&mut self, mut f: impl FnMut(u32, &Violation)) {
1116        let n = self.ring.len() as u32;
1117        let first = self.counts.total.wrapping_sub(n).wrapping_add(1);
1118        for (k, v) in self.ring.iter().enumerate() {
1119            f(first.wrapping_add(k as u32), v);
1120        }
1121        self.ring.clear();
1122    }
1123
1124    /// phase-474 I1 -- the drain-and-report hook: one log line per entry with
1125    /// its sequence number and the counters, so a reader of the log knows how
1126    /// many it missed. Called at the end of a spin when `drain_report` is on.
1127    pub(crate) fn drain_and_report(&mut self) {
1128        if !self.drain_report || self.ring.is_empty() {
1129            return;
1130        }
1131        let (total, dropped) = (self.counts.total, self.counts.dropped);
1132        self.drain(|seq, v| log_drained_violation(seq, total, dropped, v));
1133    }
1134}

1154/// Pure rate check over one window boundary. Returns `Some(violation)`
1155/// when the window elapsed AND the measured rate is below the declared
1156/// minimum (and we didn't already report last window).
1157///
1158/// Extracted from the executor so the math is unit-testable without a
1159/// session: publish counting is injected via the cell, time via `now_us`.
1160pub(crate) fn check_rate(
1161    spec: &MonitorSpec,
1162    state: &mut MonitorState,
1163    now_us: u64,
1164) -> Option<Violation> {
1165    if spec.min_rate_hz_milli == 0 {
1166        return None;
1167    }
1168    let count = spec.cell.count.load(Ordering::Relaxed);
1169    if !state.opened {
1170        // First observation: open the window, no verdict yet.
1171        state.opened = true;
1172        state.aligned = false;
1173        state.window_start_us = now_us;
1174        state.count_at_window_start = count;
1175        return None;
1176    }
1177    let window_us = now_us.saturating_sub(state.window_start_us);
1178    if !state.aligned && window_us < RATE_CHECK_INTERVAL_US {
1179        // phase-474 I8 -- the first window starts at the first tick that sees
1180        // a new sample, not where it was opened. The tick runs before the
1181        // spin's dispatch, so in steady state every boundary sits one tick
1182        // after a publish and the count matches the span. The window opened
1183        // at boot or by arming sits wherever that spin fell: off the
1184        // stream's phase it spans N samples over N periods plus the offset,
1185        // and a stream at exactly its declared rate read short (the island:
1186        // 9984 of 10000 mHz, once, after arming). Re-anchoring here puts the
1187        // first window on the same phase the later ones have. A stream that
1188        // stays silent is not held open: once a whole window passes with no
1189        // sample it is judged as opened (below), at 0.
1190        if count != state.count_at_window_start {
1191            state.aligned = true;
1192            state.window_start_us = now_us;
1193            state.count_at_window_start = count;
1194        }
1195        return None;
1196    }
1197    state.aligned = true;
1198    if window_us < RATE_CHECK_INTERVAL_US {
1199        return None;
1200    }
1201    let published = count.wrapping_sub(state.count_at_window_start) as u64;
1202    // milli-Hz = published * 1e3 / window_s = published * 1e9 / window_us
1203    let measured_milli_hz =
1204        (published.saturating_mul(1_000_000_000) / window_us.max(1)).min(u32::MAX as u64) as u32;
1205    // phase-474 I9 -- judge the count, not the floored quotient. The window
1206    // closes at the first tick that finds it elapsed, so `window_us` is the
1207    // declared interval plus that tick's lateness, while a stream at exactly
1208    // its declared minimum has published one sample per period: 50 over
1209    // 5.0005 s reads 9999 of 10000 mHz and was judged slow (the island, every
1210    // window, reported once thanks to `violated_last_window`). A stream at
1211    // the declared minimum delivers at least floor(min_rate * window) samples
1212    // in any window, whatever its phase; fewer than that is slow.
1213    let required = (spec.min_rate_hz_milli as u64).saturating_mul(window_us) / 1_000_000_000;
1214
1215    // Roll the window.
1216    state.window_start_us = now_us;
1217    state.count_at_window_start = count;
1218
1219    if published < required {
1220        if state.violated_last_window {
1221            return None; // still violated — already reported
1222        }
1223        state.violated_last_window = true;
1224        Some(Violation {
1225            rule: "rate-hierarchy-runtime",
1226            fqn: spec.fqn,
1227            measured: measured_milli_hz,
1228            declared: spec.min_rate_hz_milli,
1229        })
1230    } else {
1231        state.violated_last_window = false;
1232        None
1233    }
1234}

1236/// Pure latency check: drains the spec cell's window-max take→publish
1237/// latency and fires when it exceeds the declared node-path budget.
1238/// Same report-once-until-recovery semantics as the rate rule; runs on
1239/// every monitor tick (the cell accumulates between ticks, so no window
1240/// bookkeeping is needed — draining IS the window roll).
1241pub(crate) fn check_latency(spec: &MonitorSpec, state: &mut MonitorState) -> Option<Violation> {
1242    if spec.max_latency_ms == 0 {
1243        return None;
1244    }
1245    let max_us = spec.cell.max_latency_us.swap(0, Ordering::Relaxed);
1246    let max_ms = max_us / 1_000;
1247    if max_ms > spec.max_latency_ms {
1248        if state.latency_violated_last_window {
1249            return None;
1250        }
1251        state.latency_violated_last_window = true;
1252        Some(Violation {
1253            rule: "max-latency-runtime",
1254            fqn: spec.fqn,
1255            measured: max_ms,
1256            declared: spec.max_latency_ms,
1257        })
1258    } else {
1259        // A quiet window (no dispatch attributed) also counts as clean —
1260        // recovery resets the dedup like the rate rule's clean window.
1261        state.latency_violated_last_window = false;
1262        None
1263    }

1303pub(crate) fn route_take(table: &[MonitorSpec], slot: usize, take_us: u64) {

1311            .route_take_us

1313        spec.cell.route.store(w | ROUTE_PENDING, Ordering::Relaxed);
1314    }

1317/// phase10-B3 -- a dispatch ended at `end_us`. Every route output whose
1318/// counter advanced during it (`counts_before`, as the latency rule reads it)
1319/// and that has a take waiting is judged: take to dispatch end, an upper bound
1320/// on take to that publish, against the path's budget. Over budget is
1321/// reported once until a route is within it again.
1322///
1323/// phase-503 -- a SUPERVISED route ([`MonitorSpec::route_deadline_ms`])
1324/// answered at or after its deadline is also overdue: it is reported as
1325/// `route-deadline-runtime` and its reaction requested, as `route_overdue`
1326/// would have done had it run in time. Under `MECHANISM_EXECUTOR` this is the
1327/// only detection a single long callback gets: the callback that holds the
1328/// spin thread past the deadline publishes the output before the executor's
1329/// overdue check can run, so the miss is caught here, at completion -- late
1330/// by the callback's overrun. A route whose deadline was already caught
1331/// (`route_overdue` dropped its take) is not pending any more and is not
1332/// judged again, so each take gets at most one deadline verdict.
1333///
1334/// `report(row, violation, record, react)`: `record` is `false` while the
1335/// route is still marked violated from an earlier verdict (report once until
1336/// a route is within its budget again); `react` asks the caller to call the
1337/// reaction hook, on every late supervised take as `route_overdue` does.
1338pub(crate) fn route_judge(
1339    table: &[MonitorSpec],
1340    counts_before: &[u32; MAX_MONITORS],
1341    end_us: u64,
1342    mut report: impl FnMut(usize, Violation, bool, bool),
1343) {
1344    for (k, spec) in table.iter().take(MAX_MONITORS).enumerate() {
1345        if spec.route_max_latency_ms == 0 {
1346            continue;
1347        }
1348        let w = spec.cell.route.load(Ordering::Relaxed);
1349        if w & ROUTE_PENDING == 0 || spec.cell.count.load(Ordering::Relaxed) == counts_before[k] {
1350            continue;
1351        }
1352        let took_us = (end_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1353        let measured_ms = took_us / 1_000;
1354        let first = w & ROUTE_VIOLATED == 0;
1355        let late = measured_ms > spec.route_max_latency_ms;
1356        let overdue =
1357            route_supervised(spec) && took_us >= spec.route_deadline_ms.saturating_mul(1_000);
1358        let mut next = w & !ROUTE_PENDING;
1359        if late && first {
1360            report(
1361                k,
1362                Violation {
1363                    rule: "route-latency-runtime",
1364                    fqn: spec.fqn,
1365                    measured: measured_ms,
1366                    declared: spec.route_max_latency_ms,
1367                },
1368                true,
1369                false,
1370            );
1371        }
1372        if overdue {
1373            report(
1374                k,
1375                Violation {
1376                    rule: "route-deadline-runtime",
1377                    fqn: spec.fqn,
1378                    measured: measured_ms,
1379                    declared: spec.route_deadline_ms,
1380                },
1381                first,
1382                true,
1383            );
1384        }
1385        if late || overdue {
1386            next |= ROUTE_VIOLATED;
1387        } else {
1388            next &= !ROUTE_VIOLATED;
1389        }
1390        spec.cell.route.store(next, Ordering::Relaxed);
1391    }
1392}

1400/// phase-503 -- time from now to the earliest deadline of a pending supervised
1401/// route, in microseconds (0 when one is already due), or `None` when no
1402/// supervised route is waiting. This is the executor's wake source for the
1403/// rule, and what a port's independent timer (`MECHANISM_TIMER`) arms on.
1404///
1405/// The due time is `take + route_deadline_ms`, derived from the stored take
1406/// rather than kept in a second cell: both are the clock's low 32 bits, so the
1407/// difference is exact across a wrap as long as a route waits less than ~71
1408/// minutes, and a supervised one is reported long before that.
1409pub fn route_next_due_us(table: &[MonitorSpec], now_us: u64) -> Option<u64> {
1410    let mut best: Option<u64> = None;
1411    for spec in table.iter().take(MAX_MONITORS) {
1412        if !route_supervised(spec) {
1413            continue;
1414        }
1415        let w = spec.cell.route.load(Ordering::Relaxed);
1416        if w & ROUTE_PENDING == 0 {
1417            continue;
1418        }
1419        let waited_us =
1420            (now_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1421        let deadline_us = spec.route_deadline_ms.saturating_mul(1_000);
1422        let left = deadline_us.saturating_sub(waited_us) as u64;
1423        best = Some(best.map_or(left, |b| b.min(left)));
1424        if left == 0 {
1425            break;
1426        }
1427    }
1428    best
1429}

1431/// phase-503 -- judge every pending supervised route at `now_us`: a take still
1432/// unanswered at or after `take + route_deadline_ms` is OVERDUE. Its waiting
1433/// take is dropped (the route stops pending, so the next take starts a new
1434/// one) and the route is marked [`ROUTE_VIOLATED`], as `route_judge` marks an
1435/// over-budget route.
1436///
1437/// `react(row, violation, first)` is called for every overdue route: `first`
1438/// is `false` while the route is still marked violated from an earlier verdict
1439/// (report once until a route is within its budget again, the latency rule's
1440/// rule), and the caller records the violation only when it is `true`. The
1441/// reaction is requested every time, since each overdue take is a missed
1442/// deadline the fallback has to cover.
1443pub(crate) fn route_overdue(
1444    table: &[MonitorSpec],
1445    now_us: u64,
1446    mut react: impl FnMut(usize, Violation, bool),
1447) {
1448    for (k, spec) in table.iter().take(MAX_MONITORS).enumerate() {
1449        if !route_supervised(spec) {
1450            continue;
1451        }
1452        let w = spec.cell.route.load(Ordering::Relaxed);
1453        if w & ROUTE_PENDING == 0 {
1454            continue;
1455        }
1456        let waited_us =
1457            (now_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1458        if waited_us < spec.route_deadline_ms.saturating_mul(1_000) {
1459            continue;
1460        }
1461        spec.cell
1462            .route
1463            .store((w & !ROUTE_PENDING) | ROUTE_VIOLATED, Ordering::Relaxed);
1464        react(
1465            k,
1466            Violation {
1467                rule: "route-deadline-runtime",
1468                fqn: spec.fqn,
1469                measured: waited_us / 1_000,
1470                declared: spec.route_deadline_ms,
1471            },
1472            w & ROUTE_VIOLATED == 0,
1473        );
1474    }
1475}

1522/// phase-462 W2 -- the on-target liveliness lease: a contracted subscription
1523/// that has taken NOTHING for a whole `max_age_ms` window.
1524///
1525/// The bound needs no new declaration and deliberately does not invent one.
1526/// `max_age_ms` already says how old this input's data may be; data that never
1527/// arrives is older than that by the same clock, so the window IS the declared
1528/// bound. (`on_violation` selects what the executor then DOES about it; the
1529/// reaction beyond reporting is the fault hook phase-462 W3 owns.)
1530///
1531/// Why this is not `max-age-runtime` with a longer arm: that rule judges a
1532/// message that arrived. An input that stops entirely produces no message to
1533/// judge, so it leaves the age rule silent forever -- the exact failure a
1534/// `max_age_ms` promise is made against, and the one play_launch's reaction
1535/// engine catches on the Linux side of the same contract.
1536///
1537/// `now_us` is the executor's monotonic clock, `None` on a build with no clock
1538/// at all. Then nothing is judged: a clock that never moves is a window that
1539/// never elapses, and guessing a window from spin counts would put a tolerance
1540/// nobody declared into a safety rule.
1541///
1542/// phase-462 W5b -- `window_ms` is [`silence_window`]'s: the age bound, or the
1543/// contract's `deadline` when the row is armed for one and it is shorter.
1544fn check_silence(window_ms: u32, state: &mut AgeState, took: u32, now_us: u64) -> bool {
1545    let now_ms = (now_us / 1_000) as u32;
1546    if !state.silence_opened {
1547        state.silence_opened = true;
1548        state.last_take_ms = now_ms;
1549        return false;
1550    }
1551    if took > 0 {
1552        state.last_take_ms = now_ms;
1553        state.silence_reported = false;
1554        return false;
1555    }
1556    if now_ms.wrapping_sub(state.last_take_ms) < window_ms {
1557        return false;
1558    }
1559    if state.silence_reported {
1560        return false; // still silent -- already reported
1561    }
1562    state.silence_reported = true;
1563    true
1564}
1565
1566/// Pure age check: drains the sub cell's window-max take-age and fires
1567/// when it exceeds the declared bound. Report-once-until-recovery.
1568///
1569/// phase-462 W2 -- also the silence rule's tick, because the two verdicts read
1570/// ONE observation (what this endpoint took since the last check) and reading
1571/// it twice would let one rule's drain hide the other's evidence. They cannot
1572/// both fire: with no takes the drained age is 0, so `max-age-runtime` has
1573/// nothing to judge.
1574/// phase-462 W5b -- the silence rule's window and its evidence for one row:
1575/// `(window_ms, evidence)`, or `None` when the row judges no silence at all.
1576///
1577/// An age contract keeps W2's evidence (stamped takes, so an endpoint whose
1578/// type carries no stamp still reads as unjudgeable) and an armed deadline
1579/// shortens the window when it is the tighter bound. A row armed for a
1580/// deadline ALONE counts arrivals, since a deadline promises arrival and
1581/// nothing about stamps. Both counters are drained either way, so neither
1582/// carries a stale window into the next check.
1583fn silence_window(spec: &AgeMonitorSpec) -> Option<(u32, u32)> {
1584    let took = spec.cell.takes.swap(0, Ordering::Relaxed);
1585    let arrived = spec.cell.arrivals.swap(0, Ordering::Relaxed);
1586    let armed = spec.deadline_ms > 0 && spec.cell.deadline_slot.load(Ordering::Relaxed) != 0;
1587    match (spec.max_age_ms, armed) {
1588        (0, false) => None,
1589        (0, true) => Some((spec.deadline_ms, arrived)),
1590        (age, false) => Some((age, took)),
1591        (age, true) => Some((age.min(spec.deadline_ms), took)),
1592    }
1593}
1594
1595pub(crate) fn check_age(
1596    spec: &AgeMonitorSpec,
1597    state: &mut AgeState,
1598    now_us: Option<u64>,
1599) -> Option<Violation> {
1600    let (window_ms, took) = silence_window(spec)?;
1601    if let Some(now_us) = now_us
1602        && check_silence(window_ms, state, took, now_us)
1603    {
1604        return Some(Violation {
1605            rule: "silence-runtime",
1606            fqn: spec.fqn,
1607            // Takes in the window, against the window the contract declares.
1608            measured: 0,
1609            declared: window_ms,
1610        });
1611    }
1612    if spec.max_age_ms == 0 {
1613        return None;
1614    }
1615    let max_ms = spec.cell.max_age_ms.swap(0, Ordering::Relaxed);
1616    if max_ms > spec.max_age_ms {
1617        if state.violated_last_window {
1618            return None;
1619        }
1620        state.violated_last_window = true;
1621        Some(Violation {
1622            rule: "max-age-runtime",
1623            fqn: spec.fqn,
1624            measured: max_ms,
1625            declared: spec.max_age_ms,
1626        })
1627    } else {
1628        state.violated_last_window = false;
1629        None
1630    }
1631}

1715const HAZARD_CLEAR: u32 = 0;

1719/// Whether `member` has faulted, and since when (ms) when the row knows.
1720fn member_fault(
1721    member: GuardRef,
1722    monitor_states: &[MonitorState],
1723    age_states: &[AgeState],
1724) -> Option<Option<u32>> {
1725    match member {
1726        GuardRef::Age(i) => {
1727            let s = age_states.get(i as usize)?;
1728            s.silence_reported.then_some(Some(s.last_take_ms))
1729        }
1730        GuardRef::Rate(i) => {
1731            let s = monitor_states.get(i as usize)?;
1732            s.violated_last_window.then_some(None)
1733        }
1734    }
1735}

1737/// Whether any guard of `spec` has faulted, and the earliest fault start the
1738/// faulting rows know.
1739fn hazard_fault(
1740    spec: &HazardSpec,
1741    monitor_states: &[MonitorState],
1742    age_states: &[AgeState],
1743) -> Option<Option<u32>> {
1744    let mut faulted = false;
1745    let mut since: Option<u32> = None;
1746    for g in spec.guards {
1747        let mut seen = 0usize;
1748        let mut g_since: Option<u32> = None;
1749        for m in g.members {
1750            if let Some(at) = member_fault(*m, monitor_states, age_states) {
1751                seen += 1;
1752                if let Some(at) = at {
1753                    g_since = Some(g_since.map_or(at, |s: u32| s.min(at)));
1754                }
1755            }
1756        }
1757        let guard_faulted = if g.all_of {
1758            !g.members.is_empty() && seen == g.members.len()
1759        } else {
1760            seen > 0
1761        };
1762        if guard_faulted {
1763            faulted = true;
1764            if let Some(at) = g_since {
1765                since = Some(since.map_or(at, |s| s.min(at)));
1766            }
1767        }
1768    }
1769    faulted.then_some(since)
1770}

1772/// phase-462 W3b -- one tick of a hazard's observer, after the monitor rows
1773/// have run. Emits, in play_launch's vocabulary so one log reader serves both
1774/// sides of a bridge:
1775///
1776/// - `hazard-detected` when a guard first faults: measured is the ms since
1777///   the fault began, declared the FTTI;
1778/// - `hazard-reaction` when the `safe_state` publisher publishes after that:
1779///   measured is fault-to-reaction plus `settle_ms`, declared the FTTI;
1780/// - `hazard-recovered` when no guard is faulted any more: measured is the
1781///   ms the hazard lasted.
1782///
1783/// `fqn` is the hazard's key on all three.
1784pub(crate) fn check_hazard(
1785    spec: &HazardSpec,
1786    monitor_table: &[MonitorSpec],
1787    monitor_states: &[MonitorState],
1788    age_states: &[AgeState],
1789    now_ms: u32,
1790    mut emit: impl FnMut(Violation),
1791) {
1792    let cell = spec.cell;
1793    let state = cell.state.load(Ordering::Relaxed);
1794    let sink_count = monitor_table
1795        .get(spec.sink as usize)
1796        .map(|m| m.cell.count.load(Ordering::Relaxed));
1797    let fault = hazard_fault(spec, monitor_states, age_states);
1798    let v = |rule, measured: u32| Violation {
1799        rule,
1800        fqn: spec.key,
1801        measured,
1802        declared: spec.ftti_ms,
1803    };
1804    match (state, fault) {
1805        (HAZARD_CLEAR, Some(since)) => {
1806            let at = since.unwrap_or(now_ms);
1807            cell.fault_ms.store(at, Ordering::Relaxed);
1808            cell.sink_count
1809                .store(sink_count.unwrap_or(0), Ordering::Relaxed);
1810            cell.state.store(HAZARD_DETECTED, Ordering::Relaxed);
1811            emit(v("hazard-detected", now_ms.wrapping_sub(at)));
1812        }
1813        (HAZARD_DETECTED, Some(_)) => {
1814            if let Some(count) = sink_count
1815                && count != cell.sink_count.load(Ordering::Relaxed)
1816            {
1817                cell.state.store(HAZARD_REACTED, Ordering::Relaxed);
1818                let since = now_ms.wrapping_sub(cell.fault_ms.load(Ordering::Relaxed));
1819                emit(v("hazard-reaction", since.saturating_add(spec.settle_ms)));
1820            }
1821        }
1822        (HAZARD_DETECTED | HAZARD_REACTED, None) => {
1823            cell.state.store(HAZARD_CLEAR, Ordering::Relaxed);
1824            let lasted = now_ms.wrapping_sub(cell.fault_ms.load(Ordering::Relaxed));
1825            emit(v("hazard-recovered", lasted));
1826        }
1827        _ => {}
1828    }
1829}

2577/// `last_reported` is the value at the previous check, so the verdict
2578/// is on the delta. Returns a violation when more than `tolerated`
2579/// activations were dropped since the last check.
2580pub(crate) fn check_timer_overrun(
2581    overruns: u32,
2582    last_reported: &mut u32,
2583    tolerated: u32,
2584) -> Option<Violation> {
2585    let dropped = overruns.saturating_sub(*last_reported);
2586    *last_reported = overruns;
2587    if dropped <= tolerated {
2588        return None;
2589    }
2590    Some(Violation {
2591        rule: "timer-overrun-runtime",
2592        // Timer entries carry no name at this altitude; same stand-in
2593        // as `deadline-miss-runtime`.
2594        fqn: "timer",
2595        measured: dropped,
2596        declared: tolerated,
2597    })
2598}

2600/// Issue #515 — report a spin wake that arrived so late the cadence it
2601/// claims cannot have been met.
2602///
2603/// Like `check_timer_overrun` and unlike the rate/age/latency rules, this
2604/// needs no baked spec table. The bound is the spin period ITSELF: the
2605/// caller passes it to `spin_once` as the pacing quantum, it is what
2606/// `system.toml` declares as `spin_period_us`, and a wake later than a full
2607/// period past its predecessor means an activation's worth of cadence was
2608/// lost. That is a contract failure for any declared period, so there is
2609/// nothing further to declare.
2610///
2611/// The tolerance is one whole period rather than zero, and deliberately so.
2612/// Sub-period lateness is ordinary scheduling noise -- on the measured FVP
2613/// lane the executor is late on a large fraction of wakes while still
2614/// holding its rate -- and a rule that fired on each one would report a
2615/// healthy system as broken thousands of times a second. What is NOT
2616/// ordinary is being a full period late, because by then the wake that
2617/// should have happened in between never did.
2618///
2619/// phase-474 I11 -- for a `spin_once(period)` loop with no declared cadence
2620/// the lateness is release minus scheduled release on the executor's release
2621/// grid (a dropped release counts its age when dropped), not entry-to-entry
2622/// minus the period; see `Executor::record_release_jitter`.
2623///
2624/// `max_jitter_us` is the executor's high-water since the last check and
2625/// `last_reported` the value at the previous one, so the verdict is on the
2626/// delta -- the same shape as the overrun counter, and for the same reason:
2627/// a maximum that has not moved is not a new fault.
2628pub(crate) fn check_release_jitter(
2629    max_jitter_us: u64,
2630    last_reported: &mut u64,
2631    period_us: u64,
2632) -> Option<Violation> {
2633    if period_us == 0 || max_jitter_us <= *last_reported {
2634        return None;
2635    }
2636    *last_reported = max_jitter_us;
2637    if max_jitter_us < period_us {
2638        return None;
2639    }
2640    Some(Violation {
2641        rule: "release-jitter-runtime",
2642        // Same stand-in as the timer and deadline rules: the spin loop is
2643        // not an endpoint and carries no fqn at this altitude.
2644        fqn: "spin",
2645        measured: max_jitter_us.min(u32::MAX as u64) as u32,
2646        declared: period_us.min(u32::MAX as u64) as u32,
2647    })
2648}

2650/// Report a spin thread whose stack has come closer to its end than the
2651/// declared minimum.
2652///
2653/// Unlike every other rule here the bound CANNOT be derived from something
2654/// already declared, and that is worth stating rather than papering over.
2655/// `check_timer_overrun` and `check_release_jitter` both judge against a
2656/// period the caller already passes in; there is no equivalent for a stack.
2657/// The executor never sees `stack_bytes` -- it lives in the spawn attr and
2658/// goes no further -- and the total is not portably queryable either:
2659/// FreeRTOS exposes the high-water mark and not the size it was taken
2660/// against, so even a percentage cannot be computed. A minimum headroom is
2661/// therefore a real declaration, and `min_bytes == 0` means the caller has
2662/// not made one, which disables the rule.
2663///
2664/// Reports on the WORST case, not on each crossing: `worst_reported` holds
2665/// the lowest headroom already reported, so a stack hovering just under the
2666/// bound says so once and then only when it gets worse. The same delta
2667/// discipline as the overrun and jitter rules, inverted because for headroom
2668/// smaller is worse.
2669pub(crate) fn check_stack_headroom(
2670    unused_bytes: usize,
2671    min_bytes: usize,
2672    worst_reported: &mut usize,
2673) -> Option<Violation> {
2674    if min_bytes == 0 || unused_bytes >= min_bytes {
2675        return None;
2676    }
2677    // `usize::MAX` is the "nothing reported yet" sentinel: any real headroom
2678    // is below it, so the first breach always reports.
2679    if *worst_reported != usize::MAX && unused_bytes >= *worst_reported {
2680        return None;
2681    }
2682    *worst_reported = unused_bytes;
2683    Some(Violation {
2684        rule: "stack-headroom-runtime",
2685        // The spin thread is not an endpoint; same stand-in as the timer,
2686        // deadline and jitter rules.
2687        fqn: "stack",
2688        measured: unused_bytes.min(u32::MAX as usize) as u32,
2689        declared: min_bytes.min(u32::MAX as usize) as u32,
2690    })
2691}

2800/// Per-SchedContext liveness accounting, one per SC slot.
2801///
2802/// `Default` is DERIVED, not hand-written: every field's default is its type's
2803/// own (`false`, `0`), so a manual impl restates four of them and is one edit
2804/// away from disagreeing with the struct — `clippy::derivable_impls` is a
2805/// `-D warnings` error in the embedded lane, which is where this was caught.
2806#[derive(Debug, Clone, Copy, Default)]
2807pub(crate) struct AliveState {
2808    pub opened: bool,
2809    pub window_start_us: u64,
2810    pub count_at_window_start: u32,
2811    /// Report-once-until-recovery, matching the rate rule.
2812    pub violated_last_window: bool,
2813}

2815/// One SchedContext's alive-supervision record: the counter the dispatch
2816/// path bumps and the window state the monitor tick reads.
2817///
2818/// A region of the carved backing (`storage::carve`), one per SC the
2819/// executor was sized for — NOT an inline `[_; MAX_SC]` in the header.
2820/// `MAX_SC` is a sizing knob, so an inline table grows the `Executor` value
2821/// with it, which is the regression issue 0961 exists to prevent.
2822#[derive(Debug, Clone, Copy, Default)]
2823pub(crate) struct AliveSlot {
2824    pub dispatches: u32,
2825    pub state: AliveState,
2826}
2827
2828/// Report a SchedContext that has not dispatched AT ALL over a full window
2829/// while declaring a period that says it should have.
2830///
2831/// AUTOSAR's Watchdog Manager separates ALIVE supervision -- did it run at
2832/// all, at roughly the right rate -- from DEADLINE supervision, did it finish
2833/// in time. Every rule here is the second kind or a variant of it: they fire
2834/// when something happens and is wrong. Nothing fires when a callback stops
2835/// happening altogether.
2836///
2837/// `rate-hierarchy-runtime` does not cover it. That rule counts PUBLISHES on
2838/// a contracted publisher, so a timer callback that silently stops firing
2839/// while its topic is published from elsewhere -- another tier, a bridge, a
2840/// republisher -- leaves it satisfied. The gap is a callback, not an
2841/// endpoint.
2842///
2843/// The bound needs no declaration: `period_us` is already on the SC, and a
2844/// context claiming a period that produced no activation in a window many
2845/// times longer than it is a contract failure for any period. `period_us ==
2846/// 0` declares no cadence, so nothing is judged.
2847///
2848/// ZERO, not a fraction. A throttled-but-alive context is a different fault
2849/// with different evidence -- `SporadicState` already counts window skips and
2850/// dispatches for exactly that -- and picking a percentage here would invent
2851/// a tolerance nobody declared. Zero activations against a declared period is
2852/// unambiguous.
2853pub(crate) fn check_alive(
2854    period_us: u64,
2855    dispatches: u32,
2856    state: &mut AliveState,
2857    now_us: u64,
2858) -> Option<Violation> {
2859    if period_us == 0 {
2860        return None;
2861    }
2862    if !state.opened {
2863        state.opened = true;
2864        state.window_start_us = now_us;
2865        state.count_at_window_start = dispatches;
2866        return None;
2867    }
2868    let window_us = now_us.saturating_sub(state.window_start_us);
2869    if window_us < RATE_CHECK_INTERVAL_US {
2870        return None;
2871    }
2872    let fired = dispatches.wrapping_sub(state.count_at_window_start);
2873    state.window_start_us = now_us;
2874    state.count_at_window_start = dispatches;
2875
2876    // Only judge a window long enough to have contained an activation. A
2877    // period longer than the check interval is not late merely for not having
2878    // fired yet.
2879    if window_us < period_us {
2880        return None;
2881    }
2882    if fired > 0 {
2883        state.violated_last_window = false;
2884        return None;
2885    }
2886    if state.violated_last_window {
2887        return None; // still silent — already reported
2888    }
2889    state.violated_last_window = true;
2890    Some(Violation {
2891        rule: "alive-supervision-runtime",
2892        // SCs carry no name at this altitude; same stand-in as the deadline
2893        // rule, which reports against the SC too.
2894        fqn: "sched-context",
2895        measured: 0,
2896        declared: (window_us / period_us).min(u32::MAX as u64) as u32,
2897    })
2898}
