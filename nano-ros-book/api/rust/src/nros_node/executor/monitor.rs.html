1//! RFC-0052 / phase-296 W3b.4/.5 — on-target contract monitors.
2//!
3//! The baked shape mirrors Phase 211.H's `qos_overrides`: codegen emits a
4//! `&'static [MonitorSpec]` table (plus one `static PubMonitorCell` per
5//! contracted publisher) from the SystemModel's contract layer; the entry
6//! installs it on the executor before entity creation. An uncontracted
7//! image bakes an empty table — every path below dead-code-eliminates.
8//!
9//! Publish counting is an atomic bump on the publisher handle (no clock,
10//! no lock on the hot path); the rate check runs on spin ticks over a
11//! ~[`RATE_CHECK_INTERVAL_US`] window and pushes violations into a small
12//! ring the entry glue drains into the `nros-diagnostics` reporter.
13//!
14//! W3b.5 adds three more rules on the same drain:
15//! - `max-age-runtime` — subscriber take-age (`epoch_now - header.stamp`
16//!   peeked from the raw CDR buffer at `RosMessage::STAMP_OFFSET`,
17//!   recorded into a [`SubMonitorCell`] on the take path).
18//! - `max-latency-runtime` — node-path (take → publish) latency: the
19//!   dispatch elapsed time is attributed to every monitored publisher
20//!   whose counter advanced during that dispatch (an upper bound on
21//!   take → publish, measured on the executor's monotonic clock). The span
22//!   is callback entry to exit, for every dispatch kind: a timer callback
23//!   is timed whether it fires in the drains or in the trigger-miss sweep
24//!   (phase-474 I6), and a service call it makes is inside the span. The
25//!   timer's release jitter (a late start) is not part of it; that is
26//!   `release-jitter-runtime`.
27//! - `deadline-miss-runtime` — a dispatched callback ran past its bound
28//!   SchedContext's `deadline_us`; what ELSE happens is the tier's
29//!   [`DeadlineAction`](super::sched_context::DeadlineAction).
30//!
31//! phase10-B3 adds the route rule beside it:
32//! - `route-latency-runtime` -- a node path whose trigger is an INPUT is
33//!   budgeted from the TAKE of that input to its output, and on a node that
34//!   reads its input on a timer tick that span includes the wait for the next
35//!   tick. `max-latency-runtime` times one dispatch and cannot see the wait,
36//!   so a route made of a long tick wait and a slow dispatch could exceed its
37//!   budget while every callback passed. The executor stamps the dispatch that
38//!   takes the trigger input (the earliest take not yet answered) and, at the
39//!   end of a dispatch that published one of the path's outputs, judges
40//!   take-to-dispatch-end against the path's `max_latency_ms`
41//!   (`route_take`, `route_judge`). Record only: the rule has no action.
42//!
43//! phase-462 W2 adds one more on the same drain, and it is the other half of
44//! what the contract's `on_violation` lowers to:
45//! - `silence-runtime` -- a contracted subscription that took NOTHING for a
46//!   whole `max_age_ms` window (`check_silence`). A violation is either "the
47//!   callback ran too long", which is the deadline action, or "the input
48//!   stopped coming", which is this; the four rules above can only see the
49//!   first kind.

57/// One contracted publisher's counters. Baked as a `static` by codegen
58/// (or declared by the fixture); the publisher handle bumps `count` on
59/// every publish, the executor reads deltas on spin ticks.
60#[derive(Debug, Default)]
61pub struct PubMonitorCell {
62    pub count: AtomicU32,
63    /// W3b.5 — max observed take→publish latency (µs) in the current
64    /// check window. Written by the dispatch loop (fetch_max), drained
65    /// (swap 0) by the latency check.
66    pub max_latency_us: AtomicU32,
67    /// Age of the stamp this publisher last put ON THE WIRE, in
68    /// microseconds: `epoch_now - outgoing header.stamp`.
69    ///
70    /// Distinct from `max_latency_us`, which times this node's own
71    /// take→publish work. This says how old the DATA is that the node just
72    /// published, which is the quantity a chain is made of.
73    ///
74    /// It exists to answer a question `max-age-runtime` cannot. That rule
75    /// measures `epoch_now - stamp` on the TAKE path, so if every node in a
76    /// chain propagates the original stamp -- the usual ROS convention, each
77    /// node copying its input's stamp to its output -- the age at the final
78    /// consumer already IS the end-to-end latency. If any node re-stamps
79    /// with `now`, the clock silently resets and the same number becomes
80    /// single-hop age instead. Same units, same magnitude, no warning.
81    ///
82    /// A publish age near zero on a node that consumes input is the
83    /// signature of re-stamping. Recording it here is what lets a chain's
84    /// provenance be checked at all, rather than assumed.
85    ///
86    /// `0` = never observed, matching the other cells: the type has no
87    /// `STAMP_OFFSET`, or no epoch source is installed.
88    pub last_publish_stamp_age_us: AtomicU32,
89    /// phase10-B3 -- the route rule's state for this output
90    /// ([`MonitorSpec::route_trigger`]): the trigger subscription's executor
91    /// slot + 1 in the low 16 bits (0 = no subscription bound, set when the
92    /// subscription registers), [`ROUTE_VIOLATED`] and [`ROUTE_PENDING`] above.
93    pub route: AtomicU32,
94    /// phase10-B3 -- when the earliest take not yet answered by a publish of
95    /// this output happened, executor clock in microseconds (wrapping). Valid
96    /// while [`ROUTE_PENDING`] is set in `route`.
97    pub route_take_us: AtomicU32,
98}
99
100/// phase10-B3 -- `PubMonitorCell::route`: a take of the trigger input is
101/// waiting for this output.
102pub const ROUTE_PENDING: u32 = 1 << 31;
103/// phase10-B3 -- `PubMonitorCell::route`: the last judged route was over its
104/// budget (report once until one is within it, as the latency rule does).
105pub const ROUTE_VIOLATED: u32 = 1 << 30;
106/// phase10-B3 -- `PubMonitorCell::route`: the bound slot + 1.
107pub const ROUTE_SLOT_MASK: u32 = 0xffff;

109impl PubMonitorCell {
110    pub const fn new() -> Self {

113            max_latency_us: AtomicU32::new(0),
114            last_publish_stamp_age_us: AtomicU32::new(0),
115            route: AtomicU32::new(0),
116            route_take_us: AtomicU32::new(0),
117        }
118    }

121/// One contracted subscriber's take-age accumulator (W3b.5). The take
122/// path records `epoch_now - header.stamp` per message (fetch_max); the
123/// age check drains it (swap 0) per window.
124#[derive(Debug, Default)]
125pub struct SubMonitorCell {
126    /// Max observed take-age (ms) in the current check window.
127    pub max_age_ms: AtomicU32,
128    /// phase-462 W2 -- observations recorded since the last check, drained
129    /// (swap 0) by `check_age`. The age itself cannot answer "did anything
130    /// arrive": a window with no take and a window whose only take was
131    /// perfectly fresh both leave `max_age_ms` at 0.
132    pub takes: AtomicU32,
133}
134
135impl SubMonitorCell {
136    pub const fn new() -> Self {
137        Self {
138            max_age_ms: AtomicU32::new(0),
139            takes: AtomicU32::new(0),
140        }
141    }
142
143    /// Take-path hook: record one message's age. `stamp_us` is the
144    /// peeked `header.stamp` as µs since the UNIX epoch, `epoch_now_us`
145    /// the receive-side wall clock. A stamp from the future clamps to 0.
146    ///
147    /// phase-462 W2 -- also the silence rule's only evidence that this
148    /// endpoint is being fed. It counts what the AGE rule can see, which is
149    /// stamped takes on a type that carries a stamp: a contracted endpoint
150    /// whose messages carry no readable stamp records nothing here and is
151    /// reported silent. That is the intended verdict rather than a gap --
152    /// its `max_age_ms` cannot be judged either, and an unjudgeable promise
153    /// reported as met is the silent class this phase exists to remove.
154    pub fn observe(&self, stamp_us: u64, epoch_now_us: u64) {
155        let age_ms = (epoch_now_us.saturating_sub(stamp_us) / 1_000).min(u32::MAX as u64) as u32;
156        self.max_age_ms.fetch_max(age_ms, Ordering::Relaxed);
157        self.takes.fetch_add(1, Ordering::Relaxed);
158    }
159}

161/// Peek `Time { i32 sec; u32 nanosec }` little-endian at `offset` in a
162/// raw CDR receive buffer (encapsulation header included) and return µs
163/// since the UNIX epoch. `None` when the buffer is too short or the
164/// stamp is pre-epoch/zero (unstamped messages never fire age monitors).
165/// Record the age of the stamp a publisher just put on the wire.
166///
167/// Called from the publish path with the encoded CDR still in hand, using the
168/// same `STAMP_OFFSET` peek the take path uses. A no-op when the type carries
169/// no stamp, when no epoch source is installed, or when the publisher is
170/// uncontracted -- the same three ways `observe_age` folds away.
171///
172/// Stores rather than accumulates: this is "how old was the last thing
173/// published", a state, not a window maximum. A chain check wants the current
174/// value, and a max would be pinned forever by one stale message at startup.
175#[inline]
176pub fn observe_publish_stamp(cell: &PubMonitorCell, raw: &[u8], offset: usize, now_us: u64) {
177    if let Some(stamp_us) = peek_stamp_us(raw, offset) {
178        let age = now_us.saturating_sub(stamp_us).min(u32::MAX as u64) as u32;
179        cell.last_publish_stamp_age_us.store(age, Ordering::Relaxed);
180    }
181}
182
183pub fn peek_stamp_us(raw: &[u8], offset: usize) -> Option<u64> {
184    let sec_b = raw.get(offset..offset + 4)?;
185    let nsec_b = raw.get(offset + 4..offset + 8)?;
186    let sec = i32::from_le_bytes([sec_b[0], sec_b[1], sec_b[2], sec_b[3]]);
187    let nsec = u32::from_le_bytes([nsec_b[0], nsec_b[1], nsec_b[2], nsec_b[3]]);
188    if sec <= 0 {
189        return None;
190    }
191    Some(sec as u64 * 1_000_000 + nsec as u64 / 1_000)
192}

292/// phase-436 E4 — how often the stack-headroom rule may query the port, in µs.
293///
294/// On a painted Zephyr stack the query walks every UNUSED byte from the stack
295/// base (`z_stack_space_get`), so querying on every spin put that scan inside
296/// the control loop. The high-water mark only grows, so a throttled check sees
297/// the same low mark and only sees it later. Since E5 the query is also capped
298/// at the declared minimum (`stack_unused_bytes_upto`), so it reads at most
299/// that many bytes.
300pub(crate) const STACK_HEADROOM_CHECK_INTERVAL_US: u64 = 1_000_000;
301
302/// The same limit for a build with no clock: once per this many spins.
303pub(crate) const STACK_HEADROOM_CHECK_SPIN_STRIDE: u32 = 1_000;
304
305/// Whether the stack-headroom query is due.
306///
307/// `last_check_us` is `None` until the first check, which is immediate, so a
308/// bound set at boot is checked on the first spin. After that a clocked build
309/// waits one full interval and a clockless build one full stride of spins.
310pub(crate) fn stack_headroom_check_due(
311    now_us: Option<u64>,
312    last_check_us: Option<u64>,
313    spins_since_check: u32,
314) -> bool {
315    match (last_check_us, now_us) {
316        (None, _) => true,
317        (Some(last), Some(now)) => now.saturating_sub(last) >= STACK_HEADROOM_CHECK_INTERVAL_US,
318        (Some(_), None) => spins_since_check >= STACK_HEADROOM_CHECK_SPIN_STRIDE,
319    }
320}

469/// 32-bit FNV-1a of an endpoint ref -- the identity a trace marker and the SWD
470/// record carry for `Violation::fqn` (a string neither can hold).
471///
472/// FNV-1a because a decoder can recompute it in one line from the model's
473/// endpoint list (`scripts/read-violation-record.py` does), with no table
474/// baked into the image.
475pub const fn fqn_hash(fqn: &str) -> u32 {
476    let b = fqn.as_bytes();
477    let mut h: u32 = 0x811c_9dc5;
478    let mut i = 0;
479    while i < b.len() {
480        h ^= b[i] as u32;
481        h = h.wrapping_mul(0x0100_0193);
482        i += 1;
483    }
484    h
485}

501/// executor's sequence number; its low 24 bits ride in the first event.
502pub fn violation_marker_words(seq: u32, v: &Violation) -> [(u32, u32); 4] {
503    [
504        (
505            MARKER_VIOLATION,
506            ((seq & 0x00ff_ffff) << 8) | (rule_code(v.rule) & 0xff),
507        ),
508        (MARKER_VIOLATION_FQN, fqn_hash(v.fqn)),
509        (MARKER_VIOLATION_MEASURED, v.measured),
510        (MARKER_VIOLATION_DECLARED, v.declared),
511    ]
512}

566/// phase-474 I1 -- the image-wide violation record a debugger reads by NAME,
567/// for a board whose console reaches nobody.
568///
569/// The executor's ring is carved out of executor storage (no symbol, and a
570/// drain empties it), so on the Autoware Safety Island it could only be found
571/// by scanning RAM for rule-id string pointers, and it held the FIRST eight
572/// verdicts since boot. This record is the black box beside it: a `#[repr(C)]`
573/// static, every word a `u32`, never drained, keeping the LATEST
574/// [`MAX_VIOLATIONS`] stored violations of every executor in the image, with
575/// the running total.
576///
577/// Layout (version [`RECORD_VERSION`], little-endian `u32` words):
578///
579/// | word | field | meaning |
580/// | --- | --- | --- |
581/// | 0 | `magic` | [`RECORD_MAGIC`] (`"NRVR"`) |
582/// | 1 | `version` | [`RECORD_VERSION`] |
583/// | 2 | `capacity` | slots (`NROS_EXECUTOR_MAX_VIOLATIONS`) |
584/// | 3 | `slot_words` | [`RECORD_SLOT_WORDS`] |
585/// | 4 | `total` | violations stored since boot (the last `seq`) |
586/// | 5 | `head` | slot the NEXT violation takes (`total % capacity`) |
587/// | 6 | `dropped` | entries overwritten (`total - capacity`, saturating) |
588/// | 7 | `suppressed_before_arm` | verdicts before the monitors armed, all executors (phase-474 I2) |
589/// | 8 | `armed` | executors whose monitors armed (counted as each arms; at its first spin by default) (phase-474 I2) |
590/// | 9 | `reserved` | 0 |
591/// | 10.. | `slots` | `capacity` x [`ViolationSlot`] |
592///
593/// The newest entry is in slot `(head + capacity - 1) % capacity`; reading
594/// `capacity` slots backwards from there gives newest to oldest, and a slot
595/// whose `seq` is 0 was never written.
596///
597/// Present only when the image asked for the boot report
598/// (`NROS_BOOT_REPORT=1`, Zephyr `CONFIG_NROS_BOOT_REPORT=y`) -- the same
599/// opt-in as the SWD boot record it sits beside, so an image that does not
600/// opt in is unchanged. Read it with `scripts/read-violation-record.py`.
601#[repr(C)]
602#[derive(Debug)]
603pub struct ViolationRecord<const N: usize> {
604    pub magic: AtomicU32,
605    pub version: AtomicU32,
606    pub capacity: AtomicU32,
607    pub slot_words: AtomicU32,
608    pub total: AtomicU32,
609    pub head: AtomicU32,
610    pub dropped: AtomicU32,
611    pub suppressed_before_arm: AtomicU32,
612    pub armed: AtomicU32,
613    pub reserved: AtomicU32,
614    pub slots: [ViolationSlot; N],
615}
616
617impl<const N: usize> ViolationRecord<N> {
618    /// A valid, empty record: the header is written at compile time, so a
619    /// record with `total == 0` reads as "no violation since boot" rather than
620    /// as uninitialised RAM.
621    pub const fn new() -> Self {
622        Self {
623            magic: AtomicU32::new(RECORD_MAGIC),
624            version: AtomicU32::new(RECORD_VERSION),
625            capacity: AtomicU32::new(N as u32),
626            slot_words: AtomicU32::new(RECORD_SLOT_WORDS),
627            total: AtomicU32::new(0),
628            head: AtomicU32::new(0),
629            dropped: AtomicU32::new(0),
630            suppressed_before_arm: AtomicU32::new(0),
631            armed: AtomicU32::new(0),
632            reserved: AtomicU32::new(0),
633            slots: [const { ViolationSlot::new() }; N],
634        }
635    }
636
637    /// Store one violation, overwriting the oldest when full. Returns its
638    /// 1-based sequence number.
639    ///
640    /// Lock-free and callable from any executor thread: the slot is claimed by
641    /// a `fetch_add` on `total`, so two executors never write one slot unless
642    /// `N` more violations land during one write.
643    pub fn store(&self, v: &Violation) -> u32 {
644        let seq = self.total.fetch_add(1, Ordering::AcqRel).wrapping_add(1);
645        if N == 0 {
646            return seq;
647        }
648        let slot = &self.slots[(seq as usize - 1) % N];
649        slot.seq.store(0, Ordering::Release);
650        slot.rule.store(rule_code(v.rule), Ordering::Relaxed);
651        slot.fqn_hash.store(fqn_hash(v.fqn), Ordering::Relaxed);
652        slot.measured.store(v.measured, Ordering::Relaxed);
653        slot.declared.store(v.declared, Ordering::Relaxed);
654        slot.fqn_addr
655            .store(v.fqn.as_ptr() as usize as u32, Ordering::Relaxed);
656        slot.fqn_len.store(v.fqn.len() as u32, Ordering::Relaxed);
657        slot.seq.store(seq, Ordering::Release);
658        self.head.store(seq % N as u32, Ordering::Relaxed);
659        self.dropped
660            .store(seq.saturating_sub(N as u32), Ordering::Relaxed);
661        seq
662    }
663
664    /// The stored entries, newest first, as `(seq, rule code, fqn hash,
665    /// measured, declared)`. For tests and on-target self-checks; a debugger
666    /// reads the words directly.
667    pub fn newest_first(&self, mut f: impl FnMut(u32, u32, u32, u32, u32)) {
668        let total = self.total.load(Ordering::Acquire);
669        let n = (total as usize).min(N);
670        for k in 0..n {
671            let seq = total - k as u32;
672            let slot = &self.slots[(seq as usize - 1) % N];
673            if slot.seq.load(Ordering::Acquire) != seq {
674                continue; // overwritten or mid-write
675            }
676            f(
677                seq,
678                slot.rule.load(Ordering::Relaxed),
679                slot.fqn_hash.load(Ordering::Relaxed),
680                slot.measured.load(Ordering::Relaxed),
681                slot.declared.load(Ordering::Relaxed),
682            );
683        }
684    }
685}

687impl<const N: usize> Default for ViolationRecord<N> {
688    fn default() -> Self {
689        Self::new()
690    }
691}

763/// Issue 1635 -- where an executor hands its violations when the image asked
764/// it to (`Executor::set_violation_sink`).
765///
766/// A function and an opaque context rather than a closure, because the
767/// executor is not generic and the reporter it reaches lives in a crate above
768/// this one (`nros-cpp` publishes on `/diagnostics` through
769/// `nros-diagnostics`). Called from inside the executor's spin (never from
770/// inside a user callback) -- so the sink may publish.
771///
772/// phase-474 I7 -- called OFF the judged dispatch, not at detection: a stored
773/// verdict is queued ([`REPORT_QUEUE`] deep) and the queue is handed over at
774/// the end of a spin whose next timer is further away than the last report
775/// cost (or once a verdict has waited [`REPORT_DEFER_MAX_US`]). The sink gets
776/// every pending verdict, oldest first, and returns how many of them it took
777/// -- a PREFIX, so it may coalesce as many as fit one message and leave the
778/// rest for the next slot. Returning 0 is a failure the sink has counted;

780/// never be sent cannot stall the queue (it stays in the ring and the record).

784/// that cost tripped `release-jitter-runtime` and `timer-overrun-runtime`:
785/// one verdict bred more.

789/// guarantees `ctx` is valid for every call until the sink is replaced or the
790/// executor is dropped.

890impl<'s> ViolationChannel<'s> {
891    pub(crate) fn new(ring: super::storage::CarvedVec<'s, Violation>) -> Self {
892        Self {
893            report: true,
894            drain_report: crate::config::VIOLATION_DRAIN_REPORT,
895            sink: None,
896            reports: ReportQueue::default(),
897            ring,
898            counts: ViolationCounts {
899                total: 0,
900                dropped: 0,
901                armed: MonitorArming::DEFAULT.armed_at_first_spin(),
902                suppressed_before_arm: 0,
903                arm_on_call: MonitorArming::DEFAULT.on_call,
904                arm_grace_ms: MonitorArming::DEFAULT.grace_ms,
905                spun: false,
906                first_spin_ms: 0,
907                arm_requests_seen: arm_requests(),
908            },
909        }
910    }
911
912    /// Issue 1635 / phase-474 I1 -- THE one place a detected violation goes:
913    /// the log floor (issue 0514) unless the drain hook reports instead, the
914    /// image's sink's queue when one is installed (sent later, phase-474 I7),
915    /// the trace marker when callback
916    /// tracing is compiled in, the SWD record when the image keeps one, and
917    /// the ring [`drain_violations`] reads.
918    ///
919    /// [`drain_violations`]: super::Executor::drain_violations
920    pub(crate) fn record(&mut self, v: Violation) {
921        if !self.counts.armed {
922            // phase-474 I2 -- start-up: counted, never stored.
923            self.counts.suppressed_before_arm = self.counts.suppressed_before_arm.saturating_add(1);
924            #[cfg(nros_boot_report)]
925            NROS_VIOLATION_RECORD
926                .suppressed_before_arm
927                .fetch_add(1, Ordering::Relaxed);
928            return;
929        }
930        if self.report && !self.drain_report {
931            log_violation(&v);
932        }
933        if self.sink.is_some() {
934            // phase-474 I7 -- queued, not sent: the report leaves at the end of
935            // a spin with slack (`Executor::flush_violation_reports`), so it
936            // never costs the dispatch being judged.
937            if self.reports.pending.is_full() {
938                self.reports.pending.remove(0);
939                self.reports.overflowed = self.reports.overflowed.saturating_add(1);
940            }
941            let _ = self.reports.pending.push(v.clone());
942        }
943        // `total` is this executor's sequence number for the verdict: the log
944        // line and the trace marker carry it, so the two name one verdict by
945        // one number. The SWD record numbers across every executor in the
946        // image; on a single-executor image the two coincide.
947        self.counts.total = self.counts.total.wrapping_add(1);
948        #[cfg(nros_boot_report)]
949        NROS_VIOLATION_RECORD.store(&v);
950        #[cfg(feature = "trace-callbacks")]
951        super::callback_trace::violation(self.counts.total, &v);
952        if self.ring.capacity() == 0 {
953            self.counts.dropped = self.counts.dropped.saturating_add(1);
954            return;
955        }
956        if self.ring.len() == self.ring.capacity() {
957            self.ring.pop_front();
958            self.counts.dropped = self.counts.dropped.saturating_add(1);
959        }
960        // Cannot fail: a slot was just made if the ring was full.
961        let _ = self.ring.push(v);
962    }
963
964    /// Hand every entry still in the ring to `f`, oldest first, with its
965    /// sequence number, and empty the ring.
966    pub(crate) fn drain(&mut self, mut f: impl FnMut(u32, &Violation)) {
967        let n = self.ring.len() as u32;
968        let first = self.counts.total.wrapping_sub(n).wrapping_add(1);
969        for (k, v) in self.ring.iter().enumerate() {
970            f(first.wrapping_add(k as u32), v);
971        }
972        self.ring.clear();
973    }
974
975    /// phase-474 I1 -- the drain-and-report hook: one log line per entry with
976    /// its sequence number and the counters, so a reader of the log knows how
977    /// many it missed. Called at the end of a spin when `drain_report` is on.
978    pub(crate) fn drain_and_report(&mut self) {
979        if !self.drain_report || self.ring.is_empty() {
980            return;
981        }
982        let (total, dropped) = (self.counts.total, self.counts.dropped);
983        self.drain(|seq, v| log_drained_violation(seq, total, dropped, v));
984    }
985}

1005/// Pure rate check over one window boundary. Returns `Some(violation)`
1006/// when the window elapsed AND the measured rate is below the declared
1007/// minimum (and we didn't already report last window).
1008///
1009/// Extracted from the executor so the math is unit-testable without a
1010/// session: publish counting is injected via the cell, time via `now_us`.
1011pub(crate) fn check_rate(
1012    spec: &MonitorSpec,
1013    state: &mut MonitorState,
1014    now_us: u64,
1015) -> Option<Violation> {
1016    if spec.min_rate_hz_milli == 0 {
1017        return None;
1018    }
1019    let count = spec.cell.count.load(Ordering::Relaxed);
1020    if !state.opened {
1021        // First observation: open the window, no verdict yet.
1022        state.opened = true;
1023        state.aligned = false;
1024        state.window_start_us = now_us;
1025        state.count_at_window_start = count;
1026        return None;
1027    }
1028    let window_us = now_us.saturating_sub(state.window_start_us);
1029    if !state.aligned && window_us < RATE_CHECK_INTERVAL_US {
1030        // phase-474 I8 -- the first window starts at the first tick that sees
1031        // a new sample, not where it was opened. The tick runs before the
1032        // spin's dispatch, so in steady state every boundary sits one tick
1033        // after a publish and the count matches the span. The window opened
1034        // at boot or by arming sits wherever that spin fell: off the
1035        // stream's phase it spans N samples over N periods plus the offset,
1036        // and a stream at exactly its declared rate read short (the island:
1037        // 9984 of 10000 mHz, once, after arming). Re-anchoring here puts the
1038        // first window on the same phase the later ones have. A stream that
1039        // stays silent is not held open: once a whole window passes with no
1040        // sample it is judged as opened (below), at 0.
1041        if count != state.count_at_window_start {
1042            state.aligned = true;
1043            state.window_start_us = now_us;
1044            state.count_at_window_start = count;
1045        }
1046        return None;
1047    }
1048    state.aligned = true;
1049    if window_us < RATE_CHECK_INTERVAL_US {
1050        return None;
1051    }
1052    let published = count.wrapping_sub(state.count_at_window_start) as u64;
1053    // milli-Hz = published * 1e3 / window_s = published * 1e9 / window_us
1054    let measured_milli_hz =
1055        (published.saturating_mul(1_000_000_000) / window_us.max(1)).min(u32::MAX as u64) as u32;
1056    // phase-474 I9 -- judge the count, not the floored quotient. The window
1057    // closes at the first tick that finds it elapsed, so `window_us` is the
1058    // declared interval plus that tick's lateness, while a stream at exactly
1059    // its declared minimum has published one sample per period: 50 over
1060    // 5.0005 s reads 9999 of 10000 mHz and was judged slow (the island, every
1061    // window, reported once thanks to `violated_last_window`). A stream at
1062    // the declared minimum delivers at least floor(min_rate * window) samples
1063    // in any window, whatever its phase; fewer than that is slow.
1064    let required = (spec.min_rate_hz_milli as u64).saturating_mul(window_us) / 1_000_000_000;
1065
1066    // Roll the window.
1067    state.window_start_us = now_us;
1068    state.count_at_window_start = count;
1069
1070    if published < required {
1071        if state.violated_last_window {
1072            return None; // still violated — already reported
1073        }
1074        state.violated_last_window = true;
1075        Some(Violation {
1076            rule: "rate-hierarchy-runtime",
1077            fqn: spec.fqn,
1078            measured: measured_milli_hz,
1079            declared: spec.min_rate_hz_milli,
1080        })
1081    } else {
1082        state.violated_last_window = false;
1083        None
1084    }
1085}

1087/// Pure latency check: drains the spec cell's window-max take→publish
1088/// latency and fires when it exceeds the declared node-path budget.
1089/// Same report-once-until-recovery semantics as the rate rule; runs on
1090/// every monitor tick (the cell accumulates between ticks, so no window
1091/// bookkeeping is needed — draining IS the window roll).
1092pub(crate) fn check_latency(spec: &MonitorSpec, state: &mut MonitorState) -> Option<Violation> {
1093    if spec.max_latency_ms == 0 {
1094        return None;
1095    }
1096    let max_us = spec.cell.max_latency_us.swap(0, Ordering::Relaxed);
1097    let max_ms = max_us / 1_000;
1098    if max_ms > spec.max_latency_ms {
1099        if state.latency_violated_last_window {
1100            return None;
1101        }
1102        state.latency_violated_last_window = true;
1103        Some(Violation {
1104            rule: "max-latency-runtime",
1105            fqn: spec.fqn,
1106            measured: max_ms,
1107            declared: spec.max_latency_ms,
1108        })
1109    } else {
1110        // A quiet window (no dispatch attributed) also counts as clean —
1111        // recovery resets the dedup like the rate rule's clean window.
1112        state.latency_violated_last_window = false;
1113        None
1114    }
1115}

1149/// phase10-B3 -- the dispatch in `slot` took a sample at `take_us`: every
1150/// route whose trigger is that slot starts its clock, unless an earlier take
1151/// is still waiting for the output (the route is judged from the EARLIEST
1152/// unanswered take: a take that arrives just after a tick waits for the whole
1153/// next period, and that is the wait the budget has to hold).
1154pub(crate) fn route_take(table: &[MonitorSpec], slot: usize, take_us: u64) {
1155    let bound = slot as u32 + 1;
1156    for spec in table.iter().take(MAX_MONITORS) {
1157        let w = spec.cell.route.load(Ordering::Relaxed);
1158        if w & ROUTE_SLOT_MASK != bound || w & ROUTE_PENDING != 0 {
1159            continue;
1160        }
1161        spec.cell
1162            .route_take_us
1163            .store(take_us as u32, Ordering::Relaxed);
1164        spec.cell.route.store(w | ROUTE_PENDING, Ordering::Relaxed);
1165    }
1166}

1168/// phase10-B3 -- a dispatch ended at `end_us`. Every route output whose
1169/// counter advanced during it (`counts_before`, as the latency rule reads it)
1170/// and that has a take waiting is judged: take to dispatch end, an upper bound
1171/// on take to that publish, against the path's budget. Over budget is
1172/// reported once until a route is within it again.
1173///
1174/// phase-503 -- a SUPERVISED route ([`MonitorSpec::route_deadline_ms`])
1175/// answered at or after its deadline is also overdue: it is reported as
1176/// `route-deadline-runtime` and its reaction requested, as `route_overdue`
1177/// would have done had it run in time. Under `MECHANISM_EXECUTOR` this is the
1178/// only detection a single long callback gets: the callback that holds the
1179/// spin thread past the deadline publishes the output before the executor's
1180/// overdue check can run, so the miss is caught here, at completion -- late
1181/// by the callback's overrun. A route whose deadline was already caught
1182/// (`route_overdue` dropped its take) is not pending any more and is not
1183/// judged again, so each take gets at most one deadline verdict.
1184///
1185/// `report(row, violation, record, react)`: `record` is `false` while the
1186/// route is still marked violated from an earlier verdict (report once until
1187/// a route is within its budget again); `react` asks the caller to call the
1188/// reaction hook, on every late supervised take as `route_overdue` does.
1189pub(crate) fn route_judge(
1190    table: &[MonitorSpec],
1191    counts_before: &[u32; MAX_MONITORS],
1192    end_us: u64,
1193    mut report: impl FnMut(usize, Violation, bool, bool),
1194) {
1195    for (k, spec) in table.iter().take(MAX_MONITORS).enumerate() {
1196        if spec.route_max_latency_ms == 0 {
1197            continue;
1198        }
1199        let w = spec.cell.route.load(Ordering::Relaxed);
1200        if w & ROUTE_PENDING == 0 || spec.cell.count.load(Ordering::Relaxed) == counts_before[k] {
1201            continue;
1202        }
1203        let took_us = (end_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1204        let measured_ms = took_us / 1_000;
1205        let first = w & ROUTE_VIOLATED == 0;
1206        let late = measured_ms > spec.route_max_latency_ms;
1207        let overdue =
1208            route_supervised(spec) && took_us >= spec.route_deadline_ms.saturating_mul(1_000);
1209        let mut next = w & !ROUTE_PENDING;
1210        if late && first {
1211            report(
1212                k,
1213                Violation {
1214                    rule: "route-latency-runtime",
1215                    fqn: spec.fqn,
1216                    measured: measured_ms,
1217                    declared: spec.route_max_latency_ms,
1218                },
1219                true,
1220                false,
1221            );
1222        }
1223        if overdue {
1224            report(
1225                k,
1226                Violation {
1227                    rule: "route-deadline-runtime",
1228                    fqn: spec.fqn,
1229                    measured: measured_ms,
1230                    declared: spec.route_deadline_ms,
1231                },
1232                first,
1233                true,
1234            );
1235        }
1236        if late || overdue {
1237            next |= ROUTE_VIOLATED;
1238        } else {
1239            next &= !ROUTE_VIOLATED;
1240        }
1241        spec.cell.route.store(next, Ordering::Relaxed);
1242    }
1243}

1245/// phase-503 -- whether a pending route of `spec` has a supervised deadline.
1246#[inline]
1247fn route_supervised(spec: &MonitorSpec) -> bool {
1248    spec.route_deadline_ms > 0 && spec.route_max_latency_ms > 0
1249}

1251/// phase-503 -- time from now to the earliest deadline of a pending supervised
1252/// route, in microseconds (0 when one is already due), or `None` when no
1253/// supervised route is waiting. This is the executor's wake source for the
1254/// rule, and what a port's independent timer (`MECHANISM_TIMER`) arms on.
1255///
1256/// The due time is `take + route_deadline_ms`, derived from the stored take
1257/// rather than kept in a second cell: both are the clock's low 32 bits, so the
1258/// difference is exact across a wrap as long as a route waits less than ~71
1259/// minutes, and a supervised one is reported long before that.
1260pub fn route_next_due_us(table: &[MonitorSpec], now_us: u64) -> Option<u64> {
1261    let mut best: Option<u64> = None;
1262    for spec in table.iter().take(MAX_MONITORS) {
1263        if !route_supervised(spec) {
1264            continue;
1265        }
1266        let w = spec.cell.route.load(Ordering::Relaxed);
1267        if w & ROUTE_PENDING == 0 {
1268            continue;
1269        }
1270        let waited_us =
1271            (now_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1272        let deadline_us = spec.route_deadline_ms.saturating_mul(1_000);
1273        let left = deadline_us.saturating_sub(waited_us) as u64;
1274        best = Some(best.map_or(left, |b| b.min(left)));
1275        if left == 0 {
1276            break;
1277        }
1278    }
1279    best
1280}

1282/// phase-503 -- judge every pending supervised route at `now_us`: a take still
1283/// unanswered at or after `take + route_deadline_ms` is OVERDUE. Its waiting
1284/// take is dropped (the route stops pending, so the next take starts a new
1285/// one) and the route is marked [`ROUTE_VIOLATED`], as `route_judge` marks an
1286/// over-budget route.
1287///
1288/// `react(row, violation, first)` is called for every overdue route: `first`
1289/// is `false` while the route is still marked violated from an earlier verdict
1290/// (report once until a route is within its budget again, the latency rule's
1291/// rule), and the caller records the violation only when it is `true`. The
1292/// reaction is requested every time, since each overdue take is a missed
1293/// deadline the fallback has to cover.
1294pub(crate) fn route_overdue(
1295    table: &[MonitorSpec],
1296    now_us: u64,
1297    mut react: impl FnMut(usize, Violation, bool),
1298) {
1299    for (k, spec) in table.iter().take(MAX_MONITORS).enumerate() {
1300        if !route_supervised(spec) {
1301            continue;
1302        }
1303        let w = spec.cell.route.load(Ordering::Relaxed);
1304        if w & ROUTE_PENDING == 0 {
1305            continue;
1306        }
1307        let waited_us =
1308            (now_us as u32).wrapping_sub(spec.cell.route_take_us.load(Ordering::Relaxed));
1309        if waited_us < spec.route_deadline_ms.saturating_mul(1_000) {
1310            continue;
1311        }
1312        spec.cell
1313            .route
1314            .store((w & !ROUTE_PENDING) | ROUTE_VIOLATED, Ordering::Relaxed);
1315        react(
1316            k,
1317            Violation {
1318                rule: "route-deadline-runtime",
1319                fqn: spec.fqn,
1320                measured: waited_us / 1_000,
1321                declared: spec.route_deadline_ms,
1322            },
1323            w & ROUTE_VIOLATED == 0,
1324        );
1325    }
1326}

1363    /// array is INLINE in the `Executor` value (`[AgeState; MAX_AGE_MONITORS]`) and
1364    /// that value has a byte budget a knob-scaled table must not blow (issue
1365    /// 0961 / `storage.rs`'s `the_executor_value_does_not_scale_with_the_knobs`
1366    /// -- a `u64` here costs 8 rows x 16 B and fails it). The unit is the
1367    /// contract's own (`max_age_ms`), the comparison is a wrapping delta, so

1369    /// never shorter than a millisecond.

1373/// phase-462 W2 -- the on-target liveliness lease: a contracted subscription
1374/// that has taken NOTHING for a whole `max_age_ms` window.
1375///
1376/// The bound needs no new declaration and deliberately does not invent one.
1377/// `max_age_ms` already says how old this input's data may be; data that never
1378/// arrives is older than that by the same clock, so the window IS the declared
1379/// bound. (`on_violation` selects what the executor then DOES about it; the
1380/// reaction beyond reporting is the fault hook phase-462 W3 owns.)
1381///
1382/// Why this is not `max-age-runtime` with a longer arm: that rule judges a
1383/// message that arrived. An input that stops entirely produces no message to
1384/// judge, so it leaves the age rule silent forever -- the exact failure a
1385/// `max_age_ms` promise is made against, and the one play_launch's reaction
1386/// engine catches on the Linux side of the same contract.
1387///
1388/// `now_us` is the executor's monotonic clock, `None` on a build with no clock
1389/// at all. Then nothing is judged: a clock that never moves is a window that
1390/// never elapses, and guessing a window from spin counts would put a tolerance
1391/// nobody declared into a safety rule.
1392fn check_silence(spec: &AgeMonitorSpec, state: &mut AgeState, took: u32, now_us: u64) -> bool {
1393    let now_ms = (now_us / 1_000) as u32;
1394    if !state.silence_opened {
1395        state.silence_opened = true;
1396        state.last_take_ms = now_ms;
1397        return false;
1398    }
1399    if took > 0 {
1400        state.last_take_ms = now_ms;
1401        state.silence_reported = false;
1402        return false;
1403    }
1404    if now_ms.wrapping_sub(state.last_take_ms) < spec.max_age_ms {
1405        return false;
1406    }
1407    if state.silence_reported {
1408        return false; // still silent -- already reported
1409    }
1410    state.silence_reported = true;
1411    true
1412}

1414/// Pure age check: drains the sub cell's window-max take-age and fires
1415/// when it exceeds the declared bound. Report-once-until-recovery.
1416///
1417/// phase-462 W2 -- also the silence rule's tick, because the two verdicts read
1418/// ONE observation (what this endpoint took since the last check) and reading
1419/// it twice would let one rule's drain hide the other's evidence. They cannot
1420/// both fire: with no takes the drained age is 0, so `max-age-runtime` has
1421/// nothing to judge.
1422pub(crate) fn check_age(
1423    spec: &AgeMonitorSpec,
1424    state: &mut AgeState,
1425    now_us: Option<u64>,
1426) -> Option<Violation> {
1427    if spec.max_age_ms == 0 {
1428        return None;
1429    }
1430    let took = spec.cell.takes.swap(0, Ordering::Relaxed);
1431    if let Some(now_us) = now_us
1432        && check_silence(spec, state, took, now_us)
1433    {
1434        return Some(Violation {
1435            rule: "silence-runtime",
1436            fqn: spec.fqn,
1437            // Takes in the window, against the window the contract declares.
1438            measured: 0,
1439            declared: spec.max_age_ms,
1440        });
1441    }
1442    let max_ms = spec.cell.max_age_ms.swap(0, Ordering::Relaxed);
1443    if max_ms > spec.max_age_ms {
1444        if state.violated_last_window {
1445            return None;
1446        }
1447        state.violated_last_window = true;
1448        Some(Violation {
1449            rule: "max-age-runtime",
1450            fqn: spec.fqn,
1451            measured: max_ms,
1452            declared: spec.max_age_ms,
1453        })
1454    } else {
1455        state.violated_last_window = false;
1456        None
1457    }
1458}

1544const HAZARD_REACTED: u32 = 2;

1546/// Whether `member` has faulted, and since when (ms) when the row knows.
1547fn member_fault(
1548    member: GuardRef,
1549    monitor_states: &[MonitorState],
1550    age_states: &[AgeState],
1551) -> Option<Option<u32>> {
1552    match member {
1553        GuardRef::Age(i) => {
1554            let s = age_states.get(i as usize)?;
1555            s.silence_reported.then_some(Some(s.last_take_ms))
1556        }
1557        GuardRef::Rate(i) => {
1558            let s = monitor_states.get(i as usize)?;
1559            s.violated_last_window.then_some(None)
1560        }
1561    }
1562}

1564/// Whether any guard of `spec` has faulted, and the earliest fault start the
1565/// faulting rows know.
1566fn hazard_fault(
1567    spec: &HazardSpec,
1568    monitor_states: &[MonitorState],
1569    age_states: &[AgeState],
1570) -> Option<Option<u32>> {
1571    let mut faulted = false;
1572    let mut since: Option<u32> = None;
1573    for g in spec.guards {
1574        let mut seen = 0usize;
1575        let mut g_since: Option<u32> = None;
1576        for m in g.members {
1577            if let Some(at) = member_fault(*m, monitor_states, age_states) {
1578                seen += 1;
1579                if let Some(at) = at {
1580                    g_since = Some(g_since.map_or(at, |s: u32| s.min(at)));
1581                }
1582            }
1583        }
1584        let guard_faulted = if g.all_of {
1585            !g.members.is_empty() && seen == g.members.len()
1586        } else {
1587            seen > 0
1588        };
1589        if guard_faulted {
1590            faulted = true;
1591            if let Some(at) = g_since {
1592                since = Some(since.map_or(at, |s| s.min(at)));
1593            }
1594        }
1595    }
1596    faulted.then_some(since)
1597}

1599/// phase-462 W3b -- one tick of a hazard's observer, after the monitor rows
1600/// have run. Emits, in play_launch's vocabulary so one log reader serves both
1601/// sides of a bridge:
1602///
1603/// - `hazard-detected` when a guard first faults: measured is the ms since
1604///   the fault began, declared the FTTI;
1605/// - `hazard-reaction` when the `safe_state` publisher publishes after that:
1606///   measured is fault-to-reaction plus `settle_ms`, declared the FTTI;
1607/// - `hazard-recovered` when no guard is faulted any more: measured is the
1608///   ms the hazard lasted.
1609///
1610/// `fqn` is the hazard's key on all three.
1611pub(crate) fn check_hazard(
1612    spec: &HazardSpec,
1613    monitor_table: &[MonitorSpec],
1614    monitor_states: &[MonitorState],
1615    age_states: &[AgeState],
1616    now_ms: u32,
1617    mut emit: impl FnMut(Violation),
1618) {
1619    let cell = spec.cell;
1620    let state = cell.state.load(Ordering::Relaxed);
1621    let sink_count = monitor_table
1622        .get(spec.sink as usize)
1623        .map(|m| m.cell.count.load(Ordering::Relaxed));
1624    let fault = hazard_fault(spec, monitor_states, age_states);
1625    let v = |rule, measured: u32| Violation {
1626        rule,
1627        fqn: spec.key,
1628        measured,
1629        declared: spec.ftti_ms,
1630    };
1631    match (state, fault) {
1632        (HAZARD_CLEAR, Some(since)) => {
1633            let at = since.unwrap_or(now_ms);
1634            cell.fault_ms.store(at, Ordering::Relaxed);
1635            cell.sink_count
1636                .store(sink_count.unwrap_or(0), Ordering::Relaxed);
1637            cell.state.store(HAZARD_DETECTED, Ordering::Relaxed);
1638            emit(v("hazard-detected", now_ms.wrapping_sub(at)));
1639        }
1640        (HAZARD_DETECTED, Some(_)) => {
1641            if let Some(count) = sink_count
1642                && count != cell.sink_count.load(Ordering::Relaxed)
1643            {
1644                cell.state.store(HAZARD_REACTED, Ordering::Relaxed);
1645                let since = now_ms.wrapping_sub(cell.fault_ms.load(Ordering::Relaxed));
1646                emit(v("hazard-reaction", since.saturating_add(spec.settle_ms)));
1647            }
1648        }
1649        (HAZARD_DETECTED | HAZARD_REACTED, None) => {
1650            cell.state.store(HAZARD_CLEAR, Ordering::Relaxed);
1651            let lasted = now_ms.wrapping_sub(cell.fault_ms.load(Ordering::Relaxed));
1652            emit(v("hazard-recovered", lasted));
1653        }
1654        _ => {}
1655    }
1656}

2325/// Issue #505 — periodic activations a timer dropped because its
2326/// executor was blocked past the period boundary.
2327///
2328/// This rule exists because `check_rate` cannot see an isolated stall:
2329/// it samples publish counts over a ~5 s window, so 20 missed
2330/// activations of a 100 Hz loop are a 0.4% rate deficit — under any
2331/// sane declared minimum, silence. (And under
2332/// [`TimerOverrunPolicy::CatchUp`](super::arena::TimerOverrunPolicy)
2333/// the replayed activations refill the window entirely, so the rate
2334/// rule reports a HEALTHY loop while the tier is stalling.) The
2335/// overrun counter is exact, needs no window, and does not depend on
2336/// clock resolution.
2337///
2338/// `overruns` is the timer's monotonic saturating counter;
2339/// `last_reported` is the value at the previous check, so the verdict
2340/// is on the delta. Returns a violation when more than `tolerated`
2341/// activations were dropped since the last check.
2342pub(crate) fn check_timer_overrun(
2343    overruns: u32,
2344    last_reported: &mut u32,
2345    tolerated: u32,
2346) -> Option<Violation> {
2347    let dropped = overruns.saturating_sub(*last_reported);
2348    *last_reported = overruns;
2349    if dropped <= tolerated {
2350        return None;
2351    }
2352    Some(Violation {
2353        rule: "timer-overrun-runtime",
2354        // Timer entries carry no name at this altitude; same stand-in
2355        // as `deadline-miss-runtime`.
2356        fqn: "timer",
2357        measured: dropped,
2358        declared: tolerated,
2359    })
2360}

2362/// Issue #515 — report a spin wake that arrived so late the cadence it
2363/// claims cannot have been met.
2364///
2365/// Like `check_timer_overrun` and unlike the rate/age/latency rules, this
2366/// needs no baked spec table. The bound is the spin period ITSELF: the
2367/// caller passes it to `spin_once` as the pacing quantum, it is what
2368/// `system.toml` declares as `spin_period_us`, and a wake later than a full
2369/// period past its predecessor means an activation's worth of cadence was
2370/// lost. That is a contract failure for any declared period, so there is
2371/// nothing further to declare.
2372///
2373/// The tolerance is one whole period rather than zero, and deliberately so.
2374/// Sub-period lateness is ordinary scheduling noise -- on the measured FVP
2375/// lane the executor is late on a large fraction of wakes while still
2376/// holding its rate -- and a rule that fired on each one would report a
2377/// healthy system as broken thousands of times a second. What is NOT
2378/// ordinary is being a full period late, because by then the wake that
2379/// should have happened in between never did.
2380///
2381/// phase-474 I11 -- for a `spin_once(period)` loop with no declared cadence
2382/// the lateness is release minus scheduled release on the executor's release
2383/// grid (a dropped release counts its age when dropped), not entry-to-entry
2384/// minus the period; see `Executor::record_release_jitter`.
2385///
2386/// `max_jitter_us` is the executor's high-water since the last check and
2387/// `last_reported` the value at the previous one, so the verdict is on the
2388/// delta -- the same shape as the overrun counter, and for the same reason:
2389/// a maximum that has not moved is not a new fault.
2390pub(crate) fn check_release_jitter(
2391    max_jitter_us: u64,
2392    last_reported: &mut u64,
2393    period_us: u64,
2394) -> Option<Violation> {
2395    if period_us == 0 || max_jitter_us <= *last_reported {
2396        return None;
2397    }
2398    *last_reported = max_jitter_us;
2399    if max_jitter_us < period_us {
2400        return None;
2401    }
2402    Some(Violation {
2403        rule: "release-jitter-runtime",
2404        // Same stand-in as the timer and deadline rules: the spin loop is
2405        // not an endpoint and carries no fqn at this altitude.
2406        fqn: "spin",
2407        measured: max_jitter_us.min(u32::MAX as u64) as u32,
2408        declared: period_us.min(u32::MAX as u64) as u32,
2409    })
2410}

2412/// Report a spin thread whose stack has come closer to its end than the
2413/// declared minimum.
2414///
2415/// Unlike every other rule here the bound CANNOT be derived from something
2416/// already declared, and that is worth stating rather than papering over.
2417/// `check_timer_overrun` and `check_release_jitter` both judge against a
2418/// period the caller already passes in; there is no equivalent for a stack.
2419/// The executor never sees `stack_bytes` -- it lives in the spawn attr and
2420/// goes no further -- and the total is not portably queryable either:
2421/// FreeRTOS exposes the high-water mark and not the size it was taken
2422/// against, so even a percentage cannot be computed. A minimum headroom is
2423/// therefore a real declaration, and `min_bytes == 0` means the caller has
2424/// not made one, which disables the rule.
2425///
2426/// Reports on the WORST case, not on each crossing: `worst_reported` holds
2427/// the lowest headroom already reported, so a stack hovering just under the
2428/// bound says so once and then only when it gets worse. The same delta
2429/// discipline as the overrun and jitter rules, inverted because for headroom
2430/// smaller is worse.
2431pub(crate) fn check_stack_headroom(
2432    unused_bytes: usize,
2433    min_bytes: usize,
2434    worst_reported: &mut usize,
2435) -> Option<Violation> {
2436    if min_bytes == 0 || unused_bytes >= min_bytes {
2437        return None;
2438    }
2439    // `usize::MAX` is the "nothing reported yet" sentinel: any real headroom
2440    // is below it, so the first breach always reports.
2441    if *worst_reported != usize::MAX && unused_bytes >= *worst_reported {
2442        return None;
2443    }
2444    *worst_reported = unused_bytes;
2445    Some(Violation {
2446        rule: "stack-headroom-runtime",
2447        // The spin thread is not an endpoint; same stand-in as the timer,
2448        // deadline and jitter rules.
2449        fqn: "stack",
2450        measured: unused_bytes.min(u32::MAX as usize) as u32,
2451        declared: min_bytes.min(u32::MAX as usize) as u32,
2452    })
2453}

2593/// AUTOSAR's Watchdog Manager separates ALIVE supervision -- did it run at
2594/// all, at roughly the right rate -- from DEADLINE supervision, did it finish
2595/// in time. Every rule here is the second kind or a variant of it: they fire
2596/// when something happens and is wrong. Nothing fires when a callback stops
2597/// happening altogether.
2598///
2599/// `rate-hierarchy-runtime` does not cover it. That rule counts PUBLISHES on
2600/// a contracted publisher, so a timer callback that silently stops firing
2601/// while its topic is published from elsewhere -- another tier, a bridge, a
2602/// republisher -- leaves it satisfied. The gap is a callback, not an
2603/// endpoint.
2604///
2605/// The bound needs no declaration: `period_us` is already on the SC, and a
2606/// context claiming a period that produced no activation in a window many
2607/// times longer than it is a contract failure for any period. `period_us ==
2608/// 0` declares no cadence, so nothing is judged.
2609///
2610/// ZERO, not a fraction. A throttled-but-alive context is a different fault
2611/// with different evidence -- `SporadicState` already counts window skips and
2612/// dispatches for exactly that -- and picking a percentage here would invent
2613/// a tolerance nobody declared. Zero activations against a declared period is
2614/// unambiguous.
2615pub(crate) fn check_alive(
2616    period_us: u64,
2617    dispatches: u32,
2618    state: &mut AliveState,
2619    now_us: u64,
2620) -> Option<Violation> {
2621    if period_us == 0 {
2622        return None;
2623    }
2624    if !state.opened {
2625        state.opened = true;
2626        state.window_start_us = now_us;
2627        state.count_at_window_start = dispatches;
2628        return None;
2629    }
2630    let window_us = now_us.saturating_sub(state.window_start_us);
2631    if window_us < RATE_CHECK_INTERVAL_US {
2632        return None;
2633    }
2634    let fired = dispatches.wrapping_sub(state.count_at_window_start);
2635    state.window_start_us = now_us;
2636    state.count_at_window_start = dispatches;
2637
2638    // Only judge a window long enough to have contained an activation. A
2639    // period longer than the check interval is not late merely for not having
2640    // fired yet.
2641    if window_us < period_us {
2642        return None;
2643    }
2644    if fired > 0 {
2645        state.violated_last_window = false;
2646        return None;
2647    }
2648    if state.violated_last_window {
2649        return None; // still silent — already reported
2650    }
2651    state.violated_last_window = true;
2652    Some(Violation {
2653        rule: "alive-supervision-runtime",
2654        // SCs carry no name at this altitude; same stand-in as the deadline
2655        // rule, which reports against the SC too.
2656        fqn: "sched-context",
2657        measured: 0,
2658        declared: (window_us / period_us).min(u32::MAX as u64) as u32,
2659    })
2660}
