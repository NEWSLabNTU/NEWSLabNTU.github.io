1//! phase-457 W5 (issue 1522) — which registration entry point a DECLARED
2//! subscription reaches, as ONE value.
3//!
4//! # The hole this fills
5//!
6//! W3 made `[[endpoint]] registration_path`'s third row an OBSERVATION:
7//! `SubscriptionRequest::in_place_capable` is stated at each of the executor's
8//! eleven subscription entry points, read at
9//! [`Executor::open_subscription`][open], and reported from there through
10//! [`registration_observer`][obs]. A row nobody observed REFUSES, and every
11//! consumer then budgets the receive region — the safe direction.
12//!
13//! The **Rust producer observes nothing**. `nros::record_node_metadata::<C>`
14//! runs a component's `register()` against a recording `NodeContext` and opens
15//! no executor at all, so no registration happens in the probe and every Rust
16//! endpoint's row refuses. That is issue 1522.
17//!
18//! # Why a classifier is allowed here, when W3 deleted one
19//!
20//! W3 deleted an inference: the sizing descriptor composed the in-place row
21//! from the entry's LANGUAGE, which is wrong for nine of the eleven entry
22//! points. That was a SECOND OPINION — a table in the CLI about code it cannot
23//! see.
24//!
25//! The declarative road is not that shape. Its registrar is ONE function —
26//! `nros::node_runtime`'s `EntityKind::Subscription` arm — and it lowers every
27//! declared subscription to exactly one of two entry points. So the shape a
28//! declared endpoint takes is a FUNCTION OF THE DECLARATION, computed in one
29//! place, and this enum is that function's codomain.
30//!
31//! It stays one opinion only because of the two rules below, both gated by
32//! `check-declared-subscription-shape`:
33//!
34//! 1. **The registrar branches on it.** The subscription arm does not test the
35//!    declaration's `safety` flag itself; it asks for a
36//!    [`DeclaredSubscriptionShape`] and dispatches on the answer. A variant it
37//!    does not name is a gate failure, not a silent fall-through.
38//! 2. **The entry point takes its value from here.** Each entry point's
39//!    `SubscriptionRequest::in_place_capable` is spelled
40//!    `DeclaredSubscriptionShape::<V>.in_place_capable()`, so there is exactly
41//!    one `bool` per shape in the tree. Issue 1340's first candidate — letting
42//!    the raw buffered path take the in-place row — is then a one-line change
43//!    here that moves the entry point and the probe together, which is the
44//!    property that makes this cheaper than teaching the probe to register.
45//!
46//! [open]: super::Executor
47//! [obs]: super::registration_observer
48
49/// Which of the executor's registration entry points a DECLARED subscription
50/// lowers to.
51///
52/// One variant per lowering the declarative registrar can choose. Exhaustive:
53/// a new lowering is a new variant, which breaks
54/// [`in_place_capable`](Self::in_place_capable) at compile time and the
55/// registrar at its gate.
56#[derive(Debug, Clone, Copy, PartialEq, Eq)]
57pub enum DeclaredSubscriptionShape {
58    /// `Node::create_generic_subscription_with_qos` →
59    /// `Executor::register_subscription_buffered_raw_on`.
60    BufferedRaw,
61    /// A `.safety()` declaration:
62    /// `Node::create_generic_subscription_with_integrity` →
63    /// `Executor::register_subscription_buffered_raw_safety_on`.
64    BufferedRawSafety,
65}
66
67impl DeclaredSubscriptionShape {
68    /// Classify a declaration.
69    ///
70    /// `safety` is the declaration's `.safety()` flag **as the runtime will
71    /// see it**: a build whose `safety-e2e` capability is off ignores the flag
72    /// and registers the basic path, so its caller masks the flag to `false`
73    /// before asking. That mask has exactly one home on the caller's side, for
74    /// the same reason this classifier has one here.
75    pub const fn of_declaration(safety: bool) -> Self {
76        if safety {
77            Self::BufferedRawSafety
78        } else {
79            Self::BufferedRaw
80        }
81    }
82
83    /// Can a registration of this shape dispatch out of the backend's own
84    /// receive slot?
85    ///
86    /// **The definition, not a copy of one.** Each entry point writes this
87    /// call into its `SubscriptionRequest`, so the answer a probe states and
88    /// the answer the executor acts on are the same expression.
89    ///
90    /// Both shapes answer `false` today, and that is worth a sentence rather
91    /// than a collapse into `false`: they are false for DIFFERENT reasons —
92    /// the raw path because its arena entry is shared with
93    /// `add_arena_subscription_callback`, the safety path because
94    /// `process_raw_in_place` has no validating form — and only the first is a
95    /// limit anyone plans to lift (issue 1340).
96    pub const fn in_place_capable(self) -> bool {
97        match self {
98            Self::BufferedRaw => false,
99            Self::BufferedRawSafety => false,
100        }
101    }
102}

104#[cfg(test)]
105mod tests {
106    use super::*;
107
108    #[test]
109    fn a_declaration_classifies_by_its_safety_flag() {
110        assert_eq!(
111            DeclaredSubscriptionShape::of_declaration(false),
112            DeclaredSubscriptionShape::BufferedRaw
113        );
114        assert_eq!(
115            DeclaredSubscriptionShape::of_declaration(true),
116            DeclaredSubscriptionShape::BufferedRawSafety
117        );
118    }
119
120    /// Not a restatement of `in_place_capable`'s body: this is the claim the
121    /// PROBE ships, and issue 1522's whole point is that closing it states
122    /// `unbounded` rather than unlocking a saving. When issue 1340 flips the
123    /// raw arm, this test is what says out loud that every Rust image's
124    /// declared subscriptions just changed price.
125    #[test]
126    fn neither_declarative_shape_dispatches_in_place_today() {
127        assert!(!DeclaredSubscriptionShape::BufferedRaw.in_place_capable());
128        assert!(!DeclaredSubscriptionShape::BufferedRawSafety.in_place_capable());
129    }
130}
