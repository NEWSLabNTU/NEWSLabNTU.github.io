1//! A fixed RAM record the image writes about itself, for targets where no log
2//! sink reaches a human.
3//!
4//! # Why this exists
5//!
6//! phase-412 derived six pool counts and the executor arena for the
7//! mr-canhubk344 island, and then could not tell whether the derived image was
8//! correct. The only available signal was the ROS graph's node count, and one
9//! unchanged configuration produced 4, 0, 0, 4, 4 across five runs. Every other
10//! channel was already disqualified for that board:
11//!
12//! * The console is on `lpuart0`, which is not wired on the MR-CANHUBK344.
13//!   `lpuart2` is the zenoh serial transport and cannot carry a second protocol.
14//! * `nros_log` therefore reaches nothing. Both arena diagnostics (issue 0900)
15//!   go through it, so the two messages written specifically to explain an
16//!   arena failure are invisible on the one board that needed them.
17//! * SEGGER RTT was tried and could not discriminate: a working image and a
18//!   derived image both emitted only the Zephyr banner, and a deliberate
19//!   positive control produced nothing at all.
20//! * Semihosting halts the core until a probe answers and FAULTS with no probe
21//!   attached, so an image carrying it cannot run standalone.
22//!
23//! What all of those share is that they are STREAMS: they need the board to
24//! still be running, and they need somebody attached at the moment the
25//! interesting thing happens. The failure this campaign is trying to see is the
26//! opposite shape. An under-sized arena halts DURING entity creation, before
27//! the first spin, so issue 0900's advisory never prints -- the failure cannot
28//! report itself through any stream.
29//!
30//! So this is not a stream. It is a fixed-size record in RAM that the image
31//! keeps up to date as it boots, read out AFTERWARDS by halting the core and
32//! dumping memory. It survives the halt because it does not depend on anything
33//! still running, and a PARTIAL record is the useful case rather than a lost
34//! one: the last stage reached and the allocation that did not fit are exactly
35//! what names the knob to change.
36//!
37//! # Reading it
38//!
39//! The record is a `#[no_mangle]` static, so it has a symbol in the ELF and a
40//! debugger can find it without the address being wired in anywhere:
41//!
42//! ```text
43//! pyocd commander -t s32k344 -c "halt" -c "savemem <addr> <len> report.bin"
44//! python3 scripts/read-boot-report.py <elf> report.bin
45//! ```
46//!
47//! [`MAGIC`](crate::boot_report::MAGIC) distinguishes a written record from uninitialised RAM, and
48//! `BootReport::struct_size` lets a reader refuse a layout it does not know
49//! rather than decode it wrongly.
50//!
51//! # Cost, and why it is opt-in
52//!
53//! Enabled by setting `NROS_BOOT_REPORT=1` at build time (Zephyr:
54//! `CONFIG_NROS_BOOT_REPORT=y`), which makes `nros-node`'s build script emit
55//! `cfg(nros_boot_report)`. With the cfg absent every function here is an empty
56//! `#[inline(always)]` body and the static does not exist, so an image that
57//! does not opt in is byte-identical to one built before this module -- the
58//! same rule issue 0900's arena knob and phase-403's `rx_buffer_from_type()`
59//! both keep.
60//!
61//! Enabled, it costs `BootReport::struct_size` bytes of `.bss` -- 92, the
62//! same on every target because every field is a `u32` -- and a handful of
63//! relaxed atomic stores on paths that run once per entity at registration.
64//!
65//! The 92 is not a detail: it is the LENGTH an operator types into `savemem`,
66//! and this sentence said 60 for as long as the record had fifteen fields. A
67//! short dump decodes -- `read-boot-report.py` needs `23 * 4` bytes and an
68//! 88-byte one is refused, but a reader who trusts the prose over the tool
69//! spends the refusal looking at the wrong thing. Ask the tool instead:
70//! `read-boot-report.py --addr-only <elf>` prints the address AND the length,
71//! from the ELF's own symbol size.
72//!
73//! # Adding a field (phase-460 W5, for W7 and after)
74//!
75//! The record is meant to grow, and the order it grows in is the whole
76//! contract: `read-boot-report.py` decodes POSITIONALLY. So a new field is
77//! APPENDED -- after the last field, never inserted between two -- and the
78//! four edits are one commit:
79//!
80//! 1. the field on `BootReport`, its zero in `BootReport::new`, the same
81//!    name in the same position on `Snapshot`, and its load in `snapshot`;
82//! 2. [`VERSION`](crate::boot_report::VERSION) bumped, so an older decoder REFUSES the record instead of
83//!    reading the new word as one it knows;
84//! 3. `FIELDS` in `scripts/read-boot-report.py`, same name, same position, and
85//!    `KNOWN_VERSION` to match;
86//! 4. the field count in `the_record_is_twenty_three_packed_u32s` below.
87//!
88//! `check-boot-report-layout` fails on 1 without 3, and the Rust test fails if
89//! the compiler laid the record out with padding. Appending is what keeps a
90//! dump taken from an older image decodable by eye: every word before the new
91//! one is still where it was, and the version says which words exist.

95/// `"NRSR"` -- nano-ros self report. Written LAST, so a reader that finds it
96/// knows every field before it is already valid.
97pub const MAGIC: u32 = 0x4e52_5352;

99/// Layout version. Bump on any field change; a reader refuses what it does not
100/// know rather than decoding a record it would misread.
101///
102/// 4 since phase-460 W5 appended `heap_peak_bytes` and `heap_capacity_bytes`;
103/// 5 since phase-460 W7 appended `samples_dropped_too_small`.
104pub const VERSION: u32 = 5;

106/// How far boot got. Monotonic, and the single most useful field: an arena
107/// failure halts during entity creation, so the stage that was NOT reached
108/// names the phase to look at.
109///
110/// Numbers follow EXECUTION ORDER, because `checkpoint` keeps the maximum
111/// and a stage that runs earlier but numbers higher would make the record
112/// claim less progress than was made. Inserting one therefore renumbers the
113/// rest and bumps [`VERSION`]; the decoder refuses a version it does not
114/// know rather than misreading it, which is what makes that safe.
115#[derive(Clone, Copy, PartialEq, Eq, Debug)]
116#[repr(u32)]
117pub enum Stage {
118    /// RAM as the loader left it. Never stored; a reader seeing this with a
119    /// valid magic has found a record that was reset but not re-entered.
120    Untouched = 0,
121    /// The record itself is initialised and the compile-time knobs are in it.
122    ///
123    /// Stamped at the TOP of the C++ entry point, before any argument is
124    /// validated, so "the image never entered nano-ros" is distinguishable
125    /// from "it entered and died before the executor". Version 1 stamped this
126    /// inside the executor constructor instead, which made those two cases
127    /// identical -- both read magic 0 -- and cost a disassembly walk to tell
128    /// apart on the first board run.
129    ReportReady = 1,
130    /// The boot config resolved: node name, namespace, locator and domain id
131    /// all parsed. Everything between here and [`Stage::ReportReady`] is
132    /// argument validation, and `BootReport::cpp_init_ret` says which check
133    /// rejected it.
134    BootConfigResolved = 2,
135    /// An `Executor` has bound its arena, so `BootReport::arena_capacity`
136    /// is the real slice length rather than the compiled constant.
137    ExecutorReady = 3,
138    /// Entity registration has begun: something claimed arena bytes.
139    ///
140    /// Stamped by [`note_alloc`] and [`note_alloc_failed`], which is to say by
141    /// the arena allocator itself rather than by any register seam. The arena
142    /// is claimed by entity registration and by nothing else, so an allocation
143    /// ATTEMPT is the event, and putting the stamp on the record's own writers
144    /// means every present and future `arena_alloc*` call site is covered by
145    /// construction -- there is no second place to remember.
146    ///
147    /// Issue 1036: nothing emitted this for three phases, so an image that ran
148    /// out of arena left the stage reading [`Stage::ExecutorReady`] -- the same
149    /// value as an image that opened its executor and died before registering
150    /// anything at all. The record named the allocation and could not say
151    /// WHERE, which is half of a diagnostic on a board where it is the only
152    /// channel.
153    ///
154    /// The interval between this and [`Stage::FirstSpin`] is where an
155    /// under-sized arena halts, so `stage == 4` with a non-zero
156    /// `BootReport::failed_alloc_shortfall` is the signature of the failure
157    /// this whole record exists to catch.
158    RegisteringEntities = 4,
159    /// RESERVED. Nothing emits this, and nothing can from inside the core.
160    ///
161    /// "Every entity the image declares was registered successfully" has no
162    /// observable moment here: an application may register lazily, which is the
163    /// same reason issue 0900's headroom advisory fires at the first spin
164    /// rather than at an end of registration that does not exist. A stamp at
165    /// the top of `spin_once` would be a claim the core cannot support.
166    ///
167    /// Kept rather than removed, and DOCUMENTED rather than left looking
168    /// unfinished (issue 1036): removing it renumbers [`Stage::FirstSpin`] and
169    /// bumps [`VERSION`] to retire a value no image can produce, and the next
170    /// reader would file the renumbering as the bug. An entry shape that DOES
171    /// know when its register pass ended -- a generated component `setup`
172    /// callback returning OK -- can stamp it without moving anything.
173    EntitiesReady = 5,
174    /// The first `spin_once` was entered, which is where issue 0900's
175    /// headroom advisory would have printed had a sink existed.
176    ///
177    /// Because [`Stage::EntitiesReady`] has no producer, this is also what
178    /// "registration finished" reads as: reaching 6 means the application
179    /// stopped registering and started spinning.
180    FirstSpin = 6,
181}

191    /// The record. One per image, in `.bss`.
192    ///
193    /// `#[repr(C)]` with every field an `AtomicU32` -- which is
194    /// `repr(transparent)` over `u32` -- so the layout is exactly the sequence
195    /// of 32-bit words the reader script decodes, on every target this crate
196    /// builds for.
197    ///
198    /// Atomics rather than a `static mut` because the record is written from
199    /// registration paths that an application may reach from more than one
200    /// thread. `Relaxed` throughout: there is no ordering relationship to
201    /// establish with any other data, and the reader is a debugger that has
202    /// already halted the core.
203    #[repr(C)]
204    pub struct BootReport {
205        magic: AtomicU32,
206        version: AtomicU32,
207        struct_size: AtomicU32,
208        stage: AtomicU32,
209
210        // Compile-time, so that comparing these against what the build system
211        // BELIEVES it delivered turns a "derived value did not arrive" defect
212        // into a measurement. `scripts/check-knob-delivery.py` asserts the same
213        // identity one step earlier, at `build.ninja`; this is the same
214        // assertion made by the silicon.
215        arena_size: AtomicU32,
216        max_cbs: AtomicU32,
217        max_sc: AtomicU32,
218        max_nodes: AtomicU32,
219        default_rx_buf_size: AtomicU32,
220
221        // Runtime.
222        arena_capacity: AtomicU32,
223        arena_used: AtomicU32,
224        alloc_count: AtomicU32,
225        last_alloc_size: AtomicU32,
226        /// Bytes the allocation that FAILED asked for, or 0 if none has.
227        failed_alloc_size: AtomicU32,
228        /// Bytes by which that allocation overran the arena. This is the
229        /// number to add to `NROS_EXECUTOR_ARENA_SIZE`, which is why it is
230        /// stored rather than left to be recomputed from the two above.
231        failed_alloc_shortfall: AtomicU32,
232        /// `nros_cpp_init`'s return code, as the two's-complement bits of an
233        /// `i32`, or 0 (`NROS_CPP_RET_OK`) if it has not returned yet.
234        ///
235        /// The stage says HOW FAR init got; this says why it stopped. Without
236        /// it, every early return in that function -- a null argument, a
237        /// non-UTF-8 name, a bad domain id, a backend that refused to open --
238        /// is one indistinguishable "did not reach the executor".
239        cpp_init_ret: AtomicU32,
240        /// The LAST `NodeError` that crossed the C++ FFI, as a stable code.
241        ///
242        /// Stable here means assigned by `nros-cpp`'s exhaustive mapper, not
243        /// taken from the Rust discriminant -- a discriminant shifts whenever a
244        /// variant is inserted, and a dump decoded against the wrong numbering
245        /// names the wrong error, confidently.
246        err_class: AtomicU32,
247        /// For [`Self::err_class`] == Transport, which `TransportError`.
248        ///
249        /// The C++ ABI collapses eight distinct transport variants onto the
250        /// single code -100, which is what made an island subscription failure
251        /// undiagnosable: the return code said "transport" and nothing said
252        /// which. This is the field that separates them.
253        err_transport: AtomicU32,
254        /// Address of the `Backend(&'static str)` message, or 0.
255        ///
256        /// The pointer rather than the text: the message is a static string
257        /// already in the image, so copying it would cost the record a buffer
258        /// to hold something the reader can fetch. Paired with
259        /// [`Self::err_backend_len`].
260        err_backend_ptr: AtomicU32,
261        /// Length of the message at [`Self::err_backend_ptr`], or 0.
262        err_backend_len: AtomicU32,
263
264        // The platform heap -- the arena `nros_platform_alloc` hands out of,
265        // which on Zephyr is CONFIG_NROS_ZEPHYR_HEAP_SIZE. Appended by
266        // phase-460 W5; see "Adding a field" above for why the two words are
267        // at the END.
268        /// High-water mark of the platform heap, in bytes, or 0 if this image
269        /// never sampled it.
270        ///
271        /// `peak`, not `used`: `used` read at an arbitrary instant reports
272        /// whatever happened to be live at the moment of the read, which is
273        /// not what a size knob bounds. Issue 1424 -- the reporter behind this
274        /// (`nros_zephyr_heap_peak`) has existed and been compiled into every
275        /// Zephyr image since phase-412, and nothing read it off a board with
276        /// no console, so the one knob it could have sized
277        /// (`CONFIG_NROS_ZEPHYR_HEAP_SIZE`) was set by hand and annotated as a
278        /// guess.
279        ///
280        /// MONOTONIC here as well as at the source, so a later sample of a
281        /// heap that has since freed memory cannot lower the figure the knob
282        /// is sized from.
283        heap_peak_bytes: AtomicU32,
284        /// Bytes the platform heap was given, or 0 if never sampled.
285        ///
286        /// The pair is what makes the peak actionable: a peak alone says how
287        /// much was needed and says nothing about how close to the edge the
288        /// image ran. `capacity - peak` is the headroom the gate refuses on.
289        heap_capacity_bytes: AtomicU32,
290
291        /// Samples received, ACKed and then THROWN AWAY because the
292        /// subscription's buffer was smaller than the sample. Appended by
293        /// phase-460 W7; see "Adding a field" above for why it is at the END.
294        ///
295        /// Issue 1425. A drop is a QoS fact, not a fault -- nothing halts --
296        /// which is exactly why it needs a record: the image keeps running,
297        /// every outside probe reports the subscription matched and healthy
298        /// (the transport completed and ACKed the sample before the buffer was
299        /// consulted), and the application simply never sees the message. On a
300        /// board with a console the drop announces itself in a log line. On the
301        /// island's target there is no console, so before this field the only
302        /// evidence of a dropped 13.4 KiB trajectory was that nothing arrived.
303        ///
304        /// A TOTAL, not a per-entity figure, for the reason
305        /// `executor::arena`'s `DROPPED_TAKES` is one: a per-entity counter is
306        /// a field on the arena's entry structs, which are sized by knob at
307        /// build time, so it would move every image's executor footprint to buy
308        /// a diagnostic. Non-zero here means "read the log lines, or raise
309        /// `NROS_SUBSCRIPTION_BUFFER_SIZE` and see whether it goes to zero".
310        samples_dropped_too_small: AtomicU32,
311    }

342        /// Size of the record in bytes, as the reader must expect it.
343        ///
344        /// ASKED OF THE COMPILER, not counted by hand. A hand-written word
345        /// count is a second statement of the field list that drifts the first
346        /// time a field is added, and it would drift SILENTLY -- the reader
347        /// would accept the record and decode one field short. This whole
348        /// campaign is about not hand-picking numbers the build already knows.
349        #[must_use]
350        pub const fn struct_size() -> u32 {
351            // The record is all `AtomicU32`, so this is exact on every target
352            // and there is no padding for the cast to lose.
353            core::mem::size_of::<Self>() as u32
354        }

422    /// The record, findable by symbol name from a debugger.
423    ///
424    /// `#[used]` because nothing in a minimal image necessarily reads it, and a
425    /// static whose only writes are through this module's functions is exactly
426    /// what a linker is entitled to discard.
427    #[unsafe(no_mangle)]
428    #[used]
429    pub static NROS_BOOT_REPORT: BootReport = BootReport::new();

431    /// Stamp the header and the compile-time knobs.
432    ///
433    /// Idempotent, and safe to call from more than one place -- an image with
434    /// two executors should not have to decide which one owns the record.
435    /// MAGIC is stored LAST so a reader that finds it knows the rest is there.
436    pub fn init() {
437        let r = &NROS_BOOT_REPORT;
438        r.version.store(VERSION, Ordering::Relaxed);
439        r.struct_size
440            .store(BootReport::struct_size(), Ordering::Relaxed);
441        r.arena_size
442            .store(saturate(crate::config::ARENA_SIZE), Ordering::Relaxed);
443        r.max_cbs
444            .store(saturate(crate::config::MAX_CBS), Ordering::Relaxed);
445        r.max_sc
446            .store(saturate(crate::config::MAX_SC), Ordering::Relaxed);
447        r.max_nodes
448            .store(saturate(crate::config::MAX_NODES), Ordering::Relaxed);
449        r.default_rx_buf_size.store(
450            saturate(crate::config::DEFAULT_RX_BUF_SIZE),
451            Ordering::Relaxed,
452        );
453        r.magic.store(MAGIC, Ordering::Relaxed);
454        checkpoint(Stage::ReportReady);
455    }

457    /// Record that boot reached `stage`.
458    ///
459    /// MONOTONIC: a lower stage never overwrites a higher one, so a late call
460    /// on a re-entered path cannot make the record claim less progress than was
461    /// actually made. That matters because the field's whole purpose is to be
462    /// believed about a boot that did not finish.
463    pub fn checkpoint(stage: Stage) {
464        let want = stage as u32;
465        let r = &NROS_BOOT_REPORT;
466        let mut cur = r.stage.load(Ordering::Relaxed);
467        while want > cur {
468            match r
469                .stage
470                .compare_exchange_weak(cur, want, Ordering::Relaxed, Ordering::Relaxed)
471            {
472                Ok(_) => return,
473                Err(actual) => cur = actual,
474            }
475        }
476    }

478    /// Record the arena slice an `Executor` actually bound.
479    ///
480    /// Not the same number as `ARENA_SIZE`, and the difference is a finding
481    /// rather than noise: the arena's placement is the caller's choice
482    /// (issue 0900), so an image can compile one size and hand the executor
483    /// another. Both are in the record so a dump can say which happened.
484    pub fn note_arena_capacity(capacity: usize) {
485        NROS_BOOT_REPORT
486            .arena_capacity
487            .store(saturate(capacity), Ordering::Relaxed);
488    }

490    /// Record a successful arena allocation.
491    ///
492    /// Also stamps [`Stage::RegisteringEntities`]: see that variant for why the
493    /// stamp belongs to the record's writers rather than to a register seam.
494    pub fn note_alloc(size: usize, used_after: usize) {
495        let r = &NROS_BOOT_REPORT;
496        r.alloc_count.fetch_add(1, Ordering::Relaxed);
497        r.last_alloc_size.store(saturate(size), Ordering::Relaxed);
498        r.arena_used.store(saturate(used_after), Ordering::Relaxed);
499        checkpoint(Stage::RegisteringEntities);
500    }
501
502    /// Record the arena allocation that did not fit.
503    ///
504    /// FIRST writer wins, on the same reasoning as [`checkpoint`]: the first
505    /// failure is the one that explains the boot, and any later one is a
506    /// consequence of it.
507    /// Also stamps [`Stage::RegisteringEntities`], and UNCONDITIONALLY -- outside
508    /// the first-writer branch. A second failure adds nothing to the numbers but
509    /// it is still evidence that registration was in flight, and a stage that
510    /// depended on winning a race would be exactly the sort of number this
511    /// record must never print.
512    pub fn note_alloc_failed(size: usize, shortfall: usize) {
513        let r = &NROS_BOOT_REPORT;
514        checkpoint(Stage::RegisteringEntities);
515        if r.failed_alloc_size
516            .compare_exchange(0, saturate(size), Ordering::Relaxed, Ordering::Relaxed)
517            .is_ok()
518        {
519            r.failed_alloc_shortfall
520                .store(saturate(shortfall), Ordering::Relaxed);
521        }
522    }

524    /// Record the PLATFORM HEAP allocation that did not fit.
525    ///
526    /// phase-460 W7 / issue 1425. `nros-platform-zephyr`'s `platform.c` calls
527    /// this through the C entry below from `nros_platform_alloc`'s exhaustion
528    /// path, BEFORE the printk and before the fatal hook, so a board halted by
529    /// an exhausted heap names the request that killed it in the same two words
530    /// an exhausted executor ARENA does.
531    ///
532    /// ONE PAIR OF FIELDS FOR TWO ARENAS. They cannot both fail in a boot that
533    /// continues -- the first one to fail stops it -- and first-writer-wins is
534    /// what makes the record name the cause rather than a consequence.
535    ///
536    /// NO STAGE STAMP, which is the whole reason this is not
537    /// [`note_alloc_failed`]. That one stamps [`Stage::RegisteringEntities`]
538    /// because the executor arena is claimed by entity registration and by
539    /// nothing else. The platform heap is claimed by anything at any time --
540    /// zenoh-pico's read task, a reply buffer, a reconnect -- so stamping would
541    /// make the record claim registration was in flight on a boot that had long
542    /// since reached its first spin. `checkpoint` is monotonic, so it would be
543    /// an unfalsifiable claim: the stage would read 4 and nothing later could
544    /// correct it.
545    pub fn note_heap_alloc_failed(size: usize) {
546        let r = &NROS_BOOT_REPORT;
547        if r.failed_alloc_size
548            .compare_exchange(0, saturate(size), Ordering::Relaxed, Ordering::Relaxed)
549            .is_ok()
550        {
551            // The shortfall is the REQUEST, not `size - free`: the heap is
552            // fragmented by the time it refuses, so the bytes that would have
553            // made this request fit are not the deficit against the largest
554            // free block. A number that looks like a precise deficit and is not
555            // would be sized from.
556            r.failed_alloc_shortfall
557                .store(saturate(size), Ordering::Relaxed);
558        }
559    }
560
561    /// [`note_heap_alloc_failed`] across the C ABI, for a platform in C.
562    #[unsafe(no_mangle)]
563    pub extern "C" fn nros_boot_report_note_heap_alloc_failed(size: usize) {
564        note_heap_alloc_failed(size);
565    }
566
567    /// Record `nros_cpp_init`'s return code.
568    ///
569    /// LAST writer wins, unlike [`note_alloc_failed`]: an image may call
570    /// `nros_cpp_init` more than once (per component, per tier), and the
571    /// interesting one is the call that did not get through, which is the one
572    /// that leaves the stage where it stopped.
573    pub fn note_cpp_init_ret(ret: i32) {
574        NROS_BOOT_REPORT
575            .cpp_init_ret
576            .store(ret as u32, Ordering::Relaxed);
577    }
578
579    /// Record an error that crossed the FFI.
580    ///
581    /// Takes CODES, not the error type: `nros-node` must not need to know how
582    /// `nros-cpp` numbers its variants, and the numbering has to be assigned by
583    /// an exhaustive match that a new variant breaks at compile time. The caller
584    /// owns both.
585    ///
586    /// LAST writer wins. An image that fails one entity and carries on would
587    /// otherwise keep the first stumble instead of the one that stopped it, and
588    /// the failure that stops setup is the one that explains the boot.
589    pub fn note_error(class: u32, transport: u32, backend_ptr: u32, backend_len: u32) {
590        let r = &NROS_BOOT_REPORT;
591        r.err_class.store(class, Ordering::Relaxed);
592        r.err_transport.store(transport, Ordering::Relaxed);
593        r.err_backend_ptr.store(backend_ptr, Ordering::Relaxed);
594        r.err_backend_len.store(backend_len, Ordering::Relaxed);
595    }
596
597    /// Record the platform heap's high-water mark and its capacity.
598    ///
599    /// `peak` keeps the MAXIMUM, `capacity` the last value: the peak is the
600    /// figure a knob is sized from and must not be lowered by a later sample,
601    /// while the capacity is a constant of the image that a second sample can
602    /// only restate.
603    ///
604    /// Called from the port that owns the heap, because only that port can
605    /// read it: `nros_zephyr_heap_peak()` is deliberately NOT in
606    /// `nros/platform.h` (the cross-port ABI would need a stub per port for a
607    /// figure one port can produce), so the core cannot pull the number and
608    /// the platform pushes it instead. See
609    /// [`nros_boot_report_note_heap`] for the C entry point.
610    pub fn note_heap(peak: usize, capacity: usize) {
611        let r = &NROS_BOOT_REPORT;
612        r.heap_peak_bytes
613            .fetch_max(saturate(peak), Ordering::Relaxed);
614        r.heap_capacity_bytes
615            .store(saturate(capacity), Ordering::Relaxed);
616    }
617
618    /// [`note_heap`] across the C ABI, for a platform written in C.
619    ///
620    /// `nros-platform-zephyr`'s `platform.c` calls this from
621    /// `nros_platform_alloc` and `nros_platform_realloc` -- the only two
622    /// places the heap's peak can change -- so the record is current at every
623    /// stage transition without the stage transitions having to sample
624    /// anything, and it is written on the exhaustion path BEFORE the printk
625    /// that path emits, which is the case where the board is about to stop.
626    ///
627    /// Takes `usize`, not `u32`: the saturation rule belongs on this side
628    /// (see [`saturate`]), and a C caster would truncate instead.
629    #[unsafe(no_mangle)]
630    pub extern "C" fn nros_boot_report_note_heap(peak: usize, capacity: usize) {
631        note_heap(peak, capacity);
632    }
633
634    /// Count one sample dropped because the subscription buffer was too small.
635    ///
636    /// Returns the total AFTER this drop, so a caller can throttle its log on
637    /// the same number the record carries rather than keeping a second one.
638    ///
639    /// SATURATES at `u32::MAX` instead of wrapping. A wrapping counter can
640    /// read 0 on an image that dropped four billion samples, and 0 is the one
641    /// answer here that means "nothing is wrong" -- the same rule
642    /// [`saturate`] applies to every size in the record, applied to a tally.
643    /// `fetch_update` rather than `fetch_add` is what makes that true under
644    /// the concurrent callers `take_serialized` has.
645    pub fn note_sample_dropped_too_small() -> u32 {
646        let r = &NROS_BOOT_REPORT;
647        let prev = r
648            .samples_dropped_too_small
649            .fetch_update(Ordering::Relaxed, Ordering::Relaxed, |n| {
650                Some(n.saturating_add(1))
651            })
652            .unwrap_or(u32::MAX);
653        prev.saturating_add(1)
654    }
655
656    /// [`note_sample_dropped_too_small`] across the C ABI.
657    ///
658    /// Present for the same reason [`nros_boot_report_note_heap`] is: the
659    /// counting side may be a C translation unit, and a symbol that exists in
660    /// only one of the two builds is a link error naming nothing in
661    /// particular.
662    #[unsafe(no_mangle)]
663    pub extern "C" fn nros_boot_report_note_sample_dropped_too_small() -> u32 {
664        note_sample_dropped_too_small()
665    }
666
667    /// Preload the drop tally. TEST ONLY.
668    ///
669    /// The record's fields are private and `mod tests` is a sibling of this
670    /// module, not a child, so it cannot reach one. The saturation rule is
671    /// worth a test and `u32::MAX` is not reachable by calling the writer, so
672    /// the seam is this, compiled only under `cfg(test)`.
673    #[cfg(test)]
674    pub fn set_samples_dropped_too_small_for_test(v: u32) {
675        NROS_BOOT_REPORT
676            .samples_dropped_too_small
677            .store(v, Ordering::Relaxed);
678    }
679
680    /// `usize` -> `u32`, saturating.
681    ///
682    /// Every field is a `u32` so the record's layout does not change between a
683    /// 32-bit board and a 64-bit host running the same tests. Saturating rather
684    /// than truncating because a value too large to represent should read as
685    /// "enormous", not as its low half -- a truncated 4 GiB reads as 0, which
686    /// is the one wrong answer that looks like a normal one.
687    fn saturate(v: usize) -> u32 {
688        u32::try_from(v).unwrap_or(u32::MAX)
689    }
690}

764    /// The reader decodes twenty-three u32s positionally, so the record must
