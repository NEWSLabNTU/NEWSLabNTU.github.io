1//! A fixed RAM record the image writes about itself, for targets where no log
2//! sink reaches a human.
3//!
4//! # Why this exists
5//!
6//! phase-412 derived six pool counts and the executor arena for the
7//! mr-canhubk344 island, and then could not tell whether the derived image was
8//! correct. The only available signal was the ROS graph's node count, and one
9//! unchanged configuration produced 4, 0, 0, 4, 4 across five runs. Every other
10//! channel was already disqualified for that board:
11//!
12//! * The console is on `lpuart0`, which is not wired on the MR-CANHUBK344.
13//!   `lpuart2` is the zenoh serial transport and cannot carry a second protocol.
14//! * `nros_log` therefore reaches nothing. Both arena diagnostics (issue 0900)
15//!   go through it, so the two messages written specifically to explain an
16//!   arena failure are invisible on the one board that needed them.
17//! * SEGGER RTT was tried and could not discriminate: a working image and a
18//!   derived image both emitted only the Zephyr banner, and a deliberate
19//!   positive control produced nothing at all.
20//! * Semihosting halts the core until a probe answers and FAULTS with no probe
21//!   attached, so an image carrying it cannot run standalone.
22//!
23//! What all of those share is that they are STREAMS: they need the board to
24//! still be running, and they need somebody attached at the moment the
25//! interesting thing happens. The failure this campaign is trying to see is the
26//! opposite shape. An under-sized arena halts DURING entity creation, before
27//! the first spin, so issue 0900's advisory never prints -- the failure cannot
28//! report itself through any stream.
29//!
30//! So this is not a stream. It is a fixed-size record in RAM that the image
31//! keeps up to date as it boots, read out AFTERWARDS by halting the core and
32//! dumping memory. It survives the halt because it does not depend on anything
33//! still running, and a PARTIAL record is the useful case rather than a lost
34//! one: the last stage reached and the allocation that did not fit are exactly
35//! what names the knob to change.
36//!
37//! # Reading it
38//!
39//! The record is a `#[no_mangle]` static, so it has a symbol in the ELF and a
40//! debugger can find it without the address being wired in anywhere:
41//!
42//! ```text
43//! pyocd commander -t s32k344 -c "halt" -c "savemem <addr> <len> report.bin"
44//! python3 scripts/read-boot-report.py <elf> report.bin
45//! ```
46//!
47//! [`MAGIC`](crate::boot_report::MAGIC) distinguishes a written record from uninitialised RAM, and
48//! `BootReport::struct_size` lets a reader refuse a layout it does not know
49//! rather than decode it wrongly.
50//!
51//! # Cost, and why it is opt-in
52//!
53//! Enabled by setting `NROS_BOOT_REPORT=1` at build time (Zephyr:
54//! `CONFIG_NROS_BOOT_REPORT=y`), which makes `nros-node`'s build script emit
55//! `cfg(nros_boot_report)`. With the cfg absent every function here is an empty
56//! `#[inline(always)]` body and the static does not exist, so an image that
57//! does not opt in is byte-identical to one built before this module -- the
58//! same rule issue 0900's arena knob and phase-403's `rx_buffer_from_type()`
59//! both keep.
60//!
61//! Enabled, it costs `BootReport::struct_size` bytes of `.bss` -- 104, the
62//! same on every target because every field is a `u32` -- and a handful of
63//! relaxed atomic stores on paths that run once per entity at registration.
64//!
65//! The 104 is not a detail: it is the LENGTH an operator types into `savemem`,
66//! and this sentence said 60 for as long as the record had fifteen fields. A
67//! short dump decodes -- `read-boot-report.py` needs `26 * 4` bytes and a
68//! 100-byte one is refused, but a reader who trusts the prose over the tool
69//! spends the refusal looking at the wrong thing. Ask the tool instead:
70//! `read-boot-report.py --addr-only <elf>` prints the address AND the length,
71//! from the ELF's own symbol size.
72//!
73//! # Adding a field (phase-460 W5, for W7 and after)
74//!
75//! The record is meant to grow, and the order it grows in is the whole
76//! contract: `read-boot-report.py` decodes POSITIONALLY. So a new field is
77//! APPENDED -- after the last field, never inserted between two -- and the
78//! four edits are one commit:
79//!
80//! 1. the field on `BootReport`, its zero in `BootReport::new`, the same
81//!    name in the same position on `Snapshot`, and its load in `snapshot`;
82//! 2. [`VERSION`](crate::boot_report::VERSION) bumped, so an older decoder REFUSES the record instead of
83//!    reading the new word as one it knows;
84//! 3. `FIELDS` in `scripts/read-boot-report.py`, same name, same position, and
85//!    `KNOWN_VERSION` to match;
86//! 4. the field count in `the_record_is_twenty_six_packed_u32s` below.
87//!
88//! `check-boot-report-layout` fails on 1 without 3, and the Rust test fails if
89//! the compiler laid the record out with padding. Appending is what keeps a
90//! dump taken from an older image decodable by eye: every word before the new
91//! one is still where it was, and the version says which words exist.

95/// `"NRSR"` -- nano-ros self report. Written LAST, so a reader that finds it

99/// Layout version. Bump on any field change; a reader refuses what it does not
100/// know rather than decoding a record it would misread.
101///
102/// 4 since phase-460 W5 appended `heap_peak_bytes` and `heap_capacity_bytes`;
103/// 5 since phase-460 W7 appended `samples_dropped_too_small`;
104/// 6 since issue 1549 appended `rmw_local_queryable`;
105/// 7 since issue 1550 appended `domain_id`;
106/// 8 since issue 1573 appended `failed_alloc_arena`.
107pub const VERSION: u32 = 8;

109/// Which allocator refused the allocation `BootReport::failed_alloc_size`
110/// names.
111///
112/// Issue 1573. The executor ARENA and the PLATFORM HEAP share the one
113/// `failed_alloc_size` / `failed_alloc_shortfall` pair -- first writer wins,
114/// and the first failure stops the boot -- but the two are sized by different
115/// knobs, and a pair that cannot say which arena it describes names the wrong
116/// one. Measured on the Autoware Safety Island under QEMU: zenoh-pico's
117/// `_z_slist_new` asked the platform heap for 236 bytes, the console printed
118/// `HEAP EXHAUSTED`, and the decoded record told the reader to raise
119/// `NROS_EXECUTOR_ARENA_SIZE` for an arena that was 28% used.
120///
121/// Append only; `the_alloc_arena_codes_match_the_record` states the numbers
122/// `read-boot-report.py`'s `ALLOC_ARENA` restates.
123#[derive(Clone, Copy, PartialEq, Eq, Debug)]
124#[repr(u32)]
125pub enum AllocArena {
126    /// No allocation has failed, or the image predates the field.
127    None = 0,
128    /// The executor arena (`NROS_EXECUTOR_ARENA_SIZE`), claimed by entity
129    /// registration.
130    ExecutorArena = 1,
131    /// The platform heap `nros_platform_alloc` hands out of
132    /// (`CONFIG_NROS_ZEPHYR_HEAP_SIZE` on Zephyr).
133    PlatformHeap = 2,
134}

136/// Which rung of the knob ladder decided a knob the record carries.
137///
138/// Issue 1549. A knob's VALUE says what the image was built with; this says
139/// who decided it, which is the half a reader needs before changing it: a
140/// derived value is fixed by editing the declaration it came from, a stated
141/// one by editing the statement. Spelled once, here, and packed into the
142/// upper bits of each knob word that carries one (see the field docs).
143/// `zephyr/cmake/nros_cargo_build.cmake` records the rung as
144/// `NROS_KNOB_SOURCE_<knob>`; `build.rs` maps its spelling onto this.
145#[derive(Clone, Copy, PartialEq, Eq, Debug)]
146#[repr(u32)]
147pub enum KnobSource {
148    /// No resolver road reached this build (a cargo-only lane), so the record
149    /// cannot say. The value next to it is NOT evidence of anything.
150    NotRecorded = 0,
151    /// Nobody stated it and nothing derived it: the consumer's own default.
152    Default = 1,
153    /// Derived from the image's entity inventory.
154    Derived = 2,
155    /// Stated in Kconfig (a `.conf` fragment, a snippet, or its default).
156    Kconfig = 3,
157    /// Stated in the environment, which outranks everything: the build's for a
158    /// compile-time knob, `ROS_DOMAIN_ID` at run time for a hosted image's
159    /// domain.
160    Environment = 4,
161    /// Stated by a Zephyr snippet's Kconfig fragment (`-S <snippet>`), issue
162    /// 1550: a transport snippet is where an image that varies its link tends
163    /// to state its domain, and where one that forgets to is invisible.
164    Snippet = 5,
165    /// Stated on the cmake / west command line (`-DCONFIG_<symbol>=<n>`).
166    CommandLine = 6,
167}
168
169impl KnobSource {
170    /// The variant `build.rs` encoded as `code`, or [`KnobSource::NotRecorded`]
171    /// for a number this crate does not know.
172    #[must_use]
173    pub const fn from_code(code: u32) -> Self {
174        match code {
175            1 => Self::Default,
176            2 => Self::Derived,
177            3 => Self::Kconfig,
178            4 => Self::Environment,
179            5 => Self::Snippet,
180            6 => Self::CommandLine,
181            _ => Self::NotRecorded,
182        }
183    }
184}

186/// How far boot got. Monotonic, and the single most useful field: an arena
187/// failure halts during entity creation, so the stage that was NOT reached
188/// names the phase to look at.
189///
190/// Numbers follow EXECUTION ORDER, because `checkpoint` keeps the maximum
191/// and a stage that runs earlier but numbers higher would make the record
192/// claim less progress than was made. Inserting one therefore renumbers the
193/// rest and bumps [`VERSION`]; the decoder refuses a version it does not
194/// know rather than misreading it, which is what makes that safe.
195#[derive(Clone, Copy, PartialEq, Eq, Debug)]
196#[repr(u32)]
197pub enum Stage {
198    /// RAM as the loader left it. Never stored; a reader seeing this with a
199    /// valid magic has found a record that was reset but not re-entered.
200    Untouched = 0,
201    /// The record itself is initialised and the compile-time knobs are in it.
202    ///
203    /// Stamped at the TOP of the C++ entry point, before any argument is
204    /// validated, so "the image never entered nano-ros" is distinguishable
205    /// from "it entered and died before the executor". Version 1 stamped this
206    /// inside the executor constructor instead, which made those two cases
207    /// identical -- both read magic 0 -- and cost a disassembly walk to tell
208    /// apart on the first board run.
209    ReportReady = 1,
210    /// The boot config resolved: node name, namespace, locator and domain id
211    /// all parsed. Everything between here and [`Stage::ReportReady`] is
212    /// argument validation, and `BootReport::cpp_init_ret` says which check
213    /// rejected it.
214    BootConfigResolved = 2,
215    /// An `Executor` has bound its arena, so `BootReport::arena_capacity`
216    /// is the real slice length rather than the compiled constant.
217    ExecutorReady = 3,
218    /// Entity registration has begun: something claimed arena bytes.
219    ///
220    /// Stamped by [`note_alloc`] and [`note_alloc_failed`], which is to say by
221    /// the arena allocator itself rather than by any register seam. The arena
222    /// is claimed by entity registration and by nothing else, so an allocation
223    /// ATTEMPT is the event, and putting the stamp on the record's own writers
224    /// means every present and future `arena_alloc*` call site is covered by
225    /// construction -- there is no second place to remember.
226    ///
227    /// Issue 1036: nothing emitted this for three phases, so an image that ran
228    /// out of arena left the stage reading [`Stage::ExecutorReady`] -- the same
229    /// value as an image that opened its executor and died before registering
230    /// anything at all. The record named the allocation and could not say
231    /// WHERE, which is half of a diagnostic on a board where it is the only
232    /// channel.
233    ///
234    /// The interval between this and [`Stage::FirstSpin`] is where an
235    /// under-sized arena halts, so `stage == 4` with a non-zero
236    /// `BootReport::failed_alloc_shortfall` is the signature of the failure
237    /// this whole record exists to catch.
238    RegisteringEntities = 4,
239    /// RESERVED. Nothing emits this, and nothing can from inside the core.
240    ///
241    /// "Every entity the image declares was registered successfully" has no
242    /// observable moment here: an application may register lazily, which is the
243    /// same reason issue 0900's headroom advisory fires at the first spin
244    /// rather than at an end of registration that does not exist. A stamp at
245    /// the top of `spin_once` would be a claim the core cannot support.
246    ///
247    /// Kept rather than removed, and DOCUMENTED rather than left looking
248    /// unfinished (issue 1036): removing it renumbers [`Stage::FirstSpin`] and
249    /// bumps [`VERSION`] to retire a value no image can produce, and the next
250    /// reader would file the renumbering as the bug. An entry shape that DOES
251    /// know when its register pass ended -- a generated component `setup`
252    /// callback returning OK -- can stamp it without moving anything.
253    EntitiesReady = 5,
254    /// The first `spin_once` was entered, which is where issue 0900's
255    /// headroom advisory would have printed had a sink existed.
256    ///
257    /// Because [`Stage::EntitiesReady`] has no producer, this is also what
258    /// "registration finished" reads as: reaching 6 means the application
259    /// stopped registering and started spinning.
260    FirstSpin = 6,
261}

271    /// The record. One per image, in `.bss`.
272    ///
273    /// `#[repr(C)]` with every field an `AtomicU32` -- which is
274    /// `repr(transparent)` over `u32` -- so the layout is exactly the sequence
275    /// of 32-bit words the reader script decodes, on every target this crate
276    /// builds for.
277    ///
278    /// Atomics rather than a `static mut` because the record is written from
279    /// registration paths that an application may reach from more than one
280    /// thread. `Relaxed` throughout: there is no ordering relationship to
281    /// establish with any other data, and the reader is a debugger that has
282    /// already halted the core.
283    #[repr(C)]
284    pub struct BootReport {
285        magic: AtomicU32,
286        version: AtomicU32,
287        struct_size: AtomicU32,
288        stage: AtomicU32,
289
290        // Compile-time, so that comparing these against what the build system
291        // BELIEVES it delivered turns a "derived value did not arrive" defect
292        // into a measurement. `scripts/check-knob-delivery.py` asserts the same
293        // identity one step earlier, at `build.ninja`; this is the same
294        // assertion made by the silicon.
295        arena_size: AtomicU32,
296        max_cbs: AtomicU32,
297        max_sc: AtomicU32,
298        max_nodes: AtomicU32,
299        default_rx_buf_size: AtomicU32,
300
301        // Runtime.
302        arena_capacity: AtomicU32,
303        arena_used: AtomicU32,
304        alloc_count: AtomicU32,
305        last_alloc_size: AtomicU32,
306        /// Bytes the allocation that FAILED asked for, or 0 if none has.
307        failed_alloc_size: AtomicU32,
308        /// Bytes by which that allocation overran the arena. This is the
309        /// number to add to `NROS_EXECUTOR_ARENA_SIZE`, which is why it is
310        /// stored rather than left to be recomputed from the two above.
311        ///
312        /// For a PLATFORM HEAP failure it is the request itself (see
313        /// [`note_heap_alloc_failed`]), and [`Self::failed_alloc_arena`] is
314        /// what says which of the two this pair describes.
315        failed_alloc_shortfall: AtomicU32,
316        /// `nros_cpp_init`'s return code, as the two's-complement bits of an
317        /// `i32`, or 0 (`NROS_CPP_RET_OK`) if it has not returned yet.
318        ///
319        /// The stage says HOW FAR init got; this says why it stopped. Without
320        /// it, every early return in that function -- a null argument, a
321        /// non-UTF-8 name, a bad domain id, a backend that refused to open --
322        /// is one indistinguishable "did not reach the executor".
323        cpp_init_ret: AtomicU32,
324        /// The LAST `NodeError` that crossed the C++ FFI, as a stable code.
325        ///
326        /// Stable here means assigned by `nros-cpp`'s exhaustive mapper, not
327        /// taken from the Rust discriminant -- a discriminant shifts whenever a
328        /// variant is inserted, and a dump decoded against the wrong numbering
329        /// names the wrong error, confidently.
330        err_class: AtomicU32,
331        /// For [`Self::err_class`] == Transport, which `TransportError`.
332        ///
333        /// The C++ ABI collapses eight distinct transport variants onto the
334        /// single code -100, which is what made an island subscription failure
335        /// undiagnosable: the return code said "transport" and nothing said
336        /// which. This is the field that separates them.
337        err_transport: AtomicU32,
338        /// Address of the `Backend(&'static str)` message, or 0.
339        ///
340        /// The pointer rather than the text: the message is a static string
341        /// already in the image, so copying it would cost the record a buffer
342        /// to hold something the reader can fetch. Paired with
343        /// [`Self::err_backend_len`].
344        err_backend_ptr: AtomicU32,
345        /// Length of the message at [`Self::err_backend_ptr`], or 0.
346        err_backend_len: AtomicU32,
347
348        // The platform heap -- the arena `nros_platform_alloc` hands out of,
349        // which on Zephyr is CONFIG_NROS_ZEPHYR_HEAP_SIZE. Appended by
350        // phase-460 W5; see "Adding a field" above for why the two words are
351        // at the END.
352        /// High-water mark of the platform heap, in bytes, or 0 if this image
353        /// never sampled it.
354        ///
355        /// `peak`, not `used`: `used` read at an arbitrary instant reports
356        /// whatever happened to be live at the moment of the read, which is
357        /// not what a size knob bounds. Issue 1424 -- the reporter behind this
358        /// (`nros_zephyr_heap_peak`) has existed and been compiled into every
359        /// Zephyr image since phase-412, and nothing read it off a board with
360        /// no console, so the one knob it could have sized
361        /// (`CONFIG_NROS_ZEPHYR_HEAP_SIZE`) was set by hand and annotated as a
362        /// guess.
363        ///
364        /// MONOTONIC here as well as at the source, so a later sample of a
365        /// heap that has since freed memory cannot lower the figure the knob
366        /// is sized from.
367        heap_peak_bytes: AtomicU32,
368        /// Bytes the platform heap was given, or 0 if never sampled.
369        ///
370        /// The pair is what makes the peak actionable: a peak alone says how
371        /// much was needed and says nothing about how close to the edge the
372        /// image ran. `capacity - peak` is the headroom the gate refuses on.
373        heap_capacity_bytes: AtomicU32,
374
375        /// Samples received, ACKed and then THROWN AWAY because the
376        /// subscription's buffer was smaller than the sample. Appended by
377        /// phase-460 W7; see "Adding a field" above for why it is at the END.
378        ///
379        /// Issue 1425. A drop is a QoS fact, not a fault -- nothing halts --
380        /// which is exactly why it needs a record: the image keeps running,
381        /// every outside probe reports the subscription matched and healthy
382        /// (the transport completed and ACKed the sample before the buffer was
383        /// consulted), and the application simply never sees the message. On a
384        /// board with a console the drop announces itself in a log line. On the
385        /// island's target there is no console, so before this field the only
386        /// evidence of a dropped 13.4 KiB trajectory was that nothing arrived.
387        ///
388        /// A TOTAL, not a per-entity figure, for the reason
389        /// `executor::arena`'s `DROPPED_TAKES` is one: a per-entity counter is
390        /// a field on the arena's entry structs, which are sized by knob at
391        /// build time, so it would move every image's executor footprint to buy
392        /// a diagnostic. Non-zero here means "read the log lines, or raise
393        /// `NROS_SUBSCRIPTION_BUFFER_SIZE` and see whether it goes to zero".
394        samples_dropped_too_small: AtomicU32,
395
396        /// `Z_FEATURE_LOCAL_QUERYABLE` as this image was compiled, and who
397        /// decided it: bits 0..7 the value (0 or 1), bits 8..15 the
398        /// [`super::KnobSource`]. Appended by issue 1549.
399        ///
400        /// A service client and a service server in one image meet only
401        /// through zenoh-pico's same-session query path, so this is the word
402        /// to read when a call to the image's OWN server never returns. A
403        /// zero with source `Derived` is a finding about the declaration (it
404        /// holds no client or no server); a zero with source `Default` means
405        /// the inventory could not answer.
406        rmw_local_queryable: AtomicU32,
407
408        /// The ROS domain the session was opened on, and who stated it: bits
409        /// 0..7 the id (`DOMAIN_ID_MAX` is 232), bits 8..15 the
410        /// [`super::KnobSource`]. Appended by issue 1550.
411        ///
412        /// Stamped by the boot-config resolver from the value it RESOLVED, not
413        /// from the compiled constant, so a hosted image's `ROS_DOMAIN_ID`
414        /// shows here as `Environment`. The source of a baked domain is the
415        /// Kconfig fragment the configure found stating it: a board `.conf`,
416        /// a snippet, the command line, or none (the Kconfig default, 0). A
417        /// peer on another domain never sees this image and nothing at run
418        /// time says why, so this is the word to read first when the graph is
419        /// empty.
420        domain_id: AtomicU32,
421
422        /// Which allocator refused [`Self::failed_alloc_size`], as an
423        /// [`AllocArena`] code, or 0 if none has. Appended by issue 1573.
424        ///
425        /// Written in the same first-writer branch as the pair it qualifies,
426        /// so the three words always describe ONE failure.
427        failed_alloc_arena: AtomicU32,
428    }

519    /// [`snapshot`] of any record -- the image's, or a test's own, so a test

521    /// writes the one static.

554    /// The record, findable by symbol name from a debugger.
555    ///
556    /// `#[used]` because nothing in a minimal image necessarily reads it, and a
557    /// static whose only writes are through this module's functions is exactly
558    /// what a linker is entitled to discard.
559    #[unsafe(no_mangle)]
560    #[used]
561    pub static NROS_BOOT_REPORT: BootReport = BootReport::new();

563    /// Stamp the header and the compile-time knobs.
564    ///
565    /// Idempotent, and safe to call from more than one place -- an image with
566    /// two executors should not have to decide which one owns the record.
567    /// MAGIC is stored LAST so a reader that finds it knows the rest is there.
568    pub fn init() {
569        let r = &NROS_BOOT_REPORT;
570        r.version.store(VERSION, Ordering::Relaxed);
571        r.struct_size
572            .store(BootReport::struct_size(), Ordering::Relaxed);
573        r.arena_size
574            .store(saturate(crate::config::ARENA_SIZE), Ordering::Relaxed);
575        r.max_cbs
576            .store(saturate(crate::config::MAX_CBS), Ordering::Relaxed);
577        r.max_sc
578            .store(saturate(crate::config::MAX_SC), Ordering::Relaxed);
579        r.max_nodes
580            .store(saturate(crate::config::MAX_NODES), Ordering::Relaxed);
581        r.default_rx_buf_size.store(
582            saturate(crate::config::DEFAULT_RX_BUF_SIZE),
583            Ordering::Relaxed,
584        );
585        r.rmw_local_queryable
586            .store(crate::config::BOOT_RMW_LOCAL_QUERYABLE, Ordering::Relaxed);
587        r.magic.store(MAGIC, Ordering::Relaxed);
588        checkpoint(Stage::ReportReady);
589    }

591    /// Record that boot reached `stage`.
592    ///
593    /// MONOTONIC: a lower stage never overwrites a higher one, so a late call
594    /// on a re-entered path cannot make the record claim less progress than was
595    /// actually made. That matters because the field's whole purpose is to be
596    /// believed about a boot that did not finish.
597    pub fn checkpoint(stage: Stage) {
598        let want = stage as u32;
599        let r = &NROS_BOOT_REPORT;
600        let mut cur = r.stage.load(Ordering::Relaxed);
601        while want > cur {
602            match r
603                .stage
604                .compare_exchange_weak(cur, want, Ordering::Relaxed, Ordering::Relaxed)
605            {
606                Ok(_) => return,
607                Err(actual) => cur = actual,
608            }
609        }
610    }

612    /// Record the arena slice an `Executor` actually bound.
613    ///
614    /// Not the same number as `ARENA_SIZE`, and the difference is a finding
615    /// rather than noise: the arena's placement is the caller's choice
616    /// (issue 0900), so an image can compile one size and hand the executor
617    /// another. Both are in the record so a dump can say which happened.
618    pub fn note_arena_capacity(capacity: usize) {
619        NROS_BOOT_REPORT
620            .arena_capacity
621            .store(saturate(capacity), Ordering::Relaxed);
622    }

624    /// Record a successful arena allocation.
625    ///
626    /// Also stamps [`Stage::RegisteringEntities`]: see that variant for why the
627    /// stamp belongs to the record's writers rather than to a register seam.
628    pub fn note_alloc(size: usize, used_after: usize) {
629        let r = &NROS_BOOT_REPORT;
630        r.alloc_count.fetch_add(1, Ordering::Relaxed);
631        r.last_alloc_size.store(saturate(size), Ordering::Relaxed);
632        r.arena_used.store(saturate(used_after), Ordering::Relaxed);
633        checkpoint(Stage::RegisteringEntities);
634    }
635
636    /// Record the arena allocation that did not fit.
637    ///
638    /// FIRST writer wins, on the same reasoning as [`checkpoint`]: the first
639    /// failure is the one that explains the boot, and any later one is a
640    /// consequence of it.
641    /// Also stamps [`Stage::RegisteringEntities`], and UNCONDITIONALLY -- outside
642    /// the first-writer branch. A second failure adds nothing to the numbers but
643    /// it is still evidence that registration was in flight, and a stage that
644    /// depended on winning a race would be exactly the sort of number this
645    /// record must never print.
646    pub fn note_alloc_failed(size: usize, shortfall: usize) {
647        checkpoint(Stage::RegisteringEntities);
648        record_alloc_failure(
649            &NROS_BOOT_REPORT,
650            size,
651            shortfall,
652            AllocArena::ExecutorArena,
653        );
654    }
655
656    /// The first-writer-wins write both failure paths share, on any record.
657    ///
658    /// ONE function so the arena code cannot be written by one path and
659    /// forgotten by the other (issue 1573 was the heap path writing the pair
660    /// the arena path writes, with nothing saying whose it was).
661    pub(crate) fn record_alloc_failure(
662        r: &BootReport,
663        size: usize,
664        shortfall: usize,
665        arena: AllocArena,
666    ) {
667        if r.failed_alloc_size
668            .compare_exchange(0, saturate(size), Ordering::Relaxed, Ordering::Relaxed)
669            .is_ok()
670        {
671            r.failed_alloc_shortfall
672                .store(saturate(shortfall), Ordering::Relaxed);
673            r.failed_alloc_arena.store(arena as u32, Ordering::Relaxed);
674        }
675    }
676
677    /// Record the PLATFORM HEAP allocation that did not fit.
678    ///
679    /// phase-460 W7 / issue 1425. `nros-platform-zephyr`'s `platform.c` calls
680    /// this through the C entry below from `nros_platform_alloc`'s exhaustion
681    /// path, BEFORE the printk and before the fatal hook, so a board halted by
682    /// an exhausted heap names the request that killed it in the same two words
683    /// an exhausted executor ARENA does.
684    ///
685    /// ONE PAIR OF FIELDS FOR TWO ARENAS. They cannot both fail in a boot that
686    /// continues -- the first one to fail stops it -- and first-writer-wins is
687    /// what makes the record name the cause rather than a consequence.
688    ///
689    /// NO STAGE STAMP, which is the whole reason this is not
690    /// [`note_alloc_failed`]. That one stamps [`Stage::RegisteringEntities`]
691    /// because the executor arena is claimed by entity registration and by
692    /// nothing else. The platform heap is claimed by anything at any time --
693    /// zenoh-pico's read task, a reply buffer, a reconnect -- so stamping would
694    /// make the record claim registration was in flight on a boot that had long
695    /// since reached its first spin. `checkpoint` is monotonic, so it would be
696    /// an unfalsifiable claim: the stage would read 4 and nothing later could
697    /// correct it.
698    pub fn note_heap_alloc_failed(size: usize) {
699        // The shortfall is the REQUEST, not `size - free`: the heap is
700        // fragmented by the time it refuses, so the bytes that would have made
701        // this request fit are not the deficit against the largest free block.
702        // A number that looks like a precise deficit and is not would be sized
703        // from.
704        record_alloc_failure(&NROS_BOOT_REPORT, size, size, AllocArena::PlatformHeap);
705    }
706
707    /// [`note_heap_alloc_failed`] across the C ABI, for a platform in C.
708    #[unsafe(no_mangle)]
709    pub extern "C" fn nros_boot_report_note_heap_alloc_failed(size: usize) {
710        note_heap_alloc_failed(size);
711    }

713    /// Record the domain the boot-config resolver settled on, and its rung.
714    ///
715    /// Issue 1550. LAST writer wins, like [`note_cpp_init_ret`]: an image may
716    /// resolve once per component or tier, and every resolution in one image
717    /// reads the same inputs.
718    pub fn note_domain(domain_id: u32, source: super::KnobSource) {
719        NROS_BOOT_REPORT.domain_id.store(
720            (domain_id & 0xFF) | ((source as u32) << 8),
721            Ordering::Relaxed,
722        );
723    }

725    /// Record `nros_cpp_init`'s return code.
726    ///
727    /// LAST writer wins, unlike [`note_alloc_failed`]: an image may call
728    /// `nros_cpp_init` more than once (per component, per tier), and the
729    /// interesting one is the call that did not get through, which is the one

732        NROS_BOOT_REPORT
733            .cpp_init_ret
734            .store(ret as u32, Ordering::Relaxed);
735    }

737    /// Record an error that crossed the FFI.
738    ///
739    /// Takes CODES, not the error type: `nros-node` must not need to know how
740    /// `nros-cpp` numbers its variants, and the numbering has to be assigned by
741    /// an exhaustive match that a new variant breaks at compile time. The caller
742    /// owns both.
743    ///
744    /// LAST writer wins. An image that fails one entity and carries on would
745    /// otherwise keep the first stumble instead of the one that stopped it, and
746    /// the failure that stops setup is the one that explains the boot.
747    pub fn note_error(class: u32, transport: u32, backend_ptr: u32, backend_len: u32) {
748        let r = &NROS_BOOT_REPORT;
749        r.err_class.store(class, Ordering::Relaxed);
750        r.err_transport.store(transport, Ordering::Relaxed);
751        r.err_backend_ptr.store(backend_ptr, Ordering::Relaxed);
752        r.err_backend_len.store(backend_len, Ordering::Relaxed);
753    }

755    /// Record the platform heap's high-water mark and its capacity.
756    ///
757    /// `peak` keeps the MAXIMUM, `capacity` the last value: the peak is the
758    /// figure a knob is sized from and must not be lowered by a later sample,
759    /// while the capacity is a constant of the image that a second sample can
760    /// only restate.
761    ///
762    /// Called from the port that owns the heap, because only that port can
763    /// read it: `nros_zephyr_heap_peak()` is deliberately NOT in
764    /// `nros/platform.h` (the cross-port ABI would need a stub per port for a
765    /// figure one port can produce), so the core cannot pull the number and
766    /// the platform pushes it instead. See
767    /// [`nros_boot_report_note_heap`] for the C entry point.
768    pub fn note_heap(peak: usize, capacity: usize) {
769        let r = &NROS_BOOT_REPORT;
770        r.heap_peak_bytes
771            .fetch_max(saturate(peak), Ordering::Relaxed);
772        r.heap_capacity_bytes
773            .store(saturate(capacity), Ordering::Relaxed);
774    }

776    /// [`note_heap`] across the C ABI, for a platform written in C.
777    ///
778    /// `nros-platform-zephyr`'s `platform.c` calls this from
779    /// `nros_platform_alloc` and `nros_platform_realloc` -- the only two
780    /// places the heap's peak can change -- so the record is current at every
781    /// stage transition without the stage transitions having to sample
782    /// anything, and it is written on the exhaustion path BEFORE the printk
783    /// that path emits, which is the case where the board is about to stop.
784    ///
785    /// Takes `usize`, not `u32`: the saturation rule belongs on this side
786    /// (see [`saturate`]), and a C caster would truncate instead.
787    #[unsafe(no_mangle)]
788    pub extern "C" fn nros_boot_report_note_heap(peak: usize, capacity: usize) {
789        note_heap(peak, capacity);
790    }

792    /// Count one sample dropped because the subscription buffer was too small.
793    ///
794    /// Returns the total AFTER this drop, so a caller can throttle its log on
795    /// the same number the record carries rather than keeping a second one.
796    ///
797    /// SATURATES at `u32::MAX` instead of wrapping. A wrapping counter can
798    /// read 0 on an image that dropped four billion samples, and 0 is the one
799    /// answer here that means "nothing is wrong" -- the same rule
800    /// [`saturate`] applies to every size in the record, applied to a tally.
801    /// `fetch_update` rather than `fetch_add` is what makes that true under
802    /// the concurrent callers `take_serialized` has.
803    pub fn note_sample_dropped_too_small() -> u32 {
804        let r = &NROS_BOOT_REPORT;
805        let prev = r
806            .samples_dropped_too_small
807            .fetch_update(Ordering::Relaxed, Ordering::Relaxed, |n| {
808                Some(n.saturating_add(1))
809            })
810            .unwrap_or(u32::MAX);
811        prev.saturating_add(1)
812    }
813
814    /// [`note_sample_dropped_too_small`] across the C ABI.
815    ///
816    /// Present for the same reason [`nros_boot_report_note_heap`] is: the
817    /// counting side may be a C translation unit, and a symbol that exists in
818    /// only one of the two builds is a link error naming nothing in
819    /// particular.
820    #[unsafe(no_mangle)]
821    pub extern "C" fn nros_boot_report_note_sample_dropped_too_small() -> u32 {
822        note_sample_dropped_too_small()
823    }

825    /// Preload the drop tally. TEST ONLY.
826    ///
827    /// The record's fields are private and `mod tests` is a sibling of this
828    /// module, not a child, so it cannot reach one. The saturation rule is
829    /// worth a test and `u32::MAX` is not reachable by calling the writer, so
830    /// the seam is this, compiled only under `cfg(test)`.
831    #[cfg(test)]
832    pub fn set_samples_dropped_too_small_for_test(v: u32) {
833        NROS_BOOT_REPORT
834            .samples_dropped_too_small
835            .store(v, Ordering::Relaxed);
836    }

838    /// `usize` -> `u32`, saturating.
839    ///
840    /// Every field is a `u32` so the record's layout does not change between a
841    /// 32-bit board and a 64-bit host running the same tests. Saturating rather
842    /// than truncating because a value too large to represent should read as
843    /// "enormous", not as its low half -- a truncated 4 GiB reads as 0, which
844    /// is the one wrong answer that looks like a normal one.
845    fn saturate(v: usize) -> u32 {
846        u32::try_from(v).unwrap_or(u32::MAX)
847    }
