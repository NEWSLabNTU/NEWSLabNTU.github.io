1//! phase-454 W10 — the DECLARED QoS history depth, and what Rust does with it.
2//!
3//! # What this is
4//!
5//! The QoS history DEPTH of a subscription multiplies the executor arena:
6//! `sizeof(entry) + (depth + 1) * bound + (depth + 1) * 8`. A build that sizes
7//! from a declared depth and an image that registers a different one are an
8//! image sized for one number and running another — so the two have to be held
9//! to one. C++ holds them with a `static_assert` inside `NROS_SUBSCRIBE`, and C
10//! with a `_Static_assert` inside `NROS_ASSERT_DECLARED_DEPTH`.
11//!
12//! # Why Rust's half is at REGISTRATION and not at compile time
13//!
14//! Both C surfaces get a compile-time answer because a preprocessor macro sees
15//! the call site's TOPIC as a token. Rust has neither of the two things that
16//! would make the same answer possible:
17//!
18//!   * **No macro seam at the subscribe site.** `nros::main!` emits the boot
19//!     scaffold and knows nothing about subscriptions; there is no
20//!     `nros::subscribe!`. Every call site is an ordinary method call.
21//!   * **The topic is a runtime `&str`**, not a const generic. A `const`
22//!     assertion would need it in the type system.
23//!
24//! And the descriptor road differs too: a RUST component is registered as an
25//! empty cmake INTERFACE library (`NanoRosNodeRegister.cmake`), compiled by the
26//! workspace runtime crate rather than by that target, so there is no C
27//! preprocessor in the lane and no include path to put a header on. That is why
28//! `_nros_declared_qos_arm()` returns early for `RUST` — the header mechanism
29//! is not available to it, not merely unimplemented.
30//!
31//! # TWO facts arrive, on two roads
32//!
33//! The declared depths reach `nros-node/build.rs` from whichever carrier the
34//! road has, and it writes both into [`crate::config::DECLARED_QOS_ROWS`]:
35//!
36//!   * the **cmake road** (native C/C++, Zephyr west, NuttX) sets
37//!     `NROS_ENTITY_DECLARED_DEPTHS` (`type|topic=depth`), written by the entity
38//!     inventory from the resolved SystemModel;
39//!   * the **single-package cargo leaf road** — the one phase-454 W12 taught to
40//!     read a `system.contract.yaml` — sets no such variable and names a SIZING
41//!     DESCRIPTOR instead, whose `[[endpoint]]` rows carry the same fact
42//!     (RFC-0100 D4). W10 shipped reading only the first, so on exactly the road
43//!     that had a contract this table was `None` and nothing could be compared.
44//!
45//! # And two things are done with them, because the surfaces differ
46//!
47//!   * [`check`](crate::declared_qos::check) REFUSES a disagreement, with
48//!     [`NodeError::DeclaredDepthMismatch`] — the registration fails, the
49//!     subscription never exists, and the entry's `?` carries it out. Reached
50//!     from the C and C++ FFI seams, which took the declared depth at their own
51//!     call site already.
52//!   * [`honour`](crate::declared_qos::honour) is what a RUST registration calls: it TAKES a declared depth
53//!     shallower than the ask (the C++ three-argument `NROS_SUBSCRIBE`'s answer,
54//!     delivered one layer down because Rust has no call-site seam) and refuses
55//!     a declaration DEEPER than the ask. Its doc comment has the whole rule and
56//!     why the asymmetry is real.
57//!
58//! # ABSENCE IS NOT ZERO
59//!
60//! A `(type, topic)` with no row is "nobody declared this endpoint". Nothing is
61//! checked for it, nothing is taken, and nothing is defaulted. An image with no
62//! contract sidecar has `DECLARED_QOS_ROWS == None` and behaves exactly as it
63//! did before — measured, not asserted: on `examples/native/rust/listener` with
64//! the sidecar removed, `.bss + .data` and every attributed symbol are
65//! identical to `origin/main`'s, and the image carries no `declared_qos` symbol
66//! at all.

71/// Every declared endpoint this image's contract states a depth for, or `None`
72/// when it declares none. `(type name, topic, depth)`; both the ROS and the
73/// DDS-mangled spelling of a type appear, because which one a generated message
74/// class carries is a property of the codegen that produced it.
75pub use crate::config::DECLARED_QOS_ROWS;

77/// Do two topic spellings name the same endpoint?
78///
79/// One leading `/` is ignored on each side: a contract states `/chatter` and a
80/// call site may write either `"/chatter"` or the relative `"chatter"` (
81/// `examples/workspaces/launch/src/listener_pkg` writes the second). Nothing
82/// deeper is normalised — a namespace is a different endpoint, and guessing at
83/// one here would make the check match rows nobody meant.
84fn topic_eq(a: &str, b: &str) -> bool {
85    let a = a.strip_prefix('/').unwrap_or(a);
86    let b = b.strip_prefix('/').unwrap_or(b);
87    a == b
88}

90/// The declared depth for `(type_name, topic)` in `rows`, or `None`.
91///
92/// Split out from [`declared_depth`] so the lookup is testable against a table
93/// this build did not generate: in-tree, `DECLARED_QOS_ROWS` is `None` (no
94/// contract reaches a unit-test build), so a test that could only call the
95/// public form would assert nothing while passing.
96fn depth_in(rows: &[(&str, &str, u32)], type_name: &str, topic: &str) -> Option<u32> {
97    rows.iter()
98        .find(|(t, tp, _)| *t == type_name && topic_eq(tp, topic))
99        .map(|(_, _, d)| *d)
100}

102/// The declared depth for `(type_name, topic)`, or `None` when nobody declared
103/// that endpoint.
104///
105/// Linear over a handful of rows, on a path that runs once per subscription at
106/// registration. `None` when this image declares nothing at all.
107pub fn declared_depth(type_name: &str, topic: &str) -> Option<u32> {
108    depth_in(DECLARED_QOS_ROWS?, type_name, topic)
109}

111/// Refuse a subscription whose QoS depth disagrees with what the contract
112/// declared for its topic.
113///
114/// `Ok(())` when they agree AND when nothing was declared — an image that has
115/// not opted in is not an image in error. On a disagreement the TOPIC and BOTH
116/// numbers go to the log first (a `NodeError` is a unit variant and can carry
117/// none of the three), then the registration is refused.
118///
119/// Reached from the **C and C++ FFI registration seams**, which have already
120/// taken the declared depth at their own call site (`NROS_SUBSCRIBE`'s
121/// three-argument form → `qos_from_declared_depth`; C's `_Static_assert`), so a
122/// disagreement arriving here is a real one. The Rust seams call [`honour`]
123/// instead — see its doc comment for why the two surfaces differ.
124///
125/// # Keep the message inside ONE log line
126///
127/// `nros_log`'s formatting buffer is 256 bytes by default (`buffer-size-256`)
128/// and OVERFLOW TRUNCATES with a single `…`. This message used to run past 450
129/// characters, so on a real image the half a reader needs — which file to edit —
130/// was the half that got cut, and the diagnostic ended mid-sentence. The
131/// numbers and the topic come first for the same reason: a long type name may
132/// still push the tail off, and the tail is the least load-bearing part.
133pub fn check(type_name: &str, topic: &str, depth: u32) -> Result<(), NodeError> {
134    match declared_depth(type_name, topic) {
135        Some(declared) if declared != depth => {
136            nros_log::log_error!(
137                nros_log::get_logger("nros_node"),
138                "declared depth: `{}` registers KEEP_LAST({}) but this image's contract \
139                 declares {}, and the arena was sized from {}. Fix the contract row or the \
140                 QoS at the call site (type `{}`).",
141                topic,
142                depth,
143                declared,
144                declared,
145                type_name
146            );
147            Err(NodeError::DeclaredDepthMismatch)
148        }
149        _ => Ok(()),
150    }
151}

153/// The QoS a Rust subscription actually registers with, once the contract has
154/// had its say — phase-454 W13, the Rust half of W10.
155///
156/// # Why Rust TAKES the declared depth where C and C++ ASSERT it
157///
158/// C++ settles this at the call site, by arity: `NROS_SUBSCRIBE(Msg, m, topic)`
159/// states no QoS, so `qos_from_declared_depth` BUILDS one from the declaration
160/// ("nothing to assert — there is only ever one number"), and the four-argument
161/// form, where the call site did state one, `static_assert`s that the two agree.
162/// C does the same with `NROS_ASSERT_DECLARED_DEPTH`.
163///
164/// Rust has neither half of that seam: there is no `nros::subscribe!`, and the
165/// topic is a runtime `&str`, so nothing at the call site can be told apart
166/// from anything else at compile time — and by the time a QoS reaches a
167/// registration, "the caller wrote this" and "a constructor defaulted it" are
168/// the same `QoSProfile`. `Node::create_subscription` hands
169/// `QoSProfile::default()` — `rmw_qos_profile_default`, KEEP_LAST(10) — to the
170/// same `_with_qos` entry point a caller with an opinion reaches, and the
171/// declarative road folds both into one `EntityMetadata::qos` field long before
172/// this point.
173///
174/// So the distinction C++ makes is not available here, and the two candidate
175/// rules that remain each fail on their own:
176///
177/// * **Check only.** Every `QoSProfile::default()` call site in the tree would
178///   be refused the moment its endpoint is declared at anything but 10 — which
179///   is the entire point of declaring one. A declaration would become a way to
180///   stop an image booting.
181/// * **Take, always.** A caller who narrowed a queue on purpose
182///   (`create_subscription_viewable` requires KEEP_LAST(1); a control loop that
183///   wants the newest sample and no backlog) would be silently widened by a
184///   contract that over-declared.
185///
186/// # The rule, and why the asymmetry is real
187///
188/// **The contract states what the BUILD RESERVED.** W12 made that literal: the
189/// executor arena, the zenoh receive ring and both payload pools on a declared
190/// image are all sized from the declared depth, so the declaration is not a
191/// preference — it is the size of the storage that exists.
192///
193/// * `asked > declared` — the registration wants more slots than were bought.
194///   It cannot have them, and nothing is gained by refusing: this is every
195///   unstated call site in the tree (`QoSProfile::default()` asks 10; every
196///   in-tree contract declares less). **TAKEN**, and reported.
197/// * `asked < declared` — the registration fits, so nothing is at risk of
198///   overrunning; but the image paid for a queue deeper than anything wants,
199///   and taking would WIDEN a depth somebody narrowed. Two statements about one
200///   fact disagreeing, with no default that explains either (RFC-0100 D8).
201///   **REFUSED**, naming both.
202/// * equal, or nothing declared — returned unchanged. An image with no contract
203///   is byte-identical to every build before this wave.
204///
205/// # And it says so
206///
207/// A take is REPORTED, once per endpoint that diverges — the C++ surface's
208/// number is visible in the source at the call site and Rust's is not, so a
209/// registration that quietly stopped being what `lib.rs` reads would be the lie
210/// this whole model exists to remove. The severity is the DIRECTION, the same
211/// rule `nros-rmw-zenoh`'s `shim/qos.rs` states for its own grants: taking a
212/// SHALLOWER depth can drop a sample under a burst, so it is `WARN`; a deeper
213/// one costs a peer nothing and is `INFO`.
214///
215/// Called instead of [`check`] at every Rust subscription registration. The C
216/// and C++ FFI seams keep [`check`] — they have already taken the declared
217/// depth at their own call site, so a disagreement reaching THEM is a real
218/// refusal and not a default nobody wrote.
219/// # `#[inline]` is load-bearing, and it was MEASURED
220///
221/// An image with no contract must be byte-identical to every build before this
222/// wave, and "the table is empty so the work folds away" is a claim about the
223/// optimiser, not a fact. It was FALSE as first written: with the table
224/// threaded in as an `unwrap_or(&[])` argument, `honour` stayed out of line —
225/// a real `T nros_node::declared_qos::honour` symbol, +144 bytes of text and
226/// +8 of data on the no-contract listener against `origin/main`, because a
227/// 40-byte `QoSProfile` moving in and out by value is past LLVM's inlining
228/// budget. Matching the `Option` HERE, behind `#[inline]`, is what lets a
229/// `None` table fold the call to `Ok(qos)` at every one of the fourteen
230/// registration sites and leave `honour_in` unreferenced. Verified by
231/// rebuilding both trees and comparing the linked binary byte for byte.
232#[inline]
233pub fn honour(type_name: &str, topic: &str, qos: QoSProfile) -> Result<QoSProfile, NodeError> {
234    let Some(rows) = DECLARED_QOS_ROWS else {
235        return Ok(qos);
236    };
237    honour_in(rows, type_name, topic, qos)
238}

240/// [`honour`] against a table this build did not generate.
241///
242/// Split out for the reason [`depth_in`] is: in-tree `DECLARED_QOS_ROWS` is
243/// `None`, so a test that could only call the public form would exercise the
244/// "nothing declared" arm and assert nothing about the take or the refusal
245/// while reading as coverage of both.
246fn honour_in(
247    rows: &[(&str, &str, u32)],
248    type_name: &str,
249    topic: &str,
250    qos: QoSProfile,
251) -> Result<QoSProfile, NodeError> {
252    let Some(declared) = depth_in(rows, type_name, topic) else {
253        return Ok(qos);
254    };
255    if declared == qos.depth {
256        return Ok(qos);
257    }
258    if declared > qos.depth {
259        nros_log::log_error!(
260            nros_log::get_logger("nros_node"),
261            "declared depth: `{}` registers KEEP_LAST({}) and the contract declares {} -- \
262             DEEPER. Taking it would widen a queue the code narrowed; fix the contract row \
263             or the call site (type `{}`).",
264            topic,
265            qos.depth,
266            declared,
267            type_name
268        );
269        return Err(NodeError::DeclaredDepthMismatch);
270    }
271    let mut granted = qos;
272    granted.depth = declared;
273    nros_log::log_warn!(
274        nros_log::get_logger("nros_node"),
275        "declared depth: taking KEEP_LAST({}) on `{}`; the call site asked {} and the build \
276         reserved {}. Raise the contract row to keep more (type `{}`).",
277        declared,
278        topic,
279        qos.depth,
280        declared,
281        type_name
282    );
283    Ok(granted)
284}
