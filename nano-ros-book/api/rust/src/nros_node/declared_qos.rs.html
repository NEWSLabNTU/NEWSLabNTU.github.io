1//! phase-454 W10 — the DECLARED QoS history depth, and what Rust does with it.
2//!
3//! # What this is
4//!
5//! The QoS history DEPTH of a subscription multiplies the executor arena:
6//! `sizeof(entry) + (depth + 1) * bound + (depth + 1) * 8`. A build that sizes
7//! from a declared depth and an image that registers a different one are an
8//! image sized for one number and running another — so the two have to be held
9//! to one. C++ holds them with a `static_assert` inside `NROS_SUBSCRIBE`, and C
10//! with a `_Static_assert` inside `NROS_ASSERT_DECLARED_DEPTH`.
11//!
12//! # Why Rust's half is at REGISTRATION and not at compile time
13//!
14//! Both C surfaces get a compile-time answer because a preprocessor macro sees
15//! the call site's TOPIC as a token. Rust has neither of the two things that
16//! would make the same answer possible:
17//!
18//!   * **No macro seam at the subscribe site.** `nros::main!` emits the boot
19//!     scaffold and knows nothing about subscriptions; there is no
20//!     `nros::subscribe!`. Every call site is an ordinary method call.
21//!   * **The topic is a runtime `&str`**, not a const generic. A `const`
22//!     assertion would need it in the type system.
23//!
24//! And the descriptor road differs too: a RUST component is registered as an
25//! empty cmake INTERFACE library (`NanoRosNodeRegister.cmake`), compiled by the
26//! workspace runtime crate rather than by that target, so there is no C
27//! preprocessor in the lane and no include path to put a header on. That is why
28//! `_nros_declared_qos_arm()` returns early for `RUST` — the header mechanism
29//! is not available to it, not merely unimplemented.
30//!
31//! # TWO facts arrive, on two roads
32//!
33//! The declared depths reach `nros-node/build.rs` from whichever carrier the
34//! road has, and it writes both into [`crate::config::DECLARED_QOS_ROWS`]:
35//!
36//!   * the **cmake road** (native C/C++, Zephyr west, NuttX) sets
37//!     `NROS_ENTITY_DECLARED_DEPTHS` (`type|topic=depth`), written by the entity
38//!     inventory from the resolved SystemModel;
39//!   * the **single-package cargo leaf road** — the one phase-454 W12 taught to
40//!     read a `system.contract.yaml` — sets no such variable and names a SIZING
41//!     DESCRIPTOR instead, whose `[[endpoint]]` rows carry the same fact
42//!     (RFC-0100 D4). W10 shipped reading only the first, so on exactly the road
43//!     that had a contract this table was `None` and nothing could be compared.
44//!
45//! # And two things are done with them, because the surfaces differ
46//!
47//!   * [`check`](crate::declared_qos::check) REFUSES a disagreement, with
48//!     [`NodeError::DeclaredDepthMismatch`] — the registration fails, the
49//!     subscription never exists, and the entry's `?` carries it out. Reached
50//!     from the C and C++ FFI seams, which took the declared depth at their own
51//!     call site already.
52//!   * [`honour`](crate::declared_qos::honour) is what a RUST registration calls: it TAKES a declared depth
53//!     shallower than the ask (the C++ three-argument `NROS_SUBSCRIBE`'s answer,
54//!     delivered one layer down because Rust has no call-site seam) and refuses
55//!     a declaration DEEPER than the ask. Its doc comment has the whole rule and
56//!     why the asymmetry is real.
57//!
58//! # ABSENCE IS NOT ZERO
59//!
60//! A `(type, topic)` with no row is "nobody declared this endpoint". Nothing is
61//! checked for it, nothing is taken, and nothing is defaulted. An image with no
62//! contract sidecar has `DECLARED_QOS_ROWS == None` and behaves exactly as it
63//! did before — measured, not asserted: on `examples/native/rust/listener` with
64//! the sidecar removed, `.bss + .data` and every attributed symbol are
65//! identical to `origin/main`'s, and the image carries no `declared_qos` symbol
66//! at all.
67//!
68//! # issue 1256 -- RELIABILITY and DURABILITY too
69//!
70//! A contract can state three things about a subscription and this module now
71//! reads all three. The two policies are not a sizing fact the way depth is;
72//! they are an INTEROP one -- an incompatible-QoS match never delivers -- and
73//! until this they were declared, delivered to the build and never compared
74//! with the code. They arrive on the sizing DESCRIPTOR only (no env knob is
75//! added for them: re-carrying a fact the descriptor already states is the
76//! 0460/0491 shape), and [`check`](crate::declared_qos::check) / [`honour`](crate::declared_qos::honour) treat them by the same rules as
77//! the depth, with the order of the two values standing in for "deeper".
78

82/// One subscription this image's contract declares something about.
83///
84/// Each column is `None` where nobody stated it -- a row exists when ANY of the
85/// three is stated, so any one of them may be silent. `type_name` appears once
86/// in the ROS spelling and once DDS-mangled, as two rows, because which one a
87/// generated message class carries is a property of the codegen that produced
88/// it.
89#[derive(Debug, Clone, Copy, PartialEq, Eq)]
90pub struct DeclaredEndpoint {
91    pub type_name: &'static str,
92    pub topic: &'static str,
93    /// The declared KEEP_LAST depth.
94    pub depth: Option<u32>,
95    /// `Reliable` / `BestEffort` -- never `SystemDefault`, which says "the
96    /// middleware chooses" and so cannot be disagreed with.
97    pub reliability: Option<QoSReliabilityPolicy>,
98    /// `Volatile` / `TransientLocal`, on the same rule.
99    pub durability: Option<QoSDurabilityPolicy>,
100}
101
102/// Every subscription this image's contract declares something about, or
103/// `None` when it declares nothing.
104pub use crate::config::DECLARED_QOS_ROWS;

106/// Do two topic spellings name the same endpoint?
107///
108/// One leading `/` is ignored on each side: a contract states `/chatter` and a
109/// call site may write either `"/chatter"` or the relative `"chatter"` (
110/// `examples/workspaces/launch/src/listener_pkg` writes the second). Nothing
111/// deeper is normalised — a namespace is a different endpoint, and guessing at
112/// one here would make the check match rows nobody meant.
113fn topic_eq(a: &str, b: &str) -> bool {
114    let a = a.strip_prefix('/').unwrap_or(a);
115    let b = b.strip_prefix('/').unwrap_or(b);
116    a == b
117}

119/// The declared row for `(type_name, topic)` in `rows`, or `None`.
120///
121/// Split out so the lookup is testable against a table this build did not
122/// generate: in-tree, `DECLARED_QOS_ROWS` is `None` (no contract reaches a
123/// unit-test build), so a test that could only call the public form would
124/// assert nothing while passing.
125fn row_in<'r>(
126    rows: &'r [DeclaredEndpoint],
127    type_name: &str,
128    topic: &str,
129) -> Option<&'r DeclaredEndpoint> {
130    rows.iter()
131        .find(|r| r.type_name == type_name && topic_eq(r.topic, topic))
132}
133
134/// The declared depth for `(type_name, topic)` in `rows`, or `None`.
135fn depth_in(rows: &[DeclaredEndpoint], type_name: &str, topic: &str) -> Option<u32> {
136    row_in(rows, type_name, topic).and_then(|r| r.depth)
137}

139/// The declared depth for `(type_name, topic)`, or `None` when nobody declared
140/// that endpoint's depth.
141///
142/// Linear over a handful of rows, on a path that runs once per subscription at
143/// registration. `None` when this image declares nothing at all.
144pub fn declared_depth(type_name: &str, topic: &str) -> Option<u32> {
145    depth_in(DECLARED_QOS_ROWS?, type_name, topic)
146}

158/// The contract's own spelling of a reliability, for a log line.
159fn reliability_spelling(r: QoSReliabilityPolicy) -> &'static str {
160    match r {
161        QoSReliabilityPolicy::Reliable => "reliable",
162        QoSReliabilityPolicy::BestEffort => "best_effort",
163        QoSReliabilityPolicy::SystemDefault => "system_default",
164        QoSReliabilityPolicy::Unknown => "unknown",
165    }
166}

168/// The contract's own spelling of a durability, for a log line.
169fn durability_spelling(d: QoSDurabilityPolicy) -> &'static str {
170    match d {
171        QoSDurabilityPolicy::Volatile => "volatile",
172        QoSDurabilityPolicy::TransientLocal => "transient_local",
173        QoSDurabilityPolicy::SystemDefault => "system_default",
174        QoSDurabilityPolicy::Unknown => "unknown",
175    }

178/// How much a reliability ASKS FOR: the order [`honour`] reads "stronger" in.
179/// `None` is "states no opinion" -- `SystemDefault` hands the choice to the
180/// middleware and `Unknown` is a read-back sentinel nobody requests.
181fn reliability_rank(r: QoSReliabilityPolicy) -> Option<u8> {
182    match r {
183        QoSReliabilityPolicy::BestEffort => Some(0),
184        QoSReliabilityPolicy::Reliable => Some(1),
185        QoSReliabilityPolicy::SystemDefault | QoSReliabilityPolicy::Unknown => None,
186    }
187}
188
189/// How much a durability ASKS FOR. See [`reliability_rank`].
190fn durability_rank(d: QoSDurabilityPolicy) -> Option<u8> {
191    match d {
192        QoSDurabilityPolicy::Volatile => Some(0),
193        QoSDurabilityPolicy::TransientLocal => Some(1),
194        QoSDurabilityPolicy::SystemDefault | QoSDurabilityPolicy::Unknown => None,
195    }
196}

198/// Refuse a subscription whose QoS disagrees with what the contract declared
199/// for its topic -- its depth, and (issue 1256) its reliability and durability.
200///
201/// `Ok(())` when every declared column agrees AND when nothing was declared --
202/// an image that has not opted in is not an image in error. On a disagreement
203/// the TOPIC and BOTH values go to the log first (a `NodeError` is a unit
204/// variant and can carry none of the three), then the registration is
205/// refused: [`NodeError::DeclaredDepthMismatch`] for the depth,
206/// [`NodeError::DeclaredQosMismatch`] for a policy.
207///
208/// Reached from the **C and C++ FFI registration seams**, which have already
209/// taken the declared QoS at their own call site (`NROS_SUBSCRIBE`'s
210/// three-argument form → `qos_from_declared`; C's `_Static_assert`), so a
211/// disagreement arriving here is a real one. The Rust seams call [`honour`]
212/// instead — see its doc comment for why the two surfaces differ.
213///
214/// # Keep the message inside ONE log line
215///
216/// `nros_log`'s formatting buffer is 256 bytes by default (`buffer-size-256`)
217/// and OVERFLOW TRUNCATES with a single `…`. This message used to run past 450
218/// characters, so on a real image the half a reader needs — which file to edit —
219/// was the half that got cut, and the diagnostic ended mid-sentence. The
220/// numbers and the topic come first for the same reason: a long type name may
221/// still push the tail off, and the tail is the least load-bearing part.
222pub fn check(type_name: &str, topic: &str, qos: &QoSProfile) -> Result<(), NodeError> {
223    match DECLARED_QOS_ROWS {
224        Some(rows) => check_in(rows, type_name, topic, qos),
225        None => Ok(()),
226    }
227}
228
229/// [`check`] against a table this build did not generate. See [`row_in`].
230fn check_in(
231    rows: &[DeclaredEndpoint],
232    type_name: &str,
233    topic: &str,
234    qos: &QoSProfile,
235) -> Result<(), NodeError> {
236    let Some(row) = row_in(rows, type_name, topic) else {
237        return Ok(());
238    };
239    if let Some(declared) = row.depth
240        && declared != qos.depth
241    {
242        nros_log::log_error!(
243            nros_log::get_logger("nros_node"),
244            "declared depth: `{}` registers KEEP_LAST({}) but this image's contract \
245             declares {}, and the arena was sized from {}. Fix the contract row or the \
246             QoS at the call site (type `{}`).",
247            topic,
248            qos.depth,
249            declared,
250            declared,
251            type_name
252        );
253        return Err(NodeError::DeclaredDepthMismatch);
254    }
255    if let Some(declared) = row.reliability
256        && declared != qos.reliability
257    {
258        nros_log::log_error!(
259            nros_log::get_logger("nros_node"),
260            "declared QoS: `{}` registers {} but this image's contract declares reliability \
261             {}; an incompatible match never delivers. Fix the contract row or the call site.",
262            topic,
263            reliability_spelling(qos.reliability),
264            reliability_spelling(declared)
265        );
266        return Err(NodeError::DeclaredQosMismatch);
267    }
268    if let Some(declared) = row.durability
269        && declared != qos.durability
270    {
271        nros_log::log_error!(
272            nros_log::get_logger("nros_node"),
273            "declared QoS: `{}` registers {} but this image's contract declares durability \
274             {}; an incompatible match never delivers. Fix the contract row or the call site.",
275            topic,
276            durability_spelling(qos.durability),
277            durability_spelling(declared)
278        );
279        return Err(NodeError::DeclaredQosMismatch);
280    }
281    Ok(())
282}

284/// The QoS a Rust subscription actually registers with, once the contract has
285/// had its say — phase-454 W13, the Rust half of W10, widened to the two
286/// policies by issue 1256.
287///
288/// # Why Rust TAKES the declared value where C and C++ ASSERT it
289///
290/// C++ settles this at the call site, by arity: `NROS_SUBSCRIBE(Msg, m, topic)`
291/// states no QoS, so `qos_from_declared` BUILDS one from the declaration
292/// ("nothing to assert — there is only ever one statement"), and the
293/// four-argument form, where the call site did state one, `static_assert`s that
294/// the two agree. C does the same with `NROS_ASSERT_DECLARED_*`.
295///
296/// Rust has neither half of that seam: there is no `nros::subscribe!`, and the
297/// topic is a runtime `&str`, so nothing at the call site can be told apart
298/// from anything else at compile time — and by the time a QoS reaches a
299/// registration, "the caller wrote this" and "a constructor defaulted it" are
300/// the same `QoSProfile`. `Node::create_subscription` hands
301/// `QoSProfile::default()` — `rmw_qos_profile_default`, KEEP_LAST(10),
302/// RELIABLE, VOLATILE — to the same `_with_qos` entry point a caller with an
303/// opinion reaches, and the declarative road folds both into one
304/// `EntityMetadata::qos` field long before this point.
305///
306/// So the distinction C++ makes is not available here, and the two candidate
307/// rules that remain each fail on their own:
308///
309/// * **Check only.** Every `QoSProfile::default()` call site in the tree would
310///   be refused the moment its endpoint is declared at anything but the
311///   default — which is the entire point of declaring one. A declaration would
312///   become a way to stop an image booting.
313/// * **Take, always.** A caller who narrowed a queue on purpose
314///   (`create_subscription_viewable` requires KEEP_LAST(1)) or chose
315///   `best_effort` for a sensor would be silently widened by a contract that
316///   over-declared.
317///
318/// # The rule, and why the asymmetry is real
319///
320/// **The contract states what the BUILD RESERVED.** W12 made that literal for
321/// the depth: the executor arena, the zenoh receive ring and both payload pools
322/// on a declared image are all sized from the declared depth. The policies are
323/// the same kind of statement: XRCE drops both reliable stream buffers to the
324/// protocol floor when every endpoint declares `best_effort` (RFC-0100 D3), and
325/// a `transient_local` endpoint is what the build counts a late-joiner slot
326/// for. So for each column, ordered by how much it ASKS FOR (deeper; reliable
327/// over best_effort; transient_local over volatile):
328///
329/// * `asked > declared` — the registration wants more than was bought, and
330///   asking for it would ride storage the build did not reserve. **TAKEN**, and
331///   reported. For the two policies it is also the direction RxO tolerates: a
332///   `best_effort` or `volatile` reader still matches a `reliable` or
333///   `transient_local` writer.
334/// * `asked < declared` — taking would WIDEN what the code narrowed, and the
335///   image paid for something nothing wants. Two statements about one fact
336///   disagreeing, with no default that explains either (RFC-0100 D8).
337///   **REFUSED**, naming both.
338/// * equal, or nothing declared — returned unchanged. An image with no contract
339///   is byte-identical to every build before this wave.
340/// * a policy asked as `SystemDefault` — the code stated no opinion, so the
341///   declaration is TAKEN, silently: there is nothing to report a divergence
342///   from.
343///
344/// # And it says so
345///
346/// A take is REPORTED, once per endpoint that diverges — the C++ surface's
347/// value is visible in the source at the call site and Rust's is not, so a
348/// registration that quietly stopped being what `lib.rs` reads would be the lie
349/// this whole model exists to remove. Every take here narrows what the code
350/// asked for (a shallower queue, no retransmission, no late-joiner history),
351/// any of which can drop a sample, so each is `WARN`.
352///
353/// Called instead of [`check`] at every Rust subscription registration. The C
354/// and C++ FFI seams keep [`check`] — they have already taken the declared QoS
355/// at their own call site, so a disagreement reaching THEM is a real refusal
356/// and not a default nobody wrote.
357///
358/// # `#[inline]` is load-bearing, and it was MEASURED
359///
360/// An image with no contract must be byte-identical to every build before this
361/// wave, and "the table is empty so the work folds away" is a claim about the
362/// optimiser, not a fact. It was FALSE as first written: with the table
363/// threaded in as an `unwrap_or(&[])` argument, `honour` stayed out of line —
364/// a real `T nros_node::declared_qos::honour` symbol, +144 bytes of text and
365/// +8 of data on the no-contract listener against `origin/main`, because a
366/// 40-byte `QoSProfile` moving in and out by value is past LLVM's inlining
367/// budget. Matching the `Option` HERE, behind `#[inline]`, is what lets a
368/// `None` table fold the call to `Ok(qos)` at every one of the fourteen
369/// registration sites and leave `honour_in` unreferenced. Verified by
370/// rebuilding both trees and comparing the linked binary byte for byte.
371#[inline]
372pub fn honour(type_name: &str, topic: &str, qos: QoSProfile) -> Result<QoSProfile, NodeError> {
373    let Some(rows) = DECLARED_QOS_ROWS else {
374        return Ok(qos);
375    };
376    honour_in(rows, type_name, topic, qos)
377}

379/// [`honour`] against a table this build did not generate.
380///
381/// Split out for the reason [`row_in`] is: in-tree `DECLARED_QOS_ROWS` is
382/// `None`, so a test that could only call the public form would exercise the
383/// "nothing declared" arm and assert nothing about the take or the refusal
384/// while reading as coverage of both.
385fn honour_in(
386    rows: &[DeclaredEndpoint],
387    type_name: &str,
388    topic: &str,
389    qos: QoSProfile,
390) -> Result<QoSProfile, NodeError> {
391    let Some(row) = row_in(rows, type_name, topic) else {
392        return Ok(qos);
393    };
394    let mut granted = qos;
395    if let Some(declared) = row.depth
396        && declared != qos.depth
397    {
398        if declared > qos.depth {
399            nros_log::log_error!(
400                nros_log::get_logger("nros_node"),
401                "declared depth: `{}` registers KEEP_LAST({}) and the contract declares {} -- \
402                 DEEPER. Taking it would widen a queue the code narrowed; fix the contract row \
403                 or the call site (type `{}`).",
404                topic,
405                qos.depth,
406                declared,
407                type_name
408            );
409            return Err(NodeError::DeclaredDepthMismatch);
410        }
411        granted.depth = declared;
412        nros_log::log_warn!(
413            nros_log::get_logger("nros_node"),
414            "declared depth: taking KEEP_LAST({}) on `{}`; the call site asked {} and the build \
415             reserved {}. Raise the contract row to keep more (type `{}`).",
416            declared,
417            topic,
418            qos.depth,
419            declared,
420            type_name
421        );
422    }
423    if let Some(declared) = row.reliability
424        && declared != qos.reliability
425    {
426        match reliability_rank(qos.reliability) {
427            Some(asked) if asked < reliability_rank(declared).unwrap_or(asked) => {
428                nros_log::log_error!(
429                    nros_log::get_logger("nros_node"),
430                    "declared QoS: `{}` registers {} and the contract declares reliability {} \
431                     -- STRONGER. Taking it would widen what the code narrowed; fix the \
432                     contract row or the call site.",
433                    topic,
434                    reliability_spelling(qos.reliability),
435                    reliability_spelling(declared)
436                );
437                return Err(NodeError::DeclaredQosMismatch);
438            }
439            Some(_) => {
440                nros_log::log_warn!(
441                    nros_log::get_logger("nros_node"),
442                    "declared QoS: taking reliability {} on `{}`; the call site asked {} and the \
443                     contract declares {}. Raise the contract row to keep it.",
444                    reliability_spelling(declared),
445                    topic,
446                    reliability_spelling(qos.reliability),
447                    reliability_spelling(declared)
448                );
449            }
450            // The call site stated no opinion: nothing diverged, so nothing is
451            // reported.
452            None => {}
453        }
454        granted.reliability = declared;
455    }
456    if let Some(declared) = row.durability
457        && declared != qos.durability
458    {
459        match durability_rank(qos.durability) {
460            Some(asked) if asked < durability_rank(declared).unwrap_or(asked) => {
461                nros_log::log_error!(
462                    nros_log::get_logger("nros_node"),
463                    "declared QoS: `{}` registers {} and the contract declares durability {} \
464                     -- STRONGER. Taking it would widen what the code narrowed; fix the \
465                     contract row or the call site.",
466                    topic,
467                    durability_spelling(qos.durability),
468                    durability_spelling(declared)
469                );
470                return Err(NodeError::DeclaredQosMismatch);
471            }
472            Some(_) => {
473                nros_log::log_warn!(
474                    nros_log::get_logger("nros_node"),
475                    "declared QoS: taking durability {} on `{}`; the call site asked {} and the \
476                     contract declares {}. Raise the contract row to keep it.",
477                    durability_spelling(declared),
478                    topic,
479                    durability_spelling(qos.durability),
480                    durability_spelling(declared)
481                );
482            }
483            None => {}
484        }
485        granted.durability = declared;
486    }
487    Ok(granted)
488}
