1//! phase-454 W10 — the DECLARED QoS history depth, and what Rust does with it.
2//!
3//! # What this is
4//!
5//! The QoS history DEPTH of a subscription multiplies the executor arena:
6//! `sizeof(entry) + (depth + 1) * bound + (depth + 1) * 8`. A build that sizes
7//! from a declared depth and an image that registers a different one are an
8//! image sized for one number and running another — so the two have to be held
9//! to one. C++ holds them with a `static_assert` inside `NROS_SUBSCRIBE`, and C
10//! with a `_Static_assert` inside `NROS_ASSERT_DECLARED_DEPTH`.
11//!
12//! # Why Rust's half is at REGISTRATION and not at compile time
13//!
14//! Both C surfaces get a compile-time answer because a preprocessor macro sees
15//! the call site's TOPIC as a token. Rust has neither of the two things that
16//! would make the same answer possible:
17//!
18//!   * **No macro seam at the subscribe site.** `nros::main!` emits the boot
19//!     scaffold and knows nothing about subscriptions; there is no
20//!     `nros::subscribe!`. Every call site is an ordinary method call.
21//!   * **The topic is a runtime `&str`**, not a const generic. A `const`
22//!     assertion would need it in the type system.
23//!
24//! And the descriptor road differs too: a RUST component is registered as an
25//! empty cmake INTERFACE library (`NanoRosNodeRegister.cmake`), compiled by the
26//! workspace runtime crate rather than by that target, so there is no C
27//! preprocessor in the lane and no include path to put a header on. That is why
28//! `_nros_declared_qos_arm()` returns early for `RUST` — the header mechanism
29//! is not available to it, not merely unimplemented.
30//!
31//! # TWO facts arrive, on two roads
32//!
33//! The declared depths reach `nros-node/build.rs` from whichever carrier the
34//! road has, and it writes both into [`crate::config::DECLARED_QOS_ROWS`]:
35//!
36//!   * the **cmake road** (native C/C++, Zephyr west, NuttX) sets
37//!     `NROS_ENTITY_DECLARED_DEPTHS` (`type|topic=depth`), written by the entity
38//!     inventory from the resolved SystemModel;
39//!   * the **single-package cargo leaf road** — the one phase-454 W12 taught to
40//!     read a `system.contract.yaml` — sets no such variable and names a SIZING
41//!     DESCRIPTOR instead, whose `[[endpoint]]` rows carry the same fact
42//!     (RFC-0100 D4). W10 shipped reading only the first, so on exactly the road
43//!     that had a contract this table was `None` and nothing could be compared.
44//!
45//! # And two things are done with them, because the surfaces differ
46//!
47//!   * [`check`](crate::declared_qos::check) REFUSES a disagreement, with
48//!     [`NodeError::DeclaredDepthMismatch`] — the registration fails, the
49//!     subscription never exists, and the entry's `?` carries it out. Reached
50//!     from the C and C++ FFI seams, which took the declared depth at their own
51//!     call site already.
52//!   * [`honour`](crate::declared_qos::honour) is what a RUST registration calls: it TAKES a declared depth
53//!     shallower than the ask (the C++ three-argument `NROS_SUBSCRIBE`'s answer,
54//!     delivered one layer down because Rust has no call-site seam) and refuses
55//!     a declaration DEEPER than the ask. Its doc comment has the whole rule and
56//!     why the asymmetry is real.
57//!
58//! # ABSENCE IS NOT ZERO
59//!
60//! A `(type, topic)` with no row is "nobody declared this endpoint". Nothing is
61//! checked for it, nothing is taken, and nothing is defaulted. An image with no
62//! contract sidecar has `DECLARED_QOS_ROWS == None` and behaves exactly as it
63//! did before — measured, not asserted: on `examples/native/rust/listener` with
64//! the sidecar removed, `.bss + .data` and every attributed symbol are
65//! identical to `origin/main`'s, and the image carries no `declared_qos` symbol
66//! at all.
67//!
68//! # issue 1256 -- RELIABILITY and DURABILITY too
69//!
70//! A contract can state three things about a subscription and this module now
71//! reads all three. The two policies are not a sizing fact the way depth is;
72//! they are an INTEROP one -- an incompatible-QoS match never delivers -- and
73//! until this they were declared, delivered to the build and never compared
74//! with the code. They arrive on the sizing DESCRIPTOR only (no env knob is
75//! added for them: re-carrying a fact the descriptor already states is the
76//! 0460/0491 shape), and [`check`](crate::declared_qos::check) / [`honour`](crate::declared_qos::honour) treat them by the same rules as
77//! the depth, with the order of the two values standing in for "deeper".
78//!
79//! # issue 1608 -- PUBLISHERS too, with the policy direction REVERSED
80//!
81//! A contract can state the same three things about a publisher, and
82//! `transient_local` is the one QoS fact that is publisher-side by nature: it is
83//! what a zenoh image spends a queryable slot on. The descriptor's publisher
84//! rows reach [`DECLARED_PUBLISHER_QOS_ROWS`](crate::declared_qos::DECLARED_PUBLISHER_QOS_ROWS)
85//! (a table of its own: a publisher and a subscription on one `(type, topic)`
86//! are two endpoints), and every publisher registration -- the Rust seams and
87//! the C/C++ FFI seams alike -- goes through
88//! [`honour_publisher`](crate::declared_qos::honour_publisher).
89//!
90//! Its rule is NOT the subscription's copied across. Reliability and durability
91//! are matched request-vs-offered, so the tolerant direction flips: a reader may
92//! ask for less than a writer offers, a writer may offer more than a reader asks.
93//! A publisher asking LESS than its declaration is therefore RAISED to it (the
94//! build reserved it, and every reader that matched the lower offer still
95//! matches); one asking MORE is REFUSED (lowering it could break a match, and
96//! keeping it rides storage the build did not count). The depth rule is shared.
97//! Measured on `examples/native/rust/talker` with a contract declaring
98//! `/chatter` `transient_local`, depth 1: the default publisher registers
99//! transient_local, depth 1, and reports both takes; declaring `best_effort`
100//! instead refuses the registration and the image exits naming the topic.
101

105/// One subscription this image's contract declares something about.
106///
107/// Each column is `None` where nobody stated it -- a row exists when ANY of the
108/// three is stated, so any one of them may be silent. `type_name` appears once
109/// in the ROS spelling and once DDS-mangled, as two rows, because which one a
110/// generated message class carries is a property of the codegen that produced
111/// it.
112#[derive(Debug, Clone, Copy, PartialEq, Eq)]
113pub struct DeclaredEndpoint {
114    pub type_name: &'static str,
115    pub topic: &'static str,
116    /// The declared KEEP_LAST depth.
117    pub depth: Option<u32>,
118    /// `Reliable` / `BestEffort` -- never `SystemDefault`, which says "the
119    /// middleware chooses" and so cannot be disagreed with.
120    pub reliability: Option<QoSReliabilityPolicy>,
121    /// `Volatile` / `TransientLocal`, on the same rule.
122    pub durability: Option<QoSDurabilityPolicy>,
123}

134/// Do two topic spellings name the same endpoint?
135///
136/// One leading `/` is ignored on each side: a contract states `/chatter` and a
137/// call site may write either `"/chatter"` or the relative `"chatter"` (
138/// `examples/workspaces/launch/src/listener_pkg` writes the second). Nothing
139/// deeper is normalised — a namespace is a different endpoint, and guessing at
140/// one here would make the check match rows nobody meant.
141fn topic_eq(a: &str, b: &str) -> bool {
142    let a = a.strip_prefix('/').unwrap_or(a);
143    let b = b.strip_prefix('/').unwrap_or(b);
144    a == b
145}

147/// The declared row for `(type_name, topic)` in `rows`, or `None`.
148///
149/// Split out so the lookup is testable against a table this build did not
150/// generate: in-tree, `DECLARED_QOS_ROWS` is `None` (no contract reaches a
151/// unit-test build), so a test that could only call the public form would
152/// assert nothing while passing.
153fn row_in<'r>(
154    rows: &'r [DeclaredEndpoint],
155    type_name: &str,
156    topic: &str,
157) -> Option<&'r DeclaredEndpoint> {
158    rows.iter()
159        .find(|r| r.type_name == type_name && topic_eq(r.topic, topic))
160}

206/// How much a reliability ASKS FOR: the order [`honour`] reads "stronger" in.
207/// `None` is "states no opinion" -- `SystemDefault` hands the choice to the
208/// middleware and `Unknown` is a read-back sentinel nobody requests.
209fn reliability_rank(r: QoSReliabilityPolicy) -> Option<u8> {
210    match r {
211        QoSReliabilityPolicy::BestEffort => Some(0),
212        QoSReliabilityPolicy::Reliable => Some(1),
213        QoSReliabilityPolicy::SystemDefault | QoSReliabilityPolicy::Unknown => None,
214    }
215}

221        QoSDurabilityPolicy::TransientLocal => Some(1),
222        QoSDurabilityPolicy::SystemDefault | QoSDurabilityPolicy::Unknown => None,

226/// Refuse a subscription whose QoS disagrees with what the contract declared
227/// for its topic -- its depth, and (issue 1256) its reliability and durability.
228///
229/// `Ok(())` when every declared column agrees AND when nothing was declared --
230/// an image that has not opted in is not an image in error. On a disagreement
231/// the TOPIC and BOTH values go to the log first (a `NodeError` is a unit
232/// variant and can carry none of the three), then the registration is
233/// refused: [`NodeError::DeclaredDepthMismatch`] for the depth,
234/// [`NodeError::DeclaredQosMismatch`] for a policy.
235///
236/// Reached from the **C and C++ FFI registration seams**, which have already
237/// taken the declared QoS at their own call site (`NROS_SUBSCRIBE`'s
238/// three-argument form → `qos_from_declared`; C's `_Static_assert`), so a
239/// disagreement arriving here is a real one. The Rust seams call [`honour`]
240/// instead — see its doc comment for why the two surfaces differ.
241///
242/// # Keep the message inside ONE log line
243///
244/// `nros_log`'s formatting buffer is 256 bytes by default (`NROS_LOG_BUFFER_SIZE`)
245/// and OVERFLOW TRUNCATES with a single `…`. This message used to run past 450
246/// characters, so on a real image the half a reader needs — which file to edit —
247/// was the half that got cut, and the diagnostic ended mid-sentence. The
248/// numbers and the topic come first for the same reason: a long type name may
249/// still push the tail off, and the tail is the least load-bearing part.
250pub fn check(type_name: &str, topic: &str, qos: &QoSProfile) -> Result<(), NodeError> {
251    match DECLARED_QOS_ROWS {
252        Some(rows) => check_in(rows, type_name, topic, qos),
253        None => Ok(()),
254    }
255}
256
257/// [`check`] against a table this build did not generate. See [`row_in`].
258fn check_in(
259    rows: &[DeclaredEndpoint],
260    type_name: &str,
261    topic: &str,
262    qos: &QoSProfile,
263) -> Result<(), NodeError> {
264    let Some(row) = row_in(rows, type_name, topic) else {
265        return Ok(());
266    };
267    if let Some(declared) = row.depth
268        && declared != qos.depth
269    {
270        nros_log::log_error!(
271            nros_log::get_logger("nros_node"),
272            "declared depth: `{}` registers KEEP_LAST({}) but this image's contract \
273             declares {}, and the arena was sized from {}. Fix the contract row or the \
274             QoS at the call site (type `{}`).",
275            topic,
276            qos.depth,
277            declared,
278            declared,
279            type_name
280        );
281        return Err(NodeError::DeclaredDepthMismatch);
282    }
283    if let Some(declared) = row.reliability
284        && declared != qos.reliability
285    {
286        nros_log::log_error!(
287            nros_log::get_logger("nros_node"),
288            "declared QoS: `{}` registers {} but this image's contract declares reliability \
289             {}; an incompatible match never delivers. Fix the contract row or the call site.",
290            topic,
291            reliability_spelling(qos.reliability),
292            reliability_spelling(declared)
293        );
294        return Err(NodeError::DeclaredQosMismatch);
295    }
296    if let Some(declared) = row.durability
297        && declared != qos.durability
298    {
299        nros_log::log_error!(
300            nros_log::get_logger("nros_node"),
301            "declared QoS: `{}` registers {} but this image's contract declares durability \
302             {}; an incompatible match never delivers. Fix the contract row or the call site.",
303            topic,
304            durability_spelling(qos.durability),
305            durability_spelling(declared)
306        );
307        return Err(NodeError::DeclaredQosMismatch);
308    }
309    Ok(())
310}

312/// The QoS a Rust subscription actually registers with, once the contract has
313/// had its say — phase-454 W13, the Rust half of W10, widened to the two
314/// policies by issue 1256.
315///
316/// # Why Rust TAKES the declared value where C and C++ ASSERT it
317///
318/// C++ settles this at the call site, by arity: `NROS_SUBSCRIBE(Msg, m, topic)`
319/// states no QoS, so `qos_from_declared` BUILDS one from the declaration
320/// ("nothing to assert — there is only ever one statement"), and the
321/// four-argument form, where the call site did state one, `static_assert`s that
322/// the two agree. C does the same with `NROS_ASSERT_DECLARED_*`.
323///
324/// Rust has neither half of that seam: there is no `nros::subscribe!`, and the
325/// topic is a runtime `&str`, so nothing at the call site can be told apart
326/// from anything else at compile time — and by the time a QoS reaches a
327/// registration, "the caller wrote this" and "a constructor defaulted it" are
328/// the same `QoSProfile`. `Node::create_subscription` hands
329/// `QoSProfile::default()` — `rmw_qos_profile_default`, KEEP_LAST(10),
330/// RELIABLE, VOLATILE — to the same `_with_qos` entry point a caller with an
331/// opinion reaches, and the declarative road folds both into one
332/// `EntityMetadata::qos` field long before this point.
333///
334/// So the distinction C++ makes is not available here, and the two candidate
335/// rules that remain each fail on their own:
336///
337/// * **Check only.** Every `QoSProfile::default()` call site in the tree would
338///   be refused the moment its endpoint is declared at anything but the
339///   default — which is the entire point of declaring one. A declaration would
340///   become a way to stop an image booting.
341/// * **Take, always.** A caller who narrowed a queue on purpose
342///   (`create_subscription_viewable` requires KEEP_LAST(1)) or chose
343///   `best_effort` for a sensor would be silently widened by a contract that
344///   over-declared.
345///
346/// # The rule, and why the asymmetry is real
347///
348/// **The contract states what the BUILD RESERVED.** W12 made that literal for
349/// the depth: the executor arena, the zenoh receive ring and both payload pools
350/// on a declared image are all sized from the declared depth. The policies are
351/// the same kind of statement: XRCE drops both reliable stream buffers to the
352/// protocol floor when every endpoint declares `best_effort` (RFC-0100 D3), and
353/// a `transient_local` endpoint is what the build counts a late-joiner slot
354/// for. So for each column, ordered by how much it ASKS FOR (deeper; reliable
355/// over best_effort; transient_local over volatile):
356///
357/// * `asked > declared` — the registration wants more than was bought, and
358///   asking for it would ride storage the build did not reserve. **TAKEN**, and
359///   reported. For the two policies it is also the direction RxO tolerates: a
360///   `best_effort` or `volatile` reader still matches a `reliable` or
361///   `transient_local` writer.
362/// * `asked < declared` — taking would WIDEN what the code narrowed, and the
363///   image paid for something nothing wants. Two statements about one fact
364///   disagreeing, with no default that explains either (RFC-0100 D8).
365///   **REFUSED**, naming both.
366/// * equal, or nothing declared — returned unchanged. An image with no contract
367///   is byte-identical to every build before this wave.
368/// * a policy asked as `SystemDefault` — the code stated no opinion, so the
369///   declaration is TAKEN, silently: there is nothing to report a divergence
370///   from.
371///
372/// # And it says so
373///
374/// A take is REPORTED, once per endpoint that diverges — the C++ surface's
375/// value is visible in the source at the call site and Rust's is not, so a
376/// registration that quietly stopped being what `lib.rs` reads would be the lie
377/// this whole model exists to remove. Every take here narrows what the code
378/// asked for (a shallower queue, no retransmission, no late-joiner history),
379/// any of which can drop a sample, so each is `WARN`.
380///
381/// Called instead of [`check`] at every Rust subscription registration. The C
382/// and C++ FFI seams keep [`check`] — they have already taken the declared QoS
383/// at their own call site, so a disagreement reaching THEM is a real refusal
384/// and not a default nobody wrote.
385///
386/// # `#[inline]` is load-bearing, and it was MEASURED
387///
388/// An image with no contract must be byte-identical to every build before this
389/// wave, and "the table is empty so the work folds away" is a claim about the
390/// optimiser, not a fact. It was FALSE as first written: with the table
391/// threaded in as an `unwrap_or(&[])` argument, `honour` stayed out of line —
392/// a real `T nros_node::declared_qos::honour` symbol, +144 bytes of text and
393/// +8 of data on the no-contract listener against `origin/main`, because a
394/// 40-byte `QoSProfile` moving in and out by value is past LLVM's inlining
395/// budget. Matching the `Option` HERE, behind `#[inline]`, is what lets a
396/// `None` table fold the call to `Ok(qos)` at every one of the fourteen
397/// registration sites and leave `honour_in` unreferenced. Verified by
398/// rebuilding both trees and comparing the linked binary byte for byte.
399#[inline]
400pub fn honour(type_name: &str, topic: &str, qos: QoSProfile) -> Result<QoSProfile, NodeError> {
401    let Some(rows) = DECLARED_QOS_ROWS else {
402        return Ok(qos);
403    };
404    honour_in(rows, type_name, topic, qos)
405}

422/// Which side of a match an endpoint is on -- issue 1608.
423///
424/// It decides ONE thing: which direction of a POLICY disagreement
425/// [`honour_role_in`] may take. Depth is not a matched policy and is treated
426/// the same on both sides. Reliability and durability are request-vs-offered
427/// (RxO) matched, and the tolerant direction is OPPOSITE for the two roles: a
428/// reader may ask for LESS than a writer offers, a writer may offer MORE than a
429/// reader asks.
430#[derive(Debug, Clone, Copy, PartialEq, Eq)]
431enum Role {
432    Subscription,
433    Publisher,
434}
435
436impl Role {
437    fn noun(self) -> &'static str {
438        match self {
439            Role::Subscription => "subscription",
440            Role::Publisher => "publisher",
441        }
442    }
443
444    /// Why a [`PolicyVerdict::Refuse`] refuses, in the log line's words.
445    fn refusal_reason(self) -> &'static str {
446        match self {
447            Role::Subscription => "widen what the code narrowed",
448            Role::Publisher => {
449                "weaken the offer below the call site's, and a reader asking for it stops matching"
450            }
451        }
452    }
453}
454
455/// What [`honour_role_in`] does with one POLICY column that disagrees.
456#[derive(Debug, Clone, Copy, PartialEq, Eq)]
457enum PolicyVerdict {
458    /// Take the declaration and report the divergence.
459    Take,
460    /// Take the declaration silently: the call site stated no opinion.
461    TakeSilently,
462    /// Refuse the registration.
463    Refuse,
464}
465
466/// THE rule for a policy disagreement, for both roles, in rank space (`None`
467/// is "no opinion" -- see [`reliability_rank`]).
468///
469/// * **Subscription** -- refuse when the code asked for LESS than was declared
470///   (taking would widen what the code narrowed); otherwise take, which lowers
471///   the request into what the build reserved and is the direction RxO
472///   tolerates for a reader.
473/// * **Publisher** -- refuse when the code asked for MORE than was declared.
474///   Taking would WEAKEN the offer below what the code asked, so a reader that
475///   requests what the code offered stops matching -- an incompatible-QoS pair
476///   never delivers -- while keeping the ask rides storage the build did not
477///   reserve: a `transient_local` writer is a zenoh queryable slot plus its
478///   retained samples, and a `reliable` one is XRCE's reliable stream history,
479///   both counted from the declaration. Otherwise take: RAISING a writer's
480///   offer keeps every reader that matched the lower one, and it is what the
481///   build reserved.
482///
483/// So the two roles share the asymmetry's REASON -- never ride storage the
484/// build did not reserve, never silently break a match -- and get opposite
485/// directions from it, because RxO is directional.
486fn policy_verdict(role: Role, asked: Option<u8>, declared: Option<u8>) -> PolicyVerdict {
487    let (Some(asked), Some(declared)) = (asked, declared) else {
488        return PolicyVerdict::TakeSilently;
489    };
490    let refuse = match role {
491        Role::Subscription => asked < declared,
492        Role::Publisher => asked > declared,
493    };
494    if refuse {
495        PolicyVerdict::Refuse
496    } else {
497        PolicyVerdict::Take
498    }
499}

501/// [`honour`] / [`honour_publisher`] for either [`Role`].
502fn honour_role_in(
503    rows: &[DeclaredEndpoint],
504    type_name: &str,
505    topic: &str,
506    qos: QoSProfile,
507    role: Role,
508) -> Result<QoSProfile, NodeError> {
509    let Some(row) = row_in(rows, type_name, topic) else {
510        return Ok(qos);
511    };
512    let mut granted = qos;
513    // The DEPTH rule is the same for both roles: a subscription's depth
514    // multiplies the executor arena, a publisher's is its history cache (the
515    // samples a transient_local writer retains for late joiners), and in both
516    // the build reserved the DECLARED number.
517    if let Some(declared) = row.depth
518        && declared != qos.depth
519    {
520        if declared > qos.depth {
521            nros_log::log_error!(
522                nros_log::get_logger("nros_node"),
523                "declared depth: {} `{}` registers KEEP_LAST({}) and the contract declares {} \
524                 -- DEEPER. Taking it would widen a queue the code narrowed; fix the contract \
525                 row or the call site (type `{}`).",
526                role.noun(),
527                topic,
528                qos.depth,
529                declared,
530                type_name
531            );
532            return Err(NodeError::DeclaredDepthMismatch);
533        }
534        granted.depth = declared;
535        nros_log::log_warn!(
536            nros_log::get_logger("nros_node"),
537            "declared depth: taking KEEP_LAST({}) on {} `{}`; the call site asked {} and the \
538             build reserved {}. Raise the contract row to keep more (type `{}`).",
539            declared,
540            role.noun(),
541            topic,
542            qos.depth,
543            declared,
544            type_name
545        );
546    }
547    if let Some(declared) = row.reliability
548        && declared != qos.reliability
549    {
550        match policy_verdict(
551            role,
552            reliability_rank(qos.reliability),
553            reliability_rank(declared),
554        ) {
555            PolicyVerdict::Refuse => {
556                nros_log::log_error!(
557                    nros_log::get_logger("nros_node"),
558                    "declared QoS: {} `{}` registers {} and the contract declares reliability \
559                     {}; taking it would {}. Fix the contract row or the call site.",
560                    role.noun(),
561                    topic,
562                    reliability_spelling(qos.reliability),
563                    reliability_spelling(declared),
564                    role.refusal_reason()
565                );
566                return Err(NodeError::DeclaredQosMismatch);
567            }
568            PolicyVerdict::Take => {
569                nros_log::log_warn!(
570                    nros_log::get_logger("nros_node"),
571                    "declared QoS: taking reliability {} on {} `{}`; the call site asked {}. \
572                     Change the contract row to keep the call site's.",
573                    reliability_spelling(declared),
574                    role.noun(),
575                    topic,
576                    reliability_spelling(qos.reliability)
577                );
578            }
579            // The call site stated no opinion: nothing diverged, so nothing is
580            // reported.
581            PolicyVerdict::TakeSilently => {}
582        }
583        granted.reliability = declared;
584    }
585    if let Some(declared) = row.durability
586        && declared != qos.durability
587    {
588        match policy_verdict(
589            role,
590            durability_rank(qos.durability),
591            durability_rank(declared),
592        ) {
593            PolicyVerdict::Refuse => {
594                nros_log::log_error!(
595                    nros_log::get_logger("nros_node"),
596                    "declared QoS: {} `{}` registers {} and the contract declares durability \
597                     {}; taking it would {}. Fix the contract row or the call site.",
598                    role.noun(),
599                    topic,
600                    durability_spelling(qos.durability),
601                    durability_spelling(declared),
602                    role.refusal_reason()
603                );
604                return Err(NodeError::DeclaredQosMismatch);
605            }
606            PolicyVerdict::Take => {
607                nros_log::log_warn!(
608                    nros_log::get_logger("nros_node"),
609                    "declared QoS: taking durability {} on {} `{}`; the call site asked {}. \
610                     Change the contract row to keep the call site's.",
611                    durability_spelling(declared),
612                    role.noun(),
613                    topic,
614                    durability_spelling(qos.durability)
615                );
616            }
617            PolicyVerdict::TakeSilently => {}
618        }
619        granted.durability = declared;
620    }
621    Ok(granted)
622}

624/// issue 1608 -- the PUBLISHER counterpart of [`honour`]: the QoS a publisher
625/// registers with once the contract has had its say.
626///
627/// The rule is `policy_verdict`'s, with the POLICY direction reversed from a
628/// subscription's because RxO is directional: a publisher that asked for less
629/// than the contract declares is RAISED to the declaration (the build reserved
630/// it, and every reader that matched the lower offer still matches), and one
631/// that asked for more is REFUSED (lowering it could break a match, keeping it
632/// rides storage nobody reserved). The depth rule is the subscription's.
633///
634/// Called at every publisher registration -- the Rust seams AND the C/C++ FFI
635/// seams. Unlike a subscription, a publisher has no call-site seam in C or C++
636/// that already took the declaration (`NROS_SUBSCRIBE`'s three-argument form
637/// has no publisher counterpart, and the compile-time table carries no
638/// publisher rows), so the FFI seams honour too rather than strict-checking: a
639/// strict check there would refuse every `create_publisher_in<M>(topic)` whose
640/// default profile the contract refines.
641///
642/// `#[inline]` for [`honour`]'s measured reason: a `None` table must fold the
643/// call to `Ok(qos)` so an image with no contract is byte-identical.
644#[inline]
645pub fn honour_publisher(
646    type_name: &str,
647    topic: &str,
648    qos: QoSProfile,
649) -> Result<QoSProfile, NodeError> {
650    let Some(rows) = DECLARED_PUBLISHER_QOS_ROWS else {
651        return Ok(qos);
652    };
653    honour_role_in(rows, type_name, topic, qos, Role::Publisher)
654}

658/// `(type, topic)` are two endpoints with two declarations.
659pub fn declared_publisher(type_name: &str, topic: &str) -> Option<DeclaredEndpoint> {
660    row_in(DECLARED_PUBLISHER_QOS_ROWS?, type_name, topic).copied()
661}

1082    /// Everything above tests `depth_in` against a table this module wrote,

1102                !rows.is_empty(),
