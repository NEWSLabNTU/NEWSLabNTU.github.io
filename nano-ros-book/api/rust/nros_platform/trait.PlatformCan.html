Expand description

The implementer surface of <nros/platform_can.h>, the CAN frame driver.

A Rust backend implements this and turns it into the five C symbols with nros_platform_cffi::nros_platform_export_can!; a C backend defines the symbols directly. The header is the contract: return codes are its NROS_PLATFORM_CAN_* values, and each method mirrors one call there.

§Pointers

This crate has no dependencies, so it cannot name the header’s types. can points at the caller’s nros_platform_can_t (the backend’s state lives inside it and must fit the header’s size) and frame at an nros_platform_can_frame_t; the export macro passes the typed pointers through unchanged. Any of them may be NULL, and a backend checks.

§Frame validity

A backend refuses the frames nros_platform_can_frame_check (the header’s static inline) refuses, with NROS_PLATFORM_CAN_EINVAL. A C backend calls it; a Rust backend calls it through a compiled shim, so the rule has one definition.
