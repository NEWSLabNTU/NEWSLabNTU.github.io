Per-request metadata handed to a service callback — rclrs’s ServiceInfo.

Issue 1942. rclrs 0.7 can pass a service callback a ServiceInfo beside the request: who sent it (the client’s GID and its sequence number, together the upstream rmw_request_id_t) and when (source and received timestamps). This is the counterpart, registered through Node::create_service_with_info or node.service(name).service_info().

Not to be confused with nros_rmw::ServiceInfo, the RMW seam’s service DESCRIPTOR (name, type, hash, domain). That type is not re-exported by the nros facade (RFC-0071 D12, phase-506 W1), which is what lets this one take rclrs’s name there.

§What a backend reports

Every field is an Option, because whether a request carries it is a BACKEND property, and a backend that cannot say leaves the field None rather than inventing a value — the MessageInfo precedent, where a backend that reports no metadata hands the callback None instead of a zeroed struct. rclrs’s fields are not optional; ours are, and that is the one shape divergence.
