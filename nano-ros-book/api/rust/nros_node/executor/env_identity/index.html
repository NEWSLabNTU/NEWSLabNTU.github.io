$NROS_NODE_NAME / $NROS_NODE_NAMESPACE, applied to every node. What $NROS_NODE_NAME and $NROS_NODE_NAMESPACE do to a node.

Both variables are read by the hosted edge (nros::env::try_resolve_hosted, which every Linux road reaches: Rust, C’s rclc_support_init, C++’s nros_cpp_init). Until this module they reached only the executor’s own default name, so a node named in code or by the launch file kept its name and the variable was read and dropped, silently. A read whose result is discarded is not allowed: a value is honoured and a mismatch is warned once, or it is ignored with a notice that says where to state it.

The rules:

  • $NROS_NODE_NAMESPACE applies to EVERY node of the image. A namespace does not collide, so the node count does not matter. When a node stated a different non-root namespace, one warning per process says so.
  • $NROS_NODE_NAME renames the node only when the image’s sizing descriptor STATES that it creates exactly one (crate::config::STATED_NODE_COUNT == Some(1)), warning once when the stated name differs. With two or more nodes one name cannot name them all without a collision, and with an unstated count nothing here can tell, so in both cases the variable is ignored with a once-per-process notice naming where a node’s name is authored.

The values live in process-global slots because the environment is process-wide and one road (C’s rclc_node_init_default) names its node before any executor exists. They are installed once, by the edge that read them; nothing on an embedded target installs anything, so there every node keeps its stated identity, as before.
