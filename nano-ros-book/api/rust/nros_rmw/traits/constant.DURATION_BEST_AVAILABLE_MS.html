Issue 1973 — the “best available” spelling for deadline_ms and liveliness_lease_ms: resolve at creation against the discovered graph.

Upstream spells it RMW_QOS_DEADLINE_BEST_AVAILABLE / RMW_QOS_LIVELINESS_LEASE_DURATION_BEST_AVAILABLE, both RMW_DURATION_INFINITE - 1; this is the same idea in our u32-millisecond fields: DURATION_INFINITE_MS minus one. A REQUEST only — the runtime replaces it before a backend sees the profile (QoSProfile::resolve_best_available). Mirrors the C header’s NROS_RMW_DURATION_BEST_AVAILABLE_MS. Not meaningful for lifespan_ms, as upstream defines no best-available lifespan.
