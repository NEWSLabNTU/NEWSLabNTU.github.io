98// -- Policy enums (phase 379 W5) ------------------------------------------
99//
100// At NAMESPACE scope and public, under rclcpp's names, because that is where a
101// ported node looks for them (`rclcpp::ReliabilityPolicy`, `qos.hpp:34-58`).
102// Three of these were PRIVATE members of `QoS` until phase-379 W5, which is why
103// the getters had to hand back `int` — a public getter cannot name a private
104// type. Ledger: `cpp:ReliabilityPolicy` and its three siblings.
105//
106// The two rclcpp enumerators we used to decline ARRIVED in phase-444 (issue
107// 1437), and the reason each was declined is the reason it is now needed:
108//
109// * `SystemDefault` — "defer to the middleware". Declined because nothing
110// DEFERS: the backend is linked at build time (RFC-0036). True of a
111// REQUEST, and a `QoS` is no longer only a request — `get_actual_qos()`
112// hands one back, and a backend CAN report that a policy was never stated.
113// * `Unknown` — declined as "a discovery artefact for a policy read off a
114// remote endpoint, and we do no dynamic discovery". It is not that: it is
115// what `rmw_*_get_actual_qos` owes for a policy the backend looked at and
116// cannot determine, on the LOCAL endpoint. `rmw_vtable.h` has always said
117// so, and until issue 1437 no implementation anywhere wrote one.
118//
119// What is still declined is `rclcpp::SystemDefaultsQoS` — the all-sentinel
120// PRESET, whose two RMWs resolve it to depth 1 and depth 42 (issue 0829).
121// A value a backend may REPORT is not a profile a caller may REQUEST, and the
122// refusal on that class stands (`NROS_RCLCPP_REFUSE_SYSTEM_DEFAULTS_QOS`).
123//
124// The enumerators are PREFIXED — `ReliabilityUnknown`, not `Unknown` — because
125// these are UNSCOPED enums at namespace scope, so four bare `Unknown`s in
126// `nros::` would be a redeclaration rather than four policies. rclcpp's are
127// `enum class` and pay no such cost. `LivelinessPolicy` already had the
128// prefix for the same reason, so this is the file's existing convention, not
129// a new one. `LivelinessSystemDefault` is absent on purpose: `LivelinessNone`
130// IS discriminant 0, which is the sentinel's value, and a second name for one
131// value is how a vocabulary starts disagreeing with itself.
132//
133// These are UNSCOPED enums, not rclcpp's `enum class`. Both spellings work as a
134// result: `nros::Reliable` (ours, historical) and `nros::ReliabilityPolicy::
135// Reliable` (rclcpp's). Switching to `enum class` would break the first and is
136// its own decision, which no ledger row makes — see the qos.json rows.

510// ============================================================================
511// phase-417 G6 — profile comparison. `rclcpp::operator==(const QoS&, const QoS&)`
512// ============================================================================
513//
514// FREE functions, as upstream's are, and written from the PUBLIC accessors —
515// every one of the ten members has one, so no `friend` is needed and the
516// comparison stays a thing a reader can check against the accessor list.
517//
518// TEN hand-written comparisons rather than `= default`. `operator==() =
519// default` is C++20 and this surface's floor is `cxx_std_17`
520// (`packages/api/nros-cpp/CMakeLists.txt` — `target_compile_features(
521// nros-cpp-headers INTERFACE cxx_std_17)`), so the defaulted form would not
522// compile for the targets this header exists to serve. Still `constexpr`,
523// still no allocator, still no exceptions.
524//
525// Rust's `QoSProfile` derives `PartialEq, Eq` and has had this for nothing
526// since it existed; the ledger row `cpp:operator==` recorded the asymmetry as
527// having no platform reason, and it did not.
528//
529// The three time windows are compared through `Duration::nanoseconds()` rather
530// than the deprecated `_ms()` accessors: the storage is milliseconds, the
531// conversion is exact in both directions (`detail::qos_window_duration`), and
532// naming a deprecated member here would make every comparison warn.
533
539constexpr bool operator==(const QoS& left, const QoS& right) {
540 return left.reliability() == right.reliability() && left.durability() == right.durability() &&
541 left.history() == right.history() && left.liveliness() == right.liveliness() &&
542 left.depth() == right.depth() &&
543 left.deadline().nanoseconds() == right.deadline().nanoseconds() &&
544 left.lifespan().nanoseconds() == right.lifespan().nanoseconds() &&
545 left.liveliness_lease_duration().nanoseconds() ==
546 right.liveliness_lease_duration().nanoseconds() &&
547 left.avoid_ros_namespace_conventions() == right.avoid_ros_namespace_conventions() &&
548 left.tx_express() == right.tx_express();
549}
550
553constexpr bool operator!=(const QoS& left, const QoS& right) {
554 return !(left == right);
555}

609// --- THE C++ QoS profile table (phase-428 W10) -------------------------------
610//
611// Every named profile the C++ surface offers is spelled HERE and nowhere else.
612// `nros::QoS`'s three named statics and all six concrete `rclcpp::*QoS` classes
613// are defined by calling into this block; none of them restates a policy.
614//
615// Why a table and not a hand copy per class: W10 exists because upstream's 7
616// profiles were transcribed in four places across the repo — this header,
617// `nros-rmw/src/traits.rs`, `nros/src/lib.rs` and `nros-rmw-abi/.../
618// rmw_entity.h` — about 26 constants for a 7-row table, with no gate binding
619// them. `QOS_PROFILE_PARAMETER_EVENTS` is the proof: `KeepAll, 0` in Rust under
620// a comment claiming it matched `rmw_qos_profile_parameter_events`, which is
621// `KEEP_LAST, 1000`. This header had the same profile right, which is exactly
622// what an ungated mirror looks like until the day it is not.
623//
624// This block cannot CONSUME the cross-language SSoT. The C spellings in
625// `rmw_entity.h` are `((rmw_qos_profile_t){...})` compound literals, which are
626// C99 and not standard C++, over a struct whose field types differ from
627// `nros_cpp_qos_t`'s; and `qos.hpp` is deliberately self-contained and
628// freestanding (see issue 0112 at the top of this file), so it cannot take a
629// dependency on a build-generated header either. What the table DOES buy is
630// that the C++ side has ONE row per profile for a cross-language gate to read,
631// instead of nine constructor bodies to parse.
632//
633// phase-454 W1 collected on that. `scripts/check-qos-profile-ssot.py` now
634// EVALUATES these rows — the ctor supplies the base profile and each chained
635// call applies its one effect — and compares every field against
636// `QoSProfile::QOS_PROFILE_*`. So the table is bound after all; what it is not
637// is DERIVED, which is the weaker of the two and the strongest available to a
638// freestanding header. A `.setter()` the gate does not model is a hard failure
639// there, not a skipped field.
640//
641// Values read 2026-09-05 against ROS 2 Humble as installed:
642// /opt/ros/humble/include/rmw/rmw/qos_profiles.h :25,38,51,64,77,90
643// /opt/ros/humble/include/rcl/rcl/logging_rosout.h :36
644// /opt/ros/humble/include/rclcpp/rclcpp/qos.hpp :371-500
645//
646// Three fields are identical in EVERY upstream profile and are therefore folded
647// into `QoS`'s default constructor rather than spelled per row:
648// * `avoid_ros_namespace_conventions` is `false` upstream, `0` here.
649// * liveliness is `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT` upstream, and
650// `nros::QoS` now defaults to `LivelinessNone`, which is our spelling of
651// that sentinel. It defaulted to `LivelinessAutomatic` — "what every
652// reference RMW folds that sentinel to" — under a
653// `nros-qos-mirror-deviation` record whose own reason was that this
654// surface and `nros-c`'s "move together with the C ABI or not at all".
655// They moved together (issue 1329): this constructor, `nros-c`'s
656// `NROS_QOS_*` statics and `nros_c_qos_default()`.
657//
658// The forcing argument is issue 1329's per-backend QoS mask. XRCE honours
659// no liveliness, so an AUTOMATIC default would have made
660// `required_policies()` demand `LIVELINESS_AUTOMATIC` and refuse every C++
661// default profile on that backend — over a policy upstream leaves unset
662// and the application never asked for. A caller that wants automatic
663// liveliness states `.liveliness(nros::LivelinessAutomatic)`.
664//
665// * deadline and the liveliness lease are `RMW_QOS_*_DEFAULT` (infinite)
666// upstream and `0` here, which `qos_window_ms` above documents as infinite.
667//
668// `rmw_qos_profile_system_default` has NO row: every one of its fields is a
669// sentinel, so no value could be right. `rclcpp::SystemDefaultsQoS` refuses at
670// compile time instead — see the class below.

726constexpr nros_cpp_qos_t qos_to_ffi(const QoS& qos) {
727 nros_cpp_qos_t f{};
728 f.reliability = static_cast<nros_cpp_qos_reliability_t>(qos.reliability());
729 f.durability = static_cast<nros_cpp_qos_durability_t>(qos.durability());
730 f.history = static_cast<nros_cpp_qos_history_t>(qos.history());
731 f.liveliness_kind = static_cast<nros_cpp_qos_liveliness_t>(qos.liveliness());
732 f.depth = qos.depth();
733 // The FFI FIELDS are milliseconds and keep their `_ms` names; only the
734 // accessors changed. `qos_window_ms` is the exact inverse of the
735 // `Duration` the getter built, so this round-trip loses nothing.
