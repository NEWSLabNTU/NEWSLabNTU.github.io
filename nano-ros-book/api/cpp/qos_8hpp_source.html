98// -- Policy enums (phase 379 W5) ------------------------------------------
99//
100// At NAMESPACE scope and public, under rclcpp's names, because that is where a
101// ported node looks for them (`rclcpp::ReliabilityPolicy`, `qos.hpp:34-58`).
102// Three of these were PRIVATE members of `QoS` until phase-379 W5, which is why
103// the getters had to hand back `int` — a public getter cannot name a private
104// type. Ledger: `cpp:ReliabilityPolicy` and its three siblings.
105//
106// The two rclcpp enumerators we used to decline ARRIVED in phase-444 (issue
107// 1437), and the reason each was declined is the reason it is now needed:
108//
109// * `SystemDefault` — "defer to the middleware". Declined because nothing
110// DEFERS: the backend is linked at build time (RFC-0036). True of a
111// REQUEST, and a `QoS` is no longer only a request — `get_actual_qos()`
112// hands one back, and a backend CAN report that a policy was never stated.
113// * `Unknown` — declined as "a discovery artefact for a policy read off a
114// remote endpoint, and we do no dynamic discovery". It is not that: it is
115// what `rmw_*_get_actual_qos` owes for a policy the backend looked at and
116// cannot determine, on the LOCAL endpoint. `rmw_vtable.h` has always said
117// so, and until issue 1437 no implementation anywhere wrote one.
118//
119// What is still declined is `rclcpp::SystemDefaultsQoS` — the all-sentinel
120// PRESET, whose two RMWs resolve it to depth 1 and depth 42 (issue 0829).
121// A value a backend may REPORT is not a profile a caller may REQUEST, and the
122// refusal on that class stands (`NROS_RCLCPP_REFUSE_SYSTEM_DEFAULTS_QOS`).
123//
124// The enumerators are upstream's and SCOPED (phase-483 W1): one
125// `SystemDefault` and one `Unknown` per policy, reached as
126// `rclcpp::ReliabilityPolicy::Unknown`. The prefixed spellings
127// (`ReliabilityUnknown`, `LivelinessNone`) existed only because these were
128// unscoped enums, and the bare `rclcpp::Reliable` form went with them.

201constexpr uint32_t qos_window_ms(const Duration& d) {
202 return d.nanoseconds() <= 0
203 ? 0u
204 : (d.nanoseconds() > static_cast<int64_t>(UINT32_MAX) * 1000000
205 ? UINT32_MAX
206 : static_cast<uint32_t>((d.nanoseconds() + 999999) / 1000000));
207}

418// ============================================================================
419// phase-417 G6 — profile comparison. `rclcpp::operator==(const QoS&, const QoS&)`
420// ============================================================================
421//
422// FREE functions, as upstream's are, and written from the PUBLIC accessors —
423// every one of the ten members has one, so no `friend` is needed and the
424// comparison stays a thing a reader can check against the accessor list.
425//
426// TEN hand-written comparisons rather than `= default`. `operator==() =
427// default` is C++20 and this surface's floor is `cxx_std_17`
428// (`packages/api/nros-cpp/CMakeLists.txt` — `target_compile_features(
429// nros-cpp-headers INTERFACE cxx_std_17)`), so the defaulted form would not
430// compile for the targets this header exists to serve. Still `constexpr`,
431// still no allocator, still no exceptions.
432//
433// Rust's `QoSProfile` derives `PartialEq, Eq` and has had this for nothing
434// since it existed; the ledger row `cpp:operator==` recorded the asymmetry as
435// having no platform reason, and it did not.
436//
437// The three time windows are compared through `Duration::nanoseconds()`: the
438// storage is milliseconds and the conversion is exact in both directions
439// (`detail::qos_window_duration`).
440
446constexpr bool operator==(const QoS& left, const QoS& right) {
447 return left.reliability() == right.reliability() && left.durability() == right.durability() &&
448 left.history() == right.history() && left.liveliness() == right.liveliness() &&
449 left.depth() == right.depth() &&
450 left.deadline().nanoseconds() == right.deadline().nanoseconds() &&
451 left.lifespan().nanoseconds() == right.lifespan().nanoseconds() &&
452 left.liveliness_lease_duration().nanoseconds() ==
453 right.liveliness_lease_duration().nanoseconds() &&
454 left.avoid_ros_namespace_conventions() == right.avoid_ros_namespace_conventions() &&
455 left.tx_express() == right.tx_express();
456}
457
460constexpr bool operator!=(const QoS& left, const QoS& right) {
461 return !(left == right);
462}

516// --- THE C++ QoS profile table (phase-428 W10) -------------------------------
517//
518// Every named profile the C++ surface offers is spelled HERE and nowhere else.
519// `rclcpp::QoS`'s three named statics and all six concrete `rclcpp::*QoS` classes
520// are defined by calling into this block; none of them restates a policy.
521//
522// Why a table and not a hand copy per class: W10 exists because upstream's 7
523// profiles were transcribed in four places across the repo — this header,
524// `nros-rmw/src/traits.rs`, `nros/src/lib.rs` and `nros-rmw-abi/.../
525// rmw_entity.h` — about 26 constants for a 7-row table, with no gate binding
526// them. `QOS_PROFILE_PARAMETER_EVENTS` is the proof: `KeepAll, 0` in Rust under
527// a comment claiming it matched `rmw_qos_profile_parameter_events`, which is
528// `KEEP_LAST, 1000`. This header had the same profile right, which is exactly
529// what an ungated mirror looks like until the day it is not.
530//
531// This block cannot CONSUME the cross-language SSoT. The C spellings in
532// `rmw_entity.h` are `((rmw_qos_profile_t){...})` compound literals, which are
533// C99 and not standard C++, over a struct whose field types differ from
534// `nros_cpp_qos_t`'s; and `qos.hpp` is deliberately self-contained and
535// freestanding (see issue 0112 at the top of this file), so it cannot take a
536// dependency on a build-generated header either. What the table DOES buy is
537// that the C++ side has ONE row per profile for a cross-language gate to read,
538// instead of nine constructor bodies to parse.
539//
540// phase-454 W1 collected on that. `scripts/check-qos-profile-ssot.py` now
541// EVALUATES these rows — the ctor supplies the base profile and each chained
542// call applies its one effect — and compares every field against
543// `QoSProfile::QOS_PROFILE_*`. So the table is bound after all; what it is not
544// is DERIVED, which is the weaker of the two and the strongest available to a
545// freestanding header. A `.setter()` the gate does not model is a hard failure
546// there, not a skipped field.
547//
548// Values read 2026-09-05 against ROS 2 Humble as installed:
549// /opt/ros/humble/include/rmw/rmw/qos_profiles.h :25,38,51,64,77,90
550// /opt/ros/humble/include/rcl/rcl/logging_rosout.h :36
551// /opt/ros/humble/include/rclcpp/rclcpp/qos.hpp :371-500
552//
553// Three fields are identical in EVERY upstream profile and are therefore folded
554// into `QoS`'s default constructor rather than spelled per row:
555// * `avoid_ros_namespace_conventions` is `false` upstream, `0` here.
556// * liveliness is `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT` upstream, and
557// `rclcpp::QoS` now defaults to `LivelinessPolicy::SystemDefault`, which is our spelling of
558// that sentinel. It defaulted to `LivelinessAutomatic` — "what every
559// reference RMW folds that sentinel to" — under a
560// `nros-qos-mirror-deviation` record whose own reason was that this
561// surface and `nros-c`'s "move together with the C ABI or not at all".
562// They moved together (issue 1329): this constructor, `nros-c`'s
563// `NROS_QOS_*` statics and `nros_c_qos_default()`.
564//
565// The forcing argument is issue 1329's per-backend QoS mask. XRCE honours
566// no liveliness, so an AUTOMATIC default would have made
567// `required_policies()` demand `LIVELINESS_AUTOMATIC` and refuse every C++
568// default profile on that backend — over a policy upstream leaves unset
569// and the application never asked for. A caller that wants automatic
570// liveliness states `.liveliness(rclcpp::LivelinessPolicy::Automatic)`.
571//
572// * deadline and the liveliness lease are `RMW_QOS_*_DEFAULT` (infinite)
573// upstream and `0` here, which `qos_window_ms` above documents as infinite.
574//
575// `rmw_qos_profile_system_default` has NO row: every one of its fields is a
576// sentinel, so no value could be right. `rclcpp::SystemDefaultsQoS` refuses at
577// compile time instead — see the class below.
578struct qos_table {

586 static constexpr QoS sensor_data() { return QoS().best_effort().keep_last(5); }

633constexpr nros_cpp_qos_t qos_to_ffi(const QoS& qos) {
634 nros_cpp_qos_t f{};
635 f.reliability = static_cast<nros_cpp_qos_reliability_t>(qos.reliability());
636 f.durability = static_cast<nros_cpp_qos_durability_t>(qos.durability());
637 f.history = static_cast<nros_cpp_qos_history_t>(qos.history());
638 f.liveliness_kind = static_cast<nros_cpp_qos_liveliness_t>(qos.liveliness());
639 f.depth = qos.depth();
640 // The FFI FIELDS are milliseconds and keep their `_ms` names; only the
641 // accessors changed. `qos_window_ms` is the exact inverse of the
642 // `Duration` the getter built, so this round-trip loses nothing.
643 f.deadline_ms = qos_window_ms(qos.deadline());
644 f.lifespan_ms = qos_window_ms(qos.lifespan());
645 f.liveliness_lease_ms = qos_window_ms(qos.liveliness_lease_duration());
646 f.avoid_ros_namespace_conventions = qos.avoid_ros_namespace_conventions() ? 1 : 0;
647 f.tx_express = qos.tx_express() ? 1 : 0;
648 return f;
649}

804// --- Named QoS profiles (RFC-0089 W3.f; bound to one table, phase-428 W10) ---
805//
806// Each class below is a NAME for a row of `rclcpp::detail::qos_table`, and states
807// no policy of its own. Before W10 each carried its own literals, so
808// `SensorDataQoS` and `ServicesQoS` restated what `rclcpp::QoS::sensor_data()` and
809// `rclcpp::QoS::services()` already said, 400 lines up in the same header — the
810// shape upstream itself avoids: rclcpp's `SensorDataQoS` is
811// `QoSInitialization::from_rmw(rmw_qos_profile_sensor_data)`, a REFERENCE to the
812// rmw constant, never a re-transcription of it (`rclcpp/qos.hpp:391-399`).
813//
814// The reason a name-only class is still worth having is unchanged: two of these
815// shipped WRONG, which is why the values are pinned by a test rather than by
816// review.
817//
818// * `ParametersQoS()` returned `QoS(10)` where `rmw_qos_profile_parameters`
819// is KEEP_LAST/**1000** — a hundredfold history difference under a name
820// that claims to be the ROS 2 profile, costing samples under load with
821// nothing to read.
822// * `SystemDefaultsQoS()` returned `QoS(10)`, which is
823// `rmw_qos_profile_default` — a DIFFERENT upstream profile. It is now
824// REFUSE-LOUD; see the class below for why no value can be right.
825//
826// The upstream sources, and the three fields folded into `QoS()` rather than
827// spelled per row, are documented on `qos_table` itself — one place, because
828// that is the whole point of this work item.
829//
830// These are CLASSES, as upstream's are, so `rclcpp::SensorDataQoS{}` — the
831// brace form — compiles alongside `rclcpp::SensorDataQoS()`. They are
832// `constexpr`, so the table-driven check lives in `static_assert`s
833// (`tests/compile/ros2_api_adoption_stage2.cpp`) rather than in a runtime test
834// no embedded lane runs.
