101// -- Policy enums (phase 379 W5) ------------------------------------------
102//
103// At NAMESPACE scope and public, under rclcpp's names, because that is where a
104// ported node looks for them (`rclcpp::ReliabilityPolicy`, `qos.hpp:34-58`).
105// Three of these were PRIVATE members of `QoS` until phase-379 W5, which is why
106// the getters had to hand back `int` — a public getter cannot name a private
107// type. Ledger: `cpp:ReliabilityPolicy` and its three siblings.
108//
109// The two rclcpp enumerators we used to decline ARRIVED in phase-444 (issue
110// 1437), and the reason each was declined is the reason it is now needed:
111//
112// * `SystemDefault` — "defer to the middleware". Declined because nothing
113// DEFERS: the backend is linked at build time (RFC-0036). True of a
114// REQUEST, and a `QoS` is no longer only a request — `get_actual_qos()`
115// hands one back, and a backend CAN report that a policy was never stated.
116// * `Unknown` — declined as "a discovery artefact for a policy read off a
117// remote endpoint, and we do no dynamic discovery". It is not that: it is
118// what `rmw_*_get_actual_qos` owes for a policy the backend looked at and
119// cannot determine, on the LOCAL endpoint. `rmw_vtable.h` has always said
120// so, and until issue 1437 no implementation anywhere wrote one.
121//
122// What is still declined is `rclcpp::SystemDefaultsQoS` — the all-sentinel
123// PRESET, whose two RMWs resolve it to depth 1 and depth 42 (issue 0829).
124// A value a backend may REPORT is not a profile a caller may REQUEST, and the
125// refusal on that class stands (`NROS_RCLCPP_REFUSE_SYSTEM_DEFAULTS_QOS`).
126//
127// The enumerators are upstream's and SCOPED (phase-483 W1): one
128// `SystemDefault` and one `Unknown` per policy, reached as
129// `rclcpp::ReliabilityPolicy::Unknown`. The prefixed spellings
130// (`ReliabilityUnknown`, `LivelinessNone`) existed only because these were
131// unscoped enums, and the bare `rclcpp::Reliable` form went with them.

215constexpr uint32_t qos_window_ms(const Duration& d) {
216 return d.nanoseconds() <= 0 ? 0u
217 : d.nanoseconds() == INT64_MAX - 1
218 ? UINT32_MAX - 1u
219 : (d.nanoseconds() >= static_cast<int64_t>(UINT32_MAX - 1u) * 1000000 - 999999
220 ? UINT32_MAX
221 : static_cast<uint32_t>((d.nanoseconds() + 999999) / 1000000));
222}
223
231constexpr Duration qos_best_available_duration() {
232 return Duration::from_nanoseconds(INT64_MAX - 1);
233}
234
238constexpr Duration qos_window_duration(uint32_t ms) {
239 return ms == UINT32_MAX - 1u ? qos_best_available_duration()
240 : Duration::from_nanoseconds(static_cast<int64_t>(ms) * 1000000);
241}

463// ============================================================================
464// phase-417 G6 — profile comparison. `rclcpp::operator==(const QoS&, const QoS&)`
465// ============================================================================
466//
467// FREE functions, as upstream's are, and written from the PUBLIC accessors —
468// every one of the ten members has one, so no `friend` is needed and the
469// comparison stays a thing a reader can check against the accessor list.
470//
471// TEN hand-written comparisons rather than `= default`. `operator==() =
472// default` is C++20 and this surface's floor is `cxx_std_17`
473// (`packages/api/nros-cpp/CMakeLists.txt` — `target_compile_features(
474// nros-cpp-headers INTERFACE cxx_std_17)`), so the defaulted form would not
475// compile for the targets this header exists to serve. Still `constexpr`,
476// still no allocator, still no exceptions.
477//
478// Rust's `QoSProfile` derives `PartialEq, Eq` and has had this for nothing
479// since it existed; the ledger row `cpp:operator==` recorded the asymmetry as
480// having no platform reason, and it did not.
481//
482// The three time windows are compared through `Duration::nanoseconds()`: the
483// storage is milliseconds and the conversion is exact in both directions
484// (`detail::qos_window_duration`).
485
491constexpr bool operator==(const QoS& left, const QoS& right) {
492 return left.reliability() == right.reliability() && left.durability() == right.durability() &&
493 left.history() == right.history() && left.liveliness() == right.liveliness() &&
494 left.depth() == right.depth() &&
495 left.deadline().nanoseconds() == right.deadline().nanoseconds() &&
496 left.lifespan().nanoseconds() == right.lifespan().nanoseconds() &&
497 left.liveliness_lease_duration().nanoseconds() ==
498 right.liveliness_lease_duration().nanoseconds() &&
499 left.avoid_ros_namespace_conventions() == right.avoid_ros_namespace_conventions() &&
500 left.tx_express() == right.tx_express();
501}
502
505constexpr bool operator!=(const QoS& left, const QoS& right) {
506 return !(left == right);
507}

561// --- THE C++ QoS profile table (phase-428 W10) -------------------------------
562//
563// Every named profile the C++ surface offers is spelled HERE and nowhere else.
564// `rclcpp::QoS`'s three named statics and all six concrete `rclcpp::*QoS` classes
565// are defined by calling into this block; none of them restates a policy.
566//
567// Why a table and not a hand copy per class: W10 exists because upstream's 7
568// profiles were transcribed in four places across the repo — this header,
569// `nros-rmw/src/traits.rs`, `nros/src/lib.rs` and `nros-rmw-abi/.../
570// rmw_entity.h` — about 26 constants for a 7-row table, with no gate binding
571// them. `QOS_PROFILE_PARAMETER_EVENTS` is the proof: `KeepAll, 0` in Rust under
572// a comment claiming it matched `rmw_qos_profile_parameter_events`, which is
573// `KEEP_LAST, 1000`. This header had the same profile right, which is exactly
574// what an ungated mirror looks like until the day it is not.
575//
576// This block cannot CONSUME the cross-language SSoT. The C spellings in
577// `rmw_entity.h` are `((rmw_qos_profile_t){...})` compound literals, which are
578// C99 and not standard C++, over a struct whose field types differ from
579// `nros_cpp_qos_t`'s; and `qos.hpp` is deliberately self-contained and
580// freestanding (see issue 0112 at the top of this file), so it cannot take a
581// dependency on a build-generated header either. What the table DOES buy is
582// that the C++ side has ONE row per profile for a cross-language gate to read,
583// instead of nine constructor bodies to parse.
584//
585// phase-454 W1 collected on that. `scripts/check-qos-profile-ssot.py` now
586// EVALUATES these rows — the ctor supplies the base profile and each chained
587// call applies its one effect — and compares every field against
588// `QoSProfile::QOS_PROFILE_*`. So the table is bound after all; what it is not
589// is DERIVED, which is the weaker of the two and the strongest available to a
590// freestanding header. A `.setter()` the gate does not model is a hard failure
591// there, not a skipped field.
592//
593// Values read 2026-09-05 against ROS 2 Humble as installed:
594// /opt/ros/humble/include/rmw/rmw/qos_profiles.h :25,38,51,64,77,90
595// /opt/ros/humble/include/rcl/rcl/logging_rosout.h :36
596// /opt/ros/humble/include/rclcpp/rclcpp/qos.hpp :371-500
597//
598// Three fields are identical in EVERY upstream profile and are therefore folded
599// into `QoS`'s default constructor rather than spelled per row:
600// * `avoid_ros_namespace_conventions` is `false` upstream, `0` here.
601// * liveliness is `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT` upstream, and
602// `rclcpp::QoS` now defaults to `LivelinessPolicy::SystemDefault`, which is our spelling of
603// that sentinel. It defaulted to `LivelinessAutomatic` — "what every
604// reference RMW folds that sentinel to" — under a
605// `nros-qos-mirror-deviation` record whose own reason was that this
606// surface and `nros-c`'s "move together with the C ABI or not at all".
607// They moved together (issue 1329): this constructor, `nros-c`'s
608// `NROS_QOS_*` statics and (until phase-492 W4) `component.h`'s
609// `rclc_c_qos_default()`.
610//
611// The forcing argument is issue 1329's per-backend QoS mask. XRCE honours
612// no liveliness, so an AUTOMATIC default would have made
613// `required_policies()` demand `LIVELINESS_AUTOMATIC` and refuse every C++
614// default profile on that backend — over a policy upstream leaves unset
615// and the application never asked for. A caller that wants automatic
616// liveliness states `.liveliness(rclcpp::LivelinessPolicy::Automatic)`.
617//
618// * deadline and the liveliness lease are `RMW_QOS_*_DEFAULT` (infinite)
619// upstream and `0` here, which `qos_window_ms` above documents as infinite.
620//
621// `rmw_qos_profile_system_default` has NO row: every one of its fields is a
622// sentinel, so no value could be right. `rclcpp::SystemDefaultsQoS` refuses at
623// compile time instead — see the class below.

692constexpr nros_cpp_qos_t qos_to_ffi(const QoS& qos) {
693 nros_cpp_qos_t f{};
694 f.reliability = static_cast<nros_cpp_qos_reliability_t>(qos.reliability());
695 f.durability = static_cast<nros_cpp_qos_durability_t>(qos.durability());
696 f.history = static_cast<nros_cpp_qos_history_t>(qos.history());
697 f.liveliness_kind = static_cast<nros_cpp_qos_liveliness_t>(qos.liveliness());
698 f.depth = qos.depth();
699 // The FFI FIELDS are milliseconds and keep their `_ms` names; only the
700 // accessors changed. `qos_window_ms` is the exact inverse of the
701 // `Duration` the getter built, so this round-trip loses nothing.
702 f.deadline_ms = qos_window_ms(qos.deadline());
703 f.lifespan_ms = qos_window_ms(qos.lifespan());
704 f.liveliness_lease_ms = qos_window_ms(qos.liveliness_lease_duration());
705 f.avoid_ros_namespace_conventions = qos.avoid_ros_namespace_conventions() ? 1 : 0;
706 f.tx_express = qos.tx_express() ? 1 : 0;
707 return f;
708}

863// --- Named QoS profiles (RFC-0089 W3.f; bound to one table, phase-428 W10) ---
864//
865// Each class below is a NAME for a row of `rclcpp::detail::qos_table`, and states
866// no policy of its own. Before W10 each carried its own literals, so
867// `SensorDataQoS` and `ServicesQoS` restated what `rclcpp::QoS::sensor_data()` and
868// `rclcpp::QoS::services()` already said, 400 lines up in the same header — the
869// shape upstream itself avoids: rclcpp's `SensorDataQoS` is
870// `QoSInitialization::from_rmw(rmw_qos_profile_sensor_data)`, a REFERENCE to the
871// rmw constant, never a re-transcription of it (`rclcpp/qos.hpp:391-399`).
872//
873// The reason a name-only class is still worth having is unchanged: two of these
874// shipped WRONG, which is why the values are pinned by a test rather than by
875// review.
876//
877// * `ParametersQoS()` returned `QoS(10)` where `rmw_qos_profile_parameters`
878// is KEEP_LAST/**1000** — a hundredfold history difference under a name
879// that claims to be the ROS 2 profile, costing samples under load with
880// nothing to read.
881// * `SystemDefaultsQoS()` returned `QoS(10)`, which is
882// `rmw_qos_profile_default` — a DIFFERENT upstream profile. It is now
883// REFUSE-LOUD; see the class below for why no value can be right.
884//
885// The upstream sources, and the three fields folded into `QoS()` rather than
886// spelled per row, are documented on `qos_table` itself — one place, because
887// that is the whole point of this work item.
888//
889// These are CLASSES, as upstream's are, so `rclcpp::SensorDataQoS{}` — the
890// brace form — compiles alongside `rclcpp::SensorDataQoS()`. They are
891// `constexpr`, so the table-driven check lives in `static_assert`s
892// (`tests/compile/ros2_api_adoption_stage2.cpp`) rather than in a runtime test
893// no embedded lane runs.
