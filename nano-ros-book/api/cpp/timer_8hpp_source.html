237// ============================================================================
238// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
239// ============================================================================
240//
241// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
242// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
243// destructor and `detail::WallTimer : TimerBase` under it — exactly the
244// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
245// ruling is DELETE, and it is argued from the executor's dispatch:
246//
247// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
248// and there is no virtual call through a `TimerBase*` anywhere in the
249// tree — there cannot be. The executor's callback slot is
250// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
251// through the STATIC `detail::WallTimer::trampoline`. The executor never
252// holds a C++ timer object, so it never needs a type-erased base. Even
253// the destructor's virtuality was dead: the cell is built with
254// `std::make_shared<detail::WallTimer>()`, so the control block already
255// records the CONCRETE deleter and destruction through a base pointer was
256// correct without it. A vtable no dispatch uses is cost with no caller,
257// which is what clause 1 of the governing principle refuses.
258//
259// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
260// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
261// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
262// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
263// never a type parameter — phase-425 landed ROS time in exactly that
264// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
265// the header itself refuses two paragraphs later.
266//
267// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer` now
268// returns `std::shared_ptr<::nros::Timer>` aliased onto the private cell,
269// which is what `create_subscription` has always done. The returned type
270// is the type that actually exists, and the cell stays an implementation
271// detail instead of being half-exposed as a base class.
272//
273// The migration cost is one mechanical rename the compiler demands:
274// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
275// timer_;`. That is the compile-or-conform rule working as designed, and it is
276// what the RFC calls the honest outcome — we do not have the hierarchy, so we
277// do not take the name for it. Zero non-test call sites in this tree used it.
278//
279// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
280// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
281// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
282// appearing in the recorded upstream surface.
283//
284// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
285//
286// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
287// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
288// fires every spin. Activations land on spin boundaries either way, so the
289// achievable cadence was already the spin period — the truncation only
290// makes the floor explicit.
291// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
292// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
293// after a stall the callback runs once per `spin_once` until the backlog is
294// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
295// whole missed periods and re-phases onto the grid, firing once. Closing
296// the gap means a missed-deadline POLICY on the executor's timer —
297// Rust-side work, not a loop re-added here (issue 1041).
298//
299// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
300// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
301// arithmetic, the missed-deadline policy and the clock are the executor's,
302// Rust-side. Until this landed, `WallTimer` carried its own
303// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
304// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
305// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
306// loop.
307

309// `NROS_CPP_HAS_STD_FUNCTION` from the detection site included at the top.
