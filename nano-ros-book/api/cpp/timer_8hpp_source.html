361// ============================================================================
362// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
363// ============================================================================
364//
365// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
366// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
367// destructor and `detail::WallTimer : TimerBase` under it — exactly the
368// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
369// ruling is DELETE, and it is argued from the executor's dispatch:
370//
371// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
372// and there is no virtual call through a `TimerBase*` anywhere in the
373// tree — there cannot be. The executor's callback slot is
374// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
375// through the STATIC `detail::WallTimer::trampoline`. The executor never
376// holds a C++ timer object, so it never needs a type-erased base. Even
377// the destructor's virtuality was dead: the cell is built with
378// `std::make_shared<detail::WallTimer>()`, so the control block already
379// records the CONCRETE deleter and destruction through a base pointer was
380// correct without it. A vtable no dispatch uses is cost with no caller,
381// which is what clause 1 of the governing principle refuses.
382//
383// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
384// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
385// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
386// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
387// never a type parameter — phase-425 landed ROS time in exactly that
388// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
389// the header itself refuses two paragraphs later.
390//
391// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer`
392// returned `std::shared_ptr<::rclcpp::Timer>` aliased onto a private cell,
393// as `create_subscription` did. Since phase-476 W2 both return a two-word
394// handle and there is no cell: the callable is in the executor arena.
395//
396// The migration cost is one mechanical rename the compiler demands:
397// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
398// timer_;`. That is the compile-or-conform rule working as designed, and it is
399// what the RFC calls the honest outcome — we do not have the hierarchy, so we
400// do not take the name for it. Zero non-test call sites in this tree used it.
401//
402// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
403// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
404// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
405// appearing in the recorded upstream surface.
406//
407// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
408//
409// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
410// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
411// fires every spin. Activations land on spin boundaries either way, so the
412// achievable cadence was already the spin period — the truncation only
413// makes the floor explicit.
414// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
415// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
416// after a stall the callback runs once per `spin_once` until the backlog is
417// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
418// whole missed periods and re-phases onto the grid, firing once. Closing
419// the gap means a missed-deadline POLICY on the executor's timer —
420// Rust-side work, not a loop re-added here (issue 1041).
421//
422// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
423// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
424// arithmetic, the missed-deadline policy and the clock are the executor's,
425// Rust-side. Until this landed, `WallTimer` carried its own
426// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
427// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
428// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
429// loop.
