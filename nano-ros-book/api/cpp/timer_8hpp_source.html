362// ============================================================================
363// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
364// ============================================================================
365//
366// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
367// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
368// destructor and `detail::WallTimer : TimerBase` under it — exactly the
369// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
370// ruling is DELETE, and it is argued from the executor's dispatch:
371//
372// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
373// and there is no virtual call through a `TimerBase*` anywhere in the
374// tree — there cannot be. The executor's callback slot is
375// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
376// through the STATIC `detail::WallTimer::trampoline`. The executor never
377// holds a C++ timer object, so it never needs a type-erased base. Even
378// the destructor's virtuality was dead: the cell is built with
379// `std::make_shared<detail::WallTimer>()`, so the control block already
380// records the CONCRETE deleter and destruction through a base pointer was
381// correct without it. A vtable no dispatch uses is cost with no caller,
382// which is what clause 1 of the governing principle refuses.
383//
384// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
385// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
386// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
387// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
388// never a type parameter — phase-425 landed ROS time in exactly that
389// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
390// the header itself refuses two paragraphs later.
391//
392// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer`
393// returned `std::shared_ptr<::nros::Timer>` aliased onto a private cell,
394// as `create_subscription` did. Since phase-476 W2 both return a two-word
395// handle and there is no cell: the callable is in the executor arena.
396//
397// The migration cost is one mechanical rename the compiler demands:
398// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
399// timer_;`. That is the compile-or-conform rule working as designed, and it is
400// what the RFC calls the honest outcome — we do not have the hierarchy, so we
401// do not take the name for it. Zero non-test call sites in this tree used it.
402//
403// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
404// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
405// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
406// appearing in the recorded upstream surface.
407//
408// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
409//
410// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
411// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
412// fires every spin. Activations land on spin boundaries either way, so the
413// achievable cadence was already the spin period — the truncation only
414// makes the floor explicit.
415// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
416// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
417// after a stall the callback runs once per `spin_once` until the backlog is
418// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
419// whole missed periods and re-phases onto the grid, firing once. Closing
420// the gap means a missed-deadline POLICY on the executor's timer —
421// Rust-side work, not a loop re-added here (issue 1041).
422//
423// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
424// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
425// arithmetic, the missed-deadline policy and the clock are the executor's,
426// Rust-side. Until this landed, `WallTimer` carried its own
427// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
428// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
429// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
430// loop.
