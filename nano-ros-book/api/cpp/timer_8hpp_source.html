428// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
429// ============================================================================
430//
431// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
432// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
433// destructor and `detail::WallTimer : TimerBase` under it — exactly the
434// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
435// ruling is DELETE, and it is argued from the executor's dispatch:
436//
437// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
438// and there is no virtual call through a `TimerBase*` anywhere in the
439// tree — there cannot be. The executor's callback slot is
440// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
441// through the STATIC `detail::WallTimer::trampoline`. The executor never
442// holds a C++ timer object, so it never needs a type-erased base. Even
443// the destructor's virtuality was dead: the cell is built with
444// `std::make_shared<detail::WallTimer>()`, so the control block already
445// records the CONCRETE deleter and destruction through a base pointer was
446// correct without it. A vtable no dispatch uses is cost with no caller,
447// which is what clause 1 of the governing principle refuses.
448//
449// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
450// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
451// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
452// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
453// never a type parameter — phase-425 landed ROS time in exactly that
454// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
455// the header itself refuses two paragraphs later.
456//
457// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer`
458// returned `std::shared_ptr<::rclcpp::Timer>` aliased onto a private cell,
459// as `create_subscription` did. Since phase-476 W2 both return a two-word
460// handle and there is no cell: the callable is in the executor arena.
461//
462// The migration cost is one mechanical rename the compiler demands:
463// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
464// timer_;`. That is the compile-or-conform rule working as designed, and it is
465// what the RFC calls the honest outcome — we do not have the hierarchy, so we
466// do not take the name for it. Zero non-test call sites in this tree used it.
467//
468// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
469// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
470// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
471// appearing in the recorded upstream surface.
472//
473// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
474//
475// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
476// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
477// fires every spin. Activations land on spin boundaries either way, so the
478// achievable cadence was already the spin period — the truncation only
479// makes the floor explicit.
480// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
481// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
482// after a stall the callback runs once per `spin_once` until the backlog is
483// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
484// whole missed periods and re-phases onto the grid, firing once. Closing
485// the gap means a missed-deadline POLICY on the executor's timer —
486// Rust-side work, not a loop re-added here (issue 1041).
487//
488// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
489// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
490// arithmetic, the missed-deadline policy and the clock are the executor's,
491// Rust-side. Until this landed, `WallTimer` carried its own
492// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
493// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
494// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
495// loop.
