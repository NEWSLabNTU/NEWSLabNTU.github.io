172// ============================================================================
173// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
174// ============================================================================
175//
176// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
177// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
178// destructor and `detail::WallTimer : TimerBase` under it — exactly the
179// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
180// ruling is DELETE, and it is argued from the executor's dispatch:
181//
182// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
183// and there is no virtual call through a `TimerBase*` anywhere in the
184// tree — there cannot be. The executor's callback slot is
185// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
186// through the STATIC `detail::WallTimer::trampoline`. The executor never
187// holds a C++ timer object, so it never needs a type-erased base. Even
188// the destructor's virtuality was dead: the cell is built with
189// `std::make_shared<detail::WallTimer>()`, so the control block already
190// records the CONCRETE deleter and destruction through a base pointer was
191// correct without it. A vtable no dispatch uses is cost with no caller,
192// which is what clause 1 of the governing principle refuses.
193//
194// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
195// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
196// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
197// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
198// never a type parameter — phase-425 landed ROS time in exactly that
199// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
200// the header itself refuses two paragraphs later.
201//
202// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer` now
203// returns `std::shared_ptr<::nros::Timer>` aliased onto the private cell,
204// which is what `create_subscription` has always done. The returned type
205// is the type that actually exists, and the cell stays an implementation
206// detail instead of being half-exposed as a base class.
207//
208// The migration cost is one mechanical rename the compiler demands:
209// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
210// timer_;`. That is the compile-or-conform rule working as designed, and it is
211// what the RFC calls the honest outcome — we do not have the hierarchy, so we
212// do not take the name for it. Zero non-test call sites in this tree used it.
213//
214// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
215// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
216// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
217// appearing in the recorded upstream surface.
218//
219// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
220//
221// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
222// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
223// fires every spin. Activations land on spin boundaries either way, so the
224// achievable cadence was already the spin period — the truncation only
225// makes the floor explicit.
226// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
227// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
228// after a stall the callback runs once per `spin_once` until the backlog is
229// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
230// whole missed periods and re-phases onto the grid, firing once. Closing
231// the gap means a missed-deadline POLICY on the executor's timer —
232// Rust-side work, not a loop re-added here (issue 1041).
233//
234// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
235// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
236// arithmetic, the missed-deadline policy and the clock are the executor's,
237// Rust-side. Until this landed, `WallTimer` carried its own
238// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
239// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
240// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
241// loop.
242

244// `NROS_CPP_HAS_STD_FUNCTION` from the detection site included at the top.
