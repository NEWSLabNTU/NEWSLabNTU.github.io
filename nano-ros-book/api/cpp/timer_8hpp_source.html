175// ============================================================================
176// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
177// ============================================================================
178//
179// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
180// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
181// destructor and `detail::WallTimer : TimerBase` under it — exactly the
182// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
183// ruling is DELETE, and it is argued from the executor's dispatch:
184//
185// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
186// and there is no virtual call through a `TimerBase*` anywhere in the
187// tree — there cannot be. The executor's callback slot is
188// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
189// through the STATIC `detail::WallTimer::trampoline`. The executor never
190// holds a C++ timer object, so it never needs a type-erased base. Even
191// the destructor's virtuality was dead: the cell is built with
192// `std::make_shared<detail::WallTimer>()`, so the control block already
193// records the CONCRETE deleter and destruction through a base pointer was
194// correct without it. A vtable no dispatch uses is cost with no caller,
195// which is what clause 1 of the governing principle refuses.
196//
197// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
198// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
199// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
200// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
201// never a type parameter — phase-425 landed ROS time in exactly that
202// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
203// the header itself refuses two paragraphs later.
204//
205// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer` now
206// returns `std::shared_ptr<::nros::Timer>` aliased onto the private cell,
207// which is what `create_subscription` has always done. The returned type
208// is the type that actually exists, and the cell stays an implementation
209// detail instead of being half-exposed as a base class.
210//
211// The migration cost is one mechanical rename the compiler demands:
212// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
213// timer_;`. That is the compile-or-conform rule working as designed, and it is
214// what the RFC calls the honest outcome — we do not have the hierarchy, so we
215// do not take the name for it. Zero non-test call sites in this tree used it.
216//
217// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
218// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
219// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
220// appearing in the recorded upstream surface.
221//
222// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
223//
224// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
225// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
226// fires every spin. Activations land on spin boundaries either way, so the
227// achievable cadence was already the spin period — the truncation only
228// makes the floor explicit.
229// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
230// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
231// after a stall the callback runs once per `spin_once` until the backlog is
232// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
233// whole missed periods and re-phases onto the grid, firing once. Closing
234// the gap means a missed-deadline POLICY on the executor's timer —
235// Rust-side work, not a loop re-added here (issue 1041).
236//
237// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
238// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
239// arithmetic, the missed-deadline policy and the clock are the executor's,
240// Rust-side. Until this landed, `WallTimer` carried its own
241// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
242// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
243// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
244// loop.
245
246// `<functional>` for the type-erased callback cell. Gated for the same reason
247// `<memory>` is above — issue 0112, rationale in `publisher.hpp`.
