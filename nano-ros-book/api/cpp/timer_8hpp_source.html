184// ============================================================================
185// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
186// ============================================================================
187//
188// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
189// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
190// destructor and `detail::WallTimer : TimerBase` under it — exactly the
191// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
192// ruling is DELETE, and it is argued from the executor's dispatch:
193//
194// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
195// and there is no virtual call through a `TimerBase*` anywhere in the
196// tree — there cannot be. The executor's callback slot is
197// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
198// through the STATIC `detail::WallTimer::trampoline`. The executor never
199// holds a C++ timer object, so it never needs a type-erased base. Even
200// the destructor's virtuality was dead: the cell is built with
201// `std::make_shared<detail::WallTimer>()`, so the control block already
202// records the CONCRETE deleter and destruction through a base pointer was
203// correct without it. A vtable no dispatch uses is cost with no caller,
204// which is what clause 1 of the governing principle refuses.
205//
206// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
207// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
208// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
209// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
210// never a type parameter — phase-425 landed ROS time in exactly that
211// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
212// the header itself refuses two paragraphs later.
213//
214// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer` now
215// returns `std::shared_ptr<::nros::Timer>` aliased onto the private cell,
216// which is what `create_subscription` has always done. The returned type
217// is the type that actually exists, and the cell stays an implementation
218// detail instead of being half-exposed as a base class.
219//
220// The migration cost is one mechanical rename the compiler demands:
221// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
222// timer_;`. That is the compile-or-conform rule working as designed, and it is
223// what the RFC calls the honest outcome — we do not have the hierarchy, so we
224// do not take the name for it. Zero non-test call sites in this tree used it.
225//
226// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
227// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
228// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
229// appearing in the recorded upstream surface.
230//
231// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
232//
233// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
234// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
235// fires every spin. Activations land on spin boundaries either way, so the
236// achievable cadence was already the spin period — the truncation only
237// makes the floor explicit.
238// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
239// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
240// after a stall the callback runs once per `spin_once` until the backlog is
241// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
242// whole missed periods and re-phases onto the grid, firing once. Closing
243// the gap means a missed-deadline POLICY on the executor's timer —
244// Rust-side work, not a loop re-added here (issue 1041).
245//
246// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
247// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
248// arithmetic, the missed-deadline policy and the clock are the executor's,
249// Rust-side. Until this landed, `WallTimer` carried its own
250// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
251// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
252// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
253// loop.
254
255// The type-erased callback cell needs `<functional>`, which arrives with
256// `NROS_CPP_HAS_STD_FUNCTION` from the detection site included at the top.
