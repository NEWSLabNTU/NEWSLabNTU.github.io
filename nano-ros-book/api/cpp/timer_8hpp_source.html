181// ============================================================================
182// rclcpp::Timer — FLAT. No `TimerBase`, no hierarchy (phase-430 W7 ruling)
183// ============================================================================
184//
185// RFC-0089 §"Timer, studied against RTOS semantics" decided this and the tree
186// disagreed with it: phase-417 W1.a had landed `class TimerBase` with a virtual
187// destructor and `detail::WallTimer : TimerBase` under it — exactly the
188// hierarchy the RFC refused. phase-430 W7 called for a ruling either way. The
189// ruling is DELETE, and it is argued from the executor's dispatch:
190//
191// 1. THE VTABLE HAS NO CALLER. The only virtual member was `~TimerBase()`,
192// and there is no virtual call through a `TimerBase*` anywhere in the
193// tree — there cannot be. The executor's callback slot is
194// `nros_cpp_timer_callback_t`, a raw `void(*)(void*)`, and dispatch goes
195// through the STATIC `detail::WallTimer::trampoline`. The executor never
196// holds a C++ timer object, so it never needs a type-erased base. Even
197// the destructor's virtuality was dead: the cell is built with
198// `std::make_shared<detail::WallTimer>()`, so the control block already
199// records the CONCRETE deleter and destruction through a base pointer was
200// correct without it. A vtable no dispatch uses is cost with no caller,
201// which is what clause 1 of the governing principle refuses.
202//
203// 2. THE NAME PROMISES CHILDREN WE REFUSE TO HAVE. `WallTimer` and
204// `GenericTimer` are upstream's siblings under `TimerBase`, and both stay
205// absent by decision: the clock axis is a RUNTIME FIELD on the flat timer
206// plus a second VERB (`create_timer(clock, …)` beside `create_wall_timer`),
207// never a type parameter — phase-425 landed ROS time in exactly that
208// shape. A base whose one leaf is `detail::`-private advertises a taxonomy
209// the header itself refuses two paragraphs later.
210//
211// 3. THE FLAT SHAPE IS A STRICTLY BETTER KEEP-ALIVE. `create_wall_timer` now
212// returns `std::shared_ptr<::nros::Timer>` aliased onto the private cell,
213// which is what `create_subscription` has always done. The returned type
214// is the type that actually exists, and the cell stays an implementation
215// detail instead of being half-exposed as a base class.
216//
217// The migration cost is one mechanical rename the compiler demands:
218// `rclcpp::TimerBase::SharedPtr timer_;` becomes `rclcpp::Timer::SharedPtr
219// timer_;`. That is the compile-or-conform rule working as designed, and it is
220// what the RFC calls the honest outcome — we do not have the hierarchy, so we
221// do not take the name for it. Zero non-test call sites in this tree used it.
222//
223// `rclcpp::Timer` is an ours-only name in upstream's namespace (RFC-0089
224// §"Settled: `nros::` is phased out entirely"), so it carries a ledger row with
225// `disposition: extension` and the collision gate watches for `rclcpp::Timer`
226// appearing in the recorded upstream surface.
227//
228// ADOPT-BOUNDED, and both halves of the envelope come with the executor:
229//
230// * PERIOD RESOLUTION IS ONE MILLISECOND. `nros_cpp_timer_create` takes a
231// `uint64_t period_ms`, so `create_wall_timer(500us, …)` truncates to 0 and
232// fires every spin. Activations land on spin boundaries either way, so the
233// achievable cadence was already the spin period — the truncation only
234// makes the floor explicit.
235// * MISSED DEADLINES CATCH UP, where rcl's DROP. `TimerState::fire` keeps the
236// overshoot (`elapsed_ms -= period_ms`, `nros-node/src/timer.rs:298`), so
237// after a stall the callback runs once per `spin_once` until the backlog is
238// drained and the mean cadence is preserved. `rcl_timer_call` instead skips
239// whole missed periods and re-phases onto the grid, firing once. Closing
240// the gap means a missed-deadline POLICY on the executor's timer —
241// Rust-side work, not a loop re-added here (issue 1041).
242//
243// phase-417 — ONE DISPATCH PATH. `create_wall_timer` registers an EXECUTOR
244// timer via `rclcpp::Node::create_wall_timer` (`node.hpp`), so the period
245// arithmetic, the missed-deadline policy and the clock are the executor's,
246// Rust-side. Until this landed, `WallTimer` carried its own
247// `std::chrono::steady_clock` deadline and a `Node::pump()` fired it from
248// `rclcpp::spin` / `spin_some` ONLY. Scheduling in the wrapper is
249// RFC-0019/RFC-0020 violation class 2. Do not reintroduce a second dispatch
250// loop.
251
252// The type-erased callback cell needs `<functional>`, which arrives with
253// `NROS_CPP_HAS_STD_FUNCTION` from the detection site included at the top.
