Detailed Description

template<typename A>
class rclcpp_action::ClientGoalHandle< A >

rclcpp_action::ClientGoalHandle<A> — issue 2015, upstream's client-side per-goal handle.

On a HOSTED build (NROS_CPP_STD) it is what async_send_goal's SendGoalOptions callbacks receive, as upstream's SharedPtr (std::shared_ptr): the goal id and status, and — nested — the WrappedResult the result callback gets. It owns no futures and no subscription (the client does; the handle is a heap token over the goal id). A freestanding build has no allocator for it: SharedPtr and WrappedResult are refused there, and the client's goal-id-keyed callbacks (set_callbacks) are the form.
