Detailed Description

template<typename A>
class rclcpp_action::ServerGoalHandle< A >

rclcpp_action::ServerGoalHandle<A> — issue 2015, upstream's per-goal handle on a HOSTED build.

A token over (server, goal id), plus the goal message the goal callback was handed: every call forwards to the server keyed by the id, and the goal's state stays in the server's static arena (RFC-0019). Obtained only as the std::shared_ptr upstream's handle_cancel / handle_accepted receive; a freestanding build has no allocator for it, so SharedPtr is refused there and the goal-id-keyed Server<A> calls are the form.

Envelope: the handle names its server by address, so the server must not move while a handle is in use (it lives in a SharedPtr, which does not move it). Called from the executor's own task only — a goal handle used from a thread the application started races the executor (RFC-0002: no hidden threads, and no lock on a one-level image); run the goal from the accepted callback, or from a timer.
