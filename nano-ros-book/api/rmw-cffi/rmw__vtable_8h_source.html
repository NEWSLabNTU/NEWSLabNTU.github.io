4/* Phase 376 W3.a — this header defines the GENERIC RMW ABI: its types are
5 * `rmw_publisher_t`, `rmw_ret_t`, and so on, with no vendor prefix, because a
6 * backend author implements RMW rather than nano-ros.
7 *
8 * That makes it impossible to share a translation unit with upstream's

78/* ---- Phase 376 W4 — graph enumeration visitors ----
79 *
80 * Upstream returns `rcutils_string_array_t` and `rmw_names_and_types_t`, which
81 * ALLOCATE — two levels deep for names-and-types. There is no allocator at this
82 * seam, and a caller-provides-the-buffer shape is worse than it looks: the ROS
83 * graph has no bound the CALLER can know, so a 128 KiB image would have to
84 * reserve permanently for the worst graph it might ever meet, and the backend
85 * would still have to materialise the whole list to fill the buffer.
86 *
87 * So enumeration is a VISITOR. Peak extra RAM is one entry, the backend streams
88 * from state it already holds, and a caller with a bound stops early by
89 * returning `false` — a normal outcome, not a truncation error. Same shape as
90 * `process_raw_in_place` and `publish_streamed` already use here.
91 *
92 * Every string handed to a visitor is BORROWED for that call only.
93 */

177 *
178 * These six returned `void`. That was never a target constraint: upstream
179 * returns `rmw_ret_t` from all of them, and a backend that cannot release a

394 /* ---- Status events: how the three upstream parts map here ----
395 *
396 * Upstream's model is three-part: `*_event_init` fills an `rmw_event_t`
397 * HANDLE, `rmw_event_set_callback` attaches a callback to that handle, and
398 * `rmw_take_event` polls it for a status.
399 *
400 * - `rmw_event_set_callback` is FUSED into `*_event_init`, which takes the
401 * callback directly. There is no handle to attach one to afterwards.
402 * What that costs is real and small: upstream can replace or clear a
403 * callback later, and we cannot.
404 *
405 * - `rmw_take_event` is a SLOT (issue 0780), split per entity kind
406 * because we have no `rmw_event_t` to carry the entity — see
407 * `subscription_take_event` / `publisher_take_event` below.
408 *
409 * It was DECLINED until 2026-08-25 on two clauses that both turned out
410 * false, and they are worth recording because each sounded right:
411 *
412 * "Upstream polls because the WAIT SET said one was ready, and the wait
413 * set is declined here, so a poll would be blind."
414 * — This ABI is a poll-WITHOUT-a-wait-set design by construction.
415 * `has_data`'s own doc says so: "the poll a loop with no wait-set
416 * needs, and it allocates nothing." A poll with no wait set is the
417 * model here, not a blindness.
418 *
419 * "Our callback already runs on the safe context — from inside
420 * `drive_io`, on the executor thread, never an ISR or a transport
421 * thread."
422 * — True of no backend. zenoh fires from `try_recv_raw` and
423 * `has_data`; cyclonedds' DDS listeners fire on Cyclone's own
424 * worker thread while its `drive_io` is a sleep with no callback
425 * path at all. So a cyclonedds status event has nowhere safe to be
426 * delivered from, and buffer-plus-poll IS `take_event`. A
427 * per-backend fact stated ABI-wide — the same shape as the
428 * network-flow decline W5 flipped.
429 */

1095 /* ---- Phase 376 W4 — graph node lifecycle (optional) ----
1096 *
1097 * The rest of upstream's lifecycle group is deliberately absent, and the
1098 * absences are decisions rather than omissions:
1099 *
1100 * - `rmw_init` / `rmw_shutdown` / `rmw_context_fini` are
1101 * `create_session` / `destroy_session`. There is no second teardown
1102 * phase: the session shell is caller-owned, so there is nothing left to
1103 * free after the backend releases `backend_data`.
1104 *
1105 * - `rmw_init_options_{init,copy,fini}` have nothing to do here. Upstream
1106 * needs the trio because its options OWN heap and carry an
1107 * `rcutils_allocator_t`, which cannot cross this seam; ours is a
1108 * build-time POD, so "copy" is `=` and "fini" is nothing.
1109 *
1110 * This does NOT decide what the options CARRY. Of Humble's eight
1111 * fields, `create_session` takes `domain_id`; `implementation_identifier`
1112 * and `impl` are answered elsewhere (the identity slot,
1113 * `rmw_session_t::backend_data`); `allocator` is declined ABI-wide and
1114 * `instance_id` is rcl-side process identity. `security_options` is
1115 * declined on the target: it is a DDS-SROS2 keystore PATH plus an
1116 * enforcement switch, and neither a filesystem nor a security plugin
1117 * exists where this ABI runs. `localhost_only` and `enclave` are real
1118 * GAPS — issue 0785, to be carried by whatever shape issue 0808 gives
1119 * backend-private session config, because this flat argument list
1120 * cannot grow either without another ABI break.
1121 *
1122 * `discovery_options` is NOT in this list: it is an IRON field, and the
1123 * recorded contract is Humble. It was named here until issue 0785, the
1124 * third unchecked sentence about an upstream struct in this campaign
1125 * (issue 0777 supplied the other two). Read the header, not the memory.
1126 *
1127 * - `rmw_wait`, the wait set, and the guard conditions are declined
1128 * together, because `has_data` / `has_request` + `drive_io` +
1129 * `set_wake_callback` + `next_deadline_ms` ARE upstream's `rmw_wait`,
1130 * decomposed. What a vtable `wait` would add is only the BLOCK, moved
1131 * from the platform into the backend — and the block cannot live there:
1132 * one executor drives sessions from several backends at once
1133 * (`create_node_on(name, rmw)`), timers fire off the platform clock, and
1134 * guard conditions fire from another thread or an ISR. A backend can
1135 * only block on its own handles. `next_deadline_ms` is exactly the piece
1136 * of `rmw_wait` that CANNOT be answered above the seam, and it is
1137 * already a slot; that is the decomposition working, not a gap.
1138 */
