4/* Phase 376 W3.a — this header defines the GENERIC RMW ABI: its types are
5 * `rmw_publisher_t`, `rmw_ret_t`, and so on, with no vendor prefix, because a
6 * backend author implements RMW rather than nano-ros.
7 *
8 * That makes it impossible to share a translation unit with upstream's
9 * `<rmw/rmw.h>`, which defines the same names differently. Refuse LOUDLY rather
10 * than let one definition silently win a redefinition race — two types of one
11 * name whose layouts disagree is the class this repo has already paid for three
12 * times in hand-mirrored FFI structs.
13 *
14 * A target image never links real rmw, and host-side consumers reach the
15 * backend through Rust, so nothing in this repo trips this today. It exists for
16 * the day something does. */

81/* ---- Phase 376 W4 — graph enumeration visitors ----
82 *
83 * Upstream returns `rcutils_string_array_t` and `rmw_names_and_types_t`, which
84 * ALLOCATE — two levels deep for names-and-types. There is no allocator at this
85 * seam, and a caller-provides-the-buffer shape is worse than it looks: the ROS
86 * graph has no bound the CALLER can know, so a 128 KiB image would have to
87 * reserve permanently for the worst graph it might ever meet, and the backend
88 * would still have to materialise the whole list to fill the buffer.
89 *
90 * So enumeration is a VISITOR. Peak extra RAM is one entry, the backend streams
91 * from state it already holds, and a caller with a bound stops early by
92 * returning `false` — a normal outcome, not a truncation error. Same shape as
93 * `process_raw_in_place` and `publish_streamed` already use here.
94 *
95 * Every string handed to a visitor is BORROWED for that call only.
96 */

180 *
181 * These six returned `void`. That was never a target constraint: upstream
182 * returns `rmw_ret_t` from all of them, and a backend that cannot release a

432 /* ---- Status events: how the three upstream parts map here ----
433 *
434 * Upstream's model is three-part: `*_event_init` fills an `rmw_event_t`
435 * HANDLE, `rmw_event_set_callback` attaches a callback to that handle, and
436 * `rmw_take_event` polls it for a status.
437 *
438 * - `rmw_event_set_callback` is FUSED into `*_event_init`, which takes the
439 * callback directly. There is no handle to attach one to afterwards.
440 * What that costs is real and small: upstream can replace or clear a
441 * callback later, and we cannot.
442 *
443 * - `rmw_take_event` is a SLOT (issue 0780), split per entity kind
444 * because we have no `rmw_event_t` to carry the entity — see
445 * `subscription_take_event` / `publisher_take_event` below.
446 *
447 * It was DECLINED until 2026-08-25 on two clauses that both turned out
448 * false, and they are worth recording because each sounded right:
449 *
450 * "Upstream polls because the WAIT SET said one was ready, and the wait
451 * set is declined here, so a poll would be blind."
452 * — This ABI is a poll-WITHOUT-a-wait-set design by construction.
453 * `has_data`'s own doc says so: "the poll a loop with no wait-set
454 * needs, and it allocates nothing." A poll with no wait set is the
455 * model here, not a blindness.
456 *
457 * "Our callback already runs on the safe context — from inside
458 * `drive_io`, on the executor thread, never an ISR or a transport
459 * thread."
460 * — True of no backend. zenoh fires from `take` and
461 * `has_data`; cyclonedds' DDS listeners fire on Cyclone's own
462 * worker thread while its `drive_io` is a sleep with no callback
463 * path at all. So a cyclonedds status event has nowhere safe to be
464 * delivered from, and buffer-plus-poll IS `take_event`. A
465 * per-backend fact stated ABI-wide — the same shape as the
466 * network-flow decline W5 flipped.
467 */

1211 /* ---- Phase 376 W4 — graph node lifecycle (optional) ----
1212 *
1213 * The rest of upstream's lifecycle group is deliberately absent, and the
1214 * absences are decisions rather than omissions:
1215 *
1216 * - `rmw_init` / `rmw_shutdown` / `rmw_context_fini` are
1217 * `create_session` / `destroy_session`. There is no second teardown
1218 * phase: the session shell is caller-owned, so there is nothing left to
1219 * free after the backend releases `backend_data`.
1220 *
1221 * - `rmw_init_options_{init,copy,fini}` have nothing to do here. Upstream
1222 * needs the trio because its options OWN heap and carry an
1223 * `rcutils_allocator_t`, which cannot cross this seam; ours is a
1224 * build-time POD, so "copy" is `=` and "fini" is nothing.
1225 *
1226 * This does NOT decide what the options CARRY. Of Humble's eight
1227 * fields, `create_session` takes `domain_id`; `implementation_identifier`
1228 * and `impl` are answered elsewhere (the identity slot,
1229 * `rmw_session_t::backend_data`); `allocator` is declined ABI-wide and
1230 * `instance_id` is rcl-side process identity. `security_options` is
1231 * declined on the target: it is a DDS-SROS2 keystore PATH plus an
1232 * enforcement switch, and neither a filesystem nor a security plugin
1233 * exists where this ABI runs. `localhost_only` and `enclave` are
1234 * CARRIED, by `create_session`'s NULLable `rmw_session_options_t`
1235 * (issue 0808, which closed issue 0785's two gaps): Cyclone honours
1236 * `localhost_only` by restricting discovery to loopback, and a backend
1237 * with no discovery to restrict ignores both, as it does `mode`.
1238 *
1239 * `discovery_options` is NOT in this list: it is an IRON field, and the
1240 * recorded contract is Humble. It was named here until issue 0785, the
1241 * third unchecked sentence about an upstream struct in this campaign
1242 * (issue 0777 supplied the other two). Read the header, not the memory.
1243 *
1244 * - `rmw_wait`, the wait set, and the guard conditions are declined
1245 * together, because `has_data` / `has_request` + `drive_io` +
1246 * `set_wake_callback` + `next_deadline_ms` ARE upstream's `rmw_wait`,
1247 * decomposed. What a vtable `wait` would add is only the BLOCK, moved
1248 * from the platform into the backend — and the block cannot live there:
1249 * one executor drives sessions from several backends at once
1250 * (`create_node_on(name, rmw)`), timers fire off the platform clock, and
1251 * guard conditions fire from another thread or an ISR. A backend can
1252 * only block on its own handles. `next_deadline_ms` is exactly the piece
1253 * of `rmw_wait` that CANNOT be answered above the seam, and it is
1254 * already a slot; that is the decomposition working, not a gap.
1255 */
