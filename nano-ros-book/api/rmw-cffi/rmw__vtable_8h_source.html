4/* This header defines the GENERIC RMW ABI: its types are
5 * `rmw_publisher_t`, `rmw_ret_t`, and so on, with no vendor prefix, because a
6 * backend author implements RMW rather than nano-ros.
7 *
8 * That makes it impossible to share a translation unit with upstream's
9 * `<rmw/rmw.h>`, which defines the same names differently. Refuse LOUDLY rather
10 * than let one definition silently win a redefinition race — two types of one
11 * name whose layouts disagree is the class this repo has already paid for three
12 * times in hand-mirrored FFI structs.
13 *
14 * A target image never links real rmw, and host-side consumers reach the
15 * backend through Rust, so nothing in this repo trips this today. It exists for
16 * the day something does. */

81/* ---- Graph enumeration visitors ----
82 *
83 * Upstream returns `rcutils_string_array_t` and `rmw_names_and_types_t`, which
84 * ALLOCATE — two levels deep for names-and-types. There is no allocator at this
85 * seam, and a caller-provides-the-buffer shape is worse than it looks: the ROS
86 * graph has no bound the CALLER can know, so a 128 KiB image would have to
87 * reserve permanently for the worst graph it might ever meet, and the backend
88 * would still have to materialise the whole list to fill the buffer.
89 *
90 * So enumeration is a VISITOR. Peak extra RAM is one entry, the backend streams
91 * from state it already holds, and a caller with a bound stops early by
92 * returning `false` — a normal outcome, not a truncation error. Same shape as
93 * `process_raw_in_place` and `publish_streamed` already use here.
94 *
95 * Every string handed to a visitor is BORROWED for that call only.
96 */

179/* Teardown and loan-return REPORT.
180 *
181 * These six returned `void`. That was never a target constraint: upstream
182 * returns `rmw_ret_t` from all of them, and a backend that cannot release a
183 * handle — a queue still draining, a token from another publisher, a
184 * double-destroy — had no way to say so. The runtime then reported success it
185 * had not verified, which on an RTOS is the difference between a leak that
186 * shows up in a log and a leak that shows up as an allocation failure an hour
187 * later with no provenance.
188 *
189 * A caller that genuinely has nothing to do with the status may ignore it;
190 * `void` denied it the choice. Backends that cannot fail return
191 * `NROS_RMW_RET_OK` unconditionally, which costs one instruction and keeps the
192 * signature honest for the ones that can.

438 /* How status events map onto the three upstream parts.
439 *
440 * Upstream's model is three-part: `*_event_init` fills an `rmw_event_t`
441 * HANDLE, `rmw_event_set_callback` attaches a callback to that handle, and
442 * `rmw_take_event` polls it for a status.
443 *
444 * - `rmw_event_set_callback` is FUSED into `*_event_init`, which takes the
445 * callback directly. There is no handle to attach one to afterwards.
446 * What that costs is real and small: upstream can replace or clear a
447 * callback later, and we cannot.
448 *
449 * - `rmw_take_event` is a SLOT, split per entity kind
450 * because we have no `rmw_event_t` to carry the entity — see
451 * `subscription_take_event` / `publisher_take_event` below.
452 *
453 * It was DECLINED until 2026-08-25 on two clauses that both turned out
454 * false, and they are worth recording because each sounded right:
455 *
456 * "Upstream polls because the WAIT SET said one was ready, and the wait
457 * set is declined here, so a poll would be blind."
458 * — This ABI is a poll-WITHOUT-a-wait-set design by construction.
459 * `has_data`'s own doc says so: "the poll a loop with no wait-set
460 * needs, and it allocates nothing." A poll with no wait set is the
461 * model here, not a blindness.
462 *
463 * "Our callback already runs on the safe context — from inside
464 * `drive_io`, on the executor thread, never an ISR or a transport
465 * thread."
466 * — True of no backend. zenoh fires from `take` and
467 * `has_data`; cyclonedds' DDS listeners fire on Cyclone's own
468 * worker thread while its `drive_io` is a sleep with no callback
469 * path at all. So a cyclonedds status event has nowhere safe to be
470 * delivered from, and buffer-plus-poll IS `take_event`. A
471 * per-backend fact stated ABI-wide — the same shape as the
472 * network-flow decline W5 flipped.
473 */

1248 /* ---- Graph node lifecycle (optional) ----
1249 *
1250 * The rest of upstream's lifecycle group is deliberately absent, and the
1251 * absences are decisions rather than omissions:
1252 *
1253 * - `rmw_init` / `rmw_shutdown` / `rmw_context_fini` are
1254 * `create_session` / `destroy_session`. There is no second teardown
1255 * phase: the session shell is caller-owned, so there is nothing left to
1256 * free after the backend releases `backend_data`.
1257 *
1258 * - `rmw_init_options_{init,copy,fini}` have nothing to do here. Upstream
1259 * needs the trio because its options OWN heap and carry an
1260 * `rcutils_allocator_t`, which cannot cross this seam; ours is a
1261 * build-time POD, so "copy" is `=` and "fini" is nothing.
1262 *
1263 * This does NOT decide what the options CARRY. Of Humble's eight
1264 * fields, `create_session` takes `domain_id`; `implementation_identifier`
1265 * and `impl` are answered elsewhere (the identity slot,
1266 * `rmw_session_t::backend_data`); `allocator` is declined ABI-wide and
1267 * `instance_id` is rcl-side process identity. `security_options` is
1268 * declined on the target: it is a DDS-SROS2 keystore PATH plus an
1269 * enforcement switch, and neither a filesystem nor a security plugin
1270 * exists where this ABI runs. `localhost_only` and `enclave` are
1271 * CARRIED, by `create_session`'s NULLable `rmw_session_options_t`
1272 * (which closed the two gaps): Cyclone honours
1273 * `localhost_only` by restricting discovery to loopback, and a backend
1274 * with no discovery to restrict ignores both, as it does `mode`.
1275 *
1276 * `discovery_options` is NOT in this list: it is an IRON field, and the
1277 * recorded contract is Humble. It was named here once, the
1278 * third unchecked sentence about an upstream struct in this campaign.
1279 * Read the header, not the memory.
1280 *
1281 * - `rmw_wait`, the wait set, and the guard conditions are declined
1282 * together, because `has_data` / `has_request` + `drive_io` +
1283 * `set_wake_callback` + `next_deadline_ms` ARE upstream's `rmw_wait`,
1284 * decomposed. What a vtable `wait` would add is only the BLOCK, moved
1285 * from the platform into the backend — and the block cannot live there:
1286 * one executor drives sessions from several backends at once
1287 * (`create_node_on(name, rmw)`), timers fire off the platform clock, and
1288 * guard conditions fire from another thread or an ISR. A backend can
1289 * only block on its own handles. `next_deadline_ms` is exactly the piece
1290 * of `rmw_wait` that CANNOT be answered above the seam, and it is
1291 * already a slot; that is the decomposition working, not a gap.
1292 */
