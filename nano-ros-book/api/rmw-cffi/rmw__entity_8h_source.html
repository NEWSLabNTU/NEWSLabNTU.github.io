43/* Policy values carry UPSTREAM's numbering — phase-376 W5/B2.
44 *
45 * They did not until 2026-08-24, and the disagreement was not academic. Ours
46 * were a dense 0/1 pair per policy, which put a DIFFERENT meaning on the same
47 * integer:
48 *
49 * value | upstream | ours (before)
50 * ------|-----------------------------------|-------------------
51 * 0 | *_SYSTEM_DEFAULT | BEST_EFFORT / VOLATILE / KEEP_LAST
52 * 1 | RELIABLE / TRANSIENT_LOCAL / KEEP_LAST | RELIABLE / TRANSIENT_LOCAL / KEEP_ALL
53 *
54 * so `HISTORY == 1` meant KEEP_LAST to upstream and KEEP_ALL to us — the two
55 * opposite answers to the question. Liveliness was worse: MANUAL_BY_NODE and
56 * MANUAL_BY_TOPIC were SWAPPED (2 and 3).
57 *
58 * These values cross the ABI. `rmw_qos_profile_check_compatible` is a name
59 * upstream owns and we export, and the cyclonedds backend translates this
60 * struct into real DDS QoS that a ROS peer matches against. A caller reasoning
61 * in upstream's vocabulary got silently wrong policies. Same argument as W3.d
62 * step B for the return codes: where a value crosses the boundary, upstream's
63 * numbering is the only one that cannot be wrong.
64 *
65 * The names keep the `NROS_RMW_` prefix — as the return codes do — because the
66 * set is ours to extend, not upstream's to define.
67 */

266/* ====================================================================
267 * Phase 376 W4 — the two PURE functions.
268 *
269 * Plain exported C functions, deliberately NOT vtable slots, and the reason is
270 * the campaign's own rule read the other way round: a vtable slot is the
271 * mechanism for letting backends DIFFER, and these two must not. Both compute
272 * over types this header defines; if two backends disagreed about whether a QoS
273 * pair is compatible, or whether two gids name the same entity, that is a
274 * DEFECT with as many places to fix it as there are backends.
275 *
276 * Three supporting reasons:
277 *
278 * - The useful call sites have no vtable to dispatch through. QoS
279 * compatibility is wanted at `create_*` time (that is what produces
280 * `NROS_RMW_RET_INCOMPATIBLE_QOS`), in codegen'd validation, and in host
281 * tooling with no session. Neither function takes an entity, so a slot would
282 * force a caller to invent a session — and neither could be called BEFORE a
283 * backend registers, which is exactly when create-time validation runs.
284 *
285 * - Upstream is not evidence for a slot. `rmw_qos_profile_check_compatible`
286 * lives in `rmw/qos_profiles.h` and is defined by librmw ITSELF; it appears
287 * in the implementation contract only because each `librmw_*_cpp.so`
288 * statically links librmw and re-exports it. That is plugin packaging, not
289 * semantics, and we load no plugin.
290 *
291 * - Precedent: `nros_rmw_cffi_register_named` and friends are declared here
292 * and defined once in Rust with `#[no_mangle]`, so `nros-rmw-abi` stays a
293 * header-only INTERFACE target — no new compiled TU, no new link edge.
294 * (`static inline` was the alternative and is worse: bindgen does not emit
295 * it, so RFC-0054 would force a SECOND Rust implementation, which is the
296 * first reason again.)
297 * ==================================================================== */
