224/* ====================================================================
225 * Phase 376 W4 — the two PURE functions.
226 *
227 * Plain exported C functions, deliberately NOT vtable slots, and the reason is
228 * the campaign's own rule read the other way round: a vtable slot is the
229 * mechanism for letting backends DIFFER, and these two must not. Both compute
230 * over types this header defines; if two backends disagreed about whether a QoS
231 * pair is compatible, or whether two gids name the same entity, that is a
232 * DEFECT with as many places to fix it as there are backends.
233 *
234 * Three supporting reasons:
235 *
236 * - The useful call sites have no vtable to dispatch through. QoS
237 * compatibility is wanted at `create_*` time (that is what produces
238 * `NROS_RMW_RET_INCOMPATIBLE_QOS`), in codegen'd validation, and in host
239 * tooling with no session. Neither function takes an entity, so a slot would
240 * force a caller to invent a session — and neither could be called BEFORE a
241 * backend registers, which is exactly when create-time validation runs.
242 *
243 * - Upstream is not evidence for a slot. `rmw_qos_profile_check_compatible`
244 * lives in `rmw/qos_profiles.h` and is defined by librmw ITSELF; it appears
245 * in the implementation contract only because each `librmw_*_cpp.so`
246 * statically links librmw and re-exports it. That is plugin packaging, not
247 * semantics, and we load no plugin.
248 *
249 * - Precedent: `nros_rmw_cffi_register_named` and friends are declared here
250 * and defined once in Rust with `#[no_mangle]`, so `nros-rmw-abi` stays a
251 * header-only INTERFACE target — no new compiled TU, no new link edge.
252 * (`static inline` was the alternative and is worse: bindgen does not emit
253 * it, so RFC-0054 would force a SECOND Rust implementation, which is the
254 * first reason again.)
255 * ==================================================================== */
