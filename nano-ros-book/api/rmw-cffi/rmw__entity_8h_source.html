43/* Policy values carry UPSTREAM's numbering — phase-376 W5/B2.
44 *
45 * They did not until 2026-08-24, and the disagreement was not academic. Ours
46 * were a dense 0/1 pair per policy, which put a DIFFERENT meaning on the same
47 * integer:
48 *
49 * value | upstream | ours (before)
50 * ------|-----------------------------------|-------------------
51 * 0 | *_SYSTEM_DEFAULT | BEST_EFFORT / VOLATILE / KEEP_LAST
52 * 1 | RELIABLE / TRANSIENT_LOCAL / KEEP_LAST | RELIABLE / TRANSIENT_LOCAL / KEEP_ALL
53 *
54 * so `HISTORY == 1` meant KEEP_LAST to upstream and KEEP_ALL to us — the two
55 * opposite answers to the question. Liveliness was worse: MANUAL_BY_NODE and
56 * MANUAL_BY_TOPIC were SWAPPED (2 and 3).
57 *
58 * These values cross the ABI. `rmw_qos_profile_check_compatible` is a name
59 * upstream owns and we export, and the cyclonedds backend translates this
60 * struct into real DDS QoS that a ROS peer matches against. A caller reasoning
61 * in upstream's vocabulary got silently wrong policies. Same argument as W3.d
62 * step B for the return codes: where a value crosses the boundary, upstream's
63 * numbering is the only one that cannot be wrong.
64 *
65 * The names keep the `NROS_RMW_` prefix — as the return codes do — because the
66 * set is ours to extend, not upstream's to define.
67 */

376/* ====================================================================
377 * Phase 376 W4 — the two PURE functions.
378 *
379 * Plain exported C functions, deliberately NOT vtable slots, and the reason is
380 * the campaign's own rule read the other way round: a vtable slot is the
381 * mechanism for letting backends DIFFER, and these two must not. Both compute
382 * over types this header defines; if two backends disagreed about whether a QoS
383 * pair is compatible, or whether two gids name the same entity, that is a
384 * DEFECT with as many places to fix it as there are backends.
385 *
386 * Three supporting reasons:
387 *
388 * - The useful call sites have no vtable to dispatch through. QoS
389 * compatibility is wanted at `create_*` time (that is what produces
390 * `NROS_RMW_RET_INCOMPATIBLE_QOS`), in codegen'd validation, and in host
391 * tooling with no session. Neither function takes an entity, so a slot would
392 * force a caller to invent a session — and neither could be called BEFORE a
393 * backend registers, which is exactly when create-time validation runs.
394 *
395 * - Upstream is not evidence for a slot. `rmw_qos_profile_check_compatible`
396 * lives in `rmw/qos_profiles.h` and is defined by librmw ITSELF; it appears
397 * in the implementation contract only because each `librmw_*_cpp.so`
398 * statically links librmw and re-exports it. That is plugin packaging, not
399 * semantics, and we load no plugin.
400 *
401 * - Precedent: `nros_rmw_cffi_register_named` and friends are declared here
402 * and defined once in Rust with `#[no_mangle]`, so `nros-rmw-abi` stays a
403 * header-only INTERFACE target — no new compiled TU, no new link edge.
404 * (`static inline` was the alternative and is worse: bindgen does not emit
405 * it, so RFC-0054 would force a SECOND Rust implementation, which is the
406 * first reason again.)
407 * ==================================================================== */

740/* ---- Standard QoS profile constants ---- */
741/*
742 * Compound-literal macros rather than `static const` objects, so a profile is
743 * usable in every TU that includes this header with no storage and no
744 * initialisation order.
745 *
746 * **ONE STATEMENT PER PROFILE (phase-428 W10).** Every profile below is a
747 * single line through `NROS_RMW_QOS_PROFILE_FROM_POLICIES`, which is the ONLY
748 * place the fields that never vary between profiles — `_reserved0`, the three
749 * durations, `avoid_ros_namespace_conventions`, `_reserved1` — are written.
750 * They used to be written out per profile: 26 constants in one file held in
751 * agreement by eye, and the four profiles carrying a concrete liveliness had
752 * all drifted the same way while their doc comments asserted the drifted value
753 * was upstream's.
754 *
755 * **The values are UPSTREAM's, and this file is a TRANSCRIPTION of them.** An
756 * embedded image cannot include `rmw/qos_profiles.h` and an offline build has
757 * no ROS install to read, so the numbers have to live here. That makes them
758 * exactly the kind of copy that drifts, so they are not maintained by hand
759 * alone: `scripts/check-qos-profile-ssot.py` binds every profile below to the
760 * Rust SSoT (`nros_rmw::QoSProfile`'s `QOS_PROFILE_*` constants) and, when a
761 * ROS install is resolvable, re-derives both against
762 * `<prefix>/include/rmw/rmw/qos_profiles.h`. Edit a value here without the
763 * gate agreeing and the gate is what tells you.
764 *
765 * That named `scripts/check-qos-profile-table.py` from 2026-09-05 to phase-454
766 * W1, and NO SUCH SCRIPT EXISTED for any of it. Two gates were written for W10
767 * and the duplicate was deleted — correctly, one parser of one table — but this
768 * prose kept the deleted name, so the transcription claiming loudest to be
769 * checked was the one checked by nothing. W1 wrote the coverage the sentence
770 * had been describing, into the gate that survived.
771 */
772

798/* LIVELINESS IS THE SENTINEL IN EVERY CONCRETE PROFILE — phase-428 W10.
799 *
800 * `DEFAULT`, `SENSOR_DATA`, `SERVICES_DEFAULT` and `PARAMETERS` carried
801 * `NROS_RMW_LIVELINESS_AUTOMATIC` (1) until 2026-09-05, under doc comments
802 * reading "`rmw_qos_profile_default`-equivalent … automatic liveliness".
803 * Upstream's own initialisers say `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT`
804 * for all seven profiles, `rmw_qos_profile_unknown` excepted — there is no
805 * upstream profile that asks for AUTOMATIC. This is the F2 class: 0829 fixed
806 * `SYSTEM_DEFAULT`'s liveliness because that was the profile being looked at,
807 * and the four siblings carrying the same wrong value were not swept.
808 *
809 * THIS CHANGES WHAT A BACKEND COMPILES AGAINST, so what it does to the wire is
810 * stated rather than assumed. The two in-tree consumers of a changed macro are
811 * `nros-rmw-cyclonedds`'s `create_service` / `create_client`
812 * (`NROS_RMW_QOS_PROFILE_SERVICES_DEFAULT` when the caller passes NULL) and
813 * `nros-rmw-xrce`'s (same); the cyclone unit tests use `_DEFAULT`.
814 * - cyclonedds: `make_dds_qos` calls `dds_qset_liveliness` only when the kind
815 * is NOT the sentinel (`qos.cpp:99`), so AUTOMATIC(1) set
816 * `DDS_LIVELINESS_AUTOMATIC` + `DDS_INFINITY` explicitly and the sentinel
817 * omits the call — leaving Cyclone's own default, which the DDS spec fixes
818 * at AUTOMATIC with an infinite lease. Same offered QoS on the wire.
819 * - xrce: drops liveliness entirely (it lowers no liveliness field), so the
820 * value is unobservable there either way.
821 * - zenoh: reads no QoS field at all (phase-428 F1).
822 * A backend that starts honouring liveliness later sees the correct
823 * "middleware's choice" here rather than an unrequested AUTOMATIC.
824 */
