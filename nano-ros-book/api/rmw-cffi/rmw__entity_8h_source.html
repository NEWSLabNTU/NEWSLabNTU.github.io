43/* Policy values carry UPSTREAM's numbering — phase-376 W5/B2.
44 *
45 * They did not until 2026-08-24, and the disagreement was not academic. Ours
46 * were a dense 0/1 pair per policy, which put a DIFFERENT meaning on the same
47 * integer:
48 *
49 * value | upstream | ours (before)
50 * ------|-----------------------------------|-------------------
51 * 0 | *_SYSTEM_DEFAULT | BEST_EFFORT / VOLATILE / KEEP_LAST
52 * 1 | RELIABLE / TRANSIENT_LOCAL / KEEP_LAST | RELIABLE / TRANSIENT_LOCAL / KEEP_ALL
53 *
54 * so `HISTORY == 1` meant KEEP_LAST to upstream and KEEP_ALL to us — the two
55 * opposite answers to the question. Liveliness was worse: MANUAL_BY_NODE and
56 * MANUAL_BY_TOPIC were SWAPPED (2 and 3).
57 *
58 * These values cross the ABI. `rmw_qos_profile_check_compatible` is a name
59 * upstream owns and we export, and the cyclonedds backend translates this
60 * struct into real DDS QoS that a ROS peer matches against. A caller reasoning
61 * in upstream's vocabulary got silently wrong policies. Same argument as W3.d
62 * step B for the return codes: where a value crosses the boundary, upstream's
63 * numbering is the only one that cannot be wrong.
64 *
65 * The names keep the `NROS_RMW_` prefix — as the return codes do — because the
66 * set is ours to extend, not upstream's to define.
67 */

449/* ====================================================================
450 * Phase 376 W4 — the two PURE functions.
451 *
452 * Plain exported C functions, deliberately NOT vtable slots, and the reason is
453 * the campaign's own rule read the other way round: a vtable slot is the
454 * mechanism for letting backends DIFFER, and these two must not. Both compute
455 * over types this header defines; if two backends disagreed about whether a QoS
456 * pair is compatible, or whether two gids name the same entity, that is a
457 * DEFECT with as many places to fix it as there are backends.
458 *
459 * Three supporting reasons:
460 *
461 * - The useful call sites have no vtable to dispatch through. QoS
462 * compatibility is wanted at `create_*` time (that is what produces
463 * `NROS_RMW_RET_INCOMPATIBLE_QOS`), in codegen'd validation, and in host
464 * tooling with no session. Neither function takes an entity, so a slot would
465 * force a caller to invent a session — and neither could be called BEFORE a
466 * backend registers, which is exactly when create-time validation runs.
467 *
468 * - Upstream is not evidence for a slot. `rmw_qos_profile_check_compatible`
469 * lives in `rmw/qos_profiles.h` and is defined by librmw ITSELF; it appears
470 * in the implementation contract only because each `librmw_*_cpp.so`
471 * statically links librmw and re-exports it. That is plugin packaging, not
472 * semantics, and we load no plugin.
473 *
474 * - Precedent: `nros_rmw_cffi_register_named` and friends are declared here
475 * and defined once in Rust with `#[no_mangle]`, so `nros-rmw-abi` stays a
476 * header-only INTERFACE target — no new compiled TU, no new link edge.
477 * (`static inline` was the alternative and is worse: bindgen does not emit
478 * it, so RFC-0054 would force a SECOND Rust implementation, which is the
479 * first reason again.)
480 * ==================================================================== */

823/*
824 * Compound-literal macros rather than `static const` objects, so a profile is
825 * usable in every TU that includes this header with no storage and no
826 * initialisation order.
827 *
828 * **ONE STATEMENT PER PROFILE (phase-428 W10).** Every profile below is a
829 * single line through `NROS_RMW_QOS_PROFILE_FROM_POLICIES`, which is the ONLY
830 * place the fields that never vary between profiles — `_reserved0`, the three
831 * durations, `avoid_ros_namespace_conventions`, `_reserved1` — are written.
832 * They used to be written out per profile: 26 constants in one file held in
833 * agreement by eye, and the four profiles carrying a concrete liveliness had
834 * all drifted the same way while their doc comments asserted the drifted value
835 * was upstream's.
836 *
837 * **The values are UPSTREAM's, and this file is a TRANSCRIPTION of them.** An
838 * embedded image cannot include `rmw/qos_profiles.h` and an offline build has
839 * no ROS install to read, so the numbers have to live here. That makes them
840 * exactly the kind of copy that drifts, so they are not maintained by hand
841 * alone: `scripts/check-qos-profile-ssot.py` binds every profile below to the
842 * Rust SSoT (`nros_rmw::QoSProfile`'s `QOS_PROFILE_*` constants) and, when a
843 * ROS install is resolvable, re-derives both against
844 * `<prefix>/include/rmw/rmw/qos_profiles.h`. Edit a value here without the
845 * gate agreeing and the gate is what tells you.
846 *
847 * That named `scripts/check-qos-profile-table.py` from 2026-09-05 to phase-454
848 * W1, and NO SUCH SCRIPT EXISTED for any of it. Two gates were written for W10
849 * and the duplicate was deleted — correctly, one parser of one table — but this
850 * prose kept the deleted name, so the transcription claiming loudest to be
851 * checked was the one checked by nothing. W1 wrote the coverage the sentence
852 * had been describing, into the gate that survived.
853 */

880/* LIVELINESS IS THE SENTINEL IN EVERY CONCRETE PROFILE — phase-428 W10.
881 *
882 * `DEFAULT`, `SENSOR_DATA`, `SERVICES_DEFAULT` and `PARAMETERS` carried
883 * `NROS_RMW_LIVELINESS_AUTOMATIC` (1) until 2026-09-05, under doc comments
884 * reading "`rmw_qos_profile_default`-equivalent … automatic liveliness".
885 * Upstream's own initialisers say `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT`
886 * for all seven profiles, `rmw_qos_profile_unknown` excepted — there is no
887 * upstream profile that asks for AUTOMATIC. This is the F2 class: 0829 fixed
888 * `SYSTEM_DEFAULT`'s liveliness because that was the profile being looked at,
889 * and the four siblings carrying the same wrong value were not swept.
890 *
891 * THIS CHANGES WHAT A BACKEND COMPILES AGAINST, so what it does to the wire is
892 * stated rather than assumed. The two in-tree consumers of a changed macro are
893 * `nros-rmw-cyclonedds`'s `create_service` / `create_client`
894 * (`NROS_RMW_QOS_PROFILE_SERVICES_DEFAULT` when the caller passes NULL) and
895 * `nros-rmw-xrce`'s (same); the cyclone unit tests use `_DEFAULT`.
896 * - cyclonedds: `make_dds_qos` calls `dds_qset_liveliness` only when the kind
897 * is NOT the sentinel (`qos.cpp:99`), so AUTOMATIC(1) set
898 * `DDS_LIVELINESS_AUTOMATIC` + `DDS_INFINITY` explicitly and the sentinel
899 * omits the call — leaving Cyclone's own default, which the DDS spec fixes
900 * at AUTOMATIC with an infinite lease. Same offered QoS on the wire.
901 * - xrce: drops liveliness entirely (it lowers no liveliness field), so the
902 * value is unobservable there either way.
903 * - zenoh: reads no QoS field at all (phase-428 F1).
904 * A backend that starts honouring liveliness later sees the correct
905 * "middleware's choice" here rather than an unrequested AUTOMATIC.
906 */
