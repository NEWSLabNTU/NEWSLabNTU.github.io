43/* Policy values carry UPSTREAM's numbering — phase-376 W5/B2.
44 *
45 * They did not until 2026-08-24, and the disagreement was not academic. Ours
46 * were a dense 0/1 pair per policy, which put a DIFFERENT meaning on the same
47 * integer:
48 *
49 * value | upstream | ours (before)
50 * ------|-----------------------------------|-------------------
51 * 0 | *_SYSTEM_DEFAULT | BEST_EFFORT / VOLATILE / KEEP_LAST
52 * 1 | RELIABLE / TRANSIENT_LOCAL / KEEP_LAST | RELIABLE / TRANSIENT_LOCAL / KEEP_ALL
53 *
54 * so `HISTORY == 1` meant KEEP_LAST to upstream and KEEP_ALL to us — the two
55 * opposite answers to the question. Liveliness was worse: MANUAL_BY_NODE and
56 * MANUAL_BY_TOPIC were SWAPPED (2 and 3).
57 *
58 * These values cross the ABI. `rmw_qos_profile_check_compatible` is a name
59 * upstream owns and we export, and the cyclonedds backend translates this
60 * struct into real DDS QoS that a ROS peer matches against. A caller reasoning
61 * in upstream's vocabulary got silently wrong policies. Same argument as W3.d
62 * step B for the return codes: where a value crosses the boundary, upstream's
63 * numbering is the only one that cannot be wrong.
64 *
65 * The names keep the `NROS_RMW_` prefix — as the return codes do — because the
66 * set is ours to extend, not upstream's to define.
67 */

373/* ====================================================================
374 * Phase 376 W4 — the two PURE functions.
375 *
376 * Plain exported C functions, deliberately NOT vtable slots, and the reason is
377 * the campaign's own rule read the other way round: a vtable slot is the
378 * mechanism for letting backends DIFFER, and these two must not. Both compute
379 * over types this header defines; if two backends disagreed about whether a QoS
380 * pair is compatible, or whether two gids name the same entity, that is a
381 * DEFECT with as many places to fix it as there are backends.
382 *
383 * Three supporting reasons:
384 *
385 * - The useful call sites have no vtable to dispatch through. QoS
386 * compatibility is wanted at `create_*` time (that is what produces
387 * `NROS_RMW_RET_INCOMPATIBLE_QOS`), in codegen'd validation, and in host
388 * tooling with no session. Neither function takes an entity, so a slot would
389 * force a caller to invent a session — and neither could be called BEFORE a
390 * backend registers, which is exactly when create-time validation runs.
391 *
392 * - Upstream is not evidence for a slot. `rmw_qos_profile_check_compatible`
393 * lives in `rmw/qos_profiles.h` and is defined by librmw ITSELF; it appears
394 * in the implementation contract only because each `librmw_*_cpp.so`
395 * statically links librmw and re-exports it. That is plugin packaging, not
396 * semantics, and we load no plugin.
397 *
398 * - Precedent: `nros_rmw_cffi_register_named` and friends are declared here
399 * and defined once in Rust with `#[no_mangle]`, so `nros-rmw-abi` stays a
400 * header-only INTERFACE target — no new compiled TU, no new link edge.
401 * (`static inline` was the alternative and is worse: bindgen does not emit
402 * it, so RFC-0054 would force a SECOND Rust implementation, which is the
403 * first reason again.)
404 * ==================================================================== */

737/* ---- Standard QoS profile constants ---- */
738/*
739 * Compound-literal macros rather than `static const` objects, so a profile is
740 * usable in every TU that includes this header with no storage and no
741 * initialisation order.
742 *
743 * **ONE STATEMENT PER PROFILE (phase-428 W10).** Every profile below is a
744 * single line through `NROS_RMW_QOS_PROFILE_FROM_POLICIES`, which is the ONLY
745 * place the fields that never vary between profiles — `_reserved0`, the three
746 * durations, `avoid_ros_namespace_conventions`, `_reserved1` — are written.
747 * They used to be written out per profile: 26 constants in one file held in
748 * agreement by eye, and the four profiles carrying a concrete liveliness had
749 * all drifted the same way while their doc comments asserted the drifted value
750 * was upstream's.
751 *
752 * **The values are UPSTREAM's, and this file is a TRANSCRIPTION of them.** An
753 * embedded image cannot include `rmw/qos_profiles.h` and an offline build has
754 * no ROS install to read, so the numbers have to live here. That makes them
755 * exactly the kind of copy that drifts, so they are not maintained by hand
756 * alone: `scripts/check-qos-profile-ssot.py` binds every profile below to the
757 * Rust SSoT (`nros_rmw::QoSProfile`'s `QOS_PROFILE_*` constants) and, when a
758 * ROS install is resolvable, re-derives both against
759 * `<prefix>/include/rmw/rmw/qos_profiles.h`. Edit a value here without the
760 * gate agreeing and the gate is what tells you.
761 *
762 * That named `scripts/check-qos-profile-table.py` from 2026-09-05 to phase-454
763 * W1, and NO SUCH SCRIPT EXISTED for any of it. Two gates were written for W10
764 * and the duplicate was deleted — correctly, one parser of one table — but this
765 * prose kept the deleted name, so the transcription claiming loudest to be
766 * checked was the one checked by nothing. W1 wrote the coverage the sentence
767 * had been describing, into the gate that survived.
768 */

795/* LIVELINESS IS THE SENTINEL IN EVERY CONCRETE PROFILE — phase-428 W10.
796 *
797 * `DEFAULT`, `SENSOR_DATA`, `SERVICES_DEFAULT` and `PARAMETERS` carried
798 * `NROS_RMW_LIVELINESS_AUTOMATIC` (1) until 2026-09-05, under doc comments
799 * reading "`rmw_qos_profile_default`-equivalent … automatic liveliness".
800 * Upstream's own initialisers say `RMW_QOS_POLICY_LIVELINESS_SYSTEM_DEFAULT`
801 * for all seven profiles, `rmw_qos_profile_unknown` excepted — there is no
802 * upstream profile that asks for AUTOMATIC. This is the F2 class: 0829 fixed
803 * `SYSTEM_DEFAULT`'s liveliness because that was the profile being looked at,
804 * and the four siblings carrying the same wrong value were not swept.
805 *
806 * THIS CHANGES WHAT A BACKEND COMPILES AGAINST, so what it does to the wire is
807 * stated rather than assumed. The two in-tree consumers of a changed macro are
808 * `nros-rmw-cyclonedds`'s `create_service` / `create_client`
809 * (`NROS_RMW_QOS_PROFILE_SERVICES_DEFAULT` when the caller passes NULL) and
810 * `nros-rmw-xrce`'s (same); the cyclone unit tests use `_DEFAULT`.
811 * - cyclonedds: `make_dds_qos` calls `dds_qset_liveliness` only when the kind
812 * is NOT the sentinel (`qos.cpp:99`), so AUTOMATIC(1) set
813 * `DDS_LIVELINESS_AUTOMATIC` + `DDS_INFINITY` explicitly and the sentinel
814 * omits the call — leaving Cyclone's own default, which the DDS spec fixes
815 * at AUTOMATIC with an infinite lease. Same offered QoS on the wire.
816 * - xrce: drops liveliness entirely (it lowers no liveliness field), so the
817 * value is unobservable there either way.
818 * - zenoh: reads no QoS field at all (phase-428 F1).
819 * A backend that starts honouring liveliness later sees the correct
820 * "middleware's choice" here rather than an unrequested AUTOMATIC.
821 */
