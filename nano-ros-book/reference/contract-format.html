Contract format reference

Reference · Level 3: Production and tuning

Every key a contract file (<stem>.contract.yaml beside a launch file, or system.contract.yaml in a bringup with no launch/) accepts. The contract format is ros-launch-manifest’s, and this page is its format reference at v0.3.14, the release the nros CLI is built against (commit 7834e5f610e6). The CLI reads a contract with that release’s parser, so a key this page does not list is a parse error.

To write a contract for your own nodes, see Tell the build what your system creates.

Every key below is accepted in the context that heads its section, and a key that is not listed is a parse error. Contexts whose keys are chosen by the author — nodes:, topics:, services:, actions:, includes:, paths:, args:, external_topics:, the endpoint maps under pub:/sub:/srv:/cli:, and the parameter names under a node’s params: — have no section here, because no allowlist applies to them.

This is the core grammar. A contract that use:s an extension may also write the keys that extension declares, in hazards.<name> and safe_state.settle: those are listed per extension in extension-reference.md (the bundled vehicle.braking and the reference extensions), and extension-guide.md says how to write one.

The kind column is the rule of contract-primitives.md as data: a fact is what the code does, a requirement is what it must achieve, meta is structure, and a consequence is computable from the facts — a second copy the graph already knows, kept only where the graph has no answer (an external source). scripts/derivation_census.py counts how often each consequence agrees.

manifest

keykindstatusmeaning
versionmetaManifest format version. Absent means 1.
usemetaThe extensions this contract uses, a map of name -> version requirement (use: { vehicle.braking: "^1" }; ^, ~, = or >=). With it, hazards.<name> and safe_state.settle may carry the keys those extensions declare; without it an unknown key is an error.
rlmmetasince v0.1.49The grammar release this file needs, v<major>.<minor>.<patch> (or >= that). Checked before any other key: a checker whose grammar is older refuses the file naming both releases, instead of refusing the first key it does not know as if it were a typo. A checker before v0.1.49 refuses the key itself as unknown. Optional; beside version, which is the file format and stays 1.
argsmetaArguments this manifest requires, supplied by the launch scope.
exclude_patternsremovedRemoved — it was parsed and read by nothing, so it excluded nothing. Mark an expected-absent side with external:.
nodesmetaNode declarations, keyed by bare node name.
topicsmetaTopic declarations, keyed by topic name.
servicesmetaService declarations, keyed by service name.
actionsmetaAction declarations, keyed by action name.
includesmetaChild scopes, each an inline manifest (the file-reference form was removed in v0.1.59).
pathsmetaEvent chains: end-to-end requirements naming two topics and a budget.
hazardsmetaHazards: what is watched, how long the system has, and which path reaches the safe state.
functionsmetaNamed guard groups: what a set of topics together provides. A mode requires functions; a hazard may guard one by name.
modesmetaOperational modes: what each requires, and the fallback sequence (the ordered degradation levels) to fall to when it is lost.
independencerequirementsince v0.3.13Independence requirements, a list of { of, not_sharing }: the nodes or functions in of share none of the deployment facts in not_sharing, pairwise (independence-violated). Freedom from interference between nodes of different integrity in one process is derived, with no key (interference-shared-process).
severity_levelsremovedRenamed integrity_levels: in v0.3.3: an ASIL, SIL or DAL is an integrity level, and ISO 26262’s severity is the S0-S3 class it is derived from. play_launch migrate <contract> --write rewrites it.
integrity_levelsmetasince v0.3.3The integrity scale hazards draw from, ascending; the first entry derives no criticality. Default: QM, ASIL_A..ASIL_D (ISO 26262), so writing that scale out changes nothing and is only for the reader. A contract that uses a profile takes the profile’s scale and may not also write this.
external_topicsdeprecated — use topics.<name>.externalDeprecated in v0.1.59: the second place for the fact topics.<name>.external states. Move each entry under topics: as <name>: { external: <side>, type, qos }; play_launch migrate does it. Removed in the next grammar release.
chainsremovedRemoved — state the requirement as an event chain and let the route be derived.
ifmetaOnly on an INLINE includes: entry, whose value is a nested manifest: include this child only when the condition holds. Refused at the root of a standalone manifest.
unlessmetaOnly on an INLINE includes: entry: include this child unless the condition holds. Refused at the root of a standalone manifest.
policymetasince v0.1.61Project policy for the consumer’s rules: { unsupervised_measured: warn | error }. Absent: the defaults.
linksfactsince v0.3.4Named links: <name>: { max_transport, clock, monitor }, one transport stated once, with its source. A subscriber names the link its hop crosses (sub.<ep>.link). Visible to this manifest and its inline includes.
supervisionfactsince v0.1.61The platform terms of a supervised budget’s detection delay, stated once: { tick, switch }. Read by the consumer’s overrun case (supervised-fit); required once any budget states supervise:.
acknowledgedmetasince v0.2.3Findings the author has read and keeps: a list of { rule, at, reason }, at the contract’s root only. The consumer reports a warning or info whose rule id and path match an entry as acknowledged, with the reason, and counts it apart from the warnings; an entry matching an error is itself an error (errors cannot be acknowledged), and one matching nothing is a warning, so an acknowledgement cannot outlive its finding.
letmetasince v0.2.4Names for values, stated once and read as $(let <name>): a mapping of name to value, in order, at the contract’s root. An entry may read earlier entries (and $(param), $(var)); a forward reference or a cycle is an error. Separate from launch configurations: $(var) never reads it.

nodes.<name>

keykindstatusmeaning
ifmetaInclude this node only when the condition holds.
unlessmetaInclude this node unless the condition holds.
lifecyclefactTrue for a ROS 2 managed node; runtime monitors skip checks until it is Active.
pubmetaPublisher endpoints, keyed by endpoint name. A key is a LOCAL name: the node’s FQN is prefixed to it, so a / in a key is refused; connect the topic with a launch remap or a topics: entry.
submetaSubscriber endpoints, keyed by endpoint name. A key is a LOCAL name: the node’s FQN is prefixed to it, so a / in a key is refused; connect the topic with a launch remap or a topics: entry.
srvmetaService server endpoints, keyed by LOCAL endpoint name. Not neutral when omitted: a consumer sizes the image’s pools from this list (an embedded realizer derives its service counts from it), so a server the code creates and the contract leaves out is found at boot, not here.
climetaService client endpoints, keyed by LOCAL endpoint name. Not neutral when omitted, for the same reason as srv:: pools are sized from the list. A reaction route crosses a client -> server edge as a message (the resolver’s reaction walk); a server with no path its request triggers latches the request for its own timer, and the walk charges that timer’s period as a sampling hop.
pathsmetaThis node’s internal paths, keyed by path name.
criticalityconsequenceScheduling criticality: high
concurrencyfactWhich of this node’s paths may NOT run concurrently. Absent means all of them serialize: every path of the node waits for any other that is running (a single-threaded executor), and the checker charges that wait (path-exclusion). Declare exclusive groups to say which may in fact overlap.
paramsfactParameters this node declares, keyed by name, each { type: <ROS 2 type> }. Names and types only: a string or array capacity is a board fact, not a contract one. params: {} means the node declares no parameters; a missing params: means not stated. The two stay distinct in the model: {} becomes an empty contracts.node_params entry, a missing key none.

pub/sub/cli.<endpoint>

keykindstatusmeaning
min_rate_hzfact (pub) / requirement (sub)Lower bound on this endpoint’s rate. A REQUIREMENT, not a mechanism: nothing fires when a period passes. A fault is detected only by a mechanism that does – a QoS lease_duration or deadline, or a max_age someone evaluates (on_violation.mechanism) – so min_rate_hz never counts as a hazard’s detector. A publisher that promises no rate states aperiodic: true instead of leaving this out.
max_rate_hzfact (pub) / requirement (sub)Upper bound on this endpoint’s rate.
max_agerequirementSubscriber: maximum data age at receive (now - header.stamp).
max_age_msremovedRemoved — write max_age: <n>ms (or ns/us/s). The unit in a NAME is what lets a value be 1000x wrong and still parse.
statefactSubscriber: read-latest rather than causal. The node caches the message and a timer path reads it, so a reaction arriving here waits for that timer: the walk charges one period (the timer’s jitter too, when stated) as a sampling hop, shown as (+Nms sampling) in a route.
requiredfactSubscriber: this endpoint must be connected.
qosfactQoS overrides for this endpoint.
max_transportrequirementClient (since v0.2.5): the request leg’s worst-case transport, overriding the service’s max_transport; charged on a reaction route’s success branch through the call. Subscriber: the worst-case transport into THIS subscriber, overriding the topic’s (one topic does not have one cost: in-process, another process, another machine). Charged in path and chain latencies, and in a hazard’s reaction route on the GUARD EDGE (the hop into the subscriber that detects the fault), but not after a dwell’s deadline, which the dwelling level’s owner reads on its own clock. A declaration on no guard edge changes no hazard’s numbers (declared-not-charged).
linkfactsince v0.3.4Subscriber only: the link this subscriber’s hop crosses, a name under links:. The link’s max_transport is this subscriber’s, charged wherever a written one is; writing both is refused. A written max_transport stays legal and is reported as transport-inline.
max_transport_msremovedRemoved — write max_transport: <n>ms (or ns/us/s). The unit in a NAME is what lets a value be 1000x wrong and still parse.
on_violationrequirementThe reaction this subscriber owes when its assumption is violated.
ingressremovedRenamed arrival_curve: in v0.3.7: a token bucket bounding what arrives is network calculus’s arrival curve. play_launch migrate <contract> --write rewrites it.
arrival_curverequirementsince v0.3.7Subscriber: what this endpoint is made to ABSORB, an arrival curve in token-bucket form (network calculus: rate ρ, burst σ) { rate_hz, burst }. Not a QoS policy, and not the rate it needs (min_rate_hz): a consumer bounds the device’s read path and the router’s pacing by it. Both keys required, so an unstated burst never reads as unbounded. Refused under pub:/cli:.
min_interarrivalrequirementsince v0.1.68Subscriber: the least time between two arrivals. Its callback is then a sporadic task (T_min). An event input with no rate bound, no min_interarrival and no budget is unanalysable: a consumer that supervises a deadline refuses it. Refused under pub:/cli:, and above 1 / min_rate_hz.
budgetrequirementsince v0.1.68Subscriber: the execution time its callback may use per budget_period. Its callback is then served (a server of budget Q per period P, analysed as a periodic task). Requires budget_period, and may not exceed it. Refused under pub:/cli:.
budget_periodrequirementsince v0.1.68Subscriber: the server period P of budget. Only beside budget.
callfactsince v0.1.69Client: how the code waits for the response. blocking: the callback that sends the request waits for it, so under a preemptive executor the server must run at a more urgent level (a less urgent one is a priority inversion, its own level a deadlock). async: the request is sent and a later callback takes the response. Absent means not stated: a consumer checks a stated call and reports an unstated one. Refused under pub:/sub:.
timeoutfactsince v0.2.5Client: how long the code waits for the response before it gives up (a duration, $(param …)-capable): spin_until_future_complete with a timeout, a pending-request prune, a tick-counting poll. A fact about the code, not a requirement. Absent means the client may wait forever (rclcpp’s default), so a reaction route through the call is unbounded unless the degradation level is supervised (call-unbounded). Refused under pub:/sub:.
on_timeoutfactsince v0.2.5Client: what the code does when timeout passes, { reaction: <mode | event chain> } or { retry: { attempts, backoff }, then: { reaction } }. A route through the call is charged the worse of the success branch and timeout x attempts + backoff x (attempts - 1) + this reaction’s route. Refused under pub:/sub:.
on_rejectedfactsince v0.2.5Client: what the code does when the server answers and refuses (success: false), { reaction: <mode | event chain> }. Needed when the route continues at the client after a blocking call (call-rejected-unhandled). Refused under pub:/sub:.
bufferfactBuffering discriminator for a state subscriber: latest
on_demandremovedRenamed aperiodic: in v0.3.7: an activation with no period and no minimum separation is an aperiodic task. play_launch migrate <contract> --write rewrites it.
aperiodicfactsince v0.3.7Publisher: aperiodic – publishes only when asked (a service call, an operator) and promises no rate. Unlike an omitted min_rate_hz, which says nothing, this is acted on: no rate is derived for the topic, no runtime rate monitor is generated for the endpoint, and a subscriber’s min_rate_hz or a topic rate_hz against it is a rate-hierarchy error. Refused beside min_rate_hz, and under sub:/cli:.
jitterremovedRemoved — jitter is a property of a route, not one publisher. Use max_jitter on a path.
jitter_msremovedRemoved — see jitter.

keykindstatusmeaning
descriptionmetaWhat this mode is.
requiresfactFunctions (or bare topics) this mode needs; it is available while every one holds.

Values read from the launch tree

A quantity may READ a number instead of restating it: a duration, a rate, a count, the duration: or value: of a braces form, a QoS duration, and an extension key typed param. The value is an expression:

value  := term (('+' | '-') term)*
term   := factor (('*' | '/') factor)*
factor := number unit? | ref unit | '$(let' name ')' | '(' value ')'
ref    := '$(param' [node] name ')' | '$(var' name ['@' node] ')'
referencereads
$(param [<node>] <name>)the node’s effective parameter value; one argument: the node the key sits under; a bare node: a node key of this contract; /<fqn>: any node of the launch tree
$(var <name> [@<node>])a launch configuration, at the end of the contract’s launch file (or where <node> was declared)
$(let <name>)an entry of the root let:

A $(param) or $(var) takes a unit, always ($(param watchdog_ms) ms): a parameter carries none, and reading it in SI would make a 100 ms lease a 100 s one. On a count it takes none. A $(let) carries its entry’s unit. Units are rlx’s (extension-reference.md); a value of the wrong dimension for its key is param-dimension. source: beside a reference is a parse error (source-on-reference): the reference is the value’s source. A value with no reference is the literal it always was.

The consumer that holds the launch tree evaluates every reference per scope instance and hands each rule a plain number; a contract read alone leaves the value unknown (the key absent), never zero.

Integrity level to criticality

A node a hazard reaches (it feeds, detects for, or reacts for the hazard) takes a scheduling criticality from the hazard’s integrity, the MAX over every hazard that reaches it. The first entry of integrity_levels is “no safety requirement” and derives nothing; the other n entries split into three buckets by ceil(3 rank / n) (1 low, 2 medium, 3 high). A written criticality on such a node is an error; on a node no hazard reaches it stands. The default scale (no integrity_levels declared):

integritycriticality
QMnone
ASIL_Alow
ASIL_Bmedium
ASIL_Chigh
ASIL_Dhigh

A contract that uses a profile (use: { iec61508: "^1" }) draws integrity levels from the profile’s integrity_scale and takes each level’s criticality from the profile’s criticality map, stated level by level, instead of the split above; it may not also write integrity_levels:. Reference profiles ship with the checker: iso26262, iec61508, iec61511, do178c, iec62304, iso13849, en50129 (iso26262 is the default scale and map above).
